# EZD-029 · Spike: DXF parser

Verdict: go

## Question the spike answered
Can dxf-parser read the DXF content a reference drawing needs (linework, blocks, hatches, text, dims, model and paper space, layers), count what it does not read, and parse a large file inside the production function limits (Q-0027 (a): 300 s, 2 GB)? Can the Named tools writer produce a DXF the parser reads back? (R26 R9, R16; 02 Stack DXF in/out; 08 Architect drawings)

## What was tried
dxf-parser 1.1.2 plus the spike's own HATCH handler (1.1.2 ships none; registered through `registerEntityHandler`); `@tarikjabiri/dxf` 2.9.0 as writer; Node v22.23.3. Spike code: spikes/EZD-029-dxf (tests T1-T10 pass, 17 of 17 in the files). Data: the synthetic fixture fixtures/synthetic/room-12x10.dxf and a generated 150,000-entity stand-in (hand-built from DXF Reference group codes; checked only by the raw scanner and the parser). Limits emulated locally with `--max-old-space-size=2048` and a 300 s kill (not the platform).

## Result
- Synthetic fixture: 22 entities in the file, 22 read, none unread; 1.4 ms; peak 49.8 MB.
- Stand-in (150,000 entities plus 43 block entities, 16.4 MB): all read, none unread; 436 ms (parse 281 ms); peak 401 MB; fits one job slice.
- Writer: $ACADVER AC1021, $INSUNITS 1; the 26 entities on 5 named layers (including Z-MARKUP-WP) read back in full.
- calc-auditor re-derived units (inches), 1/64 in tolerance, angles, stand-in counts and the writer round trip: PASS. Code review PASS; security review PASS (dependency flags only).
- Not done: no real architect DXF supplied yet (decisions.md Still pending; Q-0065). The verdict rests on the generated stand-in. When Josh supplies files, run `spike-real` (README) and record the result here; a failure on a real file reopens this note.

## Decision
Use dxf-parser (read) and @tarikjabiri/dxf (write); recorded in docs/architecture.md `### DXF (EZD-029)`. Carry-overs:
- EZD-901a: carry `hatch-handler.mjs`; import the parser as the default export (the named `DxfParser` is undefined at run time in Node ESM); decoding rule (latin1 to find $ACADVER, UTF-8 from AC1021); binary DXF reported unreadable; unread-count method.
- EZD-905: paper-space and layout exposure via `inPaperSpace`.
- EZD-913, EZD-911: writer facts. BLOCK/INSERT, DIMENSION, pattern hatches and paper space are in the API but were not written or round-tripped; line weight (group 370) not written. Check these before relying on them.
- Stand-in paper-space text sits above the 24 in sheet (y 24.75); test input only.
