# EZD-031 · Spike: render trial

Verdict: go (stub run only; Josh's live trial and provider pick come after Phase 10, Q-0082)

## Question the spike answered
Can one script send the same 3D room image and instruction to Gemini image, GPT Image 2 and Flux Kontext pro, save each output image and a cost record per render (Q-0016)?

## What was tried
`spikes/EZD-031-render/` (TypeScript, run with `tsx`) calls EZD-021's three image adapters directly. Stub run on a synthetic 2 x 2 PNG and recorded responses, 52 spike tests passing (vitest 5.0.5). No live call was made; agents hold no keys.

## Result
Stub run: 3 ok renders, 124,240 micro-dollars estimated (`out/stub-run/costs.json`, contact sheet `index.html`, CSV). Live mode refuses CI, no terminal, no cap, and needs a typed `yes`. Default models and rates were read from official pages on 2026-10-23 (R-014): `gemini-3.1-flash-image`, `gpt-image-2`, `flux-kontext-pro`; Gemini 0.50/60 and OpenAI 8/30 per million tokens; Kontext price is null (no official page states it). Billed cost per render is recorded by Josh after the live run.

## Decision
The build uses the script as is. Josh runs it by hand (`spike-live`, README) with his keys, rooms manifest and `--max-usd`, then picks the provider. His pick confirms or changes R21 and re-plans EZD-1103 and EZD-1121. Open: `gpt-image-2` as the edit endpoint id is first tested live (OpenAI's pages disagree).
