# EZD-027 · Spike: plan canvas on the tablet

Verdict: go

## Question the spike answered

Can one persistent Three.js orthographic canvas draw the benchmark plan (150,000 line segments in 10 layers, 3,000 symbols, 3,000 labels) inside the tablet budget of 11 Budgets: frames every 33 ms (30 fps), no frame over 100 ms (Q-0061 (a), Q-0097 (a)), with the countable rules of 11 rule 4 (one atlas, few draw calls, nothing rebuilt per frame, no idle rendering)?

## What was tried

- Plain `three` 0.186.1 (the pinned row), spike package `spikes/EZD-027-canvas/` (merged 661bd4a), synthetic seeded scene (seed 27, 960 × 720 extent): one line buffer per layer, instanced symbols, all labels as instanced quads from one 512 × 512 DM Mono glyph atlas. Scripted pan and zoom, 3 measured passes of 3,000 ms after a warm-up.
- Automated runs (builder, 2026-10-23, `spikes/EZD-027-canvas/README.md` Findings): unit tests U1–U8 and D1 9 of 9 pass; browser tests B1–B4 pass (B1 in `desktop` and `ipad-landscape`; B2–B4 desktop only by design).
- Field run (Josh, 2026-10-24 01:00–01:02 UTC): served from the Mac build machine on the office network (`server.mjs --lan`, `http://192.168.1.116:4027/?device=surface`), opened in Edge on Josh's Windows machine. **Josh decided this Windows machine is the verdict device (Q-0263, overriding the Surface of Q-0088 for this verdict).** Results: `vault/spikes/EZD-027-results/windows-main-20261024T010056Z.json`, `windows-labels15000-20261024T010148Z.json`, `windows-dpr1-20261024T010216Z.json`.

Verdict rule (vault/plans/EZD-027.md Step 10):
1. Countable tests pass (README Findings): pass. Every field frame: 21 draw calls, 150,000 lines, 64,500 triangles (256,500 with 15,000 labels); 21 geometries, 1 texture; 1 context, 1 canvas; 0 buffers rebuilt during the script; 0 renders in the 2,000 ms idle window.
2. p95 ≤ 34.33 ms and max ≤ 100 ms on the verdict device: pass (33.4 ms, 50.1 ms).
3. No reload, blank page or error: Josh reported the testing complete and raised no problem; all three runs saved complete results files. Memory recorded: JS heap 10,535,946 bytes (main), 13,010,017 (stress); GPU buffers 4,178,040 bytes (5,714,040 stress); atlas texture 1,048,576 bytes.
4. Build-PC desktop run (recorded only, Q-0063 (a)): not run on the Mac build machine for this note. The automated `desktop` run was software WebGL (SwiftShader), not a desktop result.

Other numbers: build 59.7 ms, first frame 768 ms (main run). Frame intervals fall on 16.7 / 33.3 / 50 ms steps: the page holds 60 fps most of the time and drops single frames, while the drawing work itself stays near 1 ms per frame, so the dropped frames come from the integrated GPU, not from the app's code. Five times the text changed p95 not at all.

Not measured: no real iPad (Josh has none, Q-0053), so the iPad-only warning of 11 Also ("Safari memory limits can crash large 3D scenes") is untested on hardware; the Surface itself was not measured (Q-0263). The automated `ipad-landscape` run was WebKit on a Mac GPU (p95 18 ms), not Safari on an iPad.

## Decision

Go: the build keeps the canvas design of 02 Stack and 11 rule 4 as built in the spike. Phase 2 may start (next_ticket.mjs `spikeNote` checkpoint).
