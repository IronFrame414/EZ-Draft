1. Chunk size: the docs say "Chunk size (required, 6MB): ... it must be set to 6MB (for now) do not change it", with the code `6 * 1024 * 1024`. Source: https://supabase.com/docs/guides/storage/uploads/resumable-uploads (JavaScript example comment). The prose does not say "must" versus "recommended" beyond that comment.
2. Storage source: `partSize: tusPartSize * 1024 * 1024` in https://raw.githubusercontent.com/supabase/storage/master/src/http/routes/tus/index.ts, with the value of `tusPartSize` not shown in that file. The docs do not state the chunk size as a requirement elsewhere.
3. Signed upload token: the docs say the returned token goes "in the `x-signature` header of the resumable upload" and that resumable uploads "support using signed upload tokens to create time-limited URLs". Source: https://supabase.com/docs/guides/storage/uploads/resumable-uploads (Presigned uploads section). Source code confirms `allowedHeaders` includes `x-signature` and that a missing or non-string header throws "Missing x-signature header" (index.ts and lifecycle.ts in the same tus folder: https://raw.githubusercontent.com/supabase/storage/master/src/http/routes/tus/lifecycle.ts).
4. Sign endpoint path: NOT stated in the docs. The docs give only `https://${projectId}.storage.supabase.co/storage/v1/upload/resumable`. The JS client's `createSignedUploadUrl` posts to `${url}/object/upload/sign/${bucket}/${path}` (https://github.com/supabase/storage-js/blob/master/src/packages/StorageFileApi.ts). I could not confirm a `/storage/v1/upload/resumable/sign` route in the sources read; the tus routes file lists only POST `/`, PUT, PATCH, HEAD, DELETE, OPTIONS and a signed prefix `SIGNED_URL_SUFFIX` whose value is in lifecycle.ts, not shown.
5. Signed upload URL and token validity: the createSignedUploadUrl reference says "They are valid for 2 hours." Source: https://github.com/supabase/storage-js/blob/master/src/packages/StorageFileApi.ts (doc comment). The public reference page https://supabase.com/docs/reference/javascript/storage-from-createsigneduploadurl says the same. Neither says whether this is configurable.
6. Configurability: no docs page or source read states an env var for the signed upload expiry. A search for `SIGNED_UPLOAD_URL_EXPIRATION_TIME` found nothing, so the name in KNOWN could not be confirmed on any scoped page.
7. Standard uploads page (https://supabase.com/docs/guides/storage/uploads/standard-uploads) says standard upload is for files "not larger than 6MB" and recommends TUS "for uploading files greater than 6MB in size for better reliability". It has no signed-upload expiry and no chunk statement.
8. Hostname: the docs say "For optimal performance when uploading large files you should always use the direct storage hostname", "Instead of `https://project-id.supabase.co` use `https://project-id.storage.supabase.co`". Source: https://supabase.com/docs/guides/storage/uploads/resumable-uploads.
9. Resumable session lifetime: the docs say "This unique upload URL will be valid for up to 24 hours." Source: https://supabase.com/docs/guides/storage/uploads/resumable-uploads (Upload URL section). The tus lifecycle code sets `expirationPeriodInMilliseconds: tusUrlExpiryMs` (value not shown in index.ts); the docs' 24 hours is the only stated figure.
10. Lock: `lockTtlMs: 15 * 1000` in https://raw.githubusercontent.com/supabase/storage/master/src/http/routes/tus/index.ts (a server-side lock, not a client-visible limit).
11. Gap: the hosted platform's values for the signed upload token lifetime (2 hours in the SDK comment) and the TUS part size are not confirmed from a hosted-platform page. Open question for the planner: whether the 2-hour token is enough for a resumable session that the docs allow up to 24 hours.
