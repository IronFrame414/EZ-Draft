REPORT: pending/retriever-web-supabase-auth-captcha-enforcement.md

Caveat: GoTrue source was read from `master`, not from the GoTrue version bundled with Supabase CLI 2.121.0. Not verified against that version.

(1) Enforcement
- `verifyCaptcha` wraps POST /signup, /recover, /resend, /magiclink, /otp, /token, /sso, /passkeys/authentication/options [S2].
- /verify (GET and POST) has only `api.limitHandler(api.limiterOpts.Verify)`, no captcha. So verifyOtp (token or token_hash) is not checked [S2].
- /token skips captcha for grant_type `pkce`, `refresh_token`, `id_token`; `password` and `web3` are checked [S1].
- verifyCaptcha returns early when `Captcha.Enabled` is false, and when the request has admin credentials (`requireAdminCredentials`) [S1].
- /admin routes (e.g. /admin/users, /admin/generate_link) have no captcha middleware; they use `requireAdminCredentials` [S2].
- Consequence: the sign-in code request (signInWithOtp email, POST /otp) is checked; the code verify is not.

(2) Errors
- Missing token: HTTP 400, `apierrors.NewBadRequestError` with `ErrorCodeCaptchaFailed`, message "captcha protection: request disallowed (no captcha_token found)" [S1].
- Provider rejects: HTTP 400, same code, message "captcha protection: request disallowed (<provider error-codes>)" [S1].
- Verify process failure (network, non-JSON reply): HTTP 500, "captcha verification process failed" [S1, S3].
- The string value of `ErrorCodeCaptchaFailed` was not in the fetched source. The brief's "captcha_failed" is unconfirmed.

(3) Config
- Dashboard path: Settings > Authentication > Bot and Abuse Protection; provider, then secret [S4].
- CLI config reference has no captcha key [S5]. The CLI template fetch returned 404, so config.toml keys are unconfirmed; the only `[auth.captcha]` text found was in third-party copies. `env()` support: not verified.
- GoTrue env names (self-host example): `GOTRUE_SECURITY_CAPTCHA_ENABLED` (default false), `_PROVIDER` (default hcaptcha), `_SECRET`, `_TIMEOUT` (10s) [S6].
- Struct: Enabled, Provider (must be `hcaptcha` or `turnstile`), Secret (JSON `provider_secret`), Timeout [S7].
- Custom verify URL: none. Endpoints are hard-coded: https://hcaptcha.com/siteverify and https://challenges.cloudflare.com/turnstile/v0/siteverify. Only the timeout is configurable [S3]. A local stub cannot be used through GoTrue config.

(4) supabase-js
- signInWithOtp: `options.captchaToken` goes into `gotrue_meta_security: { captcha_token }` (email and phone branches) [S8].
- verifyOtp: reads `params.options?.captchaToken` into `gotrue_meta_security: { captcha_token }`, and spreads all of `params` into the body [S8].
- Docs example uses `options: { captchaToken }` on signUp only [S4].

(5) Test keys
- Turnstile sitekeys: visible `1x00000000000000000000AA` always passes; `2x00000000000000000000AB` always fails; invisible `1x00000000000000000000BB` passes, `2x00000000000000000000BB` fails; `3x00000000000000000000FF` forces a challenge [S9].
- Turnstile secrets: `1x0000000000000000000000000000000AA` always passes; `2x0000000000000000000000000000000AA` always fails; `3x0000000000000000000000000000000AA` returns "token already spent" [S9].
- Turnstile dummy token: `XXXX.DUMMY.TOKEN.XXXX` [S9].
- Turnstile siteverify: the page says the test secret is used for server-side validation; it does not say siteverify is skipped. Inference: it is called.
- hCaptcha test sitekey `10000000-ffff-ffff-ffff-000000000001` never challenges and always gives response token `10000000-aaaa-bbbb-cccc-000000000001`; secret `0x0000000000000000000000000000000000000000` [S10].
- hCaptcha enterprise test keys: sitekeys `20000000-ffff-ffff-ffff-000000000002` (safe user) and `30000000-ffff-ffff-ffff-000000000003` (bot detected), same secret [S10].
- hCaptcha always-fail sitekey: not named in the fetched page. Test passcodes "can only be verified using the test secret", which implies siteverify is called (summary of the page) [S10].
- hCaptcha rejects localhost and 127.0.0.1; the page suggests a hosts-file entry [S10].

(6) Widgets and tokens
- Turnstile script: https://challenges.cloudflare.com/turnstile/v0/api.js; add `?render=explicit`, then `turnstile.render("#id", { sitekey, callback })` [S11].
- Turnstile tokens: expire after 300 s; each validates once [S11].
- hCaptcha: `hcaptcha.render('<container>', {...})` and `hcaptcha.execute(widgetId)` are documented. Tokens are single-use. Default expiry is 120 s (`expired-input-response`) [S10]. The hCaptcha script URL was not verified.

Not answered: the Supabase captcha guide names only sign-in, sign-up and password-reset forms; it does not list endpoints or error codes [S4]. No test was run against a live GoTrue.
