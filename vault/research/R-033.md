## Summary

Of 371 tickets in phases 2–55: **0 port, 58 reference, 313 none** (count script over the five map files, 2026-10-28; the one candidate port, the take-off feet-inch parser for EZD-201 and EZD-1416, was set to reference by Josh, see below). Nothing met the copy bar: every other candidate either imports its own app's types/store/React/three, behaves differently from the spec, or is a thin helper not worth a notices entry.

Decision (Josh, 2026-10-28): "Treat the parser as reference only. No notices file, no grant." EZD-201 writes its own parser from the spec; the take-off file is read while planning. Background: the parser accepts a fifth form (`10-6`) the spec does not list and returns decimal feet. Porting it means deleting that branch and adding ×12 and 1/16" rounding. Josh's bar is "fits perfectly, saves time" (2026-10-28). Options: (a) port it as described, with its MIT header and a THIRD_PARTY_NOTICES.md row; (b) treat it as reference and write our own (~60 lines) with no notices file at all, which also drops the guard grant. Outcome: nothing staged, no THIRD_PARTY_NOTICES.md, no guard grant; vault/reuse/code/ stays empty and the unit closes with the maps and this report.

## License rules (handoff rule 1)

Copy only from MIT, Apache-2.0, BSD-2/3, ISC, 0BSD, Unlicense or CC0, confirmed by the LICENSE file at a pinned SHA (a package.json field alone counts but is flagged). MPL-2.0 only as an unmodified npm dependency. GPL/LGPL/AGPL, custom, source-available, all-rights-reserved or no license: not usable. Ported code keeps its copyright line in a header comment and a row in THIRD_PARTY_NOTICES.md; Apache NOTICE text is carried. Josh's note (2026-10-28): "realistically this will not be sold"; the rule is the same, nothing goes in the UI.

## Copy criteria (Josh, 2026-10-28)

All six must hold for `port`: (1) license as above; (2) does what the spec section says, no behaviour difference; (3) standalone: no framework, store or UI imports; (4) conversion limited to units, names and types; (5) replaces most of a ticket or a whole step; (6) no code-rule text or numbers (CLAUDE.md rule 13). Otherwise `reference` (only when it answers a real how-does-it-work question) or `skip`.
