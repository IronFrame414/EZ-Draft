1. Max duration, Pro, Node.js, Fluid compute. Default 300s, maximum 800s, extended maximum 1800s (Beta).
   - https://vercel.com/docs/functions/limitations (last_updated 2026-08-24), table row "Maximum duration": "Pro and Enterprise: 300s default, 800s maximum, and 1800s extended maximum Beta."
   - Same page, section "Max duration": "With [fluid compute](/docs/fluid-compute) enabled, Vercel Functions have the following defaults and maximum limits"; Pro row: "Pro | 300s (5 minutes) | 800s | 1800s (30 minutes) Beta".
   - Note: "Values above 800 seconds require function-level configuration and are only supported for specific Node.js, Bun, and Python runtime versions."
   - The configuration page (/docs/functions/configuring-functions/duration) was not fetched; the setting syntax is not verified here.

2. Memory and vCPU. Default 2 GB / 1 vCPU on Pro; maximum 4 GB / 2 vCPU.
   - https://vercel.com/docs/functions/limitations (last_updated 2026-08-24), section "Memory size limits", table row "Pro / Enterprise | 2 GB / 1 vCPU | 4 GB / 2 vCPU" (columns Default, Maximum).
   - Same section: "Users on Pro and Enterprise plans can [configure the default memory size](/docs/functions/configuring-functions/memory#setting-your-default-function-memory-/-cpu-size) for all functions in the dashboard."
   - The page does not name a specific alternative memory size. The memory page (/docs/functions/configuring-functions/memory) was not fetched.

3. maxDuration 300 and a once-a-minute cron on Pro. Both allowed.
   - Duration: 300 is the stated Pro default and sits under the 800s maximum (https://vercel.com/docs/functions/limitations, as in item 1).
   - Cron: https://vercel.com/docs/cron-jobs/usage-and-pricing (last_updated 2026-07-15), table row "**Pro** | 100 cron jobs | Once per minute | Per-minute": "Number of cron jobs per project" 100; "Minimum interval" once per minute.
   - Same page: "Cron jobs invoke [Vercel Functions](/docs/functions). This means the same [usage](/docs/limits) and [pricing](/pricing) limits will apply."

4. x-forwarded-for. The docs still say it is the client's public IP. The overwrite sentence is stated for the proxy case only.
   - https://vercel.com/docs/headers/request-headers (last_updated 2025-12-13), section "`x-forwarded-for`": "The public IP address of the client that made the request."
   - Same section: "If you are trying to use Vercel behind a proxy, we currently overwrite the [`X-Forwarded-For`] header and **do not forward external IPs**. This restriction is in place to prevent IP spoofing."
   - Section "`x-vercel-forwarded-for`": "This header is identical to the `x-forwarded-for` header. However, `x-forwarded-for` could be overwritten if you're using a proxy on top of Vercel."
   - The page does not say in plain words that a client-sent X-Forwarded-For is overwritten when no proxy sits in front of Vercel. Only the proxy case is stated.

Not found in SCOPE: a page stating the Fluid compute default for existing Pro projects. The limitations page says only: "Fluid compute is enabled by default for new projects" (https://vercel.com/docs/functions/limitations, section "Large functions Beta").
