# Findings

1. actions/checkout tag v4.4.0 is a lightweight tag: commit `11d5960a326750d5838078e36cf38b85af677262`. Source: https://api.github.com/repos/actions/checkout/git/ref/tags/v4.4.0 (object.type `commit`). Confirms the pin in the brief.
2. actions/setup-node tag v4.4.0 is a lightweight tag: commit `49933ea5288caeca8642d1e84afbd3f7d6820020`. Source: https://api.github.com/repos/actions/setup-node/git/ref/tags/v4.4.0 (object.type `commit`). Confirms the pin in the brief.
3. Newest v4.x release of actions/upload-artifact: `v4.6.2`, published 2025-03-19, commit `ea165f8d65b6e75b540449e92b4886f43607fa02`. Sources: https://api.github.com/repos/actions/upload-artifact/releases?per_page=100 (list of v4.x releases, v4.6.2 first) and https://api.github.com/repos/actions/upload-artifact/git/ref/tags/v4.6.2 (object.type `commit`).
4. Current upload-artifact major is v7 (latest release `v7.0.2`, 2026-10-07): https://api.github.com/repos/actions/upload-artifact/releases/latest. The README example uses `@v7`: https://github.com/actions/upload-artifact. The README says v1/v2 and v3 were deprecated and points users to v4 or later, and says "upload-artifact@v4+ is not currently supported on GitHub Enterprise Server (GHES)": https://github.com/actions/upload-artifact. The README gives no statement on v4 support on github.com-hosted runners, and I found no 2026 deprecation notice for v4 in the sources I could reach.
5. v4.6.2 `action.yml` declares `runs.using: node20` and has no token input (inputs: name, path, if-no-files-found, retention-days, compression-level, overwrite, include-hidden-files): https://raw.githubusercontent.com/actions/upload-artifact/v4.6.2/action.yml. Because it takes no `github-token` input, the action names no GITHUB_TOKEN permission of its own. I did not verify the claim that it uses ACTIONS_RUNTIME_TOKEN, and I found no GitHub doc saying it needs more than `contents: read`.
6. Whether GitHub still runs `node20` actions on github.com-hosted runners in 2026 is not settled by these sources. A third-party mirror of the README claimed v6 moved to Node 24: https://gitea.com/actions/upload-artifact. That claim is unverified against github.com.
7. actions/checkout v4.4.0 README recommends `permissions: contents: read` "to ensure proper functionality" unless a `token` or `ssh-key` is supplied: https://raw.githubusercontent.com/actions/checkout/v4.4.0/README.md. Its fork and `allow-unsafe-pr-checkout` text applies to `pull_request_target` and `workflow_run`, not to a same-repository `pull_request` run (same README).
8. GITHUB_TOKEN default permissions are not stated on the automatic-token page I fetched. It says to "grant the GITHUB_TOKEN the least required access", and that an action can read `github.token` without the workflow passing it: https://docs.github.com/en/actions/security-for-github-actions/security-guides/automatic-token-authentication. It says nothing about same-repository pull_request events.

# Not verified

- The release-page note that v4.3.2, v4.4.0 and v4.5.0 "mention deprecation" came from a summarizer, and I did not read those release bodies myself. Check them before relying on it.
- The search results for a 2026 deprecation notice gave only older notices (the 2024 v3 retirement) and third-party mirrors.
