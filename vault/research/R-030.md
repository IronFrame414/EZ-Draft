Allow auto-merge: repository Settings, then General in the left bar, then scroll to the "Pull Requests" section and check "Allow auto-merge". The option on a pull request shows only when it cannot merge immediately. Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-auto-merge-for-pull-requests-in-your-repository and https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/automatically-merging-a-pull-request

Ruleset label "Require status checks to pass before merging" (the doc calls it the "Require status checks to pass before merging" checkbox). Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets

Ruleset label "Dismiss stale pull request approvals when new commits are pushed". The doc text is "you can choose to dismiss stale pull request approvals when commits are pushed". Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets

Ruleset label "Require approval of the most recent reviewable push". The fetched page names it only inside a note, not with its own description. Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets

Required approvals: the fetched page does not give the field's exact label. It says administrators "can require that all pull requests receive a specific number of approving reviews". Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets

Zero required approvals: the page does not state that the count may be 0 for the pull request rule. It says "The pull request doesn't necessarily have to be approved, but it must be opened", and "This setting has no effect if the ruleset requires zero approvals". The 0 to 10 range it gives is for required reviewers from teams. Source: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets

Not answered by SCOPE: the exact UI label for the Required approvals number field, and an explicit statement that 0 is allowed with "Require a pull request before merging".
