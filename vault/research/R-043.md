(1) permission_denials on the final result object. Each entry is typed `SDKPermissionDenial = { tool_name: string; tool_use_id: string; tool_input: Record<string, unknown> }`, with no reason or message field. It is on both success and error result arms. Docs call it "the authoritative record". https://code.claude.com/docs/en/agent-sdk/typescript
Stream-json: denials appear as `permission_denied` system messages and the final result lists them in `permission_denials`. https://code.claude.com/docs/en/headless
Not stated in the fetched text: whether PreToolUse-hook denials, deny-rule denials, or subagent denials are included in `permission_denials`. The docs do not settle this.

(2) PermissionDenied hook: yes, it exists (33 events listed). https://code.claude.com/docs/en/hooks
Fires: "When auto mode denies a tool call, including denials without a classifier verdict." It does not run "when a PreToolUse hook blocks a call, or when a deny rule matches." https://code.claude.com/docs/en/hooks
Input: common fields plus tool_name, tool_input, tool_use_id, reason (and mcp_server for MCP tools); agent_type/agent_id in subagents. https://code.claude.com/docs/en/hooks
Output: `hookSpecificOutput: {hookEventName: "PermissionDenied", retry: true}`. retry adds a message telling the model it may retry; it does not reverse the denial. Ignored when the classifier gave no verdict. https://code.claude.com/docs/en/hooks
The typed stream event `SDKPermissionDeniedMessage` (subtype "permission_denied") skips denials decided on the PreToolUse hook path, and is best-effort; permission_denials is the authoritative record. https://code.claude.com/docs/en/agent-sdk/typescript

(3) bypassPermissions: docs say it "disables permission prompts and safety checks so tool calls execute immediately". The classifier is described only as part of auto mode. https://code.claude.com/docs/en/permission-modes
Deny rules: "Deny rules block in every mode, including bypassPermissions." https://code.claude.com/docs/en/permission-modes
PreToolUse deny under bypassPermissions: not stated in the fetched text. The permission-modes page does not say; the headless page says permission rules, PermissionRequest hooks and the mode "still decide every call first" (https://code.claude.com/docs/en/headless). Unverified for PreToolUse.

(4) PreToolUse deny text: docs say `permissionDecisionReason` is "For "deny", shown to Claude." The wrapper text around it is not documented. Exit code 2 denial: stderr is the reason, shown as `PreToolUse:Bash hook error: [<script>]: Blocked: ...` in the docs example. https://code.claude.com/docs/en/hooks
Verbatim pass-through of the reason string is not confirmed by the docs.
