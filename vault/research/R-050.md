## replication_connection.ex at tag v2.151.5 (https://github.com/supabase/realtime/blob/v2.151.5/lib/realtime/tenants/replication_connection.ex)
- Child spec `restart: :temporary`; `auto_reconnect: false`.
- DB connection loss handler only logs "Disconnecting broadcast changes handler in the step : ..." and sets `step: :disconnected`. No retry timer or backoff in this file.
- `{:DOWN, _, :process, _, _}` returns `{:disconnect, :shutdown}`.
- Pushes no messages to channels (only broadcasts via TenantBroadcaster).

## Conflict, unresolved
- The main-branch copy of replication_connection.ex (https://github.com/supabase/realtime/blob/main/lib/realtime/tenants/replication_connection.ex) and connect.ex (https://github.com/supabase/realtime/blob/main/lib/realtime/tenants/connect.ex) were read as summaries. They describe `open_replication_recovery/1` with Backoff (5 s min, 5 min max, rand_exp), a `:recover_replication_connection` retry, and a 2-hour `@max_replication_recovery_ms` stop. The v2.151.5 copy has no such code. Main may be ahead of the tag, or the summaries may be wrong. Needs a line-by-line check of the raw file at a tag.
- connect.ex on main: `restart: :temporary`; DB monitor DOWN logs "Database connection has been terminated" and stops with `:shutdown`; pool `{:disconnected, ...}` opens a 10-minute recovery window (`@max_db_recovery_ms`), stop `:shutdown` if not reconnected; rebalancer `{:error, :wrong_region}` stops with `{:shutdown, :rebalancing}`. Not checked at a tag.

## realtime_channel.ex at tag v2.151.5 (https://github.com/supabase/realtime/blob/v2.151.5/lib/realtime_web/channels/realtime_channel.ex), read only to about line 700 of 1,239
- `shutdown_response/2` pushes `"system"` with status `"error"` and returns `{:stop, :normal, socket}` (channel closes).
- Used for: replication not ready in time ("Replication connection was not established in time"); token refresh with `:tenant_database_unavailable` ("Realtime was unable to connect to the project database"); `:unable_to_set_policies`; `:missing_partition`.
- Replication ready success pushes `"system"`, status `"ok"`, message "Replication connection established".
- Postgres CDC subscribe errors push `"postgres_changes"`, status `"error"`, with the error text; channel stays open and retries (`postgres_subscribe(5, 10)`).
- Join-time DB errors reply with a join error, not a push to a joined channel.
- `terminate/2` pushes nothing.
- Not seen: any `phx_error` or `phx_close` push on connection loss. The rest of the file (lines 700 to 1,239, including `join_error/1`) was not read.
