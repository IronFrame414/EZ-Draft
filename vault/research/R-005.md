1. Project get: GET /v9/projects/{idOrName}; query teamId, slug. https://vercel.com/docs/rest-api/reference/endpoints/projects/retrieve-a-project
2. Fields: autoAssignCustomDomains (boolean), autoAssignCustomDomainsUpdatedBy (string), gitForkProtection (boolean), ssoProtection (object or null, requires deploymentType). Same URL.
3. ssoProtection.deploymentType enum: all, all_except_custom_domains, preview, prod_deployment_urls_and_all_previews. The example also shows april2026SecurityIncidentMigrationAppliedFrom and cve55182MigrationAppliedFrom. Same URL.
4. Writes: PATCH /v9/projects/{idOrName} takes gitForkProtection, autoAssignCustomDomains, ssoProtection; deploymentType default "preview". https://vercel.com/docs/rest-api/projects/update-an-existing-project
5. targets: the schema describes an object of deployment objects (fields include id, readyState, url, target); the example shows only "targets": "value". No page names a "production" key, so targets.production.id is unconfirmed. Same URL as item 1.
6. Dashboard labels (Standard Protection, All Deployments) are not mapped to deploymentType values; the page is silent on the mapping. https://vercel.com/docs/deployment-protection
7. Git Fork Protection is under Settings > Security; the API description says it makes PRs from forks "require a team member's authorization before it can be deployed". https://vercel.com/docs/project-configuration/security-settings
8. Auto-assign toggle is under Settings > Environments > Production > Branch Tracking. The docs do not name the API field; the link to autoAssignCustomDomains is by name only. https://vercel.com/docs/deployments/environments
9. Token: GET /v5/user/tokens/{tokenId}, where tokenId "current" returns the token the request uses. Body is { "token": {...} }. https://vercel.com/docs/rest-api/authentication/get-auth-token-metadata (the URL /reference/endpoints/authentication/get-the-current-token returned 404.)
10. expiresAt is a number, "Timestamp (in milliseconds)". It is not in the required list; the docs are silent on tokens with no expiry. Same URL as item 9.
11. Deployments: path is GET /v7/deployments, not /v6. https://vercel.com/docs/rest-api/deployments/list-deployments
12. Query: projectId, target, limit, state, sha, branch, from, to, since, until, teamId, slug. state filter enum: BUILDING, ERROR, INITIALIZING, QUEUED, READY, CANCELED, BLOCKED. Same URL.
13. Body: { deployments: [...], pagination: {count, next, prev} }. Both state and readyState exist, each with enum BLOCKED, BUILDING, CANCELED, DELETED, ERROR, INITIALIZING, QUEUED, READY. target enum: production, staging, null. Same URL.
14. meta is "Metadata information from the Git provider" with no keys listed; githubCommitSha is not in the REST schema. A search snippet of https://vercel.com/docs/cli/list shows `vercel ls -m githubCommitSha=<sha>` (page not fetched).
15. The REST filter sha ("Filter deployments based on the SHA") exists; the page does not say which field it matches. Same URL as item 11.
16. Project env list: GET /v10/projects/{idOrName}/env; query decrypt (enum true | false: "If true, the environment variable value will be decrypted"), gitBranch, source, customEnvironmentId, customEnvironmentSlug, teamId, slug. https://vercel.com/docs/rest-api/projects/retrieve-the-environment-variables-of-a-project-by-id-or-name
17. Body: envs[] with pagination, or envs[] with hiddenProductionEnvCount. Item fields: id, key, value, type (encrypted | plain | secret | sensitive | system), target (array, or production | preview | development), gitBranch, decrypted, securityIssues, visibility (config | secret), comment. Same URL.
18. Community post dated 2026-10-16, no staff reply, reports that v9 and v10 return the encrypted payload when decrypt=true, while v8 returns plaintext. Not verified by me. https://community.vercel.com/t/rest-api-v9-v10-get-projects-idorname-env-ignores-decrypt-true-parameter/50913
19. One variable: GET /v1/projects/{idOrName}/env/{id}; query teamId, slug. The body has decrypted (boolean); value appears in one response variant. https://vercel.com/docs/rest-api/projects/retrieve-the-decrypted-value-of-an-environment-variable-of-a-project-by-id
20. Sensitive: that page is silent on what a sensitive or secret variable returns. The Config/Secret page says "Config values remain readable after saving", "Secret values are write-only after saving", and "Existing Sensitive environment variables are treated as Secret in the dashboard and API." https://vercel.com/docs/environment-variables/sensitive-environment-variables
21. Promote: POST /v10/projects/{projectId}/promote/{deploymentId}; query teamId, slug. https://vercel.com/docs/rest-api/projects/point-production-traffic-to-a-given-deployment
22. Success: the page lists responses 201 and 202, neither with a body schema; the docs are silent on which one is returned. The page says "This does NOT rebuild the deployment."
23. Conflict: https://vercel.com/docs/deployments/promoting-a-deployment says dashboard promotion of a preview goes "through a complete rebuild", while promoting a staged production deployment "doesn't require a rebuild".
24. Scope: teamId and slug are query parameters on every endpoint above ("The Team identifier to perform the request on behalf of"); auth is Authorization: Bearer. The docs are silent on team-specific 403 and 404 cases.
25. Error body: { "error": { "code", "message" } }. 403: code "forbidden", message "Not authorized", "usually happens due to missing a user token". 404: code "not_found", message "Could not find the RESOURCE: ID". https://vercel.com/docs/rest-api/errors
26. Gaps: https://vercel.com/openapi.json exceeded the fetch size limit (10 MB); openapi.vercel.sh was not tried.
