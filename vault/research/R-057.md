## (1) sharp 0.35 on Vercel
- Latest sharp is 0.35.5; Linux x64 prebuilt needs glibc >= 2.28 (also musl >= 1.2.5, needs SSE4.2). https://sharp.pixelplumbing.com/install ; 0.35.5 glibc floor also in https://github.com/antra-tess/zulip_mcp/pull/41 (third party).
- Node: "Node-API v9 compatible runtime e.g. Node.js >= 20.9.0". https://sharp.pixelplumbing.com/install ; https://github.com/lovell/sharp
- Licence: Apache-2.0. https://github.com/lovell/sharp
- Next.js: `sharp` is in Next's built-in list of automatically opted-out serverExternalPackages (no config needed). https://nextjs.org/docs/app/api-reference/config/next-config-js/serverExternalPackages (page lastUpdated 2025-12-05).
- Vercel Node functions: 250 MB uncompressed limit (500 MB is Python only). Large functions beta up to 5 GB needs VERCEL_SUPPORT_LARGE_FUNCTIONS=1. Request and response body limit 4.5 MB. Default region iad1. https://vercel.com/docs/functions/limitations
- Vercel build log can show per-function size with VERCEL_ANALYZE_BUILD_OUTPUT=1. https://vercel.com/docs/functions/limitations
- Node 22 specifically on Vercel: unknown (not stated in fetched sources; >= 20.9 is the sharp floor).
- outputFileTracing: Vercel says use outputFileTracingIncludes / outputFileTracingExcludes in next.config for Next.js. https://vercel.com/docs/functions/limitations . Whether sharp needs them: unknown.
- Constructor `limitInputPixels`: exists; default 268402689 (0x3FFF x 0x3FFF); accepts integer, 0/false to disable, true for default. https://sharp.pixelplumbing.com/api-constructor
- `withExif(exif)`, `withXmp(xmp)`, `withMetadata()`, `keepMetadata()`, `keepExif()`, `keepXmp()` exist. https://sharp.pixelplumbing.com/api-output
- Default: "By default all metadata will be removed, which includes EXIF-based orientation." Default keepMetadata strips all metadata including ICC. This covers EXIF (incl. GPS) and XMP on output. https://sharp.pixelplumbing.com/api-output
- `metadata()` returns exif (Buffer), xmp (Buffer), xmpAsString, density, orientation, icc, iptc, width, height, format, etc. https://sharp.pixelplumbing.com/api-input
- Does `metadata()` return `density` as a number: unknown (field named, type not stated in fetched text).

## (2) Browser HEIC decoders
- heic2any: MIME/licence MIT; uses web workers per README. Latest 0.0.4 per search snippet (not verified on npm); libheif build, API and size not stated. https://github.com/alexcorvi/heic2any ; https://www.npmjs.com/package/heic2any
- heic-to (hoppergee/heic-to): latest 1.6.7 per repo page; libheif 1.23.6 (text) and 1.23.7 (release table); decodes in Web Workers via "heic-to/next"; libheif is WebAssembly (Emscripten build); licence per npm snippet LGPL-3.0 (repo page did not state licence). API: `isHeic(file)`, `heicTo({ blob, type, quality?, options? })` where type is "image/jpeg", "image/png" or "bitmap"; return type for JPEG output is a Promise (Blob implied, not stated); bundle size: not stated. https://github.com/hoppergee/heic-to ; https://www.npmjs.com/package/heic-to (snippet)
- libheif-js (catdad-experiments): LGPL-3.0 per npm snippet, latest 1.23.5 per snippet; Emscripten wasm build for browsers and Node. Decode API: unknown (not fetched). https://github.com/catdad-experiments/libheif-js ; https://www.npmjs.com/package/libheif-js

## (3) iOS Safari and Windows Chrome/Edge
- iOS Safari HEIC into file input: Zenn test on iOS Safari 604.1 (WebKit build; not a marketing version) with dog.HEIC: JPEG returned for every accept value tested, including image/heic. Filename extension changes on iOS; exact extension not stated. https://zenn.dev/kou_pg_0131/articles/safari-input-file-heic
- Same article: macOS Safari 17.6 returns HEIC unchanged for accept "" / image/* / image/heic, and converts to first listed format otherwise. https://zenn.dev/kou_pg_0131/articles/safari-input-file-heic
- Apple Developer Forums thread (Safari 17+, no iOS version given): with accept="image/*,image/heic" the file came back named tempImageHjyd3l.heic with File.type image/heic; removing image/heic from accept stopped it. No Apple reply. https://developer.apple.com/forums/thread/743049
- Whether iOS 18 or iOS 26 transcodes: unknown (no fetched source names those versions).
- Whether iOS Safari 17+ returns File.type image/heic for an unconverted HEIC: unknown; the forum thread is the only report and it is inconsistent with the Zenn test.
- Safari HEIC decode in browser: Safari 17.0 added HEIC support, including in Safari View Controller and WKWebView. https://webkit.org/blog/14445/webkit-features-in-safari-17-0/ ; caniuse HEIF page lists Safari 17.0+ (https://caniuse.com/heif).
- Whether createImageBitmap accepts a HEIC Blob in Safari: unknown (search found no source; test in Safari 17+).
- Chrome/Edge on Windows: File.type for .heic is reported as empty string per community reports (no MIME mapping without paid HEVC codec). Not confirmed against Chromium source. https://community.gumlet.com/t/why-do-heic-heif-files-show-an-empty-file-type-in-filelist/1959 ; https://github.com/open-webui/open-webui/issues/28411 ; https://forum.inaturalist.org/t/heic-uploads-from-browser-still-not-working/78348
- Chrome native HEIC decode: no licensed HEVC decoder per one 2025 comparison (not authoritative). Source: https://dev.to/iterandum/chrome-fires-onerror-webkit-shows-it-feature-detect-heic-before-you-preview-3ake (search snippet only).
