# Findings

Note: npmjs.com returned HTTP 403 to WebFetch. Version, date and license come from the npm registry JSON (registry.npmjs.org). Source files come from unpkg.

## Candidate: @jsquash/webp (best fit)
- Latest dist-tag 1.5.0, published 2025-05-12, license Apache-2.0. Registry snapshot taken 2026-11-09. https://registry.npmjs.org/@jsquash/webp
- Description: "Wasm webp encoder and decoder supporting the browser. Repackaged from Squoosh App." Same registry page.
- Dependency: wasm-feature-detect ^1.2.11. https://unpkg.com/@jsquash/webp@1.5.0/package.json
- Encoder .wasm files are separate, not embedded: webp_enc.wasm 281 kB and webp_enc_simd.wasm 346 kB. Also webp_enc.js 38.7 kB and webp_enc_simd.js 38.6 kB. https://app.unpkg.com/@jsquash/webp@1.5.0/files/codec/enc
- SIMD and non-SIMD are both shipped. Choice is made at run time with `await simd()` from wasm-feature-detect, then a dynamic import of webp_enc_simd.js or webp_enc.js. https://unpkg.com/@jsquash/webp@1.5.0/encode.js
- API: `encode(data: ImageData, options?: Partial<EncodeOptions>): Promise<ArrayBuffer>`. Input is ImageData, not a raw RGBA buffer. https://unpkg.com/@jsquash/webp@1.5.0/encode.d.ts
- EncodeOptions is a flat set of `number` fields. Includes `quality` (default 75), `method` (default 4), `lossless` (default 0), `alpha_quality` (default 100), `alpha_compression`, `alpha_filtering`, `thread_level`, `low_memory`, `use_sharp_yuv` and others. The d.ts has no comments and the source gives no value ranges. https://unpkg.com/@jsquash/webp@1.5.0/codec/enc/webp_enc.d.ts and https://unpkg.com/@jsquash/webp@1.5.0/meta.js
- WASM location: if Module.locateFile is absent, the code uses `new URL("webp_enc.wasm", import.meta.url).href`. Otherwise it uses locateFile. https://unpkg.com/@jsquash/webp@1.5.0/codec/enc/webp_enc.js
- Manual init: `init(module, moduleOptionOverrides?)` takes a compiled WebAssembly.Module (not an ArrayBuffer). The README says manual init is mainly for Cloudflare Workers. https://unpkg.com/@jsquash/webp@1.5.0/index.js and https://github.com/jamsinclair/jSquash/tree/main/packages/webp
- Known problem, Safari (closed 2025-02-23): a Next.js worker app called canvas.toBlob("image/webp"). Safari fell back to PNG and the WebP decoder failed. Fix: call getImageData() and pass the ImageData straight to encode(). https://github.com/jamsinclair/jSquash/issues/77
- Known problem, Next.js with webpack (closed 2025-06-19, Next 15.3.3): "Critical dependency" and circular-chunk warnings from Emscripten worker files in @jsquash/jxl and @jsquash/avif. Maintainer said the warnings are non-fatal and can be ignored. Not verified for the webp package or for Turbopack. https://github.com/jamsinclair/jSquash/issues/92
- Turbopack: the docs list `new Worker()` among the expressions that take webpack-style magic comments. They do not document a `new Worker(new URL(...))` pattern or .wasm loading under Turbopack for Next 16. `turbopackWorkerAssetPrefix` exists. https://nextjs.org/docs/app/api-reference/turbopack

## Not found in sources
- Node 22 support for Vitest. Not documented. The fallback uses import.meta.url, and the encoder takes ImageData, which Node does not provide globally. Needs a test-only stub or a check.
- Byte-identical output across browsers and across SIMD and non-SIMD builds. Not documented.
- Quality range (0–100) and method range. Not stated in the package sources.

## Other candidates

- wasm-webp: no matching npm package found in search. The jsDelivr listing shows a 0.1.0 package. https://www.jsdelivr.com/package/npm/wasm-webp (search result only, not fetched)
