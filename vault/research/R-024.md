# Findings

## 1. typescript 7.0.2

- npm registry: `https://registry.npmjs.org/-/package/typescript/dist-tags` gives `"latest": "7.0.2"`. Fetched 2026-10-24.
- npm registry: `https://registry.npmjs.org/typescript/7.0.2` gives `"version": "7.0.2"`, no `deprecated` field, and no time value. The full `https://registry.npmjs.org/typescript` document (which holds the `time` map) exceeded the fetch size limit (10 MB), so `time["7.0.2"]` was NOT read.
- npm page `https://www.npmjs.com/package/typescript?activeTab=versions` returned HTTP 403; not read.
- Secondary (search summary, not a primary page): third-party issues and a search snippet state 7.0.2 was published 2026-07-08 (cites GitHub issue `https://github.com/microsoft/TypeScript/issues/63637` as a 2026-07-09 issue date, which is not a publish date).
- GitHub release `https://github.com/microsoft/TypeScript/releases/tag/v7.0.2`: title "TypeScript 7.0.2", tag `v7.0.2`, marked "Latest", text "released this 20 Aug 18:09" (year not shown on the page).
- CONFLICT: the GitHub release page gives 20 Aug, the search summary gives 2026-07-08. The registry `time["7.0.2"]` value would settle it and was not retrievable. The docs/architecture.md date (2026-10-18) matches neither source.

Answer to "is 7.0.2 the latest dist-tag": yes (registry dist-tags, above).

## 2. Vercel x-forwarded-for

- URL: `https://vercel.com/docs/headers/request-headers`, section `## x-forwarded-for` (page `last_updated: 2025-12-13`).
- Sentence: "If you are trying to use Vercel behind a proxy, we currently overwrite the [`X-Forwarded-For`] header and **do not forward external IPs**. This restriction is in place to prevent IP spoofing."
- The page's first line for this header: "The public IP address of the client that made the request."
- The page also says `x-vercel-forwarded-for` "is identical to the `x-forwarded-for` header. However, `x-forwarded-for` could be overwritten if you're using a proxy on top of Vercel."
