Findings (WebFetch of GitHub pages, same session; partial, see gaps):

1. Premise conflict: the pinned CLI does not appear to use pgx v5 for the --db-url parse. The v2.121.0 go.mod lists `github.com/jackc/pgconn v1.14.3` and `github.com/jackc/pgx/v4 v4.18.3` as direct requires and no pgx/v5 line (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/go.mod). The same tag's connect.go calls `pgxv5.Connect(ctx, url, options...)` in ConnectByUrl (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/internal/utils/connect.go). These two readings conflict and are unresolved here; check go.mod and the connect.go import alias directly.
2. db_url.go imports `github.com/jackc/pgconn` and, in case `direct`, runs `config, err := pgconn.ParseConfig(flag.Value.String())` then `DbConfig = *config` with no password override in that branch (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/internal/utils/flags/db_url.go). So a password absent from the URL comes from pgconn's own defaults.
3. pgconn v1.14.3 parseEnvSettings maps PGPASSWORD to `password`, PGSSLMODE to `sslmode`, PGHOST to `host`, and reads each with `os.Getenv` (https://github.com/jackc/pgconn/blob/v1.14.3/config.go). Settings merge as `mergeSettings(defaultSettings, envSettings, connStringSettings)`, so URL values win over env (same file). The passfile is read only when the password is still empty (same file, `pgpassfile.ReadPassfile(settings["passfile"])`).
4. PGOPTIONS, PGSERVICE, PGPASSFILE and PGSERVICEFILE: the v1.14.3 page fetched did not show the full name map, so they are not confirmed for v1.14.3. The pgx v5.7.6 pgconn lists PGOPTIONS, PGSERVICE, PGPASSFILE and PGSERVICEFILE in parseEnvSettings and says PGOPTIONS becomes a runtime parameter that a URL `options` value replaces (https://github.com/jackc/pgx/blob/v5.7.6/pgconn/config.go). That is v5, not the CLI's pinned pgconn.
5. The CLI's own pooler code reads `options` from RuntimeParams, so a URL `options=` is carried as a runtime parameter in this code (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/internal/utils/connect.go, GetPoolerConfig). Startup-parameter delivery for db push with a passwordless URL is inferred from this, not traced to the apply path.
6. Prompts: `PromptPassword` (masked stdin, "Enter your database password (or leave blank to generate one)") and `viper.GetString("DB_PASSWORD")` appear only in NewDbConfigWithPassword and ResolvePoolerConfigForFallback, which are the linked path (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/internal/utils/flags/db_url.go). The direct branch shows no prompt. SUPABASE_DB_PASSWORD was not found in either file.
7. ConnectLocalPostgres sets `config.Password = Config.Db.Password` only when the password is empty (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/internal/utils/connect.go). Whether a --db-url to 127.0.0.1 routes there was not confirmed. This may explain the KNOWN no-PGPASSWORD local dump success, but that is inference.
8. Not located: `db push`, `db dump` and the pg_dump container code. cmd/db.go defines only db branch, diff and remote, and internal/db contains diff, reset and start (https://github.com/supabase/cli/blob/v2.121.0/apps/cli-go/cmd/db.go; https://github.com/supabase/cli/tree/v2.121.0/apps/cli-go/internal/db). internal/migration/apply contains apply.go (https://github.com/supabase/cli/tree/v2.121.0/apps/cli-go/internal/migration/apply), not fetched. Therefore (1) for push/dump, (2) whether dump passes PGPASSWORD as env rather than an argument, and (3) for push, are unanswered.
9. Community reports say a passwordless --db-url with CLI 2.121.0 fails SCRAM without PGPASSWORD (https://github.com/bhaveshbusa/tutor-mbos/pull/25). Secondary, not source.

Gaps: dump and push source; pgconn v1.14.3 PGOPTIONS; the pgx/v5 vs v4 conflict. Question (4) is answered for the direct branch only: no prompt and no SUPABASE_DB_PASSWORD read seen.
