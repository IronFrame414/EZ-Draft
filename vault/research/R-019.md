# Findings (retriever-web, 2026-10-24)

Q1 (Supavisor Session pooler and the `options` startup parameter): NOT ANSWERED by primary sources.
- https://supabase.com/docs/guides/database/postgres/timeouts : session-level `statement_timeout` "can only be used with connections through Supavisor in session mode (port 5432) or a direct connection". Supported: session mode 5432 and direct. Not supported: dashboard, Client API, transaction mode 6543. Example given is `set statement_timeout = '10min';` run as SQL, not a startup option.
- https://supabase.com/docs/guides/database/connecting-to-postgres : "Port `5432` reaches Postgres for a direct connection and Supavisor for session mode." No mention of startup parameters or `options`.
- https://github.com/supabase/supavisor (README) : no statement on startup parameters, libpq `options`, or refusal of unknown startup parameters. Session pooling is listed under Future Work.
- Third-party PRs report a pooler refusing a timeout sent as a startup parameter with "unsupported startup parameter" (08P01). These are about PgBouncer, not Supavisor, and are not evidence for Supavisor: https://github.com/formbricks/formbricks/pull/9604 and https://github.com/rowsafe/rowsafe/pull/72.

Q2 (`supabase db push --db-url` forwards URL `options`; reads PGPASSWORD):
- https://pkg.go.dev/github.com/jackc/pgx/v5/pgconn : ParseConfig reads PG* env vars including PGPASSWORD and PGOPTIONS. URL query parameters libpq does not recognize "become runtime parameters or pgx-specific options". `Config.RuntimeParams` = "Run-time parameters to set on connection as session default values". The page does not say how the URL `options=` value maps to RuntimeParams.
- https://github.com/supabase/cli/blob/develop/apps/cli-go/internal/utils/flags/db_url.go : the `--db-url` flag value is passed to `pgconn.ParseConfig` (seen in search snippet only; file not fetched).
- https://github.com/supabase/cli/issues/4185 : a report that the CLI did not respect PGPASSWORD (CLI 2.40.7). Old; current behavior unverified.
- Not verified: whether the CLI forwards `options`, or whether it uses pgconn's PGPASSWORD fallback. Source paths internal/utils/connect.go and internal/db/push on develop and main returned 404 to WebFetch.

Q3 (`supabase db push` sets lock_timeout or statement_timeout for the migration session): NOT ANSWERED.
- No primary source reached. The CLI apply source (internal/migration/apply) returned 404. Search found no CLI text about SET lock_timeout or statement_timeout.
