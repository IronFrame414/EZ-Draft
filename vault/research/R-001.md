# Findings

1. Connection string
- Direct `db.<ref>.supabase.co:5432` is IPv6 on Free and Paid plans; IPv4 only with the IPv4 add-on, which "swaps the project's IPv6 (AAAA) DNS record for an IPv4 (A) record". Supabase recommends the direct connection for migrations. https://supabase.com/docs/guides/database/connecting-to-postgres ; https://supabase.com/docs/guides/platform/ipv4-address
- Shared pooler (Supavisor), session mode port 5432 and transaction mode port 6543: IPv4 on all plans. Username `postgres.<ref>`; host `aws-[INDEX]-[REGION].pooler.supabase.com`, copied from the Connect dialog because it cannot be derived from the region. https://supabase.com/docs/guides/database/connecting-to-postgres
- Transaction mode (6543) has no prepared statements and loses session state; Supabase positions it for serverless. Not the usual choice for migrations. https://supabase.com/docs/guides/database/connecting-to-postgres
- GitHub hosted-runner reference does not mention IPv6; it says Ubuntu runners have the Azure datacenter IP ranges. No GitHub page found that confirms outbound IPv6 on ubuntu-latest. https://docs.github.com/en/actions/reference/runners/github-hosted-runners
- Third-party (not authoritative): standard ubuntu-latest images lack public IPv6 by default. https://oneuptime.com/blog/post/2026-03-20-github-actions-ipv6/view
- Community reports (other projects): the direct host fails on GitHub runners with "network is unreachable" and switching to the session pooler (5432) fixed it. https://github.com/lama010101/GH-NEW2/pull/316 ; https://github.com/haidang21ktvptu/vptu-mvp-task/pull/113
- Session pooler with `db push`: no Supabase page states this. The only evidence is a community PR using `supabase db push --db-url` on the session pooler, 5432, unverified.
- Answer: on ubuntu-latest the direct host needs the paid IPv4 add-on; the session pooler on 5432 needs no add-on; `db push` through it is community-evidenced, not Supabase-documented.

2. Password
- `--db-url` "must be percent-encoded". https://supabase.com/docs/reference/cli/supabase-db-push
- Connecting page: "Percent-encode any reserved characters it contains, such as `&`, `#`, `?`, or a space." Examples only; encoding every reserved URL character (for example `%`, `@`, `:`, `/`) is the safe reading (inference). https://supabase.com/docs/guides/database/connecting-to-postgres

3. Link, token, config.toml, migrations
- db push reference: "Requires your local project to be linked to a remote database by running `supabase link`." The same page describes `--db-url` for self-hosted databases. No page read says `--db-url` removes the link requirement; unverified. https://supabase.com/docs/reference/cli/supabase-db-push
- Access token: the login page says CI can skip login by setting `SUPABASE_ACCESS_TOKEN`. The db push page does not say a token is needed with `--db-url`. Token is needed for `supabase link`. https://supabase.com/docs/reference/cli/supabase-login ; https://supabase.com/docs/guides/deployment/managing-environments
- config.toml: `supabase init` creates it; `supabase start` requires it. The db push page does not say db push needs it. https://supabase.com/docs/reference/cli/supabase-db-push
- History: first `db push` creates `supabase_migrations.schema_migrations`; later pushes skip applied migrations. https://supabase.com/docs/reference/cli/supabase-db-push
- `--include-all`: "Include all migrations not found on remote history table." Needed for older-timestamped unapplied files. The page does not state the default without it, and I did not verify the error text. https://supabase.com/docs/reference/cli/supabase-db-push
- `--dry-run`: "Print the migrations that would be applied, but don't actually apply them." https://supabase.com/docs/reference/cli/supabase-db-push

4. Supabase's own GitHub Actions guidance
- Managing Environments guide: plain `run` steps `supabase link --project-ref $SUPABASE_PROJECT_ID` then `supabase db push`, with `SUPABASE_ACCESS_TOKEN` and `SUPABASE_DB_PASSWORD` in `env`. No `--db-url`. Token scope: Project Settings, API Keys, API Key Secrets, all Read. https://supabase.com/docs/guides/deployment/managing-environments
- Same guide lists secrets `SUPABASE_ACCESS_TOKEN`, `*_PROJECT_ID`, `*_DB_PASSWORD`. https://supabase.com/docs/guides/deployment/managing-environments
- Search snippet (not confirmed by fetch) says the guide uses `supabase/setup-cli@v1`. https://supabase.com/docs/guides/deployment/managing-environments
- Branching GitHub integration deploys migrations without a custom action; it runs each migration in one transaction, unlike db push. Search snippet only. https://supabase.com/docs/guides/deployment/branching/github-integration
- No official `--db-url` GitHub Actions workflow found.
