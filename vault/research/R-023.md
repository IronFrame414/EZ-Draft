# Findings

1. Exit codes: a command that exits 1 lets the build continue; exit 0 cancels it and marks the deployment CANCELED. https://vercel.com/kb/guide/how-do-i-use-the-ignored-build-step-field-on-vercel (search summary; the project settings page is cited there as saying the command always exits 0 or 1). The shell is not named in the sources read; the docs page /docs/builds/ignored-build-step returned 404.
2. VERCEL_GIT_* variables listed in the system environment reference: VERCEL_GIT_PROVIDER, VERCEL_GIT_REPO_SLUG, VERCEL_GIT_REPO_OWNER, VERCEL_GIT_REPO_ID, VERCEL_GIT_COMMIT_REF, VERCEL_GIT_COMMIT_SHA, VERCEL_GIT_COMMIT_MESSAGE, VERCEL_GIT_COMMIT_AUTHOR_LOGIN, VERCEL_GIT_COMMIT_AUTHOR_NAME, VERCEL_GIT_PREVIOUS_SHA (build time, set only when an Ignored Build Step is provided), VERCEL_GIT_PULL_REQUEST_ID. https://vercel.com/docs/environment-variables/system-environment-variables
   No listed variable gives a pull request's base or target branch. VERCEL_GIT_COMMIT_REF is "the git branch of the commit the deployment was triggered by" (the head branch).
3. VERCEL_GIT_PULL_REQUEST_ID: "The pull request id the deployment was triggered by. If a deployment is created on a branch before a pull request is made, this value will be an empty string." https://vercel.com/docs/environment-variables/system-environment-variables and https://vercel.com/docs/git/vercel-for-github
   The docs say empty before a PR exists. They do not say explicitly whether a push to a branch with an open PR sets it, nor whether fork PRs set it; no source read states either.
4. Fork PRs: "If you receive a pull request from a fork of your repository, Vercel will require authorization from you or a team member to deploy the pull request. This behavior protects you from leaking sensitive project information such as environment variables and the OIDC Token." https://vercel.com/docs/git/vercel-for-github
   Per the changelog, authorization is required when the fork PR changes vercel.json or when the project has Environment Variables configured. Protection can be disabled in the Security section of Project Settings. https://vercel.com/changelog/git-fork-protection-can-now-be-disabled
   The authorization step is skipped when the commit author is already a Vercel team member (search summary, not verified against a page). The docs page /docs/projects#git-fork-protection returned 404; the security-settings page was not fetched.
5. Not found in scope: a default for Git Fork Protection on public repositories, and whether the Ignored Build Step runs before or regardless of fork authorization.
