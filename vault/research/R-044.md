Findings (source files read on master branches, not pinned to the CLI 2.121.0 or supabase-js 2.118.0 tags):

- Reauthentication gate: applies only when params.Password is set and config UpdatePasswordRequireReauthentication is on. Required when session is nil or now > session.CreatedAt + 24h. Uses session created_at, not last_sign_in_at (no LastSignInAt reference). Does not check HasPassword, so it applies to users with and without a password. Missing nonce returns 400 reauthentication_needed. https://raw.githubusercontent.com/supabase/auth/master/internal/api/user.go
- Config env var: UpdatePasswordRequireReauthentication (GOTRUE_SECURITY_UPDATE_PASSWORD_REQUIRE_REAUTHENTICATION, derived from split_words, no explicit tag; default false). UpdatePasswordRequireCurrentPassword (GOTRUE_SECURITY_UPDATE_PASSWORD_REQUIRE_CURRENT_PASSWORD, default false). https://raw.githubusercontent.com/supabase/auth/master/internal/conf/configuration.go
- Current password check runs only when new password is non-empty, user.HasPassword() is true, the config is on, and session is not a recovery session. A user with no password is exempt. Missing current_password returns 400 current_password_required; mismatch returns 400 current_password_mismatch. Same password as current returns 422 same_password. https://raw.githubusercontent.com/supabase/auth/master/internal/api/user.go
- Not verified: how CLI key auth.email.secure_password_change maps to these GoTrue settings. The CLI docs say it "requires the user's current password to be provided when changing to a new password." https://supabase.com/docs/guides/cli/config . The CLI source (cli/pkg/config) returned 404 and was not read.
- Version history: "check current password on change" in 2.187.0 (2026-02-23); PKCE recovery exemption in 2.189.0 (2026-04-23); "create an email identity when a user adds their first password" in 2.196.0 (2026-08-12); password changed email notification in 2.180.0 (2025-09-23). https://raw.githubusercontent.com/supabase/auth/master/CHANGELOG.md
- supabase-js: current_password?: string and nonce on UserAttributes (types.ts on master). https://raw.githubusercontent.com/supabase/supabase-js/master/packages/core/auth-js/src/lib/types.ts . The auth passwords guide says current_password is available in supabase-js v2.102.0+ and shows updateUser({ password, current_password }). https://supabase.com/docs/guides/auth/passwords . The auth-js changelog gives a conflicting "2.98.0 currentPassword" entry; not resolved.
- Reauthenticate: sends a nonce to the user's email via GET /reauthenticate and is used with updateUser({ password, nonce }). https://supabase.com/docs/reference/javascript/auth-reauthenticate
- signOut scope: SignOutScope is 'global' | 'local' | 'others' (types.ts). 'others' signs out all other sessions and keeps the current one; no SIGNED_OUT event fires for 'others'. https://supabase.com/docs/reference/javascript/auth-signout . The version that added 'others' was not found.
- Session revocation on password update: yes. UpdatePassword with a session ID calls LogoutAllExceptMe (revokes all other sessions, keeps current); with nil session ID it logs out all sessions. It does not set last_sign_in_at and clears one-time tokens. https://raw.githubusercontent.com/supabase/auth/master/internal/models/user.go
- Password-changed notification: sent when config Mailer.Notifications.PasswordChangedEnabled is on and the user has an email (CLI key auth.email.notification.password_changed.enabled). Send failure is logged as a warning, not returned. Whether it goes through custom SMTP was not verified (sendPasswordChangedNotification body not read). https://raw.githubusercontent.com/supabase/auth/master/internal/api/user.go and https://supabase.com/docs/guides/cli/config
