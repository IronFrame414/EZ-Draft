# Findings

Source tag: v2.197.0 (raw.githubusercontent.com/supabase/auth/v2.197.0/...)

- Captcha middleware wraps these routes in internal/api/api.go: POST /signup, POST /recover, POST /resend, POST /magiclink, POST /otp, POST /token, POST / (SSO), POST /options (passkey auth). https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/api.go
- POST /token does verify captcha for the password grant. verifyCaptcha in internal/api/middleware.go skips only requireAdminCredentials callers and isIgnoreCaptchaRoute, which exempts /token grants pkce, refresh_token and id_token. https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/middleware.go
- PUT /user is registered as r.With(api.limitHandler(api.limiterOpts.User)).Put("/", api.UserUpdate), with no verifyCaptcha. https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/api.go
- UserUpdate (internal/api/user.go) has no verifyCaptcha call in its body, validateUserUpdateParams, or the password branch (verifyReauthentication and current-password checks only). https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/user.go
- GET /reauthenticate is registered as r.Get("/", api.Reauthenticate) under requireAuthentication, with no captcha wrapper. Its body runs a transaction that calls sendReauthenticationOtp. https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/api.go and https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/reauthenticate.go
- Not checked: the bodies of sendReauthenticationOtp and sendPhoneConfirmation (they may live in another file, e.g. internal/api/phone.go or helpers). No captcha call was seen in the Reauthenticate body.
- Supabase docs: the captcha page says CAPTCHA covers signup, sign-in and password reset, with hCaptcha or Cloudflare Turnstile, and the token goes in captchaToken. The docs page itself was not fetched; this comes from search snippets. https://supabase.com/docs/guides/auth/auth-captcha
- Supabase docs also name signInWithPassword, signInWithOtp and verifyOtp as methods that accept captchaToken (Flutter reference). https://supabase.com/docs/reference/dart/auth-signinanonymously
- Captcha failure returns captcha_failed. https://supabase.com/docs/guides/auth/debugging/error-codes

# Answer

- Verify captcha (middleware, when enabled): POST /token (password grant), POST /otp, POST /magiclink, POST /signup, POST /recover, POST /resend, SSO and passkey-auth options. Source: api.go and middleware.go at v2.197.0.
- PUT /user (including password change): no captcha check, in middleware or handler. Source: api.go and user.go at v2.197.0.
- GET /reauthenticate: no captcha check in middleware or handler, based on api.go and reauthenticate.go. The helper sendReauthenticationOtp was not read.
- Handler-level check: none found for PUT /user or /reauthenticate. Captcha is middleware-only on the routes listed above.
- Supabase docs say signup, sign-in and password reset are covered, which matches the source. The docs do not list PUT /user or reauthenticate. https://supabase.com/docs/guides/auth/auth-captcha
