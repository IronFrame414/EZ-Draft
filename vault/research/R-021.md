Breaking changes v4 to newest (checkout):
- v5.0.0: node24 runtime; needs runner v2.327.1 or later. https://api.github.com/repos/actions/checkout/releases/tags/v5.0.0
- v6: persist-credentials now stores the credential in a file under $RUNNER_TEMP, not .git/config; no workflow change needed; Docker container actions need runner v2.329.0 or later. https://raw.githubusercontent.com/actions/checkout/v7.0.1/README.md
- v7: refuses to check out fork PR code by default for pull_request_target and workflow_run only; ESM migration. Same-repo pull_request with default inputs is not affected. allow-unsafe-pr-checkout defaults to false. https://raw.githubusercontent.com/actions/checkout/v7.0.1/README.md
- Default inputs for a same-repo pull_request checkout: persist-credentials true, ref defaults to the event's ref or SHA (same as v4). https://raw.githubusercontent.com/actions/checkout/v7.0.1/README.md

Breaking changes v4 to newest (setup-node), with cache behaviour:
- v5.0.0: automatic caching when a valid packageManager field is present in package.json; disable with `package-manager-cache: false`. Moved to node24; runner v2.327.1 or later. https://api.github.com/repos/actions/setup-node/releases/tags/v5.0.0
- v6: caching is automatic for npm projects only; for other package managers such as Yarn and pnpm caching is disabled by default. `always-auth` removed. https://raw.githubusercontent.com/actions/setup-node/v7.1.0/README.md
- v7.0.0: dummy NODE_AUTH_TOKEN fallback removed. No caching change stated. https://raw.githubusercontent.com/actions/setup-node/v7.1.0/README.md
- `package-manager-cache` input defaults to true; turn off with `package-manager-cache: false`. Read: for a pnpm@12.14.0 packageManager field, v5 would auto-cache, v6 and later do not (pnpm is not npm). https://raw.githubusercontent.com/actions/setup-node/v7.1.0/README.md
- Our case (node-version 22 only, pnpm installed after setup-node): the README does not say how setup-node resolves pnpm before it is installed; `package-manager-cache: false` is the README's stated off switch. The v6 README describes pnpm as "disabled by default" for auto-caching.

Breaking changes v4 to newest (upload-artifact):
- v5.0.0: adds Node v24.x support (labelled breaking). https://api.github.com/repos/actions/upload-artifact/releases/tags (v5.0.0 listed in releases, 2025-10-24)
- v6.0.0 (2025-12-12): node24; needs runner v2.327.1. https://api.github.com/repos/actions/upload-artifact/releases?per_page=10
- v7.0.0 (2026-02-26): new `archive` input; archive default is 'true' (still zipped), so the existing name/path/if-no-files-found usage keeps zipping; ESM. https://raw.githubusercontent.com/actions/upload-artifact/v7.0.2/action.yml
- Inputs at v7.0.2: name default 'artifact' (with archive false the name is the file name); path required, file/directory/wildcard, multi-line allowed, least common ancestor used for multiple paths; if-no-files-found default 'warn', `ignore` allowed; compression-level default 6. https://raw.githubusercontent.com/actions/upload-artifact/v7.0.2/action.yml ; https://raw.githubusercontent.com/actions/upload-artifact/v7.0.2/README.md
- Not found: a runner minimum for upload-artifact v7 in the fetched sources.

Runner minimum: checkout v5+ and setup-node v5+ and upload-artifact v6+ each state runner v2.327.1 or later (checkout v6 Docker actions: v2.329.0). GitHub-hosted runners were not checked against these versions here; the fetched sources do not say a hosted runner is affected.

Node 20 end: GitHub changelog (2025-09-19): from 2026-06-16 runners default to Node 24; on 2026-09-23 Node 20 is removed and the ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION opt-out stops working. Per the changelog, Node 20 actions stop running on or after 2026-09-23; as of 2026-10-24 that date has passed. https://github.blog/changelog/2025-09-19-deprecation-of-node-20-on-github-actions-runners/
