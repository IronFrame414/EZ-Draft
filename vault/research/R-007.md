# Findings

- (a) URL `options=` parameter: pgx ParseConfig copies every URL key not in its `notRuntimeParams` list into `RuntimeParams`; `options` is not on that list, so it is sent as a startup parameter. Source: https://raw.githubusercontent.com/jackc/pgx/master/pgconn/config.go (fetched via summary of the file; the doc comment says ParseConfig "accepts them: they become runtime parameters or pgx-specific options"). Whether the CLI passes its `--db-url` through pgx ParseConfig: not verified (CLI source not readable, see below).
- (b) PGOPTIONS: the same pgx file maps `"PGOPTIONS": "options"` in parseEnvSettings and merges settings so the connection string overrides the environment. Source: https://raw.githubusercontent.com/jackc/pgx/master/pgconn/config.go. Whether the CLI process reads its environment through this path: not verified.
- Supavisor forwarding of the `options` startup parameter in session mode: not found. The Supabase troubleshooting page says session mode "behaves nearly identically to a standard direct connection" and gives port 5432 and user `postgres.[ref]` in its example, with no statement on startup parameters: https://supabase.com/docs/guides/troubleshooting/supavisor-and-connection-terminology-explained-9pr_ZO.md
- Supavisor README on main says transaction mode is the only pool mode and lists session pooling under "Future Work". This conflicts with the Supabase docs above and may be stale; it says nothing on options: https://raw.githubusercontent.com/supabase/supavisor/main/README.md
- CLI source: internal/db/push/push.go and internal/utils/connect.go could not be fetched (HTTP 404 on raw main, raw develop, GitHub blob develop and GitHub blob v2.121.0). So the CLI's handling of lock/statement timeouts, options, PGOPTIONS and stdin is not settled by these sources.
- `--yes`: the CLI reference lists `--yes` as a global flag ("answer yes to all prompts"), not under db push. The db push section lists `--db-url` ("must be percent-encoded"), `--dry-run`, `--include-all`, `--include-roles`, `--include-seed`, `--linked`, `--local`, `-p/--password`. Source: https://supabase.com/docs/reference/cli/supabase-db-push. The reference also documents a global `--agent` flag (default `auto`).
- Prompt without a TTY: the db push section documents no confirmation prompt. Supabase CLI issue #2238 (opened 2024-05-03, closed 2024-05-25 by PR #2318, reported on CLI 1.164.1): db push prompted and hung when run as a child process; the maintainer said the root cause was stdin not being closed; `yes |` worked as a workaround. Source: https://github.com/supabase/cli/issues/2238. Which release contains PR #2318: not found. Current behaviour on 2.121.0 with stdin closed and no --yes: not found.
- psql on ubuntu-latest (24.04): https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md lists "PostgreSQL 16.15" under Databases (service disabled by default, user postgres). The readme text fetched names no `psql` or `postgresql-client` package and its apt list does not include them. Whether `psql` is on PATH and its version: not found in this source. The readme is the main branch, not a pinned image.
