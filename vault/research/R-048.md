**Q1 Trigger**
- Env `REBALANCE_CHECK_INTERVAL_IN_MS`, default `to_timeout(minute: 10)` = 600000 ms, passed to app config `rebalance_check_interval_in_ms`. https://github.com/supabase/realtime/blob/v2.143.4/config/runtime.exs
- connect.ex schedules the first check at start: `Process.send_after(self(), {:check_connect_region, MapSet.new(Node.list())}, interval)`. On `{:error, :wrong_region}` it stops with `{:stop, {:shutdown, :rebalancing}, state}`. A passing check reschedules. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime/tenants/connect.ex
- rebalancer.ex returns `{:error, :wrong_region}` only when the node set is unchanged since the last check and the tenant's expected region differs from `Application.get_env(:realtime, :region)`. A node-set change returns `:ok`. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime/tenants/rebalancer.ex
- So the condition is a region mismatch. Connected clients and node count are not checked. A single node with an unchanged node list passes the stability gate, so it fires only on a region mismatch. The fetched code did not show how the expected region is looked up, so whether local dev mismatches is unverified.
- The KNOWN 10-minute timing matches the first check after Connect starts. Source says the check runs once per interval and stops on a mismatch, so the stop is not repeated.

**Q2 Replication slot**
- Created as `CREATE_REPLICATION_SLOT <name> TEMPORARY LOGICAL <plugin> NOEXPORT_SNAPSHOT`, name `supabase_realtime_messages_replication_slot_<suffix>`. No drop call on stop. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime/tenants/replication_connection.ex
- PostgreSQL: "Temporary slots are not saved to disk and are automatically dropped on error or when the session has finished." https://www.postgresql.org/docs/current/protocol-replication.html
- Inference, not stated by either source: when Connect stops, the slot is gone. Rows inserted into `realtime.messages` while it is down are not replayed to a later stream; a new slot starts at the current position. This fits the empty `pg_replication_slots` in KNOWN.

**Q3 Joined channels**
- `join/3` calls `Connect.lookup_or_start_connection(tenant_id)`, subscribes to the tenant broadcast topics, and starts CDC via `postgres_cdc_subscribe`. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime_web/channels/realtime_channel.ex
- Connect's `terminate/2` only logs the reason. It does not stop channels or replication. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime/tenants/connect.ex
- The channel file was truncated (about line 1000 of 1231), and no channel monitor on Connect was found in the part read. Not fully verified.
- Inferred: already-joined channels stay joined with no broadcast stream and no close or error push. No phx_close or phx_error on this path was found.
- Restart: Connect's child spec is `restart: :temporary`, so no supervisor restart. It is restarted by `lookup_or_start_connection`, which runs on the next channel join. No timer restart was found. The next authorization check was not verified.

**Q4 Disable or lengthen**
- The only setting is env `REBALANCE_CHECK_INTERVAL_IN_MS` (runtime.exs above). No disable switch was found in runtime.exs.
- `start_link` option `:check_connect_region_interval` overrides it, but that is code, not config. https://github.com/supabase/realtime/blob/v2.143.4/lib/realtime/tenants/connect.ex
- `supabase/config.toml` `[realtime]` has only `enabled` (default true) and `ip_version` (default IPv6). It cannot set the interval. https://supabase.com/docs/reference/cli/config
- Not verified: how the supabase CLI passes env to the realtime container. The CLI config.go fetch returned 404 (https://github.com/supabase/cli/blob/develop/pkg/config/config.go). Whether a container env override is possible is unknown from these sources.
