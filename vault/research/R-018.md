# Findings

1. Source of the statements (verified in source, tag v2.197.0):
   - `set local statement_timeout TO '<ms>';` is built at https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/hooks/hookspgfunc/hookspgfunc.go line 90, and `set local statement_timeout TO default;` at line 101 (reset, comment line 100). Both sit in `invokeHookFunc`.
   - Branch at lines 107-115: `if tx != nil { invokeHookFunc(tx) } else { db.Transaction(invokeHookFunc) }`. The test is pointer nil, not `tx.TX` nil.
   - `triggerBeforeUserCreated` (https://raw.githubusercontent.com/supabase/auth/v2.197.0/internal/api/hooks.go lines 35-50) calls `checkTX(db)` (lines 43, 116-122, which tests `conn.TX != nil`) and then `InvokeHook(db, ...)` (line 49). A non-transaction `*storage.Connection` passes `checkTX` and reaches the `tx != nil` branch unchanged, so the statements run on that connection outside a transaction. This matches the 25P01 warnings in KNOWN.
   - The same pattern applies to `triggerAfterUserCreated` (lines 15-33) and the MFA `send_sms` path (per issue #2852).
2. (1) custom_access_token: not settled. I could not locate its invocation in the fetched files (`internal/api/token.go` at v2.197.0 has no such call; the one `InvokeHook(nil, ...)` seen is the password-verification hook, which runs `db.Transaction`). Source for the token path is unverified; the planner should check it before relying on it.

5. (4) Timeout config: the Supabase CLI config reference lists only `auth.hook.<name>.enabled`, `.uri` and `.secrets` (https://supabase.com/docs/reference/cli/config); no timeout key. The 2 s limit is `defaultTimeout = time.Second * 2` (hookspgfunc.go line 17) with a `WithTimeout` option in code (lines 33-35); the docs state "Postgres Hooks have 2 seconds to complete processing" (https://supabase.com/docs/guides/auth/auth-hooks). No config.toml setting stops the `set local` statements from being sent.
