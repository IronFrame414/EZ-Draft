(1) createRoot / configure / render / unmount
- configure is not async; it returns a TrackedPromise<Root> (`configure(props) : TrackedPromise<...> {`, root.tsx). Configure runs after any previous configure promise settles (`previous.then(run, reject)`). Source: root.tsx.
- Renderer: `const gl = store.getState().gl ?? createRenderer(canvas, props.gl)`; gl as function is called with defaults `gl(defaults)`; a renderer instance (has `render`) is used as is; an object is merged into defaults `{ canvas, powerPreference: 'high-performance', antialias: true, alpha: true }` and passed to `new THREE.WebGLRenderer({...defaults, ...gl})`. Source: renderer.ts.
- Config keys: the Canvas docs list gl, camera, frameloop (always|demand|never, default always), dpr (default [1, 2]), events, orthographic (default false), fallback, onCreated. Source: https://r3f.docs.pmnd.rs/api/canvas. `flat` and `linear` are not described on the pages read; not verified.
- Store defaults: frameloop 'always', events `{ priority: 1, enabled: true, connected: false }`, size zeros. Source: store.ts.
- events default: the createPointerEvents default is set in web/Canvas.tsx (`events = createPointerEvents`), not in core createRoot. With no events passed to createRoot/configure, store.ts shows events.connected false. Inference (not stated in source): no pointer listeners are attached, which matches your plan to handle input yourself.
- render(children): `reconciler.updateContainerSync(element, fiber, null, noop)`; returns store. Source: root.tsx. Docs: configure must be called before render (https://r3f.docs.pmnd.rs/api/canvas).
- unmount(): `if (_roots.get(canvas) === root) unmountComponentAtNode(canvas)`. Source: root.tsx.

(2) invalidate and demand mode
- `invalidate(state?, frames = 1)`: with no state it runs `_roots.forEach(root => invalidate(root.store.getState(), frames))`, so yes, every root. Source: loop.ts.
- Early return if `state.gl.xr?.isPresenting || !state.internal.active || state.frameloop === 'never'`. Source: loop.ts.
- In loop, a root renders when `state.internal.active && (state.frameloop === 'always' || state.internal.frames > 0) && !state.gl.xr?.isPresenting`. With 'demand' a frame renders only while frames > 0. Source: loop.ts.
- The loop stops when no root requests another frame (`if (repeat === 0)` ... `running = false`). Source: loop.ts. So no idle loop in demand mode, after invalidate-driven frames finish.
- Docs: "Calling invalidate() will not render immediately, it merely requests a new frame to be rendered out." https://r3f.docs.pmnd.rs/advanced/scaling-performance
- Not verified: whether the initial render() call itself schedules a frame in demand mode (no source line read for that).

(3) WebGL context failure
- three r186 WebGLRenderer: when getContext returns null, it throws `THREE.WebGLRenderer: Error creating WebGL context with your selected attributes.` or `THREE.WebGLRenderer: Error creating WebGL context.` (the second when webgl2 also fails without the custom attributes). Its catch logs `'WebGLRenderer: ' + e.message` and rethrows. Source: https://raw.githubusercontent.com/mrdoob/three.js/r186/src/renderers/WebGLRenderer.js
- R3F configure: `run()` wraps createRenderer in try/catch and calls `reject(error)`; async factories use `.catch(reject)`. So configure's promise rejects with that Error; it is not swallowed. Source: root.tsx, renderer.ts (renderer.ts: createRenderer has no try block).
- Canvas component: configure is called with `.catch(setError)`; render is wrapped in an internal ErrorBoundary `set={setError}`, and `if (error) throw error` rethrows during render, so the error reaches the parent React error boundary. Source: https://raw.githubusercontent.com/pmndrs/react-three-fiber/v9.8.2/packages/fiber/src/web/Canvas.tsx. The Canvas docs advise a parent error boundary and a `fallback` prop: https://r3f.docs.pmnd.rs/api/canvas

(4) Public API and reconfigure
- createRoot(canvas).configure(...).render(...) on an existing canvas: the Canvas docs say "createRoot by design is not responsive, you have to take care of resize yourself" and describe configure before render (https://r3f.docs.pmnd.rs/api/canvas). The docs page for createRoot (r3f.docs.pmnd.rs/api/create-root) returned 404; a search snippet (not fetched) says the next docs state each configure() replaces the previous config and omitted props revert to defaults, so pass the full config each time (https://r3f.docs.pmnd.rs/next/).
- Second configure: renderer is reused. `store.getState().gl ?? createRenderer(...)` only creates when absent, and `if (!state.gl)` guards the assignment, so no second WebGL context from configure alone. Source: root.tsx, renderer.ts.
- configure after disposal rejects with `R3F: Cannot configure a root after disposal has started.` Source: root.tsx.
