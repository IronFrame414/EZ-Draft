# Findings

- Automatic caching is on by default through the `package-manager-cache` input, default `true`. Set it to `false` to turn automatic caching off. Sources: https://github.com/actions/setup-node/blob/main/action.yml and https://github.com/actions/setup-node/blob/main/README.md
- Introduced in v5.0.0 (release of 04 Sep, year not shown on the page): "Enhance caching in setup-node with automatic package manager detection", and "introduces automatic caching when a valid `packageManager` field is present in your `package.json`", with "To disable this automatic caching, set `package-manager-cache: false`". Source: https://github.com/actions/setup-node/releases
- Narrowed in v6.0.0 (14 Oct): "Limit automatic caching to npm, update workflows and documentation". Source: https://github.com/actions/setup-node/releases
- Automatic caching applies only to npm. It turns on when `devEngines.packageManager` or the top-level `packageManager` in package.json is npm and no `cache` input is given. Source: https://github.com/actions/setup-node/blob/main/README.md
- For `packageManager: pnpm@...` there is no automatic cache. The README says other package managers have caching "disabled by default and must be configured manually using the `cache` input". pnpm is supported only through the explicit `cache: pnpm` input. Source: https://github.com/actions/setup-node/blob/main/README.md
- The `cache` input accepts npm, yarn and pnpm; `cache-dependency-path` has no default. Source: https://github.com/actions/setup-node/blob/main/action.yml
- v6.3.0 added parsing of `devEngines` (also for `node-version-file`). This is not a caching change. Source: https://github.com/actions/setup-node/releases
- So for a pnpm project with no `cache:` input, v5, v6 and v7 do not cache. Only npm projects get the automatic cache.

Caveat: the README and action.yml were read through a summarizing fetch, and the release notes page omits years. Check the v7 release text directly before relying on it.
