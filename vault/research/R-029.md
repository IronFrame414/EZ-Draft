# Findings (retriever, web)

1. Event triggers (partly answered)
- The postgres role can create and manage event triggers through supautils: "With our Supautils extension (installed automatically for all Supabase projects), the postgres user has the ability to create and manage event triggers." https://supabase.com/docs/guides/database/postgres/event-triggers
- supautils README: "The privileged role is also able to create event triggers, while adding protection for privilege escalation." Triggers created by the privileged role "Will be executed for non-superusers." and "Will be skipped for superusers." and "Will also be skipped for [Reserved Roles]." https://github.com/supabase/supautils/blob/master/README.md (section Non-Superuser Event Triggers)
- Logging of skipped triggers: "The skipping behavior can be logged by setting the `supautils.log_skipped_evtrigs` config to true, this is false by default." Same README.
- "The privileged role won't be able to ALTER or DROP a superuser event trigger." Same README.
- Known limitation: "privileged role event triggers won't fire when creating publications, foreign data wrappers or extensions." Same README.
- Reserved roles: "Reserved roles are meant to be used by managed services that connect to the database." The README gives only the example `supautils.reserved_roles = 'connector, storage_admin'`; it does not list supabase_admin as reserved. Same README.
- Not found: whether supabase_admin is reserved or superuser on hosted projects (the README names the superuser through `supautils.superuser` only); whether ENABLE ALWAYS and DROP EVENT TRIGGER are allowed to postgres. The supautils CHANGELOG and the CLI file were not retrievable (HTTP 404 at the paths tried).
