# Findings

## 1. WebP encoding from canvas
- Safari macOS: caniuse lists image/webp in toBlob as not supported, 3.1 to 27.3; Technology Preview unknown. https://caniuse.com/mdn-api_htmlcanvaselement_toblob_type_parameter_webp
- Safari iOS / iPadOS: caniuse lists not supported, 3.2 to 27.2. Same URL.
- caniuse convertToBlob option.type image/webp: Safari not supported 3.1 to 27.3; TP unknown. https://caniuse.com/mdn-api_offscreencanvas_converttoblob_option_type_parameter_webp
- MDN WebP guide says WebP "can also be used for exporting images from a Canvas", which conflicts with caniuse for Safari. It notes Safari macOS needs Safari 14+ and macOS Big Sur or later. https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types
- No Safari version found in scope that first encodes WebP. WebKit bug 183720 (open, last modified 2023-11-07) has no WebP encode implementation statement; one 2019 comment says WebKit does not support WebP. https://bugs.webkit.org/show_bug.cgi?id=183720
- Fallback: when the type is unsupported, toBlob and convertToBlob return image/png. Check blob.type. https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob and https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob
- Chrome: toBlob WebP supported 50 to current; convertToBlob WebP from 69. Edge: toBlob 79 to 156; Firefox toBlob 96 to 162 (caniuse toBlob page); Firefox convertToBlob WebP from 105. https://caniuse.com/mdn-api_htmlcanvaselement_toblob_type_parameter_webp and https://caniuse.com/mdn-api_offscreencanvas_converttoblob_option_type_parameter_webp
- Quality: MDN says quality applies to lossy formats "such as image/jpeg or image/webp" and the default is used if out of range. No per-browser confirmation that quality is honoured for WebP in Chrome, Edge or Firefox was found in scope. Verify on device. https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob

## 2. WebGL capture with preserveDrawingBuffer false
- Spec default is false. With false, the buffer is cleared after it is presented. Using the context as a source image after the rendering function returns is undefined behaviour. The spec suggests readPixels or toDataURL in the same function that renders. https://registry.khronos.org/webgl/specs/latest/1.0/
- Spec does not name drawImage or createImageBitmap for this case. Reading the canvas with drawImage or createImageBitmap in the same task right after renderer.render is the same-function pattern. A later task reads undefined or blank pixels. No Chrome or Safari behaviour source for a later task was found in scope.
- Reported blank frame after compositing (WebKitGTK, not Safari): https://github.com/basilelt/overseer/pull/104 (search snippet only)
- three.js: preserveDrawingBuffer default false, "whether to preserve the buffer until manually cleared or overwritten." No performance or toDataURL note. https://threejs.org/docs/pages/WebGLRenderer.html
- R3F v9: no v9 doc found that combines addAfterEffect with capture. A pmndrs discussion says preserveDrawingBuffer is needed for canvas export, and older threads use a same-tick render then toBlob pattern. https://github.com/pmndrs/react-three-fiber/discussions/2054 (2020 thread, treat as sketch). The v10 migration PR lists addAfterEffect as deprecated, so it matters before an upgrade. https://github.com/pmndrs/react-three-fiber/pull/4023
- preserveDrawingBuffer cost: spec says "can cause significant performance loss on some platforms" and advises false. https://registry.khronos.org/webgl/specs/latest/1.0/
- Tile-based mobile GPU (iPad) specific cost: not found in scope. One GitHub PR reports per-frame copies and a readback stall, from a single developer's analysis, not a benchmark. https://github.com/karst10607/reien/pull/7

## 3. Worker OffscreenCanvas with 2D context and createImageBitmap
- caniuse convertToBlob: Safari 16.4 to 26.6 supported. https://caniuse.com/mdn-api_offscreencanvas_converttoblob
- MDN convertToBlob: "This feature is available in Web Workers." https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob
- caniuse createImageBitmap: Safari 17.0 to 26.6 supported; Safari 15 to 16.6 partial; no worker-specific row. https://caniuse.com/createimagebitmap (search snippet, not fetched)
- WebKit 17.0 release notes: OffscreenCanvas WebGL added in Safari 17.0. https://webkit.org/blog/14445/ (search snippet, not fetched)
- WebKit bug report: WebGL in workers did not work on Safari 17.1 with macOS 13, but worked on Sonoma. https://bugs.webkit.org/show_bug.cgi?id=183720 (linked from search, not confirmed in fetch)

## Not settled in scope
- Exact Safari version that encodes WebP (none found).
- Chrome and Safari behaviour for drawImage of a WebGL canvas in a later task.
- Quality honouring on Firefox and Chrome for WebP.
- iPad tile-based GPU cost of preserveDrawingBuffer.
