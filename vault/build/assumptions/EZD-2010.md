| EZD-2010 | Which cause is fixed: the audit's guess (the test reads the cookie from a failed request with missing headers) or a late cookie write? | The late write, in `signOutOnDevice`. The kept trace of CI run 45763424921 shows the `/sign-in` request left with a full Cookie header (the session cookie) but without `ezd_signed_out=1`, so the headers were not missing. A browser experiment showed why: Chrome accepts a `document.cookie` write without waiting for its cookie store (the write returned in 0 ms while the store process was frozen), and reading `document.cookie` back waits for the write (1,499 ms in the same experiment). The fix reads the cookies back before going to `/sign-in`. | Audit 2026-11-27 row 3 ("if the cookie really is written late, fix `signOutOnDevice`, not the wait"); AC-EZD-2010-1 ("or the real cause found from the code or a trace") |
| EZD-2010 | Should `app/e2e/sign-out-outbox.spec.ts` change to read the marker from the cookie store, as the audit proposed? | No. The spec is unchanged: it checks that the `/sign-in` request itself carries the marker, which is the thing the fix guarantees. The proof of the fix is a new unit test with a document whose cookie store is late (`app/src/lib/auth/device-sign-out-marker-stored.test.ts`). The late write could not be made to happen on demand in a browser test (1,590 local tries, none late), so no browser test reproduces it. | AC-EZD-2010-1 (the test keeps every assertion, limit and timeout); AC-EZD-2010-2 (reproduce with a stub) |
