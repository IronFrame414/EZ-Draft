| EZD-1995 | How is the catalog split: generated per-page files or a registry? | A registry of key prefixes per page (`app/src/server/messages/page-messages.ts`), checked by `page-messages-coverage.test.ts`, which reads each page's imports, its `/api/` routes and the route files under its layout and names any missing key or prefix. A generated file would conflict whenever lanes add keys in parallel. | AC-EZD-1995-1 ("build-time or registry-driven split"), AC-EZD-1995-2 |
| EZD-1995 | How does a lazy screen load "its own messages with its code"? | Each lazy screen that needs messages beyond its page's list has its own key-prefix list (`SCREEN_MESSAGES` in `server/messages/screen-prefixes.ts`) and a `lib/messages/screens/<screen>.messages.ts` file, loaded in parallel with the screen's code by `withScreenMessages`. The app build replaces that file with the slice written out (a bundler loader, `app/tools/screen-messages-loader.cjs`), so each slice is a small static script (countertops: 8,255 bytes) that the browser and service worker cache like any other, and no browser file holds the whole catalog. 11 screens have a slice: conflict panel, send dialog, lock UI, assistant, cabinets, sheets, countertops, help, fixtures, new project, my profile. The first review found the earlier version shipped the whole catalog (about 40 KB gzip) on the first pointer move; that version is gone. | AC-EZD-1995-1; reviewer finding 1 |
| EZD-1995 | Which lazy screens load without a slice? | Screens that need nothing beyond the editor page's list load plain (beam spacing, both ceiling modules, and the ones that mount at open). The room fields load on a plain open of a project with existing details, so their three extra messages (`office.cabinets.tile.pattern.*`) are in the editor page list. The lock UI loads on the first pointer move and keeps a slice (85 messages, under 20 KB) instead of adding them to every editor page's HTML; `e2e/screen-messages.spec.ts` checks that an editor open plus first pointer move fetches that slice and never the whole catalog. | reviewer finding 1 |
| EZD-1995 | The download rows counted only JS and CSS files (EZD-017 S1, EZD-1996), but the catalog travels in the page HTML, so download.projects-settings and download.editor could not fall by it. | Those two rows now also count the page's HTML document (`document: true` on their perf.config.mjs entries). The other download rows are unchanged: sign-in would go over its 200 KB budget with its HTML counted, and budgets are never raised. The budget values are unchanged. | AC-EZD-1995-3 ("download.projects-settings and download.editor fall by the measured amount"); CLAUDE.md rule 11 |
| EZD-1995 | What is the gate value for inline catalog bytes? | Two gate rows, each at its measured gzip size after the split plus 10%, rounded up (the EZD-1996 pattern): `inline-messages.projects-settings` (/dev/entry/office) measured 14,018 bytes (46,707 before), cap 15,420; `inline-messages.editor` (/dev/benchmark-plan) measured 24,612 bytes (46,520 before), cap 27,074. | AC-EZD-1995-3; Q-0071 (a) |
| EZD-1995 | Are keys that reach the browser in an `/api/` answer covered? | Yes. The check adds the keys found in the route handlers a page calls. This is a superset: it also counts keys those routes only use on the server. | AC-EZD-1995-2 ("can never crash a screen") |

The loop tooling was not edited. | process note |
