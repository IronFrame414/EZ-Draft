| EZD-903 | What two-point align is | Rigid: rotation plus offset. Scale comes only from units (there are no scale fields). Reference point P1 maps exactly to model point M1. The rotation is the angle from (P2 − P1) to (M2 − M1). The leftover offset is \|T(P2) − M2\|. The 1-point method maps P1 to M1 with a typed rotation (degrees, counter-clockwise positive, as the plan's angle convention). Stored in reference_drawing.alignment { method, offset_x, offset_y, rotation_deg, residual_in }. Corner equality uses the 1/64" inclusive comparison | S11 Decisions 2; 03-data-model.md#Q-0507 |
| EZD-903 | Worked example for AC-1 | Reference corner P1 (0, 0) and P2 (120, 0); model corner M1 (100, 50) and M2 (100, 170). Rotation 90°, offset (100, 50), residual 0". After alignment the reference point (0, 0) sits on (100, 50) and (120, 0) on (100, 170), within 1/64". A second case with M2 (100, 171) gives residual 1" | CLAUDE.md rule 2 (hand-worked) |
| EZD-903 | Who may align, lock, undo | Upload references (alignment is part of upload, S11 D2; S11 Permissions groups it with upload). No edit lock (the reference is not model data). It is not on the undo stack. A server route writes the column. "New versions inherit alignment" is EZD-908's copy-forward (phase 42; pointer only) | S11 Permissions, Decisions 2, 5 |
| EZD-903 | Floor | The Files tab also has the reference's floor select (floor_id; default is the open floor at import). Placing the drawing is part of alignment | S11 Files tab "Reference files"; S11 D2 |
| EZD-903 | Aligned readout | Status bar "Aligned": "2 points · {residual} offset" or "1 point · {rotation}° · {residual} offset"; "Not aligned" before alignment. The board's "grid A1 · 0" offset" is sample data | board S11 status bar; S11 Aligned readout |
