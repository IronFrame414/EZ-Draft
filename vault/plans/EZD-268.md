# EZD-268 · Fix: a failed unit or role goes up the model ladder before a ticket is set aside or the launcher waits

- **ACs:** AC-EZD-268-1, AC-EZD-268-2, AC-EZD-268-3, AC-EZD-268-4, AC-EZD-268-5
- **Complexity:** high (section 8)
- **Areas:** tooling, scripts, process
- **User-visible result:** a unit or agent that fails is tried again on a stronger model (up to Fable) before a ticket is set aside or the launcher waits, and Josh hears about it once, with the models tried.
- Phase: 1 · Planned by: planner · Date: 2026-10-29 · Status: ready

## 1. What to build

Terms (PROCESS-EZDRAFT.md s8 "Model ladder"):
- **Ladder:** `ladderModels(B)` = haiku → sonnet → opus → fable from base B up, padded with fable to 3 entries (s8: two escalations; Opus gets a second Fable try). **Fable fallback:** a Fable rung runs opus when `EZD_FABLE_ALLOWED` is `0` or after a Fable limit (Q-0004).
- **Failed try:** outcome not `ok`, `limit-*` or `dry-run`; or `ok` with STATUS.md hash and next-unit text unchanged (run.mjs:581-584).
- **Ticket units** `build`, `plan`; **launcher-wide units** `questions`, `review-plans`, `gate-phase`, `wrap`; `repair` per D5.
- **Outcome text** `o`: ok-no-progress → `ended ok but changed nothing in STATUS.md`; else `r.outcome` + `: <r.note>` when set; cleaned (`|` → `/`, CR/LF/tab runs → one space, cut to 200; EZD-265 D5).
