### Step 4: `EditorHeader` (`app/src/components/shell/EditorHeader.tsx` and `EditorHeader.module.css`, `'use client'`, wrapped in `React.memo`)
Props, all typed. The order of items follows 04 Header card, "left to right":

type EditorHeaderProps = {
  projectsHref: string;                 // wordmark target (Step 3)
  projectName: string;                  // data, shown as given
  onProjectMenu?: () => void;           // EZD-128 opens the switcher
  subtitle?: readonly React.ReactNode[];// client, version label, save state (04; S03 Data shown)

**Rendered order** (04 Header card, left to right):
1. `<Wordmark href={projectsHref} />`.
2. A 1 × 24 px divider in `var(--ez-border)`, `aria-hidden="true"` (S03 `<span>` divider).
3. A title block: a flex column with gap 1 px and `min-width: 0` (S03).
   - **Project name.**
     - With `onProjectMenu`: a `<button type="button">` holding the name and `<Icon name="expand_more" size={18} />`. The chevron is 18 px in `var(--ez-slate-500)` (S03 `.ms` font-size 18, color `#5e6672`), and the button calls `onProjectMenu`.
     - Without it: the name only, in a `<span>`, with no chevron and no button.
     - Name style: 15 px, weight 600 (S03). The name is truncated with `text-overflow: ellipsis` and `white-space: nowrap`, and its `title` is the full name (*planner's choice*: there is no rule for long names, and the title is data, not wording).
     - Why: a chevron with nothing behind it would be a dead control. EZD-128 passes the handler and adds `aria-haspopup`.
   - **Subtitle.** Rendered only when `subtitle` has at least one non-empty part. It is 12 px in `var(--ez-slate-500)` (S03), and truncated the same way.
     - Parts are joined by `<span aria-hidden="true"> · </span>` (space, U+00B7, space). Source: 04 "Client · version · save state"; S03 text.
     - `null`, `undefined`, `false` and `''` parts are skipped.
     - Parts are `ReactNode`, not strings, so EZD-122 can pass the version label as a button (S20 wraps it in its own `<span>`).
4. **Tabs.** A `<nav aria-label={t('office.header.views')}>` that takes the free space (`display: flex`, `flex: 1`, `justify-content: center`, `gap: 4px`, `align-self: stretch`; S03).
   - One `<button type="button">` per item of `views`, in `EDITOR_VIEWS` order whatever order `views` is given in. The label is `t(VIEW_LABEL_KEYS[view])`.
   - The active tab gets `aria-current="page"` (as the S03 markup does) and the `.active` class. Clicking a non-active tab calls `onViewChange(view)`. Clicking the active tab does nothing (*planner's choice*: it saves a pointless commit).
   - `.tab`: `display: flex; align-items: center; padding: 0 14px; color: var(--ez-slate-500); font-size: 14px; background: none; border: 0; font-family: inherit; cursor: pointer` (S03 `.ht`).
   - `.active`: `font-weight: 600; color: var(--ez-cobalt-text); box-shadow: inset 0 -2px 0 var(--ez-cobalt)` (Level-1 table).
   - Buttons, not links (*planner's choice*). 04 says the tabs "Switch the canvas view" and are "not separate pages". Whether the view also goes into the URL is decided by the editor route's owner (EZD-120b), which can pass `onViewChange` to a router call.
5. **Slots**, in this order: `reviewPill`, `share`, `export`, `issueSet` (04 Header card order; S03).
   - Each is rendered as given, with no wrapper element.
   - An empty slot renders nothing, so it leaves no gap. This covers "Hidden when N = 0" (pill) and "Hidden without *Issue permit sets* or *Issue revisions*" (Issue set), and the slot's owner decides.
   - The header does no permission checks. Permissions come from EZD-102's `can()` hook in the ticket that fills each slot (R24 "Controls a user lacks are hidden"; S03 Permissions).
