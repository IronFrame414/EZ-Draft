# EZD-169 · Fix: every 500 catch in a route reports the error

- **ACs:** AC-EZD-169-1 (`vault/spec/acceptance-criteria.md` row 326, generated from Done-when)

- **User-visible result:** nothing on screen; when the database fails behind the job, Realtime token or health address, Josh now gets the error in Sentry and the new-error email, instead of nothing.

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| What is reported | `new Error('db_unavailable')`, the same code the response carries; the caught error's message, stack and fields are never passed to Sentry or the alert store | ticket row Scope ("route location, no message text"); `actions.ts` `reportSignIn` (a code only); architecture Errors and logging (owner emails carry only scrubbed titles, ids and codes) |
