- **ACs:** AC-EZD-138-1, AC-EZD-138-2, AC-EZD-138-3, AC-EZD-138-4, AC-EZD-138-5 (`vault/spec/acceptance-criteria.md:1126-1130`, stage-0)

## 1. What to build

Design in one line: two new gated database functions (`invite_links_for_viewer` for the Users page, `invite_code_take` for the sign-in page) hand the per-invite random value to the server only; the server works out the link and the 6-digit code with EZD-105a's `invite-token.ts` (HKDF, label `ezd-invite-v1`; Q-0695 10 row 61); `listUsers` adds `invite: { link, code }` to the rows the viewer may see; a new Server Action `acceptInviteCode` checks the typed code against the derived one and, on a match, accepts through EZD-105c's one-step `acceptInviteByToken`, the same step the link's Accept uses.
