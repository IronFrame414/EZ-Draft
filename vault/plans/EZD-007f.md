### Findings against the parent text (planner, 2026-10-20; code read on develop at ae93127)
- **F1 Page title.** EZD-003's T8 and P-T14 need `document.title` to contain `EZ Draft` (P-Step 5; parent Level-1 answers). The root layout already sets `metadata.title = 'EZ Draft'` (`app/src/app/layout.tsx` lines 7–9, EZD-010c). The two signed-out pages set no title of their own and inherit it (*planner's choice*, CLAUDE.md rule 3): a page title of its own would be a literal English string on a bilingual page (R26 R17; EZD-007e lint block).
- **F2 "Use a different email" needs a cookie write.** P-Step 5 says the button "clears the cookie and returns to step 1", but EZD-007d's `actions.ts` has no action that deletes `ezd_sign_in_email` (`vault/plans/EZD-007d.md` section 3, five actions). Cookies can be written only in a Server Action or Route Handler (EZD-007c finding C3). This part adds a sixth async export to `actions.ts`, `clearSignInEmail()`, so every sign-in cookie write stays in that one file (*planner's choice*; EZD-007d D3: the file may export only async functions, which this is).
- **F3 Confirm page headers.** P-Step 5 fixes `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on `/auth/confirm`, but no P-T row checks them. A page component cannot set response headers. `Referrer-Policy` is set by `headers()` in `app/next.config.ts` for source `/auth/confirm` (*planner's choice*). `Cache-Control` comes from Next.js itself: the page reads cookies (`getSignInLanguage()`, EZD-007d), so it is rendered per request and Next sends a `Cache-Control` that includes `no-store`; Next overrides any `Cache-Control` set in `next.config` for pages in production, so the builder does not set it there *(confirm both on the pinned Next.js 16.4.2)*. T38 (b) checks both.
