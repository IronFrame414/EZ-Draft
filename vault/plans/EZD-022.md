## 1. What to build

Ticket row (vault/tickets/phases/phase-00.md):
- Scope: Typed registry of every event name in Hooks, events and integrations, plus an emit() helper; every later ticket emits through it. The event log write is added by EZD-109 and webhook delivery by EZD-1301.
- Done when: A unit test fails when code emits a name that is not in the registry.
- Depends on: EZD-001.
- Spec ref: Hooks · Internal app events (Canonical names).

**Which names (Level 1, from 07).** Section 07 names 48 distinct events, in three kinds:
- `webhook` (12): the 9 rows of "Outbound webhooks to EZ Binder" plus the 3 "Added in Round 24" names under Delivery rules (EZD-1302's row lists them among outbound payloads, phase-13.md).
- `internal` (34): every name in "Internal app events", including `import.ready` (named "(new)" in the `import.completed` row) and `render.client_ready` (named in the `render.approved` row and again in the last row; listed once).
- `log_only` (2): `catalog_item.created`, `detail.placed`; 07 Canonical names: such screen events "write the event log only and are not webhooks".
- Other screen events (e.g. `user.joined`, which EZD-007 adds, vault/plans/EZD-007.md Step 3) are not named in 07, so each emitting ticket adds its name as `log_only` in the same commit; T8 and T1 (b) force it, and EZD-1314 audits it (phase-13.md).
- Names are copied without markdown escapes (`lock.request_declined`, not `lock.request\_declined`).
- Payloads: outbound payloads are EZD-1302's ("with the payloads in the table"); 07 gives no internal payloads, so each emitting ticket narrows its own `EventPayloads` entry.
- Delivery: emit() validates the name and hands the event to an ordered sink list that is empty here; EZD-109 adds the event log sink and EZD-1301 the webhook sink (ticket Scope). Nothing is written and nothing leaves the process in this ticket.

**Step 1. Registry** `app/src/lib/events/registry.ts` (shared browser/server; docs/architecture.md Folder layout `src/lib/`). `EVENTS` holds exactly the 48 entries of section 4, grouped by kind, each group with a comment citing its 07 sub-heading. Entries are objects (`{ kind }`) so EZD-1314 can add its later-phase mark without a breaking change. `isRegisteredEvent` uses `Object.hasOwn`, so inherited keys (`toString`) are not events. `EventPayloads` is an interface (not a mapped type) so later tickets narrow one entry in place (EZD-007 does, vault/plans/EZD-007.md Files). No imports. Name format `^[a-z][a-z_]*\.[a-z][a-z_]*$` is a *planner's choice* (CLAUDE.md rule 3: how to build); all 48 names fit it; EZD-018 reuses it (vault/plans/EZD-018.md Step 3).

**Step 2. emit()** `app/src/server/events/emit.ts` (server-only folder). `createEmitter(...).emit(name, payload, ctx)`, in order:
1. If `!isRegisteredEvent(name)`: reject with `UnknownEventError` (message contains the name) before any sink runs, in production too ("Nothing fails silently", docs/architecture.md Errors and logging).
2. Build the envelope: `id` = `newId()` (default `crypto.randomUUID()`, a Node 22 and browser global; the "idempotency key per event", 07 Delivery rules), `at` = `now().toISOString()` (03 Tables event_log `at`), `projectId`/`actorId` = given value `?? null`; `tenantId` required (03 intro: every row is tenant-scoped).
3. Await each sink in array order. A throwing sink does not stop later sinks; after all ran, reject with an `AggregateError` of the sink errors; else resolve to the envelope (*planner's choice*; docs/architecture.md Errors and logging).
L-004 check: step 1's early return happens before any sink, so no later rule (ordering, all-sinks-run) is skipped for a registered name; an unregistered name must never reach a sink (T5).

`app/src/server/events/index.ts`: `defaultSinks` (empty array; comment: EZD-109 adds the event log sink, EZD-1301 the webhook sink), the app-wide `emit = createEmitter({ sinks: defaultSinks }).emit`, and re-exports. *Re-validation change:* `defaultSinks` moves into `index.ts` (was a separate `sinks.ts`) to keep the ticket at 8 files (PROCESS.md section 6 Ticket size); no other plan names `sinks.ts` (grep of vault/plans). Callers call `emit` by its bare name, never aliased, because the scan (Step 3) recognises bare `emit(` calls.
