# EZD-040 · Fix: error tunnel scrubs tags and contexts

- **ACs:** AC-EZD-040-1, AC-EZD-040-2
- **Complexity:** medium (section 8)
- **User-visible result:** none on screen. Error reports that reach Sentry no longer carry email addresses, ids, tokens or sign-in codes in their tags, contexts or stack frames, whether they come from the browser through the tunnel or from the server.
- Phase: 0 · Planned by: planner · Date: 2026-10-23 · Status: planned

## 1. What to build

The problem (ticket Scope; STATUS.md EZD-024 "Security minors for later: tunnel forwards browser tags and frame paths unscrubbed"), read at `develop`:
- `app/src/app/api/monitoring/route.ts` line 73 builds `tags: { ...raw.tags, 'ezd.source': source }`. This spreads the browser's raw tags back over the scrubbed event.
- `scrubEvent` (`app/src/lib/errors/scrub.ts` lines 31-62) scrubs only `exception.values[].value`, `message`, `request`, `user`, `extra` and `breadcrumbs`. `tags`, `contexts` and `exception.values[].stacktrace.frames` pass through unchanged.
- `scrubEvent` is also `beforeSend` in the browser (`browser-options.ts` line 21) and on the server (`sentry-options.ts` line 77). The fix therefore applies to every Sentry path, as the ticket asks: "in the route and scrubEvent".

Fix: `scrubEvent` scrubs those three parts with the existing `scrubText`. The route rebuilds `tags` from the scrubbed event.

Data: none. No migration, no table, no money field, no `schema_version`.

| D2 `tags` | Not a plain object (`null`, array, primitive) → the `tags` key is removed. Otherwise, a new object built in `Object.entries` order. Key → `scrubText(key)`. ## 9. Dependencies

Risks:
- Server events now get scrubbed tags too. Today's server tag values (`function`, `job`, `email.send`, `auth.sign_in`, route patterns, job kinds) contain nothing `scrubText` changes, and D3 keeps `ezd.job_id`. A later ticket that tags an email, UUID or token gets it scrubbed, which is intended.
- Trace ids become `<token>` (D4). Sentry may flag the trace context as invalid. Errors are still accepted, and the app runs no tracing.
- A 100,000-level context is scrubbed (D5). Forwarding it may still fail in the transport's JSON serialization. That failure is caught by the route's best-effort `try` (route.ts lines 95-99) and costs only the attacker's own event.
- Not covered (D10): `exception.values[].type` and `mechanism`, `logentry`, `transaction` and `fingerprint` still pass unscrubbed from the tunnel, and `type` also reaches the owner-email title through `errorTitle`. The orchestrator may raise a follow-up ticket from the security review.
