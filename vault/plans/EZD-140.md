# EZD-140 · Notification settings per user

- **ACs:** AC-EZD-140-1, AC-EZD-140-2, AC-EZD-140-3, AC-EZD-140-4
- **Complexity:** high (section 8)
- **Areas:** ui, data-model, migrations, security, testing
- **User-visible result:** in My profile → Notifications, Josh sees the nine notification kinds with an In app and an Email switch each, all on; he turns one kind's Email off, saves, and the next notification of that kind shows in the bell with no email.
- Phase: 2 · Planned by: planner · Date: 2026-10-29 · Status: questions

## 1. What to build

Data (03b rule 1; 11 rule 10; ARCH Row-level security):
- **M1** `supabase/migrations/20261030120000_create_notification_setting.sql`: table `public.notification_setting` (probed, section 2): `tenant_id uuid not null references public.tenant (id) on delete cascade`, `user_id uuid not null references public.app_user (id) on delete cascade`, `kind text not null check (kind in (<the nine NOTIFICATION_KINDS, EZD-110 D1 order>))`, `in_app boolean not null default true`, `email boolean not null default true`, `updated_at timestamptz not null default now()`, `primary key (tenant_id, user_id, kind)` (its first column serves as the tenant index); RLS on; policy `notification_setting_select` for select to authenticated using `tenant_id = (select private.tenant_id()) and user_id = (select private.app_user_id())`; restrictive `notification_setting_api_gate` (ARCH RLS template); no insert, update or delete policy; `grant select … to authenticated; grant select, insert, update, delete … to service_role;`.
- **M2** `…20261030120001_create_save_my_notification_settings.sql`: `public.save_my_notification_settings(p_settings jsonb) returns void`, plpgsql volatile security definer `set search_path = ''`, as probed: `perform private.require_api_gate()`; tenant or user null → `42501 not_authorized`; not an array of 9 → `22023 invalid_input`; every element an object with a listed string `kind` and boolean `in_app` and `email`, 9 distinct kinds, else `22023 invalid_input`; upsert on `(tenant_id, user_id, kind)` updating `in_app`, `email`, `updated_at = now()` only where `(in_app, email)` is distinct. `revoke all on function public.save_my_notification_settings(jsonb) from public, anon, service_role; grant execute … to authenticated;` (L-016).
- **M3** `…20261030120002_apply_notification_settings.sql` (redefines EZD-110 objects; confirm on pinned version, L-009):
  1. `alter table public.notification add column in_app boolean not null default true;`
  2. `alter policy notification_select on public.notification using (<expression> and in_app);` where `<expression>` is the merged one, read on the local stack with `select pg_get_expr(polqual, polrelid) from pg_policy where polname = 'notification_select'` (EZD-110 M2 plans `tenant_id = (select private.tenant_id()) and user_id = (select private.app_user_id()) and (project_id is null or (select private.all_projects()) or project_id = any ((select private.listed_project_ids())::uuid[]))`).
  3. `drop trigger notification_broadcast_created on public.notification;` then the same trigger with `when (new.in_app)` before `execute function private.notification_broadcast_created()` (`drop trigger` is outside Release safety's scan).
  4. `create or replace function private.create_notification(uuid, uuid, text, uuid, jsonb, text)`: EZD-110's merged body (`20261029120002_create_notification_functions.sql`, same language, volatility, security, `search_path`) plus, after its refusals: `select s.in_app, s.email into v_in_app, v_email from public.notification_setting s where s.tenant_id = p_tenant_id and s.user_id = p_user_id and s.kind = p_kind;` then `coalesce(…, true)` for each; the insert sets `in_app = v_in_app`; the `notification_email` job insert runs only `if v_email`. Returns an id whenever it did before. Then `revoke all on function private.create_notification(uuid, uuid, text, uuid, jsonb, text) from public;`.
  5. `create or replace` of `public.list_notifications(timestamptz, uuid)`, `public.open_notification(uuid)` and `public.mark_all_notifications_read()`: merged bodies plus `and <alias>.in_app` (the alias the merged body gives `public.notification`, or `notification.in_app` when it has none) in every `where` reading `public.notification` (items, `hasMore`, unread count); nothing else; then each one's merged revoke and grant lines, repeated.
