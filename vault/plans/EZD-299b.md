# EZD-299b · Conflict list: refused changes leave the outbox; Keep mine, Keep theirs, Remove

- **ACs:** AC-EZD-299-2, AC-EZD-299-3, AC-EZD-299-4, AC-EZD-299-9, AC-EZD-299-16, AC-EZD-299-17, AC-EZD-299-18
- **Complexity:** high (section 8)
- **Areas:** data-model, security, api, testing, offline
- **User-visible result:** when the server refuses a change for good, that change waits in the conflict list on this device and on the server, your other edits keep saving, and Keep mine, Keep theirs and Remove work (the screens come in EZD-299).
- Phase: 3 · Planned by: planner · Date: 2026-11-07 · Status: planned

## 1. What to build
Data: no table, no migration, no SQL function and no `schema_version` change. No money field (03b rule 2). The device database stays `ezdraft-device` **version 1** (D-Key).

Build only after EZD-299a is merged (every `app/src/lib/conflicts/conflicts.ts` type, `MAX_RECORD_*`, the sync-conflicts routes, `resolves`, `app_outdated`). Q-0631 (b) (answered-agent 2026-11-07, security-reviewer): the device stores one reason, `not_open`, for a project that was deleted and for one no longer open to the person; no presence route or function is built.

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| D-Key | Conflict rows go in the existing `outbox` store under key `[CONFLICT_KEY_PART, appUserId, tenantId, projectId, objectId]`, outside `actorRange`, so `list()`, `countQueued` and an older open tab never see them; no version bump (an older tab reopening a newer version fails with VersionError and loses the edits it holds, `outbox-idb.ts:42-45`). The idb schema's `outbox` value type is `OutboxEntry \| DeviceConflict`; values read through `conflictRange` are `DeviceConflict`, through `actorRange` `OutboxEntry` (cast). This replaces the split proposal's "new store, version 1 → 2" | rule 18; EZD-299 split proposal Part b; KNOWN-LIMITS none |
| D-Classify | `classifySave` adds `conflicts` only for status 409 with code `save_conflict` and `body.conflicts` an array of `{ id: string; serverSeq: number }`; adds `invalid` only for 400 with code `invalid_object` and `body.invalid` an array of `{ id: string; issue: string }`; otherwise the key is absent (not `undefined`). Other outcomes unchanged | objects route (`route.ts:72-88`); P202 section 3 |
| D-Settle | On a refused save, in `loop`: `save_conflict` with `conflicts` → move the sent entries whose id is listed, reason `conflict`, `serverSeq` from the list. `invalid_object` with `invalid` → move the listed sent entries, reason `invalid`, then `captureBrowserError(new Error('invalid_object'), 'outbox.invalid_object')` once per answer (dynamic import as `reportStorage`). `permission_denied` → every entry of that project in `storage.list()` (not only the batch), reason `not_editable`. `project_not_found` → every entry of that project in `storage.list()`, reason `not_open` (a deleted project and one no longer open read the same; no other call). A project-wide move first `drop`s that project's deletes with `baseSeq` 0 (pickBatch rule). When the move list is empty, and for every other code (`invalid_input`, `not_signed_in`, `stale_lock_epoch`, `app_outdated`) → block exactly as today (status `error`, problem = the code, entries kept, no drain until `retry()`). After a move: `set({ failures: 0, conflictRev: +1 })` and the loop continues (the rest keep saving, status ends `saved`, P2 "Your other edits are saved.") | Q-0502; Q-0511 e; Q-0540; Q-0631 (b); 03b rule 9; P299a D-Reason; `vault/mockups/S03bConflictList-wording.md` P2 |
| D-Move | `moveToConflicts(moves, now)`, one `outbox` transaction: per move, the entry at its key now; missing or `rev` ≠ the sent `rev` → skipped (the newer edit is refused on its own later); else the entry is deleted and the row put: `{ projectId, objectId: entry.id, reason, baseSeq: entry.baseSeq, serverSeq, lockEpoch: entry.lockEpoch, value: entry.value, refusedAt: now, state: 'listed', server: reason not_open ? 'device' : 'pending', serverId: <existing row's serverId> ?? null }` | Q-0502 "nothing is lost"; `outbox-idb.ts` `drop` |
| D-Record | At the end of every lock run (`tryRun(lockName, async () => { try { await loop(); } finally { await recordPending(); } })`), when not disposed and online: rows `state 'listed'` and `server 'pending'` from `listConflicts()`; a row whose `TextEncoder` byte length of `JSON.stringify(value.data)` > `MAX_RECORD_DATA_BYTES` (65,536) → `device`, not sent; the rest grouped by project (first-seen order), each group cut into chunks of `MAX_RECORD_CHANGES` (1,000), one `postConflicts` per chunk with changes in `listConflicts` order. Answers: `recorded` → `recorded` + `ids[i]`; refused 404 → `device` with reason `not_open` (Q-0631 (b)); refused 400 → `device` and `captureBrowserError(new Error('sync_conflict_record_refused'), 'outbox.record')`; other refused → pending; `failed` → pending and no more calls this pass. Then one `setConflictServer(updates)`; each orphan with a `serverId` gets one `removeServerConflict` (result ignored); `conflictRev + 1` when `updates` is not empty. A throw anywhere in the pass is caught and reported with `captureBrowserError(error, 'outbox.record')`; a storage throw goes through `storageFailed`. Inside the lock, so two tabs never record the same row | Q-0540 (one sync = one drain); Q-0531; P299a D-Cap, route row |
| D-Server | `setConflictServer(updates)`: row missing at the key → returned as an orphan (Keep theirs or Remove ran during the call); `refusedAt` equal → `server`, `serverId` (when not null) and `reason` (when given) applied; `refusedAt` different (a newer refusal) → only `serverId` set, `server` stays `pending` (the upsert keeps the same server id, P299a S2) | rule 18; P299a S2 `record_sync_conflicts` |
| D-Requeue | `requeue(row, baseSeq, now)`, one transaction: the row put with `state 'requeued'` (other fields kept); the outbox entry at the key, when present, gets `baseSeq` and `rev + 1` and keeps its newer value; else a new entry `{ projectId, id: objectId, baseSeq, lockEpoch: row.lockEpoch, value: row.value, rev: 1, queuedAt: now }` | Q-0511 c, d |
| D-Resolves | `resolves` is worked out at send time: after `pickBatch`, `listConflicts()`; for each sent entry a `requeued` row at its key with a `serverId` gives that id; the save body is `{ lockEpoch, changes, resolves }` with `resolves` only when not empty. `commit` deletes `requeued` rows at the saved keys (rev check not applied), in the same transaction | P299a D-Resolves; AC-EZD-299-11 |
| D-KeepMine (sync) | `keepMine(row, baseSeq)` runs on the `writes` chain (after queued puts): `storage.requeue(row, baseSeq, Date.now())`; then `conflictRev + 1`, `clearTimer()`, `void drain()` (offline: status `offline`, the entry waits, AC-4). A storage throw → `storageFailed(error)` and the promise rejects; the chain itself keeps going (`writes = p.catch(() => {})`) | Q-0511 d |
| D-Merge | `refresh()` reads `storage.listConflicts()` and `storage.list()` (queued keys `${projectId}/${id}`), then `getConflicts`, then `mergeConflicts(device, queuedKeys, server)`: a `requeued` row hides its key (and the server row at that key) when `queuedKeys` holds the key, else it counts as `listed`; a device row and a server item at one key → one row from the server item (reason, mine, saved, projectName, clientName, savedBy, savedAt, `serverId` = item.id) plus the device `serverSeq`; a device row `recorded` with no server item at its key while `server` is not null → left out and returned in `resolvedElsewhere`; other device rows → `mine` from `value` (`null` → `{ deleted: true }`), `saved`, `projectName`, `clientName`, `savedBy`, `savedAt` all null; server items alone → as they are (Q-0632 (a): the three fields pass through unchanged). `server` null (fetch failed) → device rows only, `resolvedElsewhere` empty. Order: `at` descending, then `key` ascending. `actions`: `['keep_mine', 'keep_theirs']` for reason `conflict`, else `['remove']` | Q-0502; Q-0511 e; Q-0531; Q-0540; Q-0632 (a) |
| D-Stale | One counter `rev`, bumped by every Keep mine, Keep theirs, Remove that succeeds and every `conflictRev` change of the sync (which also calls `refresh()`). Each `refresh()` takes a new token and the current `rev`: a result applies only when the token is the newest and `rev` has not moved; token newest but `rev` moved → `refresh()` runs once more; token not newest → dropped. A dropped or stale result changes nothing (neither `rows` nor `server`, nor `deleteConflicts` of `resolvedElsewhere`), whether its GET answered or failed. Generations start only at: `refresh()` (token), and Keep mine, Keep theirs, Remove that succeed and a `conflictRev` change (`rev`); a failed action changes nothing, so it starts none | L-048; planner lessons EZD-110b |
| D-KeepMine (list) | Only reason `conflict` and a non-null `sync`, else `not_allowed`; unknown key → `not_found`. Row passed: the device row, or one built from the server item (`reason 'conflict'`, `baseSeq` item.baseSeq, `serverSeq` saved?.updatedSeq ?? null, `value` from `mine`, `refusedAt` = `at`, `server 'recorded'`, `serverId` item.id). `lockEpoch`: the editor's when `editor.projectId` is the row's project, else the device row's, else 0 (stays 0 until EZD-125). `baseSeq` = `saved?.updatedSeq ?? serverSeq ?? 0`. Then `sync.keepMine` (reject → `failed`), then `editor.applyRemote([{ id, value: mine }])` for the open project | Q-0511 c, d; 00d Lock generation |
| D-KeepTheirs | Order: (1) the saved value: `row.saved`, else `fetchModel(projectId, { fetchImpl })` (`app/src/lib/outbox/model-api.ts`, `ModelLoadResult`): `ok: false` → `failed`, nothing changed; `model.objects.find((o) => o.id === objectId)` gives `{ type, schemaVersion, data }` at its `updatedSeq`; absent → deleted (value null, `updatedSeq` 0); (2) `serverId` set → `removeServerConflict` (not `removed` → `failed`, nothing changed); (3) `deleteConflicts([key])`, `setMirror(projectId, objectId, value \| null, updatedSeq)` (deleted, or absent from the load → mirror deleted, as `commit` does for a saved delete); (4) open project → `editor.applyRemote` (no queue, no undo); (5) row removed from `rows`, `rev + 1`.
