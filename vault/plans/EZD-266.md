# EZD-266 · Fix: EZD-173 K7 takes its expected question IDs from all three question files

- **ACs:** AC-EZD-266-1
- **Complexity:** low
- **Areas:** tooling, scripts, testing
- **User-visible result:** the ledger-lock test K7 no longer fails on a day when `QUESTIONS.md` holds no open questions, so the gate stops going red for a reason that has nothing to do with the ticket being built.
- Phase: 1 · Planned by: planner · Date: 2026-10-29 · Status: ready

## 1. What to build
Test-only fix (ticket row: "the code is right"; Q-0429). Code base: develop at `8957c678`; line numbers below taken with `grep -n` / `sed -n` on that commit. One file, written by the test-author (`.claude/hooks/guard-paths.mjs` lines 15-17 and 73-74: `*.test.mjs` is a test file). The builder writes no file; it runs M1 and M2 (section 4). No data, tables or migrations.

Cause (planner, from the code): K7 (`scripts/process/ledger-lock.test.mjs` lines 238-288) copies the live `vault/` and computes `max` at line 256 from the `| Q-nnnn |` rows of the copy's `QUESTIONS.md` only. `assignQuestionIds` (`vault/tools/next_ticket.mjs` line 241) starts from `questionMax(vault)`, which reads all three files (`vault/tools/questions-files.mjs`; EZD-173 contract C16). With no rows in `QUESTIONS.md`, `Math.max()` of nothing is `-Infinity` and K7 expects `Q--Infinity`. A second cause of the same class: K7's result depends on whatever the live `QUESTIONS.md` holds on the day (2 rows at `8957c678`, so it passes today). The fix closes both (rule 18): K7 sets the copy's question state itself and computes `max` over the three files.
