# EZD-241 · Fix: the release stops a migration that drops or renames a released object in production

- **ACs:** AC-EZD-241-1, AC-EZD-241-2, AC-EZD-241-3
- **Complexity:** high (section 8)
- **User-visible result:** from the second release on, while production's migrations run, two temporary database triggers stop any migration that would drop or rename something the previous release still reads, even when the drop happens only because of the rows production holds; afterwards the release proves every migration it applied ran under them (else nothing goes live and the runbook says do not re-run); they are removed after every run, and the runbook has a one-paste check (J5) for `ezdraft-dev`.
- Phase: 1 · Planned by: planner · Date: 2026-10-27 · Status: planned

## 1. What to build
Design: Q-0358 (c). SQL below was run by the planner on the pinned local stack (section 2, L-009). Data: no migration, no table. In production during step E only: schema `ezd_release_guard` (functions `protected()`, `on_sql_drop()`, `on_ddl_end()`, `on_migration_row()`; sequences `seen`, `applied`), event triggers `ezd_release_guard_sql_drop`, `ezd_release_guard_ddl_end`, and the row trigger `ezd_release_guard_migration_row` on the CLI's history table `supabase_migrations.schema_migrations` (the positive signal: the CLI inserts one history row per applied migration in the push session, so `applied` counts migrations recorded under the setting; sequences are not rolled back). The protected list lives in a function body, never a table, so a nightly dump that overlaps step E holds no guard rows in `data.sql` (architecture Off-site backups: restore builds the schema from the repo's migrations).

### Guard SQL (`release-guard.mjs`)
`lit(s)` = `'` + `s` with every `'` doubled + `'`. `<LIST>` = `lit(JSON.stringify(objects.map(({ id, kind, name }) => ({ id, kind, name }))))`; `<SNAP>` = `lit(SNAPSHOT_SQL.replace(/;\s*$/, ''))` (`SNAPSHOT_SQL` imported from `scratch-check.mjs`); `<TAG>` = `lit(baseTag)`; `<IDEXPR>` = the `case` below. `buildGuardInstallSql` returns exactly:
```sql
begin;
create schema ezd_release_guard;
revoke all on schema ezd_release_guard from public;
create sequence ezd_release_guard.seen;
create sequence ezd_release_guard.applied;
create function ezd_release_guard.protected() returns table (id text, kind text, name text) language sql immutable set search_path = '' as $ezd_guard$
  select x.id, x.kind, x.name from pg_catalog.json_to_recordset(<LIST>::json) as x(id text, kind text, name text)
$ezd_guard$;
create function ezd_release_guard.on_sql_drop() returns event_trigger language plpgsql set search_path = '' as $ezd_guard$
declare
  r record;
  p record;
begin
  if coalesce(pg_catalog.current_setting('ezd.release_guard', true), '') <> 'on' then
    return;
  end if;
  for r in select d.classid, d.objid, d.objsubid from pg_catalog.pg_event_trigger_dropped_objects() as d loop
    select o.kind, o.name into p from ezd_release_guard.protected() as o where o.id = <IDEXPR>;
    if found then
      raise exception 'ezd_release_guard: % % is dropped or renamed while % still reads it', p.kind, p.name, <TAG>;
    end if;
  end loop;
end
$ezd_guard$;
create function ezd_release_guard.on_ddl_end() returns event_trigger language plpgsql set search_path = '' as $ezd_guard$
declare
  snap json;
  p record;
begin
  if coalesce(pg_catalog.current_setting('ezd.release_guard', true), '') <> 'on' then
    return;
  end if;
  execute <SNAP> into snap;
  select o.kind, o.name into p
    from ezd_release_guard.protected() as o
    left join (select e->>'id' as id, e->>'name' as name from pg_catalog.json_array_elements(snap) as e) as c on c.id = o.id
    where c.id is null or c.name <> o.name
    order by o.id
    limit 1;
  if found then
    raise exception 'ezd_release_guard: % % is dropped or renamed while % still reads it', p.kind, p.name, <TAG>;
  end if;
end
$ezd_guard$;
create function ezd_release_guard.on_migration_row() returns trigger language plpgsql set search_path = '' as $ezd_guard$
begin
  perform pg_catalog.nextval('ezd_release_guard.seen'::pg_catalog.regclass);
  if coalesce(pg_catalog.current_setting('ezd.release_guard', true), '') = 'on' then
    perform pg_catalog.nextval('ezd_release_guard.applied'::pg_catalog.regclass);
  end if;
  return null;
end
$ezd_guard$;
revoke all on function ezd_release_guard.protected() from public, anon, authenticated, service_role;
revoke all on function ezd_release_guard.on_sql_drop() from public, anon, authenticated, service_role;
revoke all on function ezd_release_guard.on_ddl_end() from public, anon, authenticated, service_role;
revoke all on function ezd_release_guard.on_migration_row() from public, anon, authenticated, service_role;
revoke all on sequence ezd_release_guard.seen, ezd_release_guard.applied from public, anon, authenticated, service_role;
create event trigger ezd_release_guard_sql_drop on sql_drop execute function ezd_release_guard.on_sql_drop();
alter event trigger ezd_release_guard_sql_drop enable always;
create event trigger ezd_release_guard_ddl_end on ddl_command_end execute function ezd_release_guard.on_ddl_end();
alter event trigger ezd_release_guard_ddl_end enable always;
create trigger ezd_release_guard_migration_row after insert on supabase_migrations.schema_migrations for each row execute function ezd_release_guard.on_migration_row();
alter table supabase_migrations.schema_migrations enable always trigger ezd_release_guard_migration_row;
commit;
select 'ezd_release_guard_installed ' || (select pg_catalog.count(*) from ezd_release_guard.protected()) || ' ' || (<GUARDS>);
```
`<GUARDS>` (also in `GUARD_REMOVE_SQL`) = `(select pg_catalog.count(*) from pg_catalog.pg_event_trigger where evtname in ('ezd_release_guard_sql_drop', 'ezd_release_guard_ddl_end') and evtenabled = 'A') + (select pg_catalog.count(*) from pg_catalog.pg_trigger where tgname = 'ezd_release_guard_migration_row' and tgenabled = 'A')`, written out in full (3 when intact).
`<IDEXPR>` (the `SNAPSHOT_SQL` id forms `n`, `c`, `c<oid>:<attnum>`, `p`, `t`, `x`):
```sql
case r.classid when 'pg_catalog.pg_class'::pg_catalog.regclass then 'c' || r.objid || case when r.objsubid <> 0 then ':' || r.objsubid else '' end when 'pg_catalog.pg_proc'::pg_catalog.regclass then 'p' || r.objid when 'pg_catalog.pg_type'::pg_catalog.regclass then 't' || r.objid when 'pg_catalog.pg_namespace'::pg_catalog.regclass then 'n' || r.objid when 'pg_catalog.pg_extension'::pg_catalog.regclass then 'x' || r.objid end
```
Other classes give null and match nothing.

`GUARD_REMOVE_SQL` (no transaction; psql `ON_ERROR_STOP`):
```sql
select 'ezd_release_guard_before ' || ((select pg_catalog.count(*) from pg_catalog.pg_event_trigger where evtname in ('ezd_release_guard_sql_drop', 'ezd_release_guard_ddl_end') and evtenabled = 'A') + (select pg_catalog.count(*) from pg_catalog.pg_trigger where tgname = 'ezd_release_guard_migration_row' and tgenabled = 'A')) || ' ' || coalesce((select s.last_value from pg_catalog.pg_sequences as s where s.schemaname = 'ezd_release_guard' and s.sequencename = 'seen'), 0) || ' ' || coalesce((select s.last_value from pg_catalog.pg_sequences as s where s.schemaname = 'ezd_release_guard' and s.sequencename = 'applied'), 0);
drop event trigger if exists ezd_release_guard_sql_drop;
drop event trigger if exists ezd_release_guard_ddl_end;
drop schema if exists ezd_release_guard cascade;
select 'ezd_release_guard_removed ' || (select pg_catalog.count(*) from pg_catalog.pg_event_trigger where evtname in ('ezd_release_guard_sql_drop', 'ezd_release_guard_ddl_end')) || ' ' || (select pg_catalog.count(*) from pg_catalog.pg_namespace where nspname = 'ezd_release_guard') || ' ' || (select pg_catalog.count(*) from pg_catalog.pg_trigger where tgname = 'ezd_release_guard_migration_row');
```
The schema drop cascades to the row trigger (planner run 2026-10-28). An absent or never-used sequence reads 0.
`GUARD_SETTING_PROBE_SQL`: `select 'ezd_release_guard_setting ' || coalesce(pg_catalog.current_setting('ezd.release_guard', true), '');` plus `\n`.

### `createReleaseGuard({ sql })`
`SnapshotEntry` = `{ kind, name, id, ownedBy }`, all strings (EZD-153 S9); `parseSnapshot(text)` throws `Error('snapshot_unreadable')` on bad input. `retired` = base-tag entry objects `{ kind, name, ticket, reason }`. `install({ dbUrl, baseTag, retired })`, in order; any `sql` rejection in a step throws `ReleaseGuardError(<that step's code>, err)`:
1. `remove({ dbUrl })` (leftovers of a killed run); its error is rethrown as is (`remove_failed`).
2. `sql(GUARD_SETTING_PROBE_SQL, { dbUrl: withTimeouts(dbUrl, MIGRATION_TIMEOUTS, [RELEASE_GUARD_SETTING]) })`; trimmed stdout other than `ezd_release_guard_setting on` → `setting_not_applied`.
3. `sql(SNAPSHOT_SQL, { dbUrl })`; `parseSnapshot(stdout.trim())` throws or returns `[]` → `snapshot_unreadable`.
4. `objects = guardedObjects(entries, retired)`; `sql(buildGuardInstallSql({ objects, baseTag }), { dbUrl })`; trimmed stdout other than `ezd_release_guard_installed <objects.length> 3` → `install_failed`. Returns `{ protectedCount: objects.length }`.

`remove({ dbUrl })`: `sql(GUARD_REMOVE_SQL, { dbUrl })`; trimmed stdout must match `/^ezd_release_guard_before (\d+) (\d+) (\d+)\nezd_release_guard_removed 0 0 0$/`, else (or a rejection) `remove_failed`; returns `{ wasIntact: <1st> === 3, seen: <2nd>, applied: <3rd> }` (numbers).

### Step E (`release.mjs`, replaces the current E block inside `if (!alreadyLive)`)
Existing helpers of `runRelease`, used as they are: `git` (deps), `worktree()`, `childLines(err)` (prints `err.stderr` through `safeLines`; no `stderr` prints nothing), `stopV(code, built)` (summary `stoppedLine(code)` = `release stopped: <code> — nothing changed`), `partlyUpdated(code, err?)` (logs `code`, `childLines(err)`, summary `PARTLY_UPDATED_LINE(code, dumpPrefix)` = `release stopped: <code> — the live site is unchanged; the database may be partly updated; the dump from before this release is in <prefix>`). Two new summary constants next to `PARTLY_UPDATED_LINE` (texts in section 6): `GUARD_REMOVE_FAILED_LINE` (string) and `GUARD_LOST_LINE(prefix)`. Step C keeps `pendingCount = pending.length` (declared `let pendingCount = 0;` before C). Import `RETIRED_FILE`, `baseRetiredEntries` from `./check-migrations.mjs`; `createReleaseGuard`, `RELEASE_GUARD_SETTING` from `./release-guard.mjs`. The CLI's last line stays `release <code>`.
`guarded = base !== null` (`base` from step 8).
1. When guarded: no `deps.releaseGuard` → log `release_guard_failed: not_wired`, `return stopV('release_guard_failed', built)`. Else `retiredText` = `git(['show', `${base}:${RETIRED_FILE}`])`, `null` when that throws; `install({ dbUrl, baseTag: base, retired: baseRetiredEntries(retiredText) })`. Success → log `release guard on: <protectedCount> objects of <base>`. Throw → log `release_guard_failed: <err.code, else install_failed>`, `childLines(err)`, then `remove({ dbUrl })`: resolves → `return stopV('release_guard_failed', built)`; throws → log `release_guard_remove_failed`, `childLines(removeErr)`, `summary(GUARD_REMOVE_FAILED_LINE)`, return `{ ok: false, code: 'release_guard_remove_failed', prNumber, tag, resume, notices, ...built }` (stopV's object; never `stoppedLine`, since the guard objects remain). Push is not called.
2. `supabase.push({ dbUrl, workdir: worktree(), ...MIGRATION_TIMEOUTS, ...(guarded ? { settings: [RELEASE_GUARD_SETTING] } : {}) })` in `try { … } catch (err) { pushErr = err } finally { if (guarded) remove }`; the finally keeps `removeResult` or `removeErr`. Remove resolved → log `release guard removed`.
3. Outcome, first matching row wins (`r` = `removeResult`, `N` = `pendingCount`):

| # | condition | log, then return |
| --- | --- | --- |
| 1 | remove threw | `guardLost('remove_failed')` |
| 2 | `r.wasIntact` false | `guardLost('guard_lost')` |
| 3 | `r.seen !== r.applied` | `guardLost('guard_inactive')` |
| 4 | push ok and `r.applied !== N` | `guardLost('guard_inactive')` |
| 5 | push failed | `partlyUpdated('migrate_failed', pushErr)` |
| 6 | push ok | go on to F |

`guardLost(reason)` (new helper beside `partlyUpdated`): log `release_guard_lost: <reason>`; `childLines(removeErr)` for `remove_failed`; when `pushErr !== null` log `migrate_failed` and `childLines(pushErr)`; `summary(GUARD_LOST_LINE(dumpPrefix))`; return partlyUpdated's object with `code: 'release_guard_lost'`. Rows 1-4 outrank `migrate_failed`, because a fix-and-merge after a lost guard would snapshot a production that may already miss protected objects.

### Probe file (`supabase/checks/release-guard-probe.sql`, exactly)
```sql
-- EZD-241 (vault/plans/EZD-241.md; docs/runbook.md ## Cloud checks (EZD-171) J5): can postgres add an event
-- trigger that fires for its own changes? Paste all of it into the SQL Editor of ezdraft-dev and press Run.
-- It always ends in an error on purpose, so nothing it creates is kept. The error text must end with:
-- ezd_release_guard_probe user=postgres super=false fired=on
do $probe$
declare
  v_fired text;
  v_super text;
begin
  create schema ezd_release_guard_probe;
  create function ezd_release_guard_probe.mark() returns event_trigger language plpgsql set search_path = '' as $mark$
  begin
    perform pg_catalog.set_config('ezd.release_guard_probe', 'on', true);
  end
  $mark$;
  create event trigger ezd_release_guard_probe on ddl_command_end execute function ezd_release_guard_probe.mark();
  alter event trigger ezd_release_guard_probe enable always;
  create table ezd_release_guard_probe.t (id int);
  v_fired := coalesce(pg_catalog.current_setting('ezd.release_guard_probe', true), 'off');
  select case when r.rolsuper then 'true' else 'false' end into v_super from pg_catalog.pg_roles as r where r.rolname = current_user;
  raise exception 'ezd_release_guard_probe user=% super=% fired=%', current_user, v_super, v_fired;
end
$probe$;
```

| Choice | Decision | Source |
| --- | --- | --- |
| Session scope | Triggers act only when `current_setting('ezd.release_guard', true)` is `on`; only step E's push URL carries `-c ezd.release_guard=on` (startup `options`, after the timeouts). Fixed value: it scopes, it is no secret | Q-0358 (c); EZD-146 L2 |
| Setting reaches the pooled session | Before: `install` step 2 over the same URL (early stop, `setting_not_applied`). Content-independent (a data-only migration still gets its history row).
