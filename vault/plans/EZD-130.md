### Part EZD-130a · Project settings on the server: write function, read and save route, event
- **Scope:**
  - **Migration** (timestamp after develop's newest at merge time, L-060): one `security definer` function `public.update_project_settings`, `set search_path = ''`, `revoke all … from public` then grants by name (L-016), calling `private.require_api_gate()` first and listed in `GATED_RPC_CALLS` with that list test's edit (L-049; ARCH Model working copy "Functions"). It does the following:
    - name, address and scope of work need a granted `edit_model` row and project scope; no lock (Q-0697 10; Q-0202);
    - type and the copied defaults also need the caller to be the lock holder with a matching lock epoch, checked under the `edit_lock` row lock (Q-0697 10; R24 #16 (a); Q-0697 03 "Edit lock data");
    - a client change needs `settings_company` or `create_projects`, with the same customer check as `create_project` (Q-0697 10; Q-0400);
    - it writes only the per-project keys the registry flags (waste factors, the four overhangs, cabinet auto-fill increment, countertop increment; never pattern adjustment, never the load-calc default until EZD-613) under `project.settings.defaults`, apart from `plan_scale` (Q-0697 03 "Defaults data");
    - it stores nothing for code edition or submittal profile (Q-0399; Q-0697 03);
    - it leaves `tenant.defaults` and every other project untouched (S15d Decision 4; 09o Copy at creation rows 1-2).
  - **Read** (`GET /api/projects/[id]/settings`, any member who can see the project):
    - the project fields;
    - the effective value of each per-project key: the project's copy, else the company's effective value (Q-0697 03; 09o Copy at creation row 3, Effective value);
    - the client's name; email and phone only for holders of `settings_company`, `create_projects` or `send_to_client` (Q-0697 10);
    - which fields this user may change, so part b can show the rest as text.
  - **Save** (`PATCH /api/projects/[id]/settings`):
    - checks the same rules as the New project dialog: name and address required, type one of three, client from the customer list (`create_project`; Q-0203);
    - checks lengths and percents through EZD-116a's value checks (AC-EZD-116-4; 09o Value checks rows 1-5; Q-0561);
    - sends the caller's lock epoch when type or defaults change;
    - when the save carries the lock, also stores a copy of every per-project key the project lacks (09o Copy at creation row 3);
    - answers 400, 401, 403, 409 (stale lock epoch) and 500 in the existing route order (`app/src/app/api/projects/route.ts`);
    - emits `project.updated` with the changed keys (Q-0697 03; new `EVENTS` entry).
  - **Harness and docs:** the new route in `MONEY_ROUTE_CASES` (EZD-133 rule: one case per exported method of every route); error message keys in `en.ts` and `es.ts`; a "Project settings (EZD-130)" section in `docs/architecture.md`.
- **Done when:**
  - **Copies stay per project:**
    - a project's copied tile waste stays 10% after the company value changes to 12% (09o Copy at creation row 1);
    - a save of 15% on project P changes only P, and the company value and another project are unchanged (row 2);
    - a project with no copy reads the company's 12% and stores a copy on a save that carries the lock (row 3).
  - **Who may change what:**
    - name, address and scope of work save with Edit model and no lock;
    - type and defaults are refused without the lock or with a stale epoch, by the route and by the function called directly;
    - a member without Edit model, out of project scope or in another tenant is refused;
    - a client change is refused without Company settings or Create projects and saved with Create projects;
    - the read returns client email and phone only to holders of Company settings, Create projects or Send to client.
  - **Values and event:**
    - nothing is stored for code edition or submittal profile;
    - percent −1 and 100.5 and length "12 6" are refused, and 12.5' is saved as 150";
    - a seating limit equal to the standard overhang is refused;
    - a successful save emits `project.updated` with the changed keys.
- **ACs:** AC-EZD-130-1; AC-EZD-130-2; AC-EZD-130-3 (server and database clauses); AC-EZD-130-4 (route check and contact visibility in the read); AC-EZD-130-5 ("nothing is stored"); AC-EZD-130-6 (validation and `project.updated` clauses).
- **Depends on:** EZD-116a, EZD-116b, EZD-125a, EZD-118 (row: EZD-116, EZD-125 and EZD-118, as parts). Missing from the row, all done (`vault/tickets/STATUS.md` 2026-11-11):

### Part EZD-130b · Project settings dialog in the editor
- **Scope:**
  - **Dialog** (Q-0699 (a), no board): the look of the New project dialog, step 1 column of board S01b.
    - Project fields on top: client, name, type, address, then scope of work as several optional lines below Type (Q-0396).
    - Below them a "Defaults for this project" section with the per-project keys from part a's read.
    - Save and Cancel.
    - No Code edition and no Submittal profile field (Q-0399; AC-5).
  - **Field states** from part a's read (AC-3):
    - without Edit model, every field is read-only text and Save is hidden;
    - with Edit model and no lock, name, address and scope of work can be edited, and type and the defaults are read-only text;
    - the lock holder can edit every field.
  - **Client field:**
    - the client picker (`CustomerPicker`, EZD-118) shows only to holders of Company settings or Create projects;
    - everyone else sees the client name as text;
    - email and phone show only when the read returns them (Q-0697 10; AC-4).
  - **Save:**
    - field errors as in the New project dialog;
    - a failed save keeps the dialog open with a Try again message (AC-6);
    - on success the header project name changes at once, without a reload (AC-6).
  - **Wiring:**
    - a Project settings item in `ProjectSwitcherPanel` after Back to projects (P128 section 3 "For dependents"; glossary 00i "Project switcher");
    - `ProjectEditor` opens the dialog and passes in the session's lock epoch and holder state (EZD-125b);
    - proposed labels in `en.ts` and `es.ts` (section 6 at the design step);
    - one browser spec.
- **Done when:**
  - **Field states:**
    - a member without Edit model sees every field as text with no Save;
    - a member with Edit model who does not hold the lock can change the name, but type and the defaults are text;
    - the holder can change type and a waste factor.
  - **Absent fields:** neither Code edition nor Submittal profile is in the dialog.
  - **Client:** the picker shows only with Company settings or Create projects, and email and phone only when the read gives them.
  - **Save:**
    - a failed save keeps the dialog open with the Try again message;
    - a successful rename shows the new name in the header without a reload (browser test).
- **ACs:** AC-EZD-130-3 (read-only text and hidden Save); AC-EZD-130-4 (picker and contact display); AC-EZD-130-5 ("absent" clause); AC-EZD-130-6 (header at once, Try again, look per Q-0699).
- **Depends on:** EZD-130a, EZD-128, EZD-125b (row: EZD-128 and EZD-125 as a part). Missing from the row:
  - EZD-016a (browser harness; the part has a visual checklist; done);
  - EZD-118 (`NewProjectDialog`, `CustomerPicker`; done);
  - EZD-120c (editor route and `ProjectEditor`; done).
