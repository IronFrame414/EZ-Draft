# EZD-142 · Fix: error scrubbing covers every event field and runs in linear time

- **ACs:** AC-EZD-142-1, AC-EZD-142-2
- **Complexity:** medium (reasoning in section 8)
- **User-visible result:** none on screen. An error report can no longer hold a server function for seconds, and no part of an error report (threads, log entry, exception type and mechanism, fingerprint or any other field) carries an email address or id to Sentry.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data: none (no table, migration or money field).

Two pure-function changes in `app/src/lib/errors/scrub.ts` (shared by browser `beforeSend`, server `beforeSend` and the tunnel `POST /api/monitoring`): (A) `scrubText` keeps its exact output but its URL and email passes become linear-time scanners; (B) `scrubEvent` becomes an allowlist over every field of `@sentry/core` 11.8.0's `Event` (`node_modules/@sentry/core/build/types/types/event.d.ts`), so the five fields of the sweep (S1 items 1-2) and every other field are scrubbed or dropped. Plus one line in `fingerprint.ts` (`errorTitle` scrubs the type) and the docs.
