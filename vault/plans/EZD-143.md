# EZD-143 · Fix: error tunnel limits each caller

- **ACs:** AC-EZD-143-1, AC-EZD-143-2
- **Complexity:** medium (reasoning in section 8)
- **User-visible result:** nothing on screen. One computer or phone can no longer flood the error tunnel and use up the hourly limits; the app's own server errors keep their own room.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: questions

## 1. What to build

Data:
- New tenant-less table `public.error_tunnel_throttle`: `id uuid primary key default gen_random_uuid()`, `key_hash text not null check (key_hash ~ '^[0-9a-f]{64}$')`, `at timestamptz not null default now()`. Indexes `error_tunnel_throttle_key_at_idx (key_hash, at)` and `error_tunnel_throttle_at_idx (at)`. RLS on, one policy `error_tunnel_throttle_none` `for all to authenticated using (false) with check (false)`. `revoke all on public.error_tunnel_throttle from public, anon, authenticated;` `grant select, insert, update, delete on public.error_tunnel_throttle to service_role;`.
- New function `public.error_tunnel_take(p_ip_key text, p_events integer) returns boolean` (D4).
- `public.record_error_alert` replaced with `create or replace` (same signature, return type and grants): the non-runner row cap counts per source group (D6).
- No money field, no `schema_version` change.
