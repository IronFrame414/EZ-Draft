# EZD-189 · Fix: the policy check allows a Storage policy to read its screen's switch

- **ACs:** AC-EZD-189-1
- **Complexity:** medium (section 8)
- **User-visible result:** none on screen; the check that keeps table policies from reading permission switches now lets the file-storage rules (supplier PDFs, logo) check the switch their screen checks, so EZD-132 (file storage) can merge.
- Phase: 1 · Planned by: planner · Date: 2026-10-25 · Status: planned

## 1. What to build

Narrow EZD-102's D4 scan to policies outside the `storage` schema and the `private` helpers those policies call (Q-0323 (1); AC-EZD-102-6 as amended), keep EZD-102's control, and add controls that prove both halves of AC-EZD-189-1.

Also fixed here (CLAUDE.md rule 17; Q-0268): on the pinned stack `pg_policies.qual` prints a table on the search path without its schema, so `exists (select 1 from public.role)` reads back as `FROM role` and D4's `public\.role\b` pattern misses it (run by the planner on the local stack, PostgreSQL 17.11, 2026-10-25: default `search_path` `"$user", public, extensions` gives `FROM role`; after `set local search_path to ''` it gives `FROM public.role`). The scan therefore runs inside a transaction with an empty search path. Helper source (`prosrc`) is stored text and is unaffected; `private` helpers set `search_path = ''` and name tables with their schema (docs/architecture.md `### Row-level security (EZD-006)`, "Schema `private`").

Also run by the planner on the same stack (L-009): as the harness role `postgres`, inside a rolled-back transaction, `create policy … on storage.objects …`, `create function private.<name>() …` and a `public` probe table with RLS and two policies all succeed; with an empty search path every current non-`storage` policy text matches the D4 pattern 0 times.

Data: none (no migration; every probe object is created inside `withRollback` and never committed, so L-016's revoke rule does not apply).
