# EZD-166 · Fix: db:up restarts the local stack when the Auth config or templates change

- **ACs:** AC-EZD-166-1, AC-EZD-166-2
- **Complexity:** low (one small Node module, a three-line change to `up()`, node:test with an injected fake CLI; reasoning in section 8)
- **User-visible result:** after someone changes the sign-in email templates or the local Supabase settings, the next gate run picks them up by itself; nobody has to run `pnpm db:stop` by hand any more.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data: none (no migration, no table).

Problem (vault/tickets/sweep-2026-10-24.md item 49): `up()` in `scripts/db/local.mjs` starts the stack only when `supabase status` fails, then always runs `db reset --local`; Auth reads `supabase/config.toml` and the templates only at `supabase start` (docs/architecture.md `### Auth and session (EZD-007)`), so a changed template or config stayed unapplied and the gate went red.

Fix: a hash of `supabase/config.toml` plus `supabase/templates/*` is stored in a marker file after every successful start; `up()` compares it with the current files and runs `stop` then `start` when they differ (ticket row Scope).
