Step 1 detail (D-rows below give the source of each):
1. `settleReady(e, v)`: if `e.outcome === v` return; if `e.outcome === null` call `e.resolve(v)`, else set `e.ready = Promise.resolve(v)`; then `e.outcome = v`. Every current `e.settle(x)` call (in `refuse`, `tokenFailed`, `onJoinStatus`, `endSession`, `refuseInvalid`) becomes `settleReady(e, x)`.
2. `runResync(h)`: `h.synced = true`, then `for (const cb of [...h.resync]) void cb();`.
3. `onJoinStatus`, `SUBSCRIBED` branch: delete `const resync = e.everSubscribed;`; keep `e.everSubscribed = true`, `e.errors = 0`, `setStatus(e, 'subscribed')`, then `settleReady(e, 'subscribed')`, keep the `track` line, then `for (const h of [...e.handles]) runResync(h);` (no condition).
4. `tokenFailed`: the loop skips an entry when `e.refused || e.status === 'subscribed'`; for the others `setStatus(e, 'refused')` and `settleReady(e, 'refused')`.
5. `acquire`: after `let released = false;`, add `void Promise.resolve().then(() => { if (released || ended || cbs.synced || entry.status !== 'subscribed') return; runResync(cbs); });`.
6. File header comment, lines 3-4: "every onResync callback runs exactly once after each re-subscription" becomes "every handle's onResync callbacks run exactly once after each SUBSCRIBED, the first included, and once when a handle joins a channel already subscribed (EZD-318)".

Step 2 text, replacing the whole `**Resync.**` bullet:
"- **Resync.** Every `SUBSCRIBED` of a channel, the first one included, calls every `onResync` callback of every handle on it exactly once, so each subscriber refetches once per join: a change made between the server render and the first join, or while the channel was down or its token refused, is picked up (EZD-318; Q-0545, Q-0546). A handle taken on a channel that is already subscribed has its callbacks called once on the next microtask; a callback added to a handle after that handle's resync waits for the next `SUBSCRIBED`. After a drop (channel error, timeout, unexpected close, socket close) the status is `reconnecting`; on the next socket open, or when `useOnline`'s source reports online, the hub fetches a token once and rejoins. A refused token fetch sets `refused` on every channel not subscribed (a subscribed one is left as it is) and the next socket open or online report retries. `ready` always holds a channel's latest outcome: pending until the first, then a promise resolved `'subscribed'` or `'refused'`, replaced when the outcome changes."

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| D1 Which SUBSCRIBED resyncs | Every one, the first included; "the first subscription calls none" is removed. Exactly once per SUBSCRIBED per callback. | Q-0545, Q-0546 answers; phase-02.md EZD-318 Scope; AC-EZD-318-1, -3 |
| D2 Resync after a refused token | Covered by D1: the reconnect's first SUBSCRIBED calls every callback once; `everSubscribed` no longer gates resync (it still gates the `reconnecting` status in `onJoinError` and `onSocketClose`, unchanged). | Q-0546 (hub.ts:154-161, 207-216); AC-EZD-318-2 |
| D3 How `ready` settles again | `settleReady` (step 1.1); the handle reads `entry.ready` through a getter, so a read after the change sees the new promise. A caller that awaited the old promise keeps the old answer. | Q-0546 "ready cannot settle again"; AC-EZD-318-2 |
| D4 `ready` after `session.ended` | `settleReady(e, 'refused')` on every entry: a subscribed handle's `ready` becomes resolved `'refused'`, matching its `closed` status. | D3 (one rule, no exception); EZD-018 Step 5 item 8 (pending ready resolves `'refused'`) |
| D5 Handle taken on a channel already subscribed | One resync of that handle's callbacks on the next microtask (step 1.5); none if released first, the session ended, or the channel is not `subscribed` then (it gets D1's resync at the next SUBSCRIBED instead). Other handles get none. | ticket title "a subscriber's first join"; Q-0545 "same class"; CLAUDE.md rule 18 |
| D6 Token refresh fails while some channels are subscribed | `tokenFailed` leaves `subscribed` entries alone (step 1.4); today it marks a healthy channel `refused` while it still receives. | Q-0546 (same function, refused-token path); CLAUDE.md rule 18 |
| D7 Refused join | Unchanged: a join refused twice is `refused` (`e.refused`), removed, never retried. | EZD-018 Step 5 item 4; ARCH Realtime "Requests only on events" |
| D8 Requests | No new token fetch, timer or channel: resync only calls callbacks. | ARCH Realtime "Requests only on events"; 11 rule 11 |
| D9 Callback errors | Unchanged: `void cb()`; the hub does not catch. | hub.ts:216 |
