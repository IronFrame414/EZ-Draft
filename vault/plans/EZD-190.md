# EZD-190 · Fix: the API request gate is in force as soon as the local stack is up

- **ACs:** AC-EZD-190-1, AC-EZD-190-2
- **Complexity:** high (section 8)
- **User-visible result:** the gate's `@smoke` test "a request without the server gate header is refused" stops failing at random after `pnpm db:up`, and a signed-in person can no longer read company data straight from the database API in the seconds after a database restart, locally or in the cloud.
- Phase: 1 · Planned by: planner · Date: 2026-10-25 (plan-gaps 2026-10-26: B8 and `PRIVATE_EXECUTE`; 11 tables and 9 RPCs, E8) · Status: planned

## 1. What to build

**Cause (E1–E3, section 2).** When Postgres restarts and PostgREST keeps running, PostgREST's reconnect reloads its config. If the in-database settings query fails on a dead pooled connection, it still logs `Config reloaded` and serves without `pgrst.db_pre_request`, so `private.api_request_gate()` (EZD-006) does not run until a later reload. `supabase db reset --local` restarts the db container but not PostgREST. In the EZD-151 gate the window ran 10:23:59–10:24:15 UTC; the `desktop` test fell inside it (E1).
**Cloud (AC-EZD-190-2): yes, it can open.** The failing path is PostgREST's own reload, and a cloud project registers the gate the same way (our migration). Any event that drops PostgREST's connections while it keeps serving goes through it: a restart (reproduced, E2), maintenance or a failover. The hosted PostgREST version and restart behavior are unconfirmed (R-028). So the fix also closes the window inside the database.
**Fix.** (A) `pnpm db:up` restarts the PostgREST container after the reset (fresh pool, E3) and returns only when a header-less request is refused by the gate. (B) A database backstop, `private.require_api_gate()`, repeats the gate's header check for any statement that came through PostgREST. It is applied as a restrictive policy `<table>_api_gate` on every public table `authenticated` can reach, and as the first statement of every `security definer` RPC `anon` or `authenticated` can execute (except `health`). A request that skipped the pre-request gets no row and changes nothing: a row passing the table's own policy raises `42501` `api_gate`; no matching row gives an empty result (E4).
Data: three migrations (Steps 1–3); no table, column, `schema_version` or money change; `database.types.ts` unchanged (no public signature change).
