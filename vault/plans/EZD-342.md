### Do not touch
- `createSessionClient`'s signature and synchronous return; `SessionCookieJar`; `SESSION_COOKIE_OPTIONS` values; `API_GATE_HEADER`.
- The signed-out marker rules (`signOutOnDevice`, the marker name per scheme, `PUBLIC_PATHS`, the 307 and `no-store`), EZD-120d.
- Action return codes and order (throttle, Auth calls), EZD-007d, EZD-033, EZD-034.
- `app/e2e/**` (they run on http, names unchanged), `supabase/**`, every other `createSessionClient` caller.

Ticket row (vault/tickets/phases/phase-01.md):
- **Scope:** Rule 17 defect (Q-0600, security-reviewer 2026-11-05, Q-0599): the session cookies (`sb-<ref>-auth-token[.N]`, set through `@supabase/ssr`) and the sign-in cookies `ezd_sign_in_email` and `ezd_sign_in_lang` are host-only only by what the app sets, not by name, so a page on a sibling of ezcontractorbinder.com can plant one with `Domain=ezcontractorbinder.com`, and `proxy.ts`, `createSessionClient` (`app/src/server/auth/supabase-server.ts`) and the sign-in pages read the first cookie of that name (session fixation; sign-in email and language tampering). On https every app-set cookie is named with the `__Host-` prefix (the session cookies through `@supabase/ssr` `cookieOptions.name`), chosen by the same `x-forwarded-proto` test as `secure`, as the signed-out marker already is (`signedOutCookieName`, `app/src/lib/auth/device-sign-out.ts`); on http the names stay as they are. One shared name function so the writers and the readers cannot drift. A plain-named `sb-` cookie arriving on https is treated as signed out (one-time migration; everyone signs in once at deploy). The name is chosen before the client is built (`createSessionClient` is synchronous, the jar's `isHttps` is not). `docs/architecture.md` Auth and session is updated in the same commit.
- **Done when:** On https every cookie the app sets starts with `__Host-` and has no `Domain` (a test of each writer); a request carrying a plain `sb-`, `ezd_sign_in_email` or `ezd_sign_in_lang` cookie on https is not honoured (signed out, default email and language); on http the local and test names are unchanged and sign-in, sign-out and the token refresh still work (existing auth tests pass); one function names the cookies for every reader and writer.
- **Depends on:** EZD-007c, EZD-007d, EZD-120d
- **Spec ref:** Q-0600; Q-0599; spec 11 Security and audit; rule 17
