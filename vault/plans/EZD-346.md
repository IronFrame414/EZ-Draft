Ticket row (`vault/tickets/phases/phase-01.md` line 197). Scope: Rule 17 defect (phase 3 gate security review, Q-0599): the session cookie is SameSite=Lax and host-only only by name, yet a plain form POST from a sibling subdomain of ezcontractorbinder.com still carries it, and `app/src/app/api/projects/[id]/checkpoints/route.ts` (EZD-120a) checks only the session, so such a page can make a checkpoint in the signed-in person's name; `app/src/app/api/notifications/read-all/route.ts` has the same gap. Nothing in `app/src` checks Origin or Sec-Fetch-Site. Close the whole class: `app/src/proxy.ts` refuses every `/api` request whose method is not GET or HEAD unless Sec-Fetch-Site is same-origin or, when that header is absent, Origin equals the app's own origin; routes that take no browser session (webhooks, signed share links, other machine-to-machine entries) stay out only by an explicit named list with a reason. Done when: A cross-site and a sibling-subdomain POST to the checkpoints route, the notifications read-all route and the save routes get a refusal and write nothing; the same POSTs from the app's own origin succeed; a test walks every non-GET `route.ts` under `app/src/app/api` and fails when one is neither covered by the check nor on the named exceptions list; GET and HEAD are unchanged. Depends on: EZD-120a, EZD-342. Spec ref: Q-0599; spec 11 Security and audit; rules 17, 18.
