# EZD-354 · Build system: the gate's checks run as the separate ezdraft macOS user, so code they run cannot reach Josh's keychain or files

- **ACs:** AC-EZD-354-1 … AC-EZD-354-6 (proposed below under the ticket row; the orchestrator files them with `gen_acs.mjs`)
- **Complexity:** high (section 8)
- **Areas:** tooling, scripts, security
- **User-visible result:** on Josh's Mac every check the gate runs (install, typecheck, lint, tests, build, browser tests, perf) runs as the `ezdraft` user from a copy outside Josh's home, so agent-written code can no longer read Josh's files, keychain, ssh agent or Claude sessions; CI is unchanged.
- Phase: 1 · Planned by: planner · Date: 2026-11-06 · Status: questions

## Josh's steps
Only Josh can do these (account, sudo and Docker Desktop settings). Do them in this order; the build starts after step 2, step 3 comes after the orchestrator's row O1.

1. **Close your home folder to ezdraft.** Today ezdraft can list and read most of `/Users/josh`: both users are in group `staff` and the folder is `drwxr-x---` josh:staff (probe 2026-11-06: as josh, `ls /Users/ezdraft` listed ezdraft's home the same way; `~/.claude` is `drwxr-xr-x`). In Terminal, no sudo (you own the folder):
   `chmod +a "user:ezdraft deny list,search,add_file,add_subdirectory,delete_child,readattr,readextattr,readsecurity" /Users/josh`
   Check: `ls -led /Users/josh` shows a line `user:ezdraft deny list,add_file,search,…`.
2. **Let the gate switch to ezdraft without a password, for one command only.** In Terminal: `sudo visudo -f /etc/sudoers.d/ezdraft-gate`, type exactly this one line, save and quit:
   `josh ALL=(root) NOPASSWD: /bin/launchctl asuser 502 /usr/bin/sudo -n -u ezdraft -- /usr/bin/env *`
   Check: `sudo -n /bin/launchctl asuser 502 /usr/bin/sudo -n -u ezdraft -- /usr/bin/env -i /usr/bin/id -un` prints `ezdraft`.
3. **Limit what Docker containers can see** (after the orchestrator says row O1 is done). Docker Desktop → Settings (gear) → Resources → File sharing: remove `/Users`, `/Volumes`, `/private`, `/tmp` and `/var/folders`; add `/Users/josh/Projects/ezdraft/.claude/worktrees` and `/Users/ezdraft/gate`; click Apply & restart. Why: each listed folder is the only host folder the Docker VM mounts (probe 2026-11-06: a privileged container saw exactly `/host_mnt/Users`, `/Volumes`, `/private`, `/tmp`, `/var/folders`, one virtiofs mount each), so today any container reads your whole home as you.
