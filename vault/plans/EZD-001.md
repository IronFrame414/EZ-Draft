### Step 6: Test scope for Q-0006 (phase tests plus a smoke set per ticket; full suite at the phase gate)

**6.1 How a test declares its phase and smoke membership** (*planner's choice*; the tickets README ID format sets the phase number):
- **Ticket ID in the describe title.** Every Vitest or Playwright test file wraps its tests in at least one top-level `describe` (Playwright: `test.describe`). Its title starts with the ticket ID that owns those tests, for example `describe('EZD-001 geometry package', …)`.
  - A later ticket that adds tests to an existing file adds its own top-level `describe` with its own ID.
  - Tests therefore inherit the ID in their full name, which Vitest's `testNamePattern` and Playwright's `grep` both match against.
  - This extends EZD-000's Tests convention ("The test that closes a ticket has the ticket id in its title").
- **Phase from the ID.** The ticket ID gives the phase: `EZD-<phase><nn>` (tickets README "How tickets are written"), so phase = floor(number / 100). EZD-001 and EZD-026a are phase 0, EZD-133 is phase 1, EZD-1710 is phase 17.
- **Smoke set.** A test is in the smoke set when its full name contains `@smoke`: Vitest puts it in the test title; Playwright puts it in the title or uses `{ tag: '@smoke' }`. The smoke set is:
  - each phase's Build gate browser test, which the phase-gate step runs, tagged when it is written;
  - any test a ticket plan marks "smoke: yes" in its Tests table, because it guards something every later phase relies on.
  - EZD-001 marks T1 smoke.
- **Root repo-script tests.** `scripts/**/*.test.mjs` run by `node:test` (EZD-000's root `test` glob) are not filtered. They always run in full, because they are the gate's own tooling checks and run in seconds.
- **Machine check C9** (builder adds it to EZD-000's `scripts/conventions/check.mjs`, same output format `[C9] <path>: <problem>`):
  - Every `*.test.ts`, `*.test.tsx` and `*.spec.ts` file under `app/`, `packages/` and `worker/` must contain a call matching `` /\bdescribe(?:\.\w+)*\(\s*['"`]EZD-\d{3,4}[a-z]?\b/ `` (this also matches `test.describe(`).
  - Files under `test-utils/`, `test-harness/` and `fixtures/` are exempt, as are config files.
  - Without C9, a test with no ID would silently never run in a ticket's check.

**6.2 How the scope reaches the runners:**
- The gate sets three environment variables for every step it runs: `EZD_TEST_SCOPE` (`phase` or `full`), `EZD_PHASE` (the number, phase scope only) and `EZD_TEST_GREP` (phase scope only).
  - Phase scope: `EZD_TEST_GREP` = `(?:EZD-<N>\d{2}[a-z]?(?![0-9]))|@smoke`. For phase 0 that is `(?:EZD-0\d{2}[a-z]?(?![0-9]))|@smoke`; for phase 1, `(?:EZD-1\d{2}[a-z]?(?![0-9]))|@smoke`, which matches EZD-133 but not EZD-1001.
  - Full scope: `EZD_TEST_GREP` is removed from the environment.
- Each `vitest.config.ts` (app and geometry; **test-author**) sets `test.testNamePattern = process.env.EZD_TEST_GREP ? new RegExp(process.env.EZD_TEST_GREP) : undefined` and `test.maxWorkers = 2` (Q-0019). Tests outside the pattern are reported as skipped. Exact option names follow the pinned Vitest major.
- **For EZD-016a (recorded in docs so its planner uses it):** `playwright.config.ts` sets `workers: 2` (Q-0019) and `grep: process.env.EZD_TEST_GREP ? new RegExp(process.env.EZD_TEST_GREP) : undefined`.
- The `perf` check (EZD-017) is not filtered. Tickets README rule 2 makes the performance check part of every ticket.
- `typecheck`, `lint` and `build` are always whole-repo. They are the cheap checks, and a type or build break anywhere fails every ticket.

#!/usr/bin/env node
// The build gate. Usage: node scripts/gate.mjs [dir] [--phase N | --full] [--print-scope]
//   dir = repo root or a ticket worktree; default ".".
// Test scope (Q-0006): a ticket worktree (folder named EZD-xxx) runs the phase's tests plus the @smoke set;
// any other folder, or --full, runs the full suite (phase gate, CI). --phase N forces phase scope.
// Runners read EZD_TEST_SCOPE, EZD_PHASE and EZD_TEST_GREP (see docs/architecture.md, Test scope).
// Only one gate runs at a time on this machine (Q-0019).
// Exits 0 only if every check that exists passes. Same script runs locally, in review, and in CI.
import { existsSync, readFileSync, readdirSync, statSync, openSync, writeSync, closeSync, unlinkSync } from 'node:fs';
import { spawnSync } from 'node:child_process';
import os from 'node:os';
import path from 'node:path';

const args = process.argv.slice(2);
const phaseIdx = args.indexOf('--phase');
const positional = args.filter((a, i) => !a.startsWith('--') && !(phaseIdx >= 0 && i === phaseIdx + 1));
const dir = path.resolve(positional[0] || '.');
const pkgPath = path.join(dir, 'package.json');
const shell = process.platform === 'win32';

function scopeFor() {
  if (args.includes('--full')) return { mode: 'full' };
  let phase;
  if (phaseIdx >= 0) {
    const v = args[phaseIdx + 1];
    if (!/^\d{1,2}$/.test(v || '')) { console.error(`GATE FAIL: --phase needs a phase number, got "${v || ''}".`); process.exit(1); }
    phase = Number(v);
  } else {
    const m = /^EZD-(\d{3,4})[a-z]?$/.exec(path.basename(dir));
    if (!m) return { mode: 'full' };
    phase = Math.floor(Number(m[1]) / 100);
  }
  return { mode: 'phase', phase, grep: `(?:EZD-${phase}\\d{2}[a-z]?(?![0-9]))|@smoke` };
}
const scope = scopeFor();
const scopeText = scope.mode === 'full' ? 'full suite' : `phase ${scope.phase} tests + @smoke`;

if (args.includes('--print-scope')) {
  console.log(JSON.stringify({ dir, ...scope }));
  process.exit(0);
}

const env = { ...process.env, CI: '1', EZD_TEST_SCOPE: scope.mode };
delete env.EZD_TEST_GREP; delete env.EZD_PHASE;
if (scope.mode === 'phase') { env.EZD_PHASE = String(scope.phase); env.EZD_TEST_GREP = scope.grep; }

// One gate at a time (Q-0019). A lock left by a dead process is taken over.
const lockPath = path.join(os.tmpdir(), 'ezdraft-gate.lock');
function takeLock() {
  for (let attempt = 0; attempt < 2; attempt++) {
    try {
      const fd = openSync(lockPath, 'wx'); writeSync(fd, String(process.pid)); closeSync(fd); return;
    } catch (e) {
      if (e.code !== 'EEXIST') throw e;
      let pid = 0;
      try { pid = Number(readFileSync(lockPath, 'utf8')) || 0; } catch {}
      let alive = false;
      if (pid) { try { process.kill(pid, 0); alive = true; } catch (err) { alive = err.code === 'EPERM'; } }
      if (alive) { console.error(`GATE FAIL: another gate is running (pid ${pid}). Run one gate at a time (Q-0019).`); process.exit(1); }
      try { unlinkSync(lockPath); } catch {}
    }
  }

function hasTests(d, depth = 0) {

  }
  return false;

  console.log(`\n=== ${label}: ${pm} ${cmdArgs.join(' ')} ===`);
  const r = spawnSync(pm, cmdArgs, { cwd: dir, stdio: 'inherit', shell, env });
  return r.status === 0;
};

  if (!run(pm === 'pnpm' ? ['install', '--frozen-lockfile'] : ['ci'], 'install')) { console.error('GATE FAIL: install'); process.exit(1); }
}

// Order matters: cheap checks first. "test:e2e" and "perf" join once EZD-016 / EZD-017 add them.
const checks = ['typecheck', 'lint', 'test', 'build', 'test:e2e', 'perf'];
const required = ['typecheck', 'lint', 'test', 'build'];
const results = [];
for (const name of checks) {
  if (!scripts[name]) { results.push([name, required.includes(name) ? 'MISSING' : 'not yet']); continue; }
  results.push([name, run(['run', name], name) ? 'pass' : 'FAIL']);
}

console.log('\n=== GATE SUMMARY ===');
console.log(`scope      ${scopeText}`);

## Risks
- **Tests with no ID never run per ticket.** With phase scope, a test whose describe title lacks a ticket ID, or carries the wrong one, runs only at the phase gate. C9 catches a missing ID, not a wrong one, and the code-reviewer checks the ID. Earlier phases' non-smoke tests are not re-run per ticket (Q-0006's accepted trade-off), so a regression there first shows at the phase gate or in the after-merge run on develop if Josh's step B is not applied.
- **Josh's step A and T13.** If step A is not applied, T13 blocks EZD-001 (Step 6.6). If Josh applies a different text, T13's expected values must be re-checked against it.
- **Stale gate lock.** A gate killed hard (power loss) leaves a lock whose PID may be reused by another process. The gate then refuses until `ezdraft-gate.lock` in the temp folder is deleted, and its message names the PID.
- **Next.js version specifics.** `next typegen`, flat `eslint-config-next`, `turbopack.root`, and `next build` no longer running lint all depend on the Next.js major EZD-000 pins. The builder adapts to the pinned version, and T3 proves the result on a clean tree.
- **Worktree nesting.** Worktrees sit inside the main checkout. Next.js root inference, `@types` lookup and ESLint config lookup all walk upward, so each is pinned explicitly (Steps 2–3). If any tool still escapes, it shows up as a gate failure only inside worktrees, not on `develop`.
- **Vitest option names.** `testNamePattern`, `maxWorkers`, `vitest list --filesOnly --json` and the JSON reporter fields used in T14 (per-test `fullName` and `status`, `numFailedTests`) must exist in the Vitest major EZD-000 pins. The test-author checks them against the installed version.
- **Formatting is not gated.** Formatting is a convention here, not a gate check. Drift is possible until a later ticket moves `format:check` into `lint`; that should be after every test file has been formatted once. The code-reviewer may prefer to enforce it now. If so, the orchestrator must have the test-author run `pnpm format` on the test files after the builder installs Prettier, so the builder is not blocked.
- **`--passWithNoTests` on the app.** It hides a mis-set include until the first app unit test exists.
- **`workspace-concurrency=1`.** It makes typecheck, lint and build run one package at a time. That is slower but safe on 16 GB (Q-0019).
- **Download size.** An empty Next.js + React page already spends part of the 200 KB Projects budget (11 Budgets). EZD-017 measures this, not this ticket.
- **Version conflicts.** If EZD-000's pinned versions conflict, EZD-001 is where it surfaces, because it is the first real `pnpm install`. Row bumps are allowed but must be visible in the commit.
