**Why.** Planned whole at develop e9a865f5, the ticket touches about 37 files (22 source and doc files, 15 test files) and needs about 31 tests. **Why cut here.**

- Each AC lands in one part: AC-1 and AC-2 are counted recomputes (part a), AC-3 is the long-task count while a worker job runs (part b, 09-calc Q-0664 "Worker check").
- The dependents that need the derived cache now (EZD-216 auto dimensions, 09-calc Q-0664 "recomputed through EZD-235"; EZD-218b room areas, review-phase-06 finding 6; EZD-6001's `planDrawingList`/`openFloorId` signatures, review-phase-06 finding 1) need only part a. The build risk (the first Turbopack module worker; R-059 via EZD-224) sits entirely in part b.
- Part b is not cut further: its pool has no AC of its own. The only proof that the pool runs a real worker off the main thread is the perf row (AC-3), so splitting the pool from the probe and collector would leave a part with no AC and an unproven worker build (Josh 2026-10-22: fewer, fuller tickets). At 22 files it sits at "about 20".

### Part EZD-235a · Derived values
- **Scope:**
  - A pure derived-value cache in the geometry package (no DOM, so workers and the server can run it; 11 "Where each output is produced"). A value is computed only inside a `get` (pull). It is cached by the identities of the objects it read through a source that offers `object(id)` and `objectsOf(type, level)`. It is valid while each object it read is the same reference and each list it read has the same members in the same order (11 rule 2; ticket Scope; glossary 00g "Derived value"). An edit never computes anything. A value nobody asks for is never computed (AC-2). `prune` drops entries whose objects are gone (11 Also, iPad memory). The cache counts computes and hits per definition, so tests count recomputes (AC-1).
  - `ROOM_AREA`, the first definition: a room's `roomAreaSqFt(boundary)` (`packages/geometry/src/rooms/area.ts:29`; ARCH Rooms "Area is derived from the outline in whole square feet, never stored", `docs/architecture.md:868`; Q-0207; Q-0568).
  - `formatRoomLabel(name, areaSqFt)` in `rooms/area.ts`. `roomLabelText` (`area.ts:121-124`) keeps its output and calls it.
  - `buildDrawingList` gains a fourth parameter `options: DrawingListOptions = {}` with `roomAreaSqFt?: (room: RoomObject) => number`, and the room label uses it when given (`packages/geometry/src/drawing/build.ts:107-111,295`).
