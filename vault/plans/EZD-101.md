# EZD-101 · Permission and role tables

- **ACs:** AC-EZD-101-1, AC-EZD-101-2, AC-EZD-101-3, AC-EZD-101-4, AC-EZD-101-5, AC-EZD-101-6
- **Complexity:** medium (section 8)
- **User-visible result:** nothing on screen yet; every company has the four fixed roles and every person their 37 permission switches, ready for EZD-102 and EZD-106.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data (sources: 03c `user_permission`, 03d `role`; 10; S15 Permission list; AC-EZD-101-1..6; Q-0034, Q-0210, Q-0223, Q-0224, Q-0225, Q-0234, Q-0235):
- `public.role` (tenant-owned): `id uuid pk default gen_random_uuid()`, `tenant_id uuid not null references public.tenant (id) on delete cascade`, `name text not null check (length(btrim(name)) > 0)`, `preset text check (preset in ('owner','designer','foreman','crew'))` (null = custom role), `default_permissions text[] not null default '{}' check (default_permissions <@ KEYS)`, `created_at`, `updated_at` (both `timestamptz not null default now()`), `unique (id, tenant_id)`, `unique (tenant_id, preset)`. No money fields.
- `public.user_permission` (tenant-owned): `tenant_id uuid not null references public.tenant (id) on delete cascade`, `membership_id uuid not null`, `permission_key text not null check (permission_key = any (KEYS))`, `granted boolean not null`, `primary key (membership_id, permission_key)`, `foreign key (membership_id, tenant_id) references public.membership (id, tenant_id) on delete cascade`. One row per switch per membership (03c "one row per checklist box"). Keyed by membership because `app_user` is tenant-less (architecture `### Tenancy tables (EZD-005)`); `membership.user_id` gives the user.
- `public.membership.role_id uuid` (nullable; the comment in `20261019165204_create_membership.sql` reserves it for EZD-101), `foreign key (role_id, tenant_id) references public.role (id, tenant_id)` (no action: a held role cannot be deleted, S15 Role card), index `membership_role_id_idx`.
- KEYS = the 37 keys below, written as this SQL literal wherever the steps say KEYS (a check constraint calling a private function fails as `authenticated`, tried on pinned 17.11):
  `array['view_projects','create_projects','edit_model','delete_projects','upload_references','add_markup','run_code_check','run_fast_renders','run_standard_renders','run_photoreal_renders','approve_renders','mark_client_ready','see_company_costs','see_sell_prices','edit_catalog','create_change_orders','flag_to_supplier','issue_permit_sets','issue_revisions','send_to_client','export','edit_field_tasks','check_off_tasks','photo_notes','flag_conflict','send_field_measurement','approve_field_measurements','settings_company','settings_users','settings_title_block','settings_sheet_presets','settings_defaults','settings_catalog','settings_render_models','settings_code_edition','settings_libraries','settings_system_status']::text[]`
- Groups, in this order, keys in KEYS order: `projects` (first 7), `renders` (next 5), `money` (5), `issue_send` (4), `field` (6), `admin` (last 10). Sources: S15 Permission list (S15 Decision 1: plan names, not mockup names); AC-EZD-101-2 and Q-0234 drop two switches; page switches in S15 Layout nav order plus System status (Q-0210, Q-0225), in `admin`, the group of the Manage users and settings switch they replace (keeps the row's 6 groups).
- Presets (`private.preset_permissions`), each array in KEYS order:
  - `owner`: all 37.
  - `designer` (26): KEYS minus `delete_projects`, `issue_permit_sets`, `issue_revisions` and minus every `settings_*` except `settings_catalog`, `settings_libraries`.
  - `foreman` (11): `view_projects`, `create_projects`, `add_markup`, `run_fast_renders`, `export`, `edit_field_tasks`, `check_off_tasks`, `photo_notes`, `flag_conflict`, `send_field_measurement`, `settings_libraries`.
  - `crew` (4): `view_projects`, `check_off_tasks`, `photo_notes`, `flag_conflict`.
  - Derivation: 10 table less Approve translations (Q-0234), less See company costs for Foreman and Crew (Q-0235), plus Create projects for Foreman (Q-0224), page switches Q-0223, Q-0225 (AC-EZD-101-3). "Own jobs" is `membership.scope = 'listed'`, not a key (Q-0202; S15 Decision 13).
