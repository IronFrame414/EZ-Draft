# EZD-366 · Fix: a crafted wall or opening number cannot stop a project from taking new walls

- **ACs:** AC-EZD-366-1, AC-EZD-366-2
- **Complexity:** medium
- **Areas:** data-model, migrations, security, testing
- **User-visible result:** a project where someone saved a wall or door numbered 2147483647 still takes new walls and doors, and no number already stored changes.
- Phase: 4 · Planned by: planner · Date: 2026-11-09 · Status: planned

## 1. What to build
The rule, decided by the planner as the ticket row asks (Q-0625 (a), Q-0629 (b), Q-0650; CLAUDE.md rule 18): **when a key's highest stored number + 1 is above 2147483647, the number trigger gives the lowest whole number from 1 that no row of that project and key holds (deleted rows counted). It refuses with 22023 only when every number from 1 to 2147483647 is taken.** Every other branch of the trigger stays as it is (keep the stored number on update; keep a sent number that is unused and at most 2147483647; otherwise highest + 1). Each new row takes one number, so a project would need 2147483647 rows of one key before a new object is refused, and no sent number can bring that about. In the same pass, the schema and the device numbering stop at the same bound (D3 (a), CLAUDE.md rule 18).

Data: one forward-only migration that replaces the body of `private.model_object_number()` (same signature, same trigger, same index). No table, column, policy, grant or `schema_version` change. No `update`, no backfill call: stored numbers are untouched (AC-EZD-366-2).

**SQL F1** (run on the pinned local PostgreSQL 17.11 inside a rolled-back transaction at plan time, L-009). This is the 20261109100000 body with the lines from `if v_top > 2147483647 then` through its `end if;` replaced by:
```sql
  if v_top > 2147483647 then
    select c.n into v_top
    from (
      select 1::numeric as n
      union all
      select private.object_number(o.type, o.data) + 1
      from public.model_object o
      where o.project_id = new.project_id and private.object_number_key(o.type, o.data) = v_key
        and private.object_number(o.type, o.data) < 2147483647
    ) c
    where not exists (
      select 1 from public.model_object u
      where u.project_id = new.project_id and private.object_number_key(u.type, u.data) = v_key
        and private.object_number(u.type, u.data) = c.n
    )
    order by c.n
    limit 1;
    if v_top is null then
      raise exception 'object_number_out_of_range' using errcode = '22023';
    end if;
  end if;
```
