- **Complexity:** medium

- Phase: 1 · Planned by: orchestrator (session 13) · Date: 2026-11-09 · Status: ready

## 1. What to build
Two faults, one chain (Josh 2026-11-09 chat: "please fix this left over server issue so it doesn't continue to happen").

1. **Cause.** Claude Code 2.1.321 stops a `run_in_background` Bash command at its background deadline, the larger of the call's `timeout` and `BASH_MAX_TIMEOUT_MS` (default 600000 ms). The gate-phase unit's full gate (`scripts/gate.mjs . --full`, gate-phase SKILL step 1) runs longer than 10 minutes, so it was stopped at exactly 10:00 (session 6780e373, task b285203og: started 20:13:35, "stopped after reaching its background time limit" 20:23:35 UTC, 2026-11-09). `scripts/run.mjs` `runUnit` already sets `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` for the same class of stop after the last turn (run.mjs:324-326); it does not set `BASH_MAX_TIMEOUT_MS`.
2. **Symptom.** Playwright starts its `webServer` (`app/playwright.config.ts:135`, `pnpm start -p <web> -H 127.0.0.1`) in its own process group, so when the gate is stopped mid e2e the server survives as user `ezdraft`, parent 1, and holds the lane's web port. The next gate's e2e fails with "http://127.0.0.1:3000/api/health is already used" (gate-phase 4 handoff, 18:11 UTC). It happened twice on 2026-11-09 (pids 48275 from about 16:43, 46893 from about 20:20); only `sudo kill` cleared it.

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| D-Limit | 7200000 ms (2 hours): well over a full gate, still a bound for a hung background command. Only `BASH_MAX_TIMEOUT_MS`; `BASH_DEFAULT_TIMEOUT_MS` is not set, so foreground calls keep the 2-minute default | Claude Code 2.1.321 deadline = max(timeout, BASH_MAX_TIMEOUT_MS); run.mjs:324 |
| D-Find | Listeners: `/usr/sbin/lsof -nP -t -iTCP:<port> -sTCP:LISTEN`. Status 0 = the pids on stdout; status 1 with empty stdout and stderr = none the gate user can see; any other result = not ok with the line `port <port>: could not check (lsof status <status>: <first stderr line>)`. Per pid: `/bin/ps -o user=,pgid=,command= -p <pid>` and `/usr/sbin/lsof -a -p <pid> -d cwd -Fn` (the `n` line is the cwd) | macOS lsof, ps |
| D-Hidden | macOS lsof run as ezdraft lists only ezdraft's processes (code-reviewer, 2026-11-09). When lsof sees no listener, `portInUse(port)` (injected; gate.mjs, from Josh's side: true when a connect to 127.0.0.1 or ::1 is answered, so a listener on 127.0.0.1, 0.0.0.0 or :: counts, or when a 127.0.0.1 bind fails for any reason; no 0.0.0.0 bind, so no firewall prompt; code-review re-check 2026-11-09) decides: true = not ok with the line `port <port>: held by a process the gate user cannot see; stop it and run the gate again`; false = `port <port>: free`. After a kill the same check confirms the port is free. When `portInUse` is not given, it is treated as false | code-reviewer finding 1 |
| D-Gone | A listener whose ps output is empty (it exited between lsof and ps) is not foreign: lsof is asked again once, and the port is judged on that answer | code-reviewer note 5 |
| D-Match | A leftover gate server is exactly: user equals `GATE_USER`, command contains `next-server` or matches `next start -p <port>` / `pnpm start -p <port>`, and cwd equals `runTree` or starts with `runTree + '/'`. Anything else is never signalled | gate-user.mjs RUN_ROOT; playwright.config.ts:135-139; perf/check.mjs:300 |
| D-Kill | `/bin/kill -TERM -<pgid>`, poll the port every 500 ms up to 10 s, then `/bin/kill -KILL -<pgid>` and poll 5 s more. Port still held → not ok | Playwright detached webServer group |
| D-Foreign | A listener that does not match D-Match: not ok, with the line `port <port>: held by pid <pid> (<user>, <command>), not a leftover gate server; stop it and run the gate again` | CLAUDE.md rule 16 (report, never work around) |
| D-When | Only in user mode (macOS, gate user), after the lane lock is held and the preflight armed the spawner, before `typecheck`. The lock means no live gate uses this lane, so a running gate's server is never touched. Linux CI and `EZD_GATE_AS_SELF=1` skip it (no row) | gate.mjs lock (Q-0019, EZD-172), runPreflight |
| D-Row | The `ports` row goes into the results like `install` and `browsers`; a FAIL fails the gate but the checks still run (as `lane sweep`) | gate.mjs results |

## 3. Interface contract
`scripts/gate-port.mjs`:
- `parseListenPids(stdout)`: distinct positive integers, one per non-empty line, in order; anything else ignored.
- `isLeftoverGateServer({ user, command, cwd }, { gateUser, runTree })`: D-Match.
- `async freeLanePorts({ ports, exec, gateUser, runTree, sleep, portInUse })`: `exec(file, args)` returns `{ status, stdout, stderr }`; `sleep(ms)` resolves after waiting; `portInUse(port)` resolves a boolean (optional). Resolves `{ ok, lines }`; `ok` is false when any port stays held, holds a foreign or hidden listener, or could not be checked. Lines: `port <p>: free`, `port <p>: stopped leftover gate server pid <pid> (group <pgid>)` (several pids joined with `, `), `port <p>: leftover gate server <pids> still holds the port after TERM and KILL`, the D-Foreign line, the D-Hidden line, or the D-Find could-not-check line.

`scripts/launcher/unit-env.mjs`: `UNIT_ENV_LIMITS` as in build step 4.
