# EZD-035 · Fix: job progress browser test misses the queued event under load

- **ACs:** AC-EZD-035-1
- **Complexity:** medium (section 8)
- **User-visible result:** the gate's browser tests stop failing at random on the background-jobs test: `pnpm db:up` now waits until the local Realtime server is streaming database broadcasts, so the job's first `queued` event always reaches the page.
- Phase: 0 · Planned by: planner · Date: 2026-10-23 · Status: planned

## 1. What to build

**Cause (found by the planner, evidence in section 2 E1–E4).** `pnpm db:up` runs `supabase db reset --local`, which restarts the local Realtime server (E1). Realtime starts its database-broadcast stream (the temporary logical replication slot `supabase_realtime_messages_replication_slot_`) only when the first channel joins after a start, and answers that join (`SUBSCRIBED`) before the slot exists (E2). In the failing run the `/dev/jobs` page was Realtime's first client: the slot was created at 15:07:55.811 and streaming from 15:07:55.815, the `queued` row was written to `realtime.messages` at 15:07:55.813 and `running, 0` at 15:07:55.819 (E2, E3). A row committed before the slot's consistent point is never decoded, so `queued` never left the database and the page's list started at `running`. The page code is correct: it joins first and buffers early events (`app/src/app/dev/jobs/JobsProbe.tsx`; EZD-009 plan section 3 Step 7). Whether the page is Realtime's first client depends on worker timing, which is why it fails under parallel load and passes alone.

**Fix.** `pnpm db:up` ends by joining one public Realtime channel (which starts the stream, E4) and waiting until the slot is active. Every later run (Vitest and Playwright) then starts with the stream running. No app code, test page or test changes (ticket row: "without weakening the test").

Step 1 behaviour, exactly:
- `realtimeSocketUrl(apiUrl, apiKey)`: strip trailing `/` from `apiUrl`; replace a leading `https:` with `wss:` or `http:` with `ws:`; append `/realtime/v1/websocket?apikey=` + `encodeURIComponent(apiKey)` + `&vsn=1.0.0`. Any other scheme throws `Error('realtime_bad_url')`.
- `joinFrame()`: `JSON.stringify` of `{ topic: WARMUP_TOPIC, event: 'phx_join', payload: { config: { broadcast: { self: false, ack: false }, presence: { key: '' }, private: false } }, ref: '1', join_ref: '1' }` (sent by the planner to the pinned Realtime v2.143.4; reply `{"ref":"1","event":"phx_reply","payload":{"status":"ok",…},"topic":"realtime:ezd-db-up-warmup"}`, E4).
- `joinChannel({ url, WebSocketImpl = globalThis.WebSocket, joinTimeoutMs = 5000 })`: `new WebSocketImpl(url)`, then starts the `joinTimeoutMs` timer at once (before any `onopen`); sets the four property handlers `onopen`, `onmessage`, `onerror`, `onclose` (never `addEventListener`). `onopen` sends `joinFrame()` once. `onmessage(event)`: `JSON.parse(String(event.data))` (a parse error is ignored); a message with `event === 'phx_reply'`, `ref === '1'` and `topic === WARMUP_TOPIC` settles: `payload.status === 'ok'` resolves `{ close() }` (calls `ws.close()`), any other status rejects. Every reject (a constructor throw, `onerror`, `onclose` before the reply, a non-ok reply, no reply within `joinTimeoutMs`) calls `ws.close()` when a socket exists and rejects `Error('realtime_join_failed')`. Settles once: after it settles, every later `onopen`, `onmessage`, `onerror` and `onclose` call does nothing (so the `onclose` that follows `handle.close()` or a reject is ignored); the timer is cleared when it settles; `ws.close()` is called at most once per socket (by the reject, or by `handle.close()`); `handle.close()` only calls `ws.close()`.
- `waitForBroadcastStream({ join, slotActive, timeoutMs = 30000, intervalMs = 250, now = Date.now, sleep })` (`sleep` defaults to `(ms) => new Promise((r) => setTimeout(r, ms))`), returns `Promise<{ checks: number }>`. Algorithm, in this order:
  1. `start = now()`, `checks = 0`, `handle = null`.
  2. Loop: if `handle` is null, `handle = await join()`; a rejection leaves `handle` null (retried next pass).
  3. If `handle` is set: `checks += 1`; `await slotActive()`; a rejection closes `handle` and rejects with that same error; `true` closes `handle` and resolves `{ checks }`.
  4. Every pass, whether or not `join` succeeded (a failed `join` skips 3 and comes here): if `now() - start >= timeoutMs`, close `handle` if set and reject `Error(handle ? 'realtime_stream_not_started' : 'realtime_join_failed')` without calling `sleep`.
  5. `await sleep(intervalMs)`, back to 2.
  `now()` is read once at 1 and once per pass at 4, never elsewhere. Every `handle.close()` call in this function is wrapped in `try { … } catch {}` (a close error never changes the result). `slotActive` is never called while `handle` is null.
- `ensureRealtimeBroadcastStream({ apiUrl, apiKey })`: `waitForBroadcastStream({ join: () => joinChannel({ url: realtimeSocketUrl(apiUrl, apiKey) }), slotActive })` where `slotActive` runs `runLocalSql(SLOT_ACTIVE_SQL)` (exported by `scripts/db/sql.mjs`, `runLocalSql(sqlText) -> Promise<{ code, stdout, stderr }>`, never rejects; its header comment): `code !== 0` or `stdout.trim()` not matching `^\d+$` rejects `Error('realtime_slot_query_failed')`; else resolves `Number(stdout.trim()) > 0`. Resolves `void`.
