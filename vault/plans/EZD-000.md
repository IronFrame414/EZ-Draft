## Approach

The builder writes `docs/architecture.md`, a dependency-free Node check script, and the minimum root workspace files needed for the gate to run that check. Nothing else from the app is built here; EZD-001 builds the Next.js app, TypeScript, lint and Vitest on top of these files and must extend, not replace, them.

### Step 1 — Root workspace files (so the gate can run the check)
`scripts/gate.mjs` treats a repo with test files but no `package.json` as a failure, and once a `package.json` exists it requires the scripts `typecheck`, `lint`, `test` and `build` (gate.mjs, `required`). The builder may not change gate.mjs or ci.yml (guard-paths.mjs). So EZD-000 creates:
- Root `package.json`: `"name": "ezdraft"`, `"private": true`, `"packageManager": "pnpm@<exact version>"` (Named tools: pnpm; version from the Dependencies table), `"engines": { "node": "22.x" }` (Node 22 is the version `.github/workflows/ci.yml` installs), no dependencies. Scripts are fan-outs that stay correct after EZD-001:
  - `lint`: `node scripts/conventions/check.mjs` then `pnpm -r --if-present --filter "!./spikes/**" run lint`
  - `test`: `node --test "scripts/**/*.test.mjs"` then the same fan-out for `test`
  - `typecheck`, `build`: the same fan-out only (no workspace package exists yet, so they pass with nothing to do; EZD-001 adds the app's real ones).
  - The explicit glob and the `!./spikes/**` filter keep `.claude/worktrees/`, `vault/` and `spikes/` out of test discovery (PROCESS.md, Special tickets; CLAUDE.md rule 8).
- `pnpm-workspace.yaml` with exactly `packages: [app, packages/*, worker, spikes/*]` (ticket Scope folder layout; Named tools "pnpm workspace: the app, the geometry package, the local render worker").
- `.npmrc` with `save-exact=true` so later `pnpm add` writes exact versions (ticket: "version-pinned").
- `pnpm-lock.yaml` as generated by `pnpm install` (gate runs `pnpm install --frozen-lockfile`).
The builder confirms `node scripts/gate.mjs <worktree>` exits 0 with these files (risk: `pnpm -r` with zero matching packages must exit 0; if it does not, the root script calls a small Node runner that skips when no package exists).

Every workspace `package.json` is `"private": true` and named `@ezdraft/<name>` (app, geometry, worker, `spike-<dir>`). The geometry package must run in the browser, in Web Workers and in Node (02 Geometry core; 11 Where each output is produced), so it uses no DOM or React.

**Server-only data access and can()** (03 rules 1–2, 11; R26 R1, R2, R14; EZD-102 and EZD-133 rows). Documented here; implemented by EZD-133 (helper, server-route pattern, browser-query lint rule) and EZD-102 (enforcement, UI hook).
- Browser code never queries tables. It calls the app's own HTTP routes (Route Handlers under `app/src/app/api/**`) through one fetch helper in `src/lib/` that adds the app version to every request (03 rule 12; EZD-134). Planner's choice: data reads and writes use Route Handlers, not Server Actions, because the outbox (03 rule 9) and the EZ Binder inbound API need plain HTTP endpoints.
- The two exceptions: Realtime subscriptions authorized per project scope (EZD-018) and signed uploads straight to Storage (EZD-132) (03 rule 1).
- Every route: read the session → load the user's membership and permissions in one indexed query per request (EZD-102) → `can()` → query with a Supabase client carrying the user's session, so RLS stays the backstop (03 rule 1; 11 rule 10) → return an explicit field list.
- Contract: `can(ctx, permission, target?) → boolean`, where `ctx` is the per-request context (user, active tenant from the token-hook claim, membership status and scope, permission set), `permission` is a typed key from the EZD-101 list (key spelling is EZD-101's), and `target` is `{ projectId }` when the action is on a project (scoped users: listed projects only; deactivated users: always false; 03 Tables membership; EZD-006). A `requirePermission(...)` wrapper turns false into a 403 (EZD-102 Done when). The browser `can()` hook (EZD-102) only hides controls; it is never the security check.
- Money (03 rule 2; R26 R2): cost fields are added to a response only when `can(ctx, <See company costs>)`, sell/markup/total fields only when `can(ctx, <See sell prices>)`, through one serializer per resource in `src/server/`; client-link routes never touch money tables (03 rule 11).
- The service-role key is used only in job handlers, migrations, seeds and admin scripts, never in request-path routes and never in browser bundles; the render worker uses its own revocable key (03 render_worker).

**Migrations** (02 Named tools; 11 Operations; tickets README; EZD-023). Folder `supabase/migrations/`. File name `<YYYYMMDDHHMMSS>_<snake_case_description>.sql` (14-digit UTC timestamp as `supabase migration new` writes it; description lowercase letters, digits and underscores), e.g. `20261012093000_create_tenant.sql`; timestamps unique. One concern per file. Add before remove: never drop or rename what the previous release reads (11 Operations; check by EZD-023). A migration that creates a table also adds `tenant_id`, its RLS policy, the tenant_id and project_id indexes and the tenant-isolation test (tickets README; 11 rule 10; EZD-006). TypeScript types are generated from the local database by the Supabase CLI into `app/src/server/db/database.types.ts` and committed (02 Named tools; EZD-004 adds the script).

**Errors and logging** (11 Operations, Security; R26 R12, R16, R17; EZD-015, EZD-024, EZD-026, EZD-120b). Planner's pattern:
- Route error body: `{ "error": { "code": "<stable_snake_code>", "message_key": "<t() key>" } }`. Status: 400 invalid input (Zod failure), 401 not signed in, 403 permission missing (EZD-102), 404 row not found or outside the user's tenant/scope (does not reveal that it exists), 409 stale `lock_epoch` or sequence conflict (03 rules 6, 9), 500 unexpected. The browser shows `message_key` through `t()` (R26 R17); no raw server text reaches the UI.
- Browser: failed loads use the inline error with Retry (EZD-015); failed saves keep edits and show the save banner (EZD-120b). Nothing fails silently: anything skipped is counted and shown (R26 R16 pattern).
- Jobs: a failure writes `job.error` and `attempts` (03 job table); retry with backoff (EZD-009); a final failure goes to Sentry and the owner email (11 Operations; EZD-024).
- Logging: one structured JSON line per event from one logger module (`logger.ts`) on the server and in the worker: level, message, route or job kind, tenant_id, project_id, request or job id, duration. Never logged: tokens (share-link, magic-link, 6-digit code, EZ Binder sign-on code), keys and secrets, request bodies, email addresses, money values (03 rules 2, 11; CLAUDE.md rule 12). No `console.*` outside `logger.ts` and tests (check C8). Unexpected errors go to Sentry (EZD-024).

**Storage buckets and paths** (03 rules 1, 11; 03 source_file, render, catalog_item, job; 11 rule 12, Operations, Data retention; EZD-025, EZD-132). Rules from sources: every bucket private; files served through short-lived signed links; browser uploads go straight to Storage with resumable signed uploads; job inputs and outputs are Storage paths; originals are never changed; renders are stored full size plus 400 px and 1600 px copies; deletes of sent-package files are soft deletes. Planner's layout (technical choice; EZD-132 creates the buckets):
- Every path starts `<tenant_id>/` so Storage policies use the same tenant claim as table RLS (EZD-006); project files continue `<project_id>/`; tenant-level files use `<tenant_id>/tenant/`.
- Buckets: `sources` (uploaded originals: every `source_file` kind; written once, never overwritten), `renders` (`<tenant_id>/<project_id>/<render_id>/full|1600|400.<ext>`), `exports` (PDF sets, DXF, GLB, USDZ, CSV, selections PDF, markup PDF/DXF; sent-package files soft-deleted), `media` (plan thumbnails and version previews, logo, catalog images 256 px, spec sheets, textures, camera-view thumbs), `jobs` (`<tenant_id>/<project_id or tenant>/<job_id>/in|out/...` scratch).
- Object names use ids, not user file names; the original file name is kept on the row (03 source_file).
- Signed-link lifetimes are values, set by EZD-132 from its own sources (not here).

**Tests** (02 Named tools; CLAUDE.md rule 10; tickets README rule 4). Unit tests: Vitest, `*.test.ts` / `*.test.tsx`, next to the code they test. Browser tests: Playwright, `*.spec.ts`, in the folder EZD-016a creates. Repo scripts: `node:test`, `scripts/**/*.test.mjs`. Shared helpers in `test-utils/` or `test-harness/` folders (guard-paths.mjs). The test that closes a ticket has the ticket id in its title, e.g. `EZD-005 done when: seed creates Worth Properties as tenant 1`, so reviewers can find it. Tests never call live AI, email, render providers or EZ Binder; they use the stubs of EZD-008, EZD-016, EZD-019, EZD-021. Spike tests live with the spike under `spikes/` and are not run by the root gate (vault/spikes/TEMPLATE.md; PROCESS.md).

**Handoff.** Path `vault/handoff/CURRENT.md`, format `vault/handoff/TEMPLATE.md`, overwritten at session end; previous ones in `vault/handoff/log/` (CLAUDE.md; PROCESS.md Ledgers). Link only; do not copy the template.

### Step 3 — `scripts/conventions/check.mjs`
Plain Node (no dependencies, Node 22 built-ins only), run as `node scripts/conventions/check.mjs [rootDir]` (default: current directory). It prints one line per violation, `[Cn] <repo-relative path>: <problem>`, and exits 1 if any, else prints a pass line and exits 0. It never reads `node_modules`, `.next`, `dist`, `coverage`, `.git`, `.claude/`, `vault/`, `**/fixtures/**`, `**/__fixtures__/**`, `**/__tests__/**` outside the scanned roots below. Checks:

- **C1 Dependencies listed and pinned** (ticket Done when; 02 Named tools; CLAUDE.md rule 11). Reads `package.json` at the root, `app/`, `packages/*/`, `worker/`, `spikes/*/` (only these). Every name in `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies` must have a Dependencies row, unless its specifier starts with `workspace:`. For the first three fields the specifier must equal the row's Version exactly. Root `packageManager` must equal `pnpm@<pnpm row Version>`. Fails if a Dependencies row has a non-exact Version or a package appears twice, or if a `package.json` exists and `docs/architecture.md` or its Dependencies table is missing.
- **C2 Workspace layout** (ticket Scope; 02 Named tools). `pnpm-workspace.yaml` `packages` is exactly the set {`app`, `packages/*`, `worker`, `spikes/*`} (order and quote style ignored). Every workspace `package.json` has `"private": true` and a name starting `@ezdraft/`.
- **C3 Geometry has no UI** (02 Stack Geometry core "no UI code"). `packages/geometry/package.json` lists none of `react`, `react-dom`, `next`, `@react-three/*`, `@radix-ui/*`, `radix-ui`; no `.tsx`, `.jsx`, `.css`, `.scss` file under `packages/geometry/` (outside node_modules).
- **C4 Spikes are never imported** (tickets README; vault/spikes/README.md). In non-test source files under `app/`, `packages/`, `worker/` (`.ts .tsx .js .jsx .mjs .cjs`), no import/require/export-from specifier contains `spikes/` or starts with `@ezdraft/spike`; no non-spike `package.json` depends on an `@ezdraft/spike*` package. Test files (`*.test.*`, `*.spec.*`, `e2e/`, `test-utils/`, `test-harness/`) are exempt.
- **C5 Migration names** (02 Named tools "timestamp-named"). Every file in `supabase/migrations/` matches `^\d{14}_[a-z0-9]+(_[a-z0-9]+)*\.sql$`; no two share a timestamp. Passes when the folder does not exist.
- **C6 PDFKit only in jobs** (02 Named tools "PDFKit, in the job only"). Non-test source under `app/`, `packages/`, `worker/` imports `pdfkit` only from files under `app/src/server/jobs/`.
- **C7 Test file naming** (this file, Tests). Under `app/`, `packages/`, `worker/`: a file importing `vitest` is named `*.test.ts`/`*.test.tsx` unless it is under `test-utils/` or `test-harness/` or is `vitest.config.*`, `vitest.workspace.*` or `*.setup.ts`; a file importing `@playwright/test` is named `*.spec.ts` unless it is under `test-harness/` or `fixtures/` or is `playwright.config.*`.
- **C8 No console outside the logger** (Errors and logging). Non-test files under `app/src/`, `packages/*/src/`, `worker/src/` contain no `console.` call except files named `logger.ts`.

Wiring: the root `lint` script runs it, so `scripts/gate.mjs` (and therefore CI, `.github/workflows/ci.yml`) fails on any violation. No new workflow file is needed.

## Risks
- Gate on an app-less repo: the root fan-out scripts (`pnpm -r --if-present …`) must exit 0 when no workspace package exists, and `pnpm install --frozen-lockfile` must work with a dependency-free lockfile. The builder proves both with `node scripts/gate.mjs <worktree>`.
- Tool versions: CI installs Node 22 and the latest pnpm (`npm install -g pnpm`, ci.yml); this PC runs Node v24.20.0 and pnpm 12.11.2. The `packageManager` pin should match what CI and this PC will run, or pnpm may refuse or switch versions. If ci.yml needs a change, only Josh can make it.
- EZD-001 must extend, not replace, the root `package.json`, `pnpm-workspace.yaml` and `lint` script (the conventions check must stay in `lint`). Its planner should read this plan.
- Pinning about 30 packages that are not installed yet means later tickets may hit peer conflicts and need to bump a row; that is allowed (edit the row in the same commit) but every bump is visible to the reviewer.
- EZD-030's row says the spike is built "in the geometry package", while the README and spike notes keep spikes under `/spikes`. C4 does not block that, but EZD-030's planner must resolve it. The root gate does not run spike tests (PROCESS.md), so spike Done-when tests are run by the orchestrator with `pnpm --filter`, not by the gate.
- C4/C6/C7/C8 are text scans, not a parser. They can miss unusual import forms; EZD-001's lint setup can replace them later with lint rules, keeping the IDs.
