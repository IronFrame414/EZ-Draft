# Security audit, 2026-11-27

Read-only audit of `develop` at `494c0451`. Nothing was run against the database, no gate, no e2e, no server. Every finding below was read in the code named; anything not proven is marked "possible". No high or medium finding was found: no path was found by which one company reads or changes another company's rows.

## Checked and found fine

Company isolation
- All 55 `public` tables have RLS enabled (parser over `supabase/migrations/*.sql`). All 128 policies read: every member-readable table tests `tenant_id = private.tenant_id()` and, for project rows, project scope; write-only-by-function tables carry a deny policy; every table has the restrictive `require_api_gate` policy.
- `private.tenant_id()` comes from the signed token claim and refuses an ended session. `private.require_api_gate()` needs the server-held header on every PostgREST call by `anon` or `authenticated`, so a browser holding its access token cannot call tables or functions directly.
- 129 `public` functions: every one granted to `authenticated` or `anon` was classified; the `security definer` ones call the gate and take the company from the claim (directly or through `users_writer_tenant`, `project_card_tenant`, `sheet_presets_tenant`, `require_send_to_client`, `edit_lock_caller`, `version_edit_caller`, `field_action_refusal`). Read in full: `create_project`, `create_project_with_objects`, `save_member`, `save_member_scope`, `save_edge_offer`, `send_to_client`, `renew_share_link`, `revoke_share_link`, `list_share_links`, `resolve_share_link`, `resolve_sent_package`, `enqueue_job`, `delete_project`, `list_project_purge_files`, `log_event`, `record_error_alert`, `owner_password_target`, `link_app_user`, `list_users`. Ids passed in (customer, foreman membership, role, project list, edge profiles, sent package) are each checked against the caller's company.
- Service-role (secret key) client: only `server/auth/admin-auth.ts` (invite accept, Owner-set password after `owner_password_target`) and `server/jobs/db.ts` (job handlers, the cron sweep). Every handler query filters on the job row's `tenant_id` and `project_id`; Storage paths in a job payload are checked to be inside the job's company and project (`server/jobs/storage-path.ts`). `/api/jobs/sweep` needs `CRON_SECRET`, compared in constant time.
- Route handlers: 122 `route.ts` files. All but seven call `requireApiSession` / `requireApiPermission` (or the lock, member, role, field-action wrappers). The seven are `api/health`, `api/monitoring`, `api/share-links/resolve`, the cron sweep (secret) and three `/dev` routes (404 on Vercel). All member routes use the session client, so RLS and the definer checks apply to every id taken from the request. Direct table writes (customers, library items, saved groups, source files) each check a permission first.
- Realtime: broadcasts go to private channels only; `realtime.messages` policies allow `project:<id>` to members who can see the project and `user:<id>` to that user. No table is in a Realtime publication.

Share links and client pages
- Token: 32 random bytes, only its SHA-256 stored, never logged; generated on the server. Expiry and revoke are enforced in `resolve_share_link` / `resolve_sent_package`; an expired link returns the company name only; renew and revoke need Send to client and project scope. Deleting a project deletes its links (cascade).
- The resolve route returns only `{ status, expiresAt }`. No client page exists yet, so nothing else is exposed to a signed-out viewer today (see S2).
- The emailed link's origin is fixed (`server/errors/app-origin.ts`), not taken from the request Host header. Email text is HTML-escaped.

Money
- Money columns (`money-fields.ts` registry: catalog cost, sell, markup, render dollars, option cost lines, edge price differences) are read only behind `see_company_costs` / `see_sell_prices`: `api/catalog`, `api/settings/render-models`, `api/projects/[id]/edge-offer`, supplier files, order-report import and review. `order_line` has no price column. Model objects and export job results carry no money fields. Storage hides `supplier_pdf` and `order_report` objects from members without See company costs (gap: S1).
- Not re-run: `money-routes.test.ts` (needs the database).

Webhooks, uploads, redirects
- No inbound webhook route exists. `/api/monitoring` accepts only the app's own placeholder DSN, 256 KB cap, per-address throttle.
- Storage: five private buckets; no anon policy; no update policy. `sources` insert needs a pending `source_file` row started by the same member; `media` writes are the company logo (Company settings switch, server-only), checkpoint thumbnails and field photos, each path-checked in the database; `exports` are readable only for issued revisions in project scope; `jobs` and `renders` have no member policy. SVG logos are rewritten through an allow-list. Bucket size and type limits are set.
- Sign-in return (EZD-1977): `returnPath` accepts only a same-origin path; `//host`, backslash, whitespace, control characters, encoded slashes and dot-segment tricks were traced by hand and are refused; every use (`sign-in/page.tsx`, the four sign-in actions, the next cookie) re-checks the value.
- CSRF: writes to `/api` must be same-origin (`same-origin.ts`); `/dev` and `/api/dev` answer 404 on Vercel production and preview.
- Server-side fetches: the appraiser page read is limited to listed hosts with every redirect re-checked; the render provider poll URL is host-checked.

Not covered
- Cloud project settings (Auth options, Realtime "private only", Vercel env) are outside the repository. `.env` files were not read.
- The AI assistant routes, the invite pages and the event log reader were only skimmed.
