# EZD-282 · Fix: a write grant applies only to files in the agent's own worktree

- **ACs:** AC-EZD-282-1, AC-EZD-282-2
- **Complexity:** high (section 8)
- **Areas:** tooling, scripts, security
- **User-visible result:** a builder can use a write grant only inside the worktree it was sent to; a builder that strays into another ticket's worktree is refused.
- Phase: 1 · Planned by: planner · Date: 2026-10-30 · Status: questions

## 1. What to build

Section 1 follows Q-0467 (a) and Q-0468 (a) (answered-agent, security-reviewer, 2026-10-30). Q-0466 (a) says the grant applies when the worktree of the resolved path equals "the worktree of the agent's cwd". The hook input's `cwd` can't tell us that. Every builder transcript checked on 2026-10-30 records `"cwd":"/Users/josh/Projects/ezdraft"` (the main checkout) while it writes in `.claude/worktrees/<T>/`: 4 transcripts, EZD-000i, EZD-011b and two EZD-260 rounds. R-047 adds that `cwd` is the session's directory. Built literally, the rule would deny every grant to every builder. So the agent's own worktree is taken from its dispatch's `Worktree:` line (`.claude/skills/build-ticket/dispatch.md`, template line 3), read from the subagent's own transcript (Q-0467 (a)). Limit: a builder can forge this identity through Bash, because builders run with `--permission-mode bypassPermissions` (`scripts/run.mjs` line 130) and `guard-bash.mjs` lines 49-52 deny them only git branch commands, so a Bash command can write a transcript or the target file directly. The check is therefore an accident guard, like the existing grants, and opens no new hole (Q-0467). Limiting Bash and every other builder and test-author write to the dispatched worktree is a separate fix ticket after this one (Q-0468 (a)); it is not in scope here. No data, no app code. Lessons applied:
- L-002: rows 1-2 are denied to the builder by `guard-paths.mjs` lines 86 and 94, hence the Grant row.
- L-004: the new check is only an extra condition on the three existing grant exits, which all sit after every deny that applies to all agents (lines 11-33, 104).
- L-006 and L-012: every unreadable form of the identity grants nothing, and each has a failing-input row in T2.
