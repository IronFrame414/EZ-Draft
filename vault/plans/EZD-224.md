**Why cut here.**
- **Part a is the server side and the card**: Storage, policy, functions, routes, `hasThumbnail` and the card image. Its tests put a thumbnail in place through the routes and functions with a fixture WebP (db and route tests, and a browser test that loads the card). They need no canvas and no encoder.
- **Part b is the browser side**: capture, encode, the client flow and the dev hook. It calls part a's two routes through the contract fixed below (Seam) and reads nothing else of part a.
- **Size.** Each part is under the size rule: part a about 14 source files and 13 tests, part b about 11 source files and 13 tests (counts per part below). This is the cut the plan review proposed ("capture and encode as one part, Storage, routes and card as the other", `review-phase-06.md:10`).
- **Build order and planning.** Built a → b. Each part is planned as its own unit from its section here, with template v2, the Connections rows, `contract_check` and `connections_check`, and the planner lessons for its areas. Part a (security-heavy): L-009 (confirm the SQL on the pinned stack), L-014, L-016 (revoke, then grant by name), L-023, L-024, L-049 (every list edit above as a test-author edit row), L-051 (remove the uploaded objects in `afterAll`, `media-bucket.test.ts` pattern), L-052, L-059, L-060 (migration timestamp after the newest on develop at merge; the newest today is `20261110130000_object_number_free_fallback.sql`) and L-061 (the path pattern, the case of the uuids, and a `../` or extra-segment case). **Settled from the sources (both parts follow these; not questions):**
- **Size and encoding.** 440 × 256 WebP (2× the 220 × 128 card drawing). Quality 80, then 70, 60, 50, 40, stopping at the first result under 40,960 bytes. If none is under, there is no image. (09 Q-0664; 09m Thumbnail rows 2, 3; AC-1.)
- **Storage.** Bucket `media`, path `<tenant>/<project>/thumb/<model_version_id>.webp`. EZD-224 widens `media` to `image/webp`. The upload is a signed upload from a route that checked Edit model. Cards read a 900 s signed link, made only when the image loads. (03 Q-0664; `SIGNED_DOWNLOAD_SECONDS = 900`, `objects.ts:13`.)
- **Who may upload.** Only a user with Edit model on that project, only `image/webp`, and only at the tenant's own thumb path (AC-4; 03b rule 1). A Storage policy is the only check on a direct Storage call, so the path check is in SQL (ARCH "Storage buckets and paths").
- **Server checkpoints.** A checkpoint made without a browser canvas leaves `preview_path` null and `project.thumbnail_path` unchanged: lock release or timeout, Finish import, Revert (03 Q-0664; 09m row 5; AC-3).
- **Empty model.** No image, and the card keeps its empty slot (09 Q-0664; 09m row 1; Q-0403 "empty thumbnail slot"; AC-3).
- **No image on autosave.** Twenty autosaves write no image (09m row 4; 11 rule 12; 03a).
- **What is captured.** The canvas exactly as drawn at the checkpoint: the current View, floor and zoom. Nothing is fitted or redrawn, and there is no second render (05 Q-0667; PHASES Slice 6 Risks; AC-5).
- **Trigger.** EZD-224 builds the pipeline and the dev hook `__ezdraftEditor.checkpoint()` only. EZD-125's Stop editing calls `makeCheckpoint`, and Josh's slice 6 test step 6 moves to slice 8 (Q-0681 (a)).
- **Version rows.** The Versions panel and the cleanup sheet use `preview_path` in EZD-122 and EZD-123 (phase 9), not here (05 Q-0664; AC-EZD-123-10). This narrows the ticket row's "version rows" and "cleanup sheet".
- **Projects page.** No plan is drawn there and no editor code is loaded (S01 Card thumbnail; 11 rules 7, 12; AC-2).
- **Encoder.** `@jsquash/webp` 1.5.0 (libwebp in WASM), in a Web Worker, in every browser. Not canvas `toBlob`: Safari does not encode WebP from a canvas (R-058; R-059; 11 rule 3).
- **WebGL read.** The WebGL buffer is readable only in the task that drew it. The capture therefore reads inside the frame's own after-render callback, with no `preserveDrawingBuffer` (R-058).
