# EZD-389 · Every email a user's action sends also goes to that user

- **ACs:** AC-EZD-389-1, AC-EZD-389-2, AC-EZD-389-3 (`vault/spec/acceptance-criteria.md:1040-1042`)
- **Complexity:** medium (section 8)
- **Areas:** email, security, testing
- **User-visible result:** when Josh sends an email from EZ Draft (a client send, an invite, a resend, an owner-set password notice), he also gets a marked copy in his own inbox that he can forward if the recipient's copy lands in spam; emails the system sends on its own go only to their recipients.

- Template: v2

## 1. What to build
Ticket row (`vault/tickets/phases/phase-02.md:74`): Scope: in the shared send helper (EZD-008a, `app/src/server/email/`), every email sent because of a user's action (client sends, invites, resend, owner-set password notice and the rest) also sends that user a copy they can forward when the recipient's copy lands in spam. System emails with no acting user (for example cleanup_due) go only to their recipients. One switch turns the copy off when Josh lifts the rule. The planner settles how the copy is addressed and marked; any wording not on a mockup goes to Proposed wording for Josh. Done when: every email that a user's action sends also reaches that user as a copy they can forward; an email with no acting user goes only to its recipients; turning the switch off stops the copies. Depends on: EZD-008a. Spec ref: Q-0701; R26.

### Design decisions
Settled at the design step; the code-bound step turns each into Build steps and Decided rows against develop's code. Rows D3 and D11 rest on the recommended options of Q-0738 and Q-0739 (section 10); a different answer changes those two rows only.
| # | Choice | Decision | Source |
| --- | --- | --- | --- |
| D1 | How the copy is addressed | A second, separate `transport.send` call to the acting user's address alone; never Cc or Bcc on the recipient's message, so the recipient never sees the user's address and each message keeps one recipient. | ARCH Email "one recipient per call"; Q-0701 ("also goes to that user") |
| D2 | Order and condition | The recipient's message goes first. The copy is sent only when that send returned `ok: true`, because the copy says the email was sent; when the recipient's send fails there is no copy and the sender still has the link (Copy link rule). | Q-0701; Q-0035 (Copy link on every send, sent or failed) |
| D3 | How a call names the acting user | `SendEmailInput` gains a required field `sentBy: { email: string } \| null`: the acting user's sign-in email, or `null` for a system email. Required, so the type check refuses any caller that forgets it. | Q-0701; Q-0738 (a), answered-agent |
| D4 | No copy to oneself | No copy when `sentBy.email.toLowerCase()` equals `to.toLowerCase()` (no trim: `z.email()` already refuses an address with spaces, checked on zod 4.6.7): the password-changed and AI-key emails go to the user who acted (`profile.ts:80`, `user-key.ts:241`), so they keep sending one message. | Q-0701 (the copy exists so the user can forward the recipient's email) |
| D5 | Bad `sentBy` | A `sentBy.email` that fails `z.email()` refuses the whole call with `EmailInputError` before any send, as every other bad input does. | EZD-008a input checks; ARCH Email "Input checks (EZD-151)" |
| D6 | The switch | One exported constant `SENDER_COPY_ON = true` in its own file `app/src/server/email/sender-copy.ts`, read by `sendEmail` on every call; `false` stops every copy. Not an environment variable: a code constant cannot differ between Preview and Production, needs no Vercel step from Josh (agents never change Vercel settings), and lifting the rule is a one-line reviewed change. Tests turn it off by mocking that module. | phase-02.md row EZD-389 ("one switch"); ARCH Email (agents never change Vercel settings); CLAUDE.md rule 18 (cannot drift) |
| D7 | What the copy keeps | The same From (with `company`, "<Company> via EZ Draft"), the same Reply-To (the company email), the same paragraphs, link, link label and `lang` as the recipient's message. | Q-0036; Q-0035 |

| D10 | A failed copy | Never changes `SendEmailResult` (it describes the recipient's send) and never throws: a failed or throwing copy send is reported to Sentry as `email_copy_failed` with its cause code as the `ezd.cause` tag (the transport code, or `email_copy_threw`), never an address or link. A throw would make a job retry and send the recipient a second email. | ARCH Errors and logging (no email addresses logged); `reportSendFailure` in `app/src/server/email/send.ts` |

### Behaviour per role
The helper has no role check of its own: the route or job that calls it has already decided the action is allowed (ARCH Server-only data access and can()). A role matters only as "whose action sent the email".
| AC | Role | Behaviour |
| --- | --- | --- |
| AC-EZD-389-1 | owner | (1) The owner does an action that emails someone else (owner-set password notice, invite). (2) The recipient's email is sent. (3) The owner gets the marked copy (D1, D2, D8). |
| AC-EZD-389-1 | office | (1) An office user sends to a client or resends an invite. (2) The recipient's email is sent. (3) The office user gets the marked copy. |
| AC-EZD-389-1 | field | Same as office for any field action whose route sends an email to someone else; a field user acting on their own account (password change) gets one email only (D4). |
| AC-EZD-389-1 | view-only | View-only users have no action that sends an email to someone else; their own password-changed or AI-key email reaches them once (D4). |
| AC-EZD-389-1 | no permission | The calling route refuses with 403 before `sendEmail` runs (EZD-102), so no email and no copy. |
| AC-EZD-389-2 | owner | An alert email to the owner (Q-0067 (b)) or a notification email carries `sentBy: null`: the owner gets that one email and nobody gets a copy. |
| AC-EZD-389-2 | office | Same: a notification email to an office user goes only to them. |
| AC-EZD-389-2 | field | Same: a notification email to a field user goes only to them. |
| AC-EZD-389-2 | view-only | Same: a notification email goes only to its recipient. |
| AC-EZD-389-2 | no permission | A person without an active membership gets no notification email at all (ARCH Notifications); nothing changes. |

| AC-EZD-389-3 | view-only | Same as owner. |
| AC-EZD-389-3 | no permission | Same as AC-1: no send, so no copy either way. |
