# EZD-218 · Left panel: Layers and Rooms (split proposal)

- **ACs:** AC-EZD-218-1 … AC-EZD-218-6 (`vault/spec/acceptance-criteria.md:1010-1015`, stage-0), shared out to the parts below (AC-5 split by clause; AC map)
- **Complexity:** high (both parts); reasons per part
- **Areas:** ui, data-model, testing, migrations
- **User-visible result:** The plan editor gets its left panel. The Layers tab shows and hides Existing, Demo and New work, the overlays and the rooms, and locks a layer so nothing on it can be picked. The Rooms tab lists each room with its area. A room can be renamed and given a room type, floor finish and ceiling type, and these stay after a reload. Clicking a room, in the list or on the plan, selects it, and a list click also zooms to it.
- Phase: 6 · Planned by: planner · Date: 2026-11-10 · Status: split proposal

## Split proposal

**Why.** Planned whole, the ticket touches about 24 source files and 12 test files and needs about 36 tests. That is over the size rule (PROCESS.md section 6 "Ticket size": about 20 files or 25 tests; Josh 2026-10-22). It also builds on EZD-214a's phase store, whose file and names are not fixed yet: EZD-214 is still a split proposal, and its part plans settle them ("The part plan settles: … the store's file and exported names", `vault/plans/EZD-214.md`). Where the count comes from:
- **Room data.** Room attributes are `{ name }` only (`packages/geometry/src/schema/room.ts:19`, strict). Adding type, floor finish and ceiling type is not optional, so it is a new schema version (03 Q-0664 "Rooms gain …"; AC-6; 03b rule 5; ARCH Model schema "Version rule"). `CURRENT_SCHEMA_VERSION` is 4 (`schema/migrate.ts:15`), and no phase 5, 56 or 6 plan raises it. Five code paths make rooms: `rooms/sync.ts:89`, `rooms/override.ts:82`, `benchmark/benchmark.ts:129`, `app/src/server/projects/template-objects.ts:52`, and `app/src/editor/tools/model-changes.ts:62`, which passes data through. Tests pin version 4 in `numbers.test.ts:49`, `benchmark.test.ts:74`, `wall-layers.test.ts:84,106`, `opening.test.ts:96,196,201`, `migrate.test.ts:38`, `room.test.ts:79,89,93` and `app/src/server/model/opening-upgrade.db.test.ts:108`. About ten test fixtures build `attributes: { name }` rooms.
- **Rooms on the canvas.** The pick index holds walls and openings only (`app/src/editor/selection/pick-index.ts:83-97`; ARCH Selection "never rooms"; 05 Q-0630 row 8: "Rooms not selectable until EZD-218"). Rooms need a pick shape (`PickShape` has `quad` and `bar` only, `packages/geometry/src/selection/shapes.ts:10-12`). They also need a selected and hovered look: `objectGeometry` keeps only `existing`/`demo`/`new`/`flagged` items, and a room's fill is on layer `rooms` (`app/src/editor/plan/hover.ts:80-85`; `drawing/build.ts:180`). Every selection user must then cope with a room id. EZD-217 already skips rooms (P217 `copyItems`, test C5). EZD-212b moves walls and openings only (P212b D7 `moveModels`). The inspector's view skips rooms, but its edits refuse an id they do not handle (P213a "Selection ids").
- **The panel.** The tab row, the Layers tab (Phase, Overlays, Rooms) and the Rooms tab with its fields. A device-session layer store holds the Rooms and overlay eyes and every lock. Hiding reaches EZD-214a's canvas filter, and locks go through EZD-5605's `SelectionDeps.selectable?` seam (P5605 D-Selectable). Then the editor wiring, the messages and the browser tests.

**Why cut here.**

- Part b is the panel. It reads part a's room fields and part a's pick index unchanged, and EZD-214a's store through the names EZD-214a's plan fixes.
- Each part is under the size rule: part a about 14 source files and 16 tests, part b about 11 source files and 20 tests.
- Built a → b. Each part is planned as its own unit from its section here, after the questions below are answered and after EZD-214a's plan exists (part b), and applies the planner lessons for its areas. For part a: L-021 and L-049 (the pinned-version tests and room fixtures listed above, each a test-author edit row), L-042 (fixtures to update for the changed type), L-043, L-052 (every caller of the room-making paths) and L-064. For part b: L-021, L-048 (if any async read is added), L-050, L-054 and L-060 (every eye, lock, tab and row button listed for `expectTouchTargets`), L-062 and L-064.

Tasks and Takeoff are added later as text tabs by EZD-1420 and EZD-1613 (05 Q-0664 "Left panel tabs"; AC-1). What the Versions tab does before EZD-122 (phase 9) is QP-1.
- **Phase rows.** Existing, Demo and New with dots grey `#7a828e`, red `oklch(0.6 0.19 28)` and blue `oklch(0.55 0.17 262)` (`S03Plan.dc.html:82-84`). Their eyes are EZD-214a's `setEye` and eye state. A View switch resets them, and they always show what the canvas shows (05 Q-0667 "Phase eyes after a View switch"; P214 split "Phase store").
- **Rooms is a layer.** It has an eye and a lock like a Phase or Overlay row (00g "Layer": "a Phase row, an Overlay or Rooms … shown, hidden or locked"; PHASES Slice 6 Josh's script step 2 "lock the Rooms layer").
- **Locks.** Each layer row has a lock icon left of its eye (S03 Decisions "The layer filter is a lock icon on each layer row"; 05 Q-0664 "No new board"). Eyes and locks belong to the device session, are not saved and reset on reload (03 Q-0664 "View default"; AC-3).
- **Membership.**
  - An object is in the Phase layer of its `data.status`. A room is also in the Rooms layer. A later object kind joins its overlay when its ticket adds it: Dimensions is EZD-216, a dependent (00g "Overlay").
  - An object is drawn only when every layer it is in is shown.
  - An object can be selected only when none of its layers is locked (AC-2, AC-3; 00g "Eye", "Layer lock").
- **What a lock filters.** A locked object is left out of click, box select, Select all and the hover that shows what a click would select (S03 Canvas "Hover", "Drag on empty space … Respects layer filter", "Ctrl/Cmd+A … visible, selectable layers"; AC-3). Part b passes the lock test through P5605's `selectable` wrapper, combined with the assistant's Adjust filter, so both apply (P5605 D-Selectable, D-Wire).
- **View-only users.** Eyes, locks and the Rooms list work for them without saving. Room edits need Edit model, and a view-only user reads the fields as plain text (05 Q-0664 "Views and permissions"; Q-0630 row 9).
- **Room fields** (03 Q-0664 "Rooms gain …"; S15h line 22; S05 line 32; AC-4, AC-6):
  - `attributes.roomType`: one of `kitchen`, `bath`, `laundry`, `other`, or `null`.
  - `attributes.floorFinish`: free text, `''` when none, until EZD-1611a.
  - `attributes.ceilingType`: one of `flat`, `single_slope`, `vaulted`, `tray`, `coffered`, or `null`.
  - The v4 → v5 step gives every stored room `null`, `''` and `null`.
  - Photos wait for EZD-220 (03 Q-0664).
  - A name may not be blank (`roomDataSchema` `name: z.string().min(1)`, `room.ts:19`).
- **Area in the lists.** Whole square feet, halves up, shown as `{n} sf` (`roomAreaSqFt`, `rooms/area.ts:29`; 09j Room area rows 1-10; board `165 sf`; AC-4).
- **Room picking.**
  - A click first picks walls and openings exactly as now (P208a R5: under the cursor, else within 10 px).
  - Only when there is none does it pick the rooms that hold the point, smallest first.
  - A repeated click cycles outward from a wall to the room (S03 Canvas "Click", "Repeated click … next larger object"; 05 Q-0630 row 7). Rooms go last so that wall picking from inside a room keeps its 10 px capture.
  - Box select (inside or touch) and Select all include the rooms of the open floor (S03 Canvas; AC-5).
- **Selection users.** The inspector is given the selection without room ids, so neither its view nor its edits ever see one (P213a "Selection ids … rooms … view skips them"; CLAUDE.md rule 18). Delete, Copy and Duplicate already skip rooms (P217 C5), and Move moves walls and openings only (P212b D7).
- **Room row click.** It calls `selection.select([id])` (P208a A12, which keeps only selectable ids) and `handle.showObject(id)` (P207b; ARCH Plan canvas "Show"). AC-5 says "a room row", so this holds for rows in the Layers tab and in the Rooms tab.
- **Rooms tab layout.** Rows are styled as the board's Layers > Rooms rows (`S03Plan.dc.html:95-96`). The room that is selected alone shows its fields under its row, in the inspector's field style (S03dWallSelected). There is no board for this, so it follows the nearest Studio board (tickets README rule 5; 05 Q-0664 "No new board"). Rooms are listed for the open floor in stored order, the order P213a uses for room names ("Sub-line rooms … map order").
- **Room edits.** Each committed field is one `store.applyEdit` of one room change, so it is one undo step. Undo and redo follow ARCH "Patch store and outbox". The edit is saved through the existing save route, which parses it (ARCH Model schema "Save rule"), so it survives a reload (AC-4). Text fields commit on Enter or blur and reset on Escape, as P213b D-Length field does. Name and floor finish are trimmed.

### Part EZD-218a · Room fields and selectable rooms
- **Scope:**
  - **Schema v5.** `roomDataSchema.attributes` gains `roomType`, `floorFinish` and `ceilingType`, with exported `ROOM_TYPES` and `CEILING_TYPES`. A `newRoomAttributes(name)` helper returns `{ name, roomType: null, floorFinish: '', ceilingType: null }`. `CURRENT_SCHEMA_VERSION` becomes 5, with `MIGRATIONS[4]` (rooms only; it copies `data` and `data.attributes` and mutates nothing) and `samples/v5.json`. Every room-making path calls the helper: the five above, plus whatever EZD-214b leaves in `sync.ts` (L-052).
  - **Room pick shape.** `PickShape` gains `{ kind: 'ring'; points: readonly Point[]; area: number }`, and `roomPickShape(room)` is added. It returns `null` for fewer than 3 points or zero area, and area is `outlineAreaSqIn`. `shapeDistance`, `shapeBounds`, `shapeInRect` and `shapeTouchesRect` handle `ring` the way `quad` is handled, through `pointInRing` (`shapes.ts`).
  - **Pick index.** Rooms of the open floor are indexed, and EZD-214a's visibility filter applies to them like any object. `pick` puts rooms after walls and openings, as above. `inRect` and `all` include rooms. A new `outline(id)` gives a room's ring.
  - **Look.** The selected and hovered room drawing follows the answer to QP-4, through an outline lookup next to `setBodyLookup` (`hover.ts` `objectGeometry`, `controller.ts`).
  - **Drag from inside a room** follows the answer to QP-5 (`selection-controller.ts` box start, `press.candidates`).
  - **Inspector** gets the selection without room ids (settled above). What it shows for a room selected alone is QP-7.
  - **Docs.** ARCH "Selection (EZD-208)" gets the pick rule with rooms. ARCH "Model schema (EZD-202)" gets version 5 with the room fields.
- **Tests (about 16) and files (about 14 source, plus the pinned-version and fixture edits listed under Why):**

A click inside a room, away from walls, selects the room, and a click within 10 px of a wall still selects the wall. Box select and Select all take rooms.
