# EZD-177 · Fix: repo rule tests refuse pnpm_config_* environment names

- **ACs:** AC-EZD-177-1, AC-EZD-177-2
- **Complexity:** low
- **User-visible result:** The repo's own safety tests now refuse any workflow or package script that sets a `pnpm_config_` name, so dependency install scripts can no longer be switched on past `allowBuilds` that way.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned (Q-0283 is answered (a), so the scope below is decided; Q-0316 is answered (a), a separate fix ticket EZD-182, so it changes no step of this plan)

## 1. What to build

Every file the ticket changes is a test file or docs. `.claude/hooks/guard-paths.mjs` lets only test-author write files under `__tests__/` (`isTest`, line 15; builder rule line 77). So **test-author does steps 1-2** in one commit `test(EZD-177): refuse pnpm_config_ names` (T1 and T2 pass at that commit, because the checker is test code; T3 fails until step 3). **The builder does step 3** (docs only) in `docs(EZD-177): pnpm_config_ rule`. No workflow, `package.json` or `pnpm-workspace.yaml` changes, so PROCESS.md rule 19 (fix mode) is not needed: no guarded file is written.

Claim check (the ticket row asks the planner to do it first): **confirmed.** The `CHANGELOG.md` shipped in the `pnpm@12.14.0` npm package has the `PNPM_CONFIG_GLOBAL_SHIMS` entry at line 658, under the `## 12.8.2` heading, and line 2236 (`## 12.3.0`) names "a `PNPM_CONFIG_*` variable" as a general settings source. A planner probe on 2026-10-24 (pnpm 12.14.0, `pnpm config get <key>` in an empty temp project) showed the following. `PNPM_CONFIG_DANGEROUSLY_ALLOW_ALL_BUILDS=true` and `pnpm_config_dangerously_allow_all_builds=true` both give `true`; `PNPM_CONFIG_ALLOW_BUILDS='{"esbuild":true}'` sets `allowBuilds`; `pnpm_config_ignore_scripts=true` sets `ignoreScripts`. `Pnpm_Config_Dangerously_Allow_All_Builds`, `npm_config_dangerously_allow_all_builds` and `NPM_CONFIG_DANGEROUSLY_ALLOW_ALL_BUILDS` give `undefined`. Since 12.12.0 (CHANGELOG line 147), `dangerouslyAllowAllBuilds` still respects `allowBuilds` `false` entries, but it runs every other build script, including any new dependency's, without the settling Q-0140 (a) requires.

**R1, rule (l), in `checkWorkflow`**, run for every file name:
```
lines.forEach((l, i) => {
  if (l.trim().startsWith('#')) return;
  if (PNPM_CONFIG_RE.test(l)) add('l', `pnpm_config_ name at line ${i + 1}`);
});
```
One problem per line, whatever the number of matches on it. Comment line: `// (l) pnpm settings from environment names (EZD-177; Q-0283 (a))`.

**R2, `pnpmConfigScriptProblems(text)`**, for one `package.json` text, in this order:
1. `JSON.parse(text)` throws, or the result is not a plain object (`null`, an array or a primitive): return `['unreadable']`.
2. `scripts` is absent (`undefined`): return `[]`.
3. `scripts` is `null`, an array or not an object: return `['scripts not an object']`.
4. For each `[name, cmd]` of `Object.entries(scripts)`, in that order: `typeof cmd !== 'string'` pushes `` `script ${name} not a string` ``; otherwise `PNPM_CONFIG_RE.test(cmd)` pushes `` `script ${name}` ``.
5. Return the array.

**R3, `workspacePackageFiles()`**: repo-relative paths with `/` separators. First `'package.json'`; then, sorted with `Array.prototype.sort()`: `app/package.json` and `worker/package.json` when they exist, plus `<d>/<name>/package.json` for each directory entry `<name>` of `packages/` and `spikes/` (`readdirSync(…, { withFileTypes: true })`, directories only) that holds a `package.json`. A missing `packages/`, `spikes/` or `worker/` is skipped. These are the four workspace globs C2 allows (docs/architecture.md Machine checks C2).
