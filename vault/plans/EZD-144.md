# EZD-144 · Fix: error_alert refuses a project without a company

- **ACs:** AC-EZD-144-1 (the insert fails with 23514), AC-EZD-144-2 (existing tests stay green) (`vault/spec/acceptance-criteria.md` lines 287-288)
- **Complexity:** low (section 8)
- **User-visible result:** nothing on screen; the error-alert table can no longer hold a project that belongs to no company, so a later System status page (EZD-135) never shows a project row outside every company.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data: one new migration adds the check constraint `error_alert_project_needs_tenant` = `check (tenant_id is not null or project_id is null)` to `public.error_alert` (ticket row; sweep item 4). No new table, column, policy, grant, function or `schema_version` change. No money field. Why it is needed: the composite foreign key `(project_id, tenant_id) references public.project (id, tenant_id)` (`supabase/migrations/20261023120000_create_error_alert.sql:20`) is MATCH SIMPLE, so with `tenant_id` null it checks nothing, and the existing check `(kind = 'error') = (tenant_id is null)` (line 21) ties only kind to tenant; `record_error_alert` called as `service_role` passes `p_project_id` through unchanged (`20261023120001_create_error_alert_functions.sql:25-40`).
