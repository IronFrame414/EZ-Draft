# EZD-291 · Fix: the EZD-102 D5 permissions realtime test does not depend on fixed waits

- **ACs:** AC-EZD-291-1, AC-EZD-291-2
- **Complexity:** medium
- **Areas:** testing, realtime
- **User-visible result:** none in the app; the live permission-change test stops failing at random.
- Phase: 1 · Planned by: planner · Date: 2026-11-02 · Status: questions

## 1. What to build
Row: phase-01.md:164. Every file is a test or harness file (`.claude/hooks/guard-paths.mjs` `isTest`, lines 29–31).

**Cause** (P1–P4, R-048): local Realtime stops its broadcast stream 10 minutes after it starts (`{:shutdown, :rebalancing}`, tenant region `us-east-1` vs unset node region); its slot is temporary, so `realtime.send` rows written before the next channel join are never delivered, while the joined D5 channel stays `SUBSCRIBED`. A step straddling that moment gets 0 events whatever the wait. **Fix:** a probe broadcast proves the stream live before each step (a join restarts it when the probe is lost); a second probe after the step is the fence (delivery is in commit order); a step repeats once only when the stream provably broke inside it. D5 keeps no fixed sleep.
