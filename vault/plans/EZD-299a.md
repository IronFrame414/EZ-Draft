S1 table `public.sync_conflict` (D-Table): `id uuid primary key default gen_random_uuid()`, `tenant_id uuid not null references public.tenant (id) on delete cascade`, `user_id uuid not null references public.app_user (id) on delete cascade`, `project_id uuid not null`, `object_id uuid not null`, `reason text not null check (reason in ('conflict','invalid','not_editable'))`, `base_seq integer not null check (base_seq >= 0)`, `deleted boolean not null`, `type text check (type ~ '^[a-z][a-z0-9_]*$')`, `schema_version integer check (schema_version >= 1)`, `data jsonb check (jsonb_typeof(data) = 'object')`, check `(deleted and type is null and schema_version is null and data is null) or (not deleted and type is not null and schema_version is not null and data is not null)`, `created_at`, `updated_at timestamptz not null default now()`; `foreign key (project_id, tenant_id) references public.project (id, tenant_id) on delete cascade`; unique index `sync_conflict_project_user_object_key (project_id, user_id, object_id)`; indexes `sync_conflict_tenant_id_idx (tenant_id)`, `sync_conflict_user_idx (user_id, tenant_id)`. RLS on; `sync_conflict_select` to authenticated using the EZD-006 project template `and user_id = (select private.app_user_id())`; `sync_conflict_api_gate` restrictive. `grant select … to authenticated; grant select, insert, update, delete … to service_role`. Comment `'Data model entity: sync_conflict (EZD-299a)'`.

S2 functions (all `language plpgsql security definer set search_path = ''`; first line `perform private.require_api_gate();`; then `v_tenant := private.tenant_id(); v_user := private.app_user_id();` null → `raise … errcode '42501'`; each `revoke all on function public.<fn>(<types>) from public, anon, service_role; grant execute … to authenticated;` (L-016). SQL is "confirm on pinned version" (L-009): the T2-T5 rows run it):
- `record_sync_conflicts(p_project uuid, p_changes jsonb, p_payload jsonb) returns jsonb`: membership claim null → 42501; `p_project` null or `not private.can_see_project(p_project)` → P0002; `p_changes` not an array of 1..1000 strict objects with keys `id` (uuid), `base_seq` (integer 0..2147483647; ≥1 when `deleted`), `reason` (the three), `deleted` (boolean), and, only when not deleted, `type` (pattern), `schema_version` (integer ≥1), `data` (object of at most 131,072 bytes as `octet_length(data::text)`), or an id twice → 22023; `p_payload` not exactly `{count, names, more}` strings with `count = jsonb_array_length(p_changes)::text`, `more` matching `^(0|[1-9][0-9]*)$` and not above count, `names` non-empty → 22023. Then, in change order, `insert … on conflict (project_id, user_id, object_id) do update set reason, base_seq, deleted, type, schema_version, data, updated_at = now()` (id and created_at kept); then `v_note := private.create_notification(v_tenant, v_user, 'sync_conflict', p_project, p_payload, '/projects/' || p_project::text || '?conflicts=open')`. Returns `{ "ids": [row ids in change order], "notification_id": v_note }` (null when `create_notification` returns null).
- `list_my_sync_conflicts() returns jsonb`: the caller's rows (`tenant_id = v_tenant and user_id = v_user`, every project), `order by updated_at desc, id desc`, as a jsonb array (`'[]'` when none; not a set, so PostgREST `max_rows` does not cut it). Per row: `visible = private.can_see_project(project_id)`; `editable` = the `user_permission` `edit_model` granted check of `save_objects` step 3; `reason` = `not_open` when not visible, else `not_editable` when not editable, else the stored reason; keys `id, project_id, object_id, reason, base_seq, created_at, updated_at`, and, only when visible (else all six null): `project_name` (project.name), `client_name` (`customer.name` joined on `project.customer_id`, null when `customer_id` is null), `mine` (`{deleted, type, schema_version, data}`), `saved` (`{updated_seq, deleted, type, schema_version, data}` of the `model_object` row, null when none), and from that same `model_object` row `saved_at` (its `updated_at`) and `saved_by` (`app_user.name` of its `updated_by`, only when a `public.membership` row with `tenant_id = v_tenant` and `user_id = updated_by` exists, else null); no `model_object` row → `saved_by` and `saved_at` null (D-Saved by).
- `delete_my_sync_conflict(p_id uuid) returns boolean`: deletes the row with that id, `tenant_id = v_tenant` and `user_id = v_user` (no scope check, so a not-open row can be removed); true when a row went.
- `save_objects_resolving(p_project uuid, p_lock_epoch bigint, p_changes jsonb, p_resolves uuid[]) returns jsonb`: `v := public.save_objects(p_project, p_lock_epoch, p_changes)` (all its checks and codes); not `saved` → return `v`; `p_resolves` null, empty, holding a null or a repeat, or longer than `jsonb_array_length(p_changes)` → 22023 (rolls the save back); deletes rows `id = any(p_resolves)` of the caller's tenant and user and `p_project` whose `object_id` is among the saved objects; returns `v || jsonb_build_object('resolved', <deleted ids sorted, '[]' when none>)`.
