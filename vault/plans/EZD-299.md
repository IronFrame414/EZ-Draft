# EZD-299 · Conflict list: Keep mine / Keep theirs

## Split proposal
Why: the whole ticket touches about 38 files and needs about 45 tests (count below), over the 20-file and 25-test limits (plan-ticket step 3; Josh 2026-10-22). It splits along its three layers, each a working whole: (a) the server copy, the save route's refusals and the notification; (b) the device: refused changes leave the outbox, Keep mine / Keep theirs / Remove, nothing lost across reloads; (c) the screens: banner, list (board S03b), notification click, Show, and the test page's "make a conflict". Each part is planned in its own unit. Every existing AC moves to the part whose test closes it end to end; parts a and b add ACs for their own layer from their Done-when (orchestrator; `acs_source` is stage-0, so they are added by hand as gen_acs.mjs's header says).

- **ACs:** AC-EZD-299-1 … AC-EZD-299-12 (assigned below)
- **Complexity:** high (each part)
- **Areas:** data-model, migrations, security, api, ui, testing
- **User-visible result:** when someone else saved an object first (or the project or your edit right went away), your change is not lost: it waits in "Changes not saved", on every device, and you pick Keep mine or Keep theirs.
- Phase: 3 · Planned by: planner · Date: 2026-11-07 · Status: split proposal

### EZD-299a · Conflict list: server copy, save refusals and the notification
- Scope: a new table for refused changes, one row per person, project and object (Q-0531, Q-0540: shape a build choice; keyed to user, company, project; only that user reads it; `project_id` foreign key `on delete cascade`, because Delete is permanent, Q-0201), its RLS and tenant-isolation test (tickets README "first ticket whose Scope names a table"), definer functions to record, list and delete rows (TABLE_GRANTS select only, as EZD-120a and EZD-140); routes to list my rows (with the saved value only for projects still open to me, Q-0540, AC-EZD-299-8), to record one drain's refused changes for one project and to delete a row (Remove); a save that names the rows it resolves deletes them in the same transaction as the save (so a row never outlives a successful Keep mine; rule 18); the app version on save requests and the save route's refusal of an older one (Q-0530, Q-0540, the value per QP-2); the `sync_conflict` notification: params, title N1 / N1b (`vault/mockups/S03bConflictList-wording.md`) replacing "Offline changes conflict with newer edits" (`app/src/server/messages/catalogs/en.ts:354`), a link that opens the editor with the list open, one per record call, bell and email per the person's settings (EZD-110a job, EZD-140). Harness edits: TABLE_GRANTS, GATED_RPC_CALLS, PRIVATE_EXECUTE, MONEY_ROUTE_CASES, write exemptions.
- Done when: A recorded refused change is listed for the same user from a second session and after the device's data is gone; another user, and the same user in another company, cannot read it; a row is deleted on Remove and by the save that resolves it (AC-EZD-299-11). One record call for a project makes one `sync_conflict` notification naming the project and every object, in the bell and by email per the user's settings (stub transport) (new AC).
- ACs: AC-EZD-299-11 moves here; three new ACs from the other Done-when sentences.

### EZD-299b · Conflict list: refused changes leave the outbox; Keep mine, Keep theirs, Remove

## 10. Open questions
- Q-0625 (was QP-1): How an object gets its number in "Wall 4" / "Door 2" (Q-0511 b) is not decided: walls, doors and windows store no number (EZD-202 schema; only rooms have a name, "Room N", EZD-205a). Options: (a) a number stored on each object when it is drawn, per type and project, never reused, so the same wall is "Wall 4" on every device and every screen (a schema field; walls already drawn get numbers once, in save order); (b) worked out when shown, by a stable order such as drawing order, so numbers can shift when objects are deleted; (c) no number, the type and a short description ("Wall, 12' 6" long"). Recommended (a).
- Q-0626 (was QP-2): What makes a save "from an older app version" (Q-0540) is not decided, and EZD-134 must use the same value for every other request. Options: (a) a build number fixed at each build (its build time), a save carrying a lower number than the server's (or none) is refused; (b) the commit id, any difference refused (a rollback would then refuse newer devices too); (c) a number raised by hand only when the save format changes. Recommended (a).
- Q-0627 (was QP-3): The notification names every object (board S01c note: "wraps instead of cutting the list short"), but its payload holds at most 4,096 bytes (EZD-110a), about 400 names, and one drain can refuse more. Options: (a) name every object up to what fits, then "and N more"; (b) raise the cap for this kind only; (c) one notification per batch of names that fits. Recommended (a), with "and N more" as new wording for Stage 2.
- Q-0628 (was QP-4): For a row whose project is no longer open to the user (P14b), does the list show the project's name in the Other projects group? Options: (a) yes, the name stored with the row when it was refused (the user saw it before); (b) no, a generic group label (new wording) and no project name from the server, as for the saved value (Q-0540). Recommended (b).
