# EZD-373 · Fix: the plan draws no text on CI, so 9 browser tests fail only on CI

- **ACs:** AC-EZD-373-1
- **Complexity:** medium
- **Areas:** ci, testing, ui
- **User-visible result:** room labels and dimension numbers appear on the floor plan on any computer or tablet that lacks the Arial font (Linux, the CI machine), not only on Macs and iPads.
- Phase: 4 · Planned by: planner · Date: 2026-11-10 · Status: planned

## 1. What to build

**Cause (found at plan time, sources in section 2).**
1. `app/src/styles/fonts.ts` loads both fonts with `next/font/local` and no `adjustFontFallback`, so Next adds a metric-matched fallback face per font whose only source is `local(Arial)` (R-060 point 8). The built CSS in `app/.next` holds `@font-face{font-family:dmMono Fallback;src:local(Arial);…}` and `@font-face{font-family:instrumentSans Fallback;src:local(Arial);…}`, and the variables read `--ez-font-mono: "dmMono", "dmMono Fallback", monospace` (read 2026-11-10 from the local build output).
2. `createGlyphAtlas` (`app/src/editor/plan/glyph-atlas-canvas.ts:64-83`) passes the whole variable to `document.fonts.load('400 40px "dmMono", "dmMono Fallback", monospace')`. Chromium's `FontFaceSet::load` rejects as soon as one matched face fails (R-060 point 1). On Linux, `local()` matches only an installed full or PostScript name, with no alias such as Liberation Sans (R-060 point 4). The Ubuntu runner and Playwright's Ubuntu deps install no Arial (R-060 points 5, 6). So on CI the load rejects, the controller reports `plan.glyph_atlas` (`controller.ts:405-416`), `atlasSet` stays false, and `glyphs` stays 0.
3. The 9 tests started failing together. Develop CI was last green on EZD-205b (run 42270896570). The next product push was EZD-207b, which added the atlas (94299813; its run 42277742601 was cancelled), and every run since has failed (A3-regressions.md A3.1). EZD-120c B1's one extra request matches `/api/` traffic from the atlas error report: the Sentry tunnel is `app/src/app/api/monitoring/route.ts`, and the test counts every `/api/` request (`e2e/editor.spec.ts:109-115`).
4. This is an app bug a user's device can hit. Any browser without a font named Arial gets no plan text. The fix goes in the app (ticket row: "Fix the app when the app is wrong"), not in `.github` or the gate.

**Fix:** the atlas loads and draws only the first family of each font variable, which is the woff2 file the app ships (11 Performance rule 8). A fallback face that cannot load can then never stop the atlas. This closes the whole class (CLAUDE.md rule 18): any non-first face, on any device.
