## 1. What to build
Data: no new table or column; no money field. One new `security definer` function M1 that creates the project through the existing `public.create_project` (P118 M1, unchanged: one permission path, 03b rule 1) and inserts the template's `model_object` rows (P120a M2) in the same transaction (Q-0568 "writes project and walls together"; Q-0203; AC-5). It needs Create projects only, not Edit model (Q-0566). No drop or rename of any object (ARCH Release safety: add before remove), so `create_project` keeps its signature. No `schema_version` change.

M1 (confirm on pinned stack, L-009; `count(` is not used, so no cap-lock entry):
```sql
create function public.create_project_with_objects(p_name text, p_address text, p_type text,
  p_customer_id uuid, p_scope_of_work text, p_objects jsonb)
returns table (project_id uuid, tenant_id uuid)
language plpgsql volatile security definer set search_path = ''
as $$
#variable_conflict use_column
declare v_project uuid; v_tenant uuid; v_floor uuid; e jsonb;
begin
  perform private.require_api_gate();
  select c.project_id, c.tenant_id into v_project, v_tenant
    from public.create_project(p_name, p_address, p_type, p_customer_id, p_scope_of_work) c;
  if p_objects is null or jsonb_typeof(p_objects) <> 'array'
     or jsonb_array_length(p_objects) < 1 or jsonb_array_length(p_objects) > 5 then
    raise exception 'invalid_input' using errcode = '22023'; end if;
  for e in select x from jsonb_array_elements(p_objects) x loop
    if jsonb_typeof(e) <> 'object'
       or (select array_agg(k order by k) from jsonb_object_keys(e) k) <> array['data','id','schema_version','type']
       or jsonb_typeof(e->'id') <> 'string'
       or (e->>'id') !~* '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
       or jsonb_typeof(e->'type') <> 'string' or (e->>'type') not in ('wall', 'room')
       or jsonb_typeof(e->'schema_version') <> 'number' or (e->>'schema_version') !~ '^[1-9][0-9]{0,8}$'
       or jsonb_typeof(e->'data') <> 'object' then
      raise exception 'invalid_input' using errcode = '22023'; end if;
  end loop;
  if (select array_length(array_agg(distinct lower(x->>'id')), 1) from jsonb_array_elements(p_objects) x)
     <> jsonb_array_length(p_objects) then
    raise exception 'invalid_input' using errcode = '22023'; end if;
  select m.object_id into v_floor from public.model_object m
    where m.project_id = v_project and m.type = 'floor' and not m.deleted;
  insert into public.model_object (tenant_id, project_id, object_id, type, data, schema_version, updated_seq, updated_by)
    select v_tenant, v_project, (x->>'id')::uuid, x->>'type',
           jsonb_set(x->'data', '{level}', to_jsonb(v_floor::text)), (x->>'schema_version')::integer, 1,
           private.app_user_id()
      from jsonb_array_elements(p_objects) x;
  return query select v_project, v_tenant;
end $$;
revoke all on function public.create_project_with_objects(text, text, text, uuid, text, jsonb) from public, anon, service_role;
grant execute on function public.create_project_with_objects(text, text, text, uuid, text, jsonb) to authenticated;
```
Header comment cites this plan, Q-0565, Q-0566, Q-0568, L-016. Any exception rolls the whole call back, so a refusal writes no project, floor or object (AC-5).
