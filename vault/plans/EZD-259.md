## 1. What to build
Data: none (no table, migration or `schema_version` change).

What the investigation found (evidence in section 2, E1-E9): the 5 failures were one condition. The Docker daemon refused to start the scratch db container 5 times, about 2.6 s apart (E3, E4). Docker states its reason on a line `Error response from daemon: <reason>` before `failed to start containers: <name>` (E6). EZD-153's note keeps only the last stderr line (`startErrorLine`, `scripts/release/scratch-check.mjs`), so the reason was thrown away, and Docker's own log for that minute has rotated away (E5). The main stack's "restart" in Q-0419 is the normal `db:up` reset (E2). Four causes were tested and ruled out (E7-E9). The cause itself cannot be named from what survives, so this ticket builds the capture that names it, then runs the loop (AC-1). What happens if the loop does not reproduce it is QP-1; the loop length is QP-2. No retry and no longer wait anywhere (ticket row; CLAUDE.md rule 16).

**R1 `cliFailureNotes(step, { stdout, stderr })`**, a pure function:
1. `errorLines`: if `JSON.parse(stdout.trim())` succeeds and its `.error.message` is a string, that string split on `\n`, each line `trim()`med, empty lines dropped; otherwise (parse throws, no `error`, message not a string) `[]`.
2. `stderrLines`: `stderr` split on `\n`, each line `trimEnd()`ed; drop a line whose `trim()` is `''`; drop a line whose `trimStart()` starts with any `START_NOISE` entry (the 3 existing prefixes).
3. `clean(line)` = `redactUrl(line)`, then cut to its first `CLI_NOTE_MAX_CHARS` characters when longer.
4. `summary` = `errorLines[0]`, else the last of `stderrLines`, else `(no stderr)`.
5. Return, in this order: `` `scratch ${step}: ${clean(summary)}` ``; then `errorLines.slice(0, CLI_NOTE_MAX_LINES)` each as `` `scratch ${step} error: ${clean(line)}` ``; then `stderrLines.slice(-CLI_NOTE_MAX_LINES)` each as `` `scratch ${step} stderr: ${clean(line)}` ``.

**R2 `scratchBody` changes** (every other line stays as it is):
1. Pre-start stop: keep its result (`const pre = run(bin, ['stop', '--no-backup', '--workdir', w], …)`, same options). If `pre.status !== 0`: `notes.push(...cliFailureNotes('stop before start', pre))` and return `'scratch_start_failed'`; `start` is not called; the `finally` stop and `rmSync` still run (they are in `finally`, unchanged; lesson L-004).
2. Failed start: replace the one `notes.push(`scratch start: …`)` with `notes.push(...cliFailureNotes('start', started))`.
3. Failed `docker ps`: `notes.push(...cliFailureNotes('docker ps', ps))` before `return 'scratch_start_failed'`.
4. Db container missing: before `return 'scratch_start_failed'`, push `` `scratch start: ${SCRATCH_DB_CONTAINER} is not running; running: ${names.length > 0 ? names.join(', ') : 'none'}` ``, where `names` is the existing filtered list (suffix `_ezdraft-migcheck`, `docker ps` order).
5. Failed service stop: keep the result of `run('docker', ['stop', name], …)`; if `status !== 0`, `notes.push(...cliFailureNotes(`docker stop ${name}`, r))`, then return `'scratch_services_stop_failed'`.
6. Header comment: replace the sentence `Children get only SCRATCH_ENV_NAMES; their output is captured, never printed here.` with `Children get only SCRATCH_ENV_NAMES; their output is captured and printed only as failure notes (cliFailureNotes, EZD-259): URL passwords redacted, at most CLI_NOTE_MAX_LINES lines per source.` (lesson EZD-152, comment restates the rule).

**R3 docs:** in `### Release safety (EZD-023a)`, Scratch database bullet, insert this sentence directly before `A failure prints \`scratch_db_failed: <code>\``: `Before that line the notes give the reason (EZD-259): for a failed pre-start stop, start, \`docker ps\` or service \`docker stop\`, a line \`scratch <step>: <summary>\`, then the CLI's JSON error lines (\`scratch <step> error: …\`) and its stderr lines without the rerun hint and update notice (\`scratch <step> stderr: …\`), at most 20 of each, URL passwords redacted, 500 characters a line; a missing db container prints the containers that are running.`
