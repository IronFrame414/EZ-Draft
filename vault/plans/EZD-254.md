# EZD-254 · Fix: a finished phase is gated even while an earlier phase has a blocked ticket

- **ACs:** AC-EZD-254-1, AC-EZD-254-2 (`vault/spec/acceptance-criteria.md` lines 444-445)
- **Complexity:** low (section 8)
- **User-visible result:** when a phase's tickets are all done or blocked, the launcher gates, waits on and wraps that phase before it starts the next one, even while a ticket of an older, already wrapped phase (EZD-003) is still blocked.
- Phase: 1 · Planned by: planner · Date: 2026-10-28 · Status: planned

## 1. What to build
Cause (read on develop, `vault/tools/next_ticket.mjs` `nextUnit`): the gate loop ends at `if (p > phase) break;` where `phase = currentPhase()`, the lowest phase with a ticket not `done`. EZD-003 (phase 0) is `blocked`, so `phase` is 0, the loop never reaches phase 1, and `workingPhase()` then skips the finished phase 1 and starts phase 2. Proved on a scratch ledger copy (section 4, "Proof"). The fix bounds the loop by the working phase instead (ticket row Scope).
