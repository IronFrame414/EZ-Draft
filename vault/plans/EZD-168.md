**Step 2 SQL** (run on the pinned stack, F1-F3):
```sql
select format('%I.%I(%s)', n.nspname, p.proname, oidvectortypes(p.proargtypes)) as fn,
  exists (select 1 from aclexplode(coalesce(p.proacl, acldefault('f', p.proowner))) x
    where x.grantee = 0 and x.privilege_type = 'EXECUTE') as public_execute,
  r.role, has_function_privilege(r.role, p.oid, 'EXECUTE') as ok
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
cross join unnest(${[...API_ROLES]}::text[]) as r(role)
where n.nspname = 'private'
order by 1, 3
```
Row type `{ fn: string; public_execute: boolean; role: string; ok: boolean }`. `API_ROLES` is bound as a spread copy `[...API_ROLES]` (a mutable `string[]`, the same parameter form as `${ROLES}::text[]` in the `privileges` query).

**Step 2 rules** (in this order; `add(table, code)` with `table` = the `fn` text):
1. For each distinct `fn` in query order: if its rows have `public_execute` true, `add(fn, 'public_executes_private_function')`; then for each role in `API_ROLES` order whose row has `ok` true and whose `PRIVATE_EXECUTE[role]` has no entry with that `fn`, `add(fn, \`${role}_executes_private_function\`)`.
2. For each role in `API_ROLES` order, for each entry of `PRIVATE_EXECUTE[role]` in list order: if no row has that `fn`, that `role` and `ok` true, `add(entry.fn, \`${role}_private_execute_stale\`)`.
3. A function allowed for one role is not allowed for another (rule 1 checks each role against its own list only).
4. No code suppresses another: a function PUBLIC may execute gets `public_executes_private_function` and also one `<role>_executes_private_function` per API role without an entry (T1, T3).
5. Grants and revokes made earlier in the same transaction are seen by the query (`has_function_privilege` reads the transaction's catalog; planner run 2026-10-24: `revoke`, `revoke`, `grant` on `private.tenant_id()` then the query in one transaction gave `anon` true, `authenticated` false).
