## 1. What to build
Finding (gate-failures.log line 7-8, develop 63e5c705): EZD-323 T8 expects 6 non-test `app/src` files naming `createJobsDbClient` and finds 7. The seventh is `app/src/server/jobs/ai-key-rewrap.ts` (added by EZD-5601, cc1832c1; it calls `createJobsDbClient()` at line 26). Planner grep at plan time (`grep -rln createJobsDbClient app/src`, test files excluded) lists exactly the 6 pinned files plus that one.

Decision: the use is needed, so the T8 list adds it with its reason (ticket row option 1). Grounds:
- `public.user_ai_key` grants select/insert/update/delete to `service_role` only and revokes all from `anon` and `authenticated` (`supabase/migrations/20261110120001_create_user_ai_key.sql` lines 33-34; EZD-5601 M1). A publishable-key client reaches no row of it.
- The rewrap runs inside `GET /api/jobs/sweep` (`app/src/app/api/jobs/sweep/route.ts` line 35), a Vercel Cron call with no user session, and must reach every tenant's stale rows: Q-0638 (decisions `05-screens.md` row Q-0638: "Key rotation rewraps every row before the old value is removed"). The per-user definer `rewrap_my_ai_key` is executable by `authenticated` only and takes user and tenant from the claims (`20261110120003_create_user_ai_key_functions.sql` lines 217-218), so it covers rewrap on use (Q-0637, decisions `10-permissions-and-settings.md` row 56) but never a key nobody uses.
- The sweep route is the job runner, not a user request path (`route.ts` header lines 2-3; docs/architecture.md `## Server-only data access and can()`: secret key "used only in job handlers ..."). docs/architecture.md already records "The sweep runs `rewrapStaleAiKeys()` ... with the runner's client" (line 992), so no doc edit.
- EZD-5601's plan section 7 (line 158) asked its security-reviewer to confirm "rewrap runs in the sweep with the secret key"; its STATUS row records review r2 PASS. This ticket's security-reviewer confirms it again (section 7), which AC-EZD-370-1 requires.

No app code changes. The only edit is the test file, which the builder never edits (CLAUDE.md rule 5), so the test-author makes it and the builder only runs the verification.
