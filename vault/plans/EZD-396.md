## 2. Sources
- **Which area Fit fills (the ticket's question).** The sources settle it, so there is no design question for Josh:
  - `vault/spec/sections/04-app-shell-and-global-ui.md` line 3: every editor screen uses one fixed shell made of separate regions: header card, tool rail, left panel, canvas, inspector and status bar. Line 7 gives the inspector its own 336 px and puts a 16 px gap between body regions.
  - `vault/spec/sections/screens/S03-plan-editor.md` Layout: "Canvas: plan with grid; … zoom stack top right" and "Inspector 336px" are separate regions. Controls (canvas interactions): "Zoom in / Zoom out / Fit to screen | Canvas, top right stack | Step zoom; fit model to view". The view is the canvas region the stack sits in.
  - `docs/architecture.md` Editor shell (EZD-012): the body is rail, left panel, canvas and inspector, each its own `data-shell-region`, and the inspector is its own `<aside>`. Plan canvas (EZD-207a): "Screen = region px (CSS px from the top-left of `main[data-shell-region="canvas"]`)". Zoom stack: Fit sits "at the canvas region's top right". Inspector (EZD-213a): from EZD-213b, `InspectorPanel` fills the inspector aside for every viewer of a ready plan (`vault/plans/EZD-213b.md` D-Editor; decisions 05 Q-0630 row 9).
  - Decisions: `vault/spec/decisions/05-screens.md` Q-0568 leaves "Fit on an empty model" to plans and says nothing that makes Fit cover the inspector. `vault/spec/decisions/04-app-shell-and-global-ui.md` has no Fit row. `vault/questions/QUESTIONS-answered.md` and `QUESTIONS.md` have no Fit row.
  - Conclusion: Fit fills the canvas region beside the inspector, so the app is right and the tests' expected value is stale. This is a test structural repair through the reviewer (CLAUDE.md rule 5; `vault/tickets/phases/phase-04.md` EZD-396 row), the same class as EZD-368.
- **Merged code (develop HEAD, read 2026-11-12).** `app/src/editor/plan/view.ts`: `FIT_MARGIN_PX = 48` (line 22). `fitView` (lines 78-98) gives ppi = min((region.width − 2 × 48) / bounds width, (region.height − 2 × 48) / bounds height), clamped to the zoom limits. `app/src/editor/plan/controller.ts` `fit()` (lines 322-324) passes `regionSize()`, the canvas region's size.
- **The failure, worked through.** At the tests' 1600 px wide window, the canvas region was 1600 − 32 (body padding) − 56 (rail) − 16 (gap) = 1496 px, so the fit was (1496 − 96) / 120 = 1400 / 120 = 11.6667 px per inch. That is the literal at `app/e2e/plan-zoom-hover-text.spec.ts` lines 316 (B1) and 394 (B3), and the line-393 comment cites EZD-368. With the inspector aside the region loses 16 (gap) + 336 (inspector) = 352 px, leaving 1144 px, so the fit is (1144 − 96) / 120 = 1048 / 120 = 8.7333. That is exactly the value received in develop CI run 43205322837 and the phase 4 lane gates named in the ticket row. The 120 in model inches is wall W1's length, the same 120 used in `app/src/editor/plan/view.test.ts` U4 bounds `{ minX: 0, minY: -4.5, maxX: 120, maxY: 0 }`.
- **Why it was missed.** `vault/plans/EZD-213b.md` section 4 rows E1-E3 edited the other specs that see the aside (`editor.spec.ts`, `plan-canvas.spec.ts`, `drawing-tools.spec.ts`) but not these two Fit checks.
- **Other Fit checks.** A grep of `app/e2e` and `app/src` for `Fit to screen`, `/ 120, 3` and `ppi).toBeCloseTo` finds only B1 and B3 (lines 316, 394) plus B1's step-zoom checks (lines 300, 305), which do not depend on the region width. `view.test.ts` U4 tests `fitView` with fixed region sizes and is unaffected.
- **Ticket constraints.** Keep the 3-place precision and add no retry (phase-04 EZD-396 row; CLAUDE.md rule 16). Take the expected value from the canvas region, not a literal (phase-04 EZD-396 row).
- **Dependencies.** EZD-213b and EZD-207b (ticket row). Also relevant, though not listed in the row: EZD-368 (2c6d9909) and EZD-379 (3bee5a6b), both merged, last changed this spec file. No screen changes, so there is no visual checklist and EZD-016a is not needed beyond the existing harness.
