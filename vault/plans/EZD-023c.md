### Steps

**Step 1. `scripts/release/vercel-api.mjs`: `createVercelApi` and `evaluateVercelProject`.** Endpoints, fields and error shape from R-005 (Vercel REST docs read 2026-10-19), which corrects the archived plan's deployments path from `/v6` to `/v7` (R-005 item 11). Same pattern as part b's `createGitHubApi` (vault/plans/EZD-023b.md Step 3).
- `createVercelApi({ token, projectId, teamId, fetch })`. Building it sends nothing. Every request:
  - goes to `https://api.vercel.com` plus the path, with `teamId=<teamId>` as the last query parameter (R-005 item 24: `teamId` scopes every endpoint to the team; Q-0031 (a): the project is in EZ Binder's team);
  - sends `Authorization: Bearer <token>` (R-005 item 24) and no other header; ids in paths go through `encodeURIComponent`;
  - throws on a non-2xx status or a rejected `fetch`, with the message `Vercel <METHOD> <path template> failed: <status>` (`network` in place of the status when `fetch` rejects). The path template keeps the placeholders (`/v9/projects/{project}`), so the message never holds the token, project id, team id, deployment id or env id, and never the response body or the original error text, which can carry ids (R-005 item 25: 404 messages name the resource id). *Planner's choice*: the ids are release secrets (vault/plans/EZD-023b.md Step 1 `RELEASE_SECRET_NAMES`) that GitHub masks only as entered; Q-0112 finding 7.
- Methods (all async):
  - `getProject()`: GET `/v9/projects/{project}` (R-005 items 1–2). Returns only `{ autoAssignCustomDomains, ssoProtection, gitForkProtection }` from the body, each `undefined` when absent (*planner's choice*: hold nothing else).
  - `tokenInfo()`: GET `/v5/user/tokens/current`; body `{ token: { expiresAt } }`, milliseconds (R-005 items 9–10). Returns `{ expiresAt }`: the number when it is a finite number, `null` when absent or null; any other type throws.
  - `findProductionDeployment(sha)`: GET `/v7/deployments?projectId=<projectId>&target=production&limit=20&teamId=<teamId>`, parameters in that order (R-005 items 11–13; `limit` 20 is *planner's choice*: the build of a just-merged tip is among the newest). From `deployments[]` it keeps items with `target === 'production'` and `meta?.githubCommitSha === sha` (archived plan Step 6 step 9: "only a production-target deployment whose `meta.githubCommitSha` equals `sha` counts"; R-005 item 14: the key is not in the REST schema, see section 9 Risks). Each match becomes `{ id, state }` with `id = uid ?? id` and `state = readyState ?? state` (R-005 item 13: both state fields exist; the id field name is *builder confirms* on R-005 item 11's page). It returns the first match whose state is `READY`, else the first match (Vercel's order, newest first, *builder confirms*), else `null`. It never sends the `sha` filter, whose matching field the docs do not name (R-005 item 15).
  - `currentProductionDeployment()`: GET `/v9/projects/{project}`; returns `{ id: targets.production.id }` when that is a non-empty string, else `null` (R-005 item 5: `targets` is a map of deployments, but the `production` key is unconfirmed; null is also the first release's value, archived plan Step 6 step 9).
  - `listEnv()`: GET `/v10/projects/{project}/env` without `decrypt` (R-005 item 16). Returns `[{ id, key, target, gitBranch }]` per `envs[]` item, never `value`: the list's `value` can be an encrypted payload even with `decrypt=true` (R-005 items 17–18). When `pagination?.next` is neither null nor undefined it throws, because a second page could hide a Preview entry (*planner's choice*, fails closed; lesson L-006).
  - `readEnvValue(id)`: GET `/v1/projects/{project}/env/{id}` (R-005 item 19). Returns `value` when it is a string and the body has `decrypted === true` or `type === 'plain'`; otherwise `null`. A Sensitive variable is write-only (R-005 item 20), so it gives `null` and the rules report it (*planner's choice of the condition, builder confirms*).
  - `promote(deploymentId)`: POST `/v10/projects/{project}/promote/{deploymentId}` with no body; resolves on any 2xx (R-005 items 21–22: 201 or 202, "does NOT rebuild"). Nothing calls it until EZD-023e (as part b's `createTag`).
- `PROTECTED_DEPLOYMENT_TYPES`: frozen `['all', 'all_except_custom_domains', 'preview', 'prod_deployment_urls_and_all_previews']`, the `ssoProtection.deploymentType` enum (R-005 item 3). Every value protects previews; the docs do not say which one the dashboard's Standard Protection is (R-005 item 6), so all four are accepted and anything else is refused (*planner's choice*; Q-0112 finding 9 asks that previews need a Vercel login, `docs/runbook.md` `## Vercel and the subdomain (EZD-003)` step 4).
- `evaluateVercelProject(project)` (pure) returns `{ ok: true, code: null }` or `{ ok: false, code }` and fails closed (lesson L-006). In this order:
  1. `vercel_auto_assign_on` unless `project?.autoAssignCustomDomains === false` (archived plan Step 2; Q-0123 (b); runbook EZD-003 step 2). A missing field counts as on.
  2. `deployment_protection_off` unless `project.ssoProtection` is an object whose `deploymentType` is in `PROTECTED_DEPLOYMENT_TYPES` (Vercel Authentication on).
  3. `deployment_protection_off` unless `project.gitForkProtection === true` (Q-0112 finding 9; R-005 items 2, 7). A missing field counts as off.
