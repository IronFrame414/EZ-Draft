# EZD-322 · Fix: a project member without See company costs cannot create a supplier file or order report record

- **ACs:** AC-EZD-322-1, AC-EZD-322-2, AC-EZD-322-3
- **Complexity:** low
- **Areas:** security, permissions, storage, testing
- **User-visible result:** a member who may not see company costs can no longer leave a supplier file or order report entry (supplier name and email) on a project; members with the switch, and every other file type, work as before.
- Phase: 1 · Planned by: planner · Date: 2026-11-04 · Status: planned

| D2 How the check reads the switch | `loadPermissionContext(client, v.uploadedBy)` from `../permissions` on the caller's own client, then `can(ctx, 'see_company_costs')` with no target (key only, like Storage policy `K`). `null` ctx or `false` → `throw new StorageError('permission_denied')`. `loadPermissionContext` (`app/src/server/permissions/context.ts` lines 20-40) returns `null` for an rpc error with code `42501` or no row, and throws the rpc error object for any other error code; wrap the call in `try/catch` and turn any throw into `throw new StorageError('storage_unavailable')`. No row insert, no signing happens after a refusal. | ARCH-PE (`loadPermissionContext`, `can`); ARCH-S Cost files (`see_company_costs`, read live, key only); rule 18: the check reads the same token the insert uses, so no caller can pass a wrong context |
