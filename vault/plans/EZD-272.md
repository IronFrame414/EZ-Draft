# EZD-272 · Fix: every unit has a defined step for a classifier refusal or a protected path

- **ACs:** AC-EZD-272-1, AC-EZD-272-2, AC-EZD-272-3
- **Complexity:** high (section 8)
- **Areas:** tooling, scripts, process, security
- **User-visible result:** when a hook, a permission rule or the classifier refuses a tool call, the launcher writes it in the ticket's note and its log, applies the plan's grant and retries once when that clears it, and otherwise sets the ticket aside (or waits) and tells Josh once what was refused and how to clear it; it never stops.
- Phase: 1 · Planned by: planner · Date: 2026-10-29 · Status: questions

## 1. What to build

Terms. **Refusal**: `{ source, agent, tool, target, rel, tool_use_id, text }`; `source` is a hook name (`guard-paths`, `guard-bash`, `guard-agents`), `permissions` (a result `permission_denials` entry with no hook record) or `report` (a unit's `REFUSED:` line). **Recorded** = from the hook log or the result; **reported** = from `REFUSED:` lines. **Ticket unit** = `build` or `plan`; every other unit is **launcher-wide**.
