# EZD-425 plan: security advisories in next, glob and minimatch

Written 2026-11-19 by the overseer session, after a trial of this exact change (branch `trial/EZD-425`, commit 089a02d2). Josh asked for this ticket to be analysed and trialled so it passes on its first attempt. This is a dependency change only: no app code, no tests and no migrations change.

## What is wrong

`pnpm audit --prod` on develop lists four moderate advisories:

| Advisory | Package | Installed | Fixed in | Comes in through |
|---|---|---|---|---|
| GHSA-mfr8-8qww-v76h | next | 16.4.2 | >=16.4.5 | app (direct) |
| GHSA-vc7v-qv4w-wrv8 | next | 16.4.2 | >=16.4.5 | app (direct) |
| GHSA-3g3m-2fjr-6pw4 | glob | 13.0.6 | >=14.0.2 | @sentry/nextjs 11.8.0 → @sentry/bundler-plugins 11.8.0 |
| GHSA-g3hv-75wg-m249 | minimatch | 10.2.6 | >=11.0.1 | glob 13.0.6 (same chain) |

Next.js 16.4.2 also stops `next build` with `SecurityFatalError` ("Your version of Next.js is affected by a known security vulnerability") on some runs. That is why build steps fail at random across lanes, and why it is first in line.

## The change (exactly this; it is what the trial ran)

1. `app/package.json`:
   - `next` 16.4.2 → `16.4.6`
   - `eslint-config-next` 16.4.2 → `16.4.6`
   - `@sentry/browser`, `@sentry/core`, `@sentry/nextjs` 11.8.0 → `11.11.0`
   - Keep the three Sentry packages at one version.
2. Root `package.json`: `eslint-config-next` 16.4.2 → `16.4.6`.
3. Run `pnpm install` at the root to update `pnpm-lock.yaml`. Do not edit the lockfile by hand.
4. `docs/architecture.md` Dependencies table: change the Version cell of the rows for `next`, `eslint-config-next`, `@sentry/nextjs`, `@sentry/core`, `@sentry/browser` and `@sentry/node`. Check C1 reads these rows. `@sentry/node` is the render worker's row and is kept at the same version as `@sentry/nextjs`, per the Error reporting line.

### Why these versions

- **Next.js 16.4.6** is the newest 16.4.x patch. It stays inside the 16.4 line, so no API change. The same bump passed the full gate on lane 3 in the first EZD-424 attempt (its commit 39a13998, lost when EZD-424 was requeued).
- **Sentry 11.11.0** is the first `@sentry/nextjs` whose `@sentry/bundler-plugins` takes glob `^14.0.3`, which brings minimatch 11, so the glob and minimatch advisories go without a pnpm override. Versions 11.9.0 and 11.10.0 still take glob `^13.0.6`. Read from the npm registry on 2026-11-19.
- **No pnpm override is needed.** AC-EZD-425-3's override clause therefore has nothing to list.

## Checks

- `pnpm audit --prod` prints "No known vulnerabilities found". Trial: yes.
- `pnpm why glob --prod -r` shows glob 14.0.6 under @sentry/bundler-plugins 11.11.0. Trial: yes.
- `node scripts/check.mjs` passes in full. Trial: see the result line below.

Trial gate result: **CHECK PASS in 1884s** on lane 3, 2026-11-19. Every step passed: database, typecheck, lint, 3577 unit tests, build (no SecurityFatalError), scripts tests, database again, and 556 e2e tests.

## Do not

- Do not move any other dependency, and do not move to Next.js 16.5 or Sentry 12.
- Do not change a test. The trial passed with no test changes. If a test fails, rerun the check once before changing anything: a failure that goes away on a rerun is load on this Mac, not this change.
- Do not add an override "to be safe".
