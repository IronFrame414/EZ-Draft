# EZD-036 · Fix: test-harness stubs and Sentry diagnostics warnings in the production build

- **ACs:** AC-EZD-036-1, AC-EZD-036-2, AC-EZD-036-3, AC-EZD-036-4
- **Complexity:** medium (section 8)
- **User-visible result:** nothing on screen; the build stops warning about Edge Runtime, the live app no longer loads the email and Sentry test stubs, and the server stops printing the Sentry "server-runtime-injection" line.
- Phase: 0 · Planned by: planner · Date: 2026-10-23 · Status: planned

## 1. What to build

**Cause (E1–E6, section 2).** The four build warnings (E1) are `node:fs` / `node:path` in the two stub files, reached from `instrumentation.ts`'s static imports (`sentry-options.ts`; `report.ts` → `alert-email.ts` → `send.ts` → `transport.ts`) in the Edge Instrumentation build (E3). The stubs also sit in Node entries' eager chunks (E3). The start line (E2) comes from `NodeClient`'s constructor calling `registerDiagnosticsChannelInjection()` unless `enableRuntimeChannelInjection === false` (E4).

**Fix.** (a) Stubs load by `import()` in the stub branch only; (b) `instrumentation.ts` loads its modules by `import()` only when `NEXT_RUNTIME !== 'edge'`; (c) `Sentry.init` gets `enableRuntimeChannelInjection: false`. No new dependency, no tracing, transports behave as before.

Data: none (no table, migration, money field or `schema_version` change).
