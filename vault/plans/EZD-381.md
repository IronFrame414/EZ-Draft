## 1. What to build

**Finding (from merged code at develop 50330d9a and the failing run).** This is a test structural repair, not an app defect.
- Failing run: EZD-212a gate, 2026-11-10 17:35 (`.claude/worktrees/EZD-212a/gate.log:11471-11507`). B9 failed at `app/e2e/selection.spec.ts:602:39` with `Expected: 14`, `Received: 17`. So `before` was 14 and the count after the hover moves was 17: 3 commits landed in the window. The ticket title gives the two numbers the wrong way round; nothing below depends on that. The failure's trace stayed in `/Users/ezdraft/gate/lane1/tree/app/test-results/` (the ezdraft user's folder; no access, KNOWN-LIMITS "gate's checks run as the ezdraft user").
- Hover has no React path:
  - `onHover` → `updateHover` → `scene.setHighlight` → `redraw` (`app/src/editor/plan/controller.ts`, `updateHover` and `attachSurface` `onHover`).
  - In Select mode, the picker is a pure lookup (`app/src/editor/selection/selection-controller.ts`, `const picker`).
  - The only cursor listener, `PlanStatus`, writes `textContent` (`app/src/editor/status/PlanStatus.tsx`, `handle.onCursorChange`; same finding as EZD-379 section 1).
  - Spec 11 rule 4 (no React render per pointer move) holds.
- The 3 commits come from the autosave of B9's own `addSel` edit (3 objects):
  - `__ezdraftEditor.edit` → `store.applyEdit` → `onCommit` → `sync.enqueue` → status `pending` → `schedule(debounceMs)`, with `DEFAULT_DEBOUNCE_MS = 2000` (`app/src/editor/ProjectEditor.tsx` test hook; `app/src/editor/editor-session.ts` `onCommit`; `app/src/lib/outbox/outbox-sync.ts` `enqueue`; spec 11 rule 1).
  - The save then sets `saving`, calls `onSaved` (`store.applySavedNumbers`), sets `failures: 0` and finally `saved` (`outbox-sync.ts` drain loop).
  - Each set re-renders React: `SaveStateText` reads `status` (`app/src/editor/SaveStatus.tsx`), and `useConflictInputs` reads the whole sync state through `useSyncExternalStore` (`app/src/editor/conflicts/use-conflicts.ts`).
  - B9 reads `before` (line 600) without waiting for that save. When the steps between `addSel` (line 580) and line 600 take less time than the debounce plus the save's round trip, the save's commits fall inside the window.
- B5 has the same exposure: `addSel` at line 413, then `stableCommits` and `commits` reads at lines 454-483. It is fixed here in place (Decided D-B5).
- The fix is the file's own `saved` helper (`selection.spec.ts:88-89`: `save-state` text `Saved just now`, 15 s), which B10 already calls right after `addSel` (lines 613-614). The text `Saved just now` appears only after a real save, because status `idle` reads `Saved` (`app/src/editor/save-state.ts` `saveWord`). `saved` is the drain's last set, and the save word's next change comes 60 s later (`nextSaveWordChangeMs`), so no commit from this save comes after the wait.
- Step 1 (probe) checks this finding on fresh runs before Step 2 is written (D-Find).
