# EZD-192 · Fix: the net-guard browser test EZD-159 T7 does not fail at random

- **ACs:** AC-EZD-192-1, AC-EZD-192-2
- **Complexity:** low (section 8)
- **User-visible result:** none in the app; a failing gate no longer names a browser test that passed as failing, so agents stop chasing failures that did not happen.
- Phase: 1 · Planned by: planner · Date: 2026-10-26 · Status: questions

## 1. What to build

### Cause (AC-EZD-192-2; found at planning from primary artifacts)
T7 did not fail. `scripts/gate.mjs` line 152 (`isFailing`) counts every output line holding `✘` as a failing test. Playwright 1.64.1's list reporter prints `✘` for every result whose status is not `passed`, coloured green when the status is the expected one (`node_modules/.pnpm/playwright@1.64.1/node_modules/playwright/lib/runner/index.js` lines 5011-5016); the gate runs without a terminal, so the colour is lost. T7 calls `test.fail()` (`app/e2e/net-guard.spec.ts` line 41), so every correct run of T7 prints `✘`. The gate extracts failing lines only when a step exits non-zero (`scripts/gate.mjs` lines 146-160). Evidence: develop gate run 2026-10-26 08:15 (`gate.log` line 4613 `✘ 8 [desktop] › … EZD-159 T7 … (135ms)`, line 4661 `51 passed`; `app/test-results/.last-run.json` `"status": "passed"`; `app/test-results/net-guard-EZD-159-net-guar-c44b2--a-live-host-fails-the-test-desktop/error-context.md`: `Error: Live network blocked in browser tests: api.anthropic.com`, the fixture's own error). In the EZD-167 run the stale Kong templates made 7 sign-in tests fail (Q-0339), so `test:e2e` exited 1 and the extractor listed T7's expected-failure line next to them; the later runs were green, so nothing was extracted. The stale-Kong state is linked to T7 only through that exit code. The same mis-listing hits EZD-021 T14 (a) and (b) (`test.fail()`, lines 15 and 23) in any full-scope run with another browser failure.

Fix: drop `✘` from `isFailing`. Playwright's unexpected results stay listed through the numbered failure header `  1) [desktop] › …` (matched by the existing `/^\s+\d+\)\s/`), which Playwright prints only for unexpected, flaky and interrupted results (`lib/runner/index.js` lines 1258, 1278-1281, 1467-1469); Vitest (`FAIL`, `×`) and node:test (`✖`) marks are unchanged. Nothing about T7, the fixture or the Playwright config changes, so no check is retried or loosened.
