### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| Which units get fix mode | Only `EZD_UNIT_ID` matching `^repair-(check\|waiting\|ci\|probe)$`, only while `vault/handoff/LAUNCHER_FIX.md` exists, only for a path listed under its `## Paths` heading (a `- path` bullet; a trailing `/` lists a folder). Interactive fix mode (no `EZD_UNIT_ID`) is unchanged. Other units still get none. | decision (2) |
| Who writes LAUNCHER_FIX.md | Interactive sessions and repair units; any other launcher unit is denied. | decision (2) |
| Never writable by a repair unit, even when listed (the hard limits) | `.claude/hooks/` (read, shell and path guards, secret-paths, lib), `.claude/settings.json`, `.claude/settings.local.json`, `.claude/skills/repair/`, `.claude/agents/code-reviewer.md`, `.claude/agents/security-reviewer.md`, `scripts/unit-sandbox.json`, `scripts/gate.mjs`, `scripts/gate-summary.mjs`, `scripts/launcher-idle.mjs` (holds this list), `.github/`, any `package.json`, any test file (guard-paths `isTest` pattern), `.env` files, Josh-only files. One list, `repairForbidden` in scripts/launcher-idle.mjs, used by the hook and the launcher, so the two cannot drift. A `.claude/worktrees/<name>/` prefix is stripped first. | decision (3), CLAUDE.md rule 18 |
| Bash bypass | guard-paths sees Edit and Write only, so the launcher checks after every repair: the files in the repair's commits (`git diff --name-only <head before>..HEAD`) and the uncommitted files that are new or changed since before. Any forbidden file: revert the repair's commits (`git revert --no-edit <before>..HEAD`), restore or delete forbidden uncommitted files, push develop when a reverted commit had reached origin/develop, verdict `refused`. A revert that fails is aborted and the launcher writes vault/handoff/STOP and notifies (a safety stop, not a question). | decision (3) |
| Fix mode left open | A LAUNCHER_FIX.md that did not exist before the repair is removed by the launcher after it. One that existed (an interactive fix) is left alone, and the skill then makes no guarded change. | decision (2) |
| What reaches Josh | After a repair the launcher notifies only for `JOSH: design: …` or `JOSH: ui: …`. Any other `JOSH:` line becomes `failed` ("not a design or UI question: …"). `failed` and `refused` are not sent (no "repair failed" notification); state stays `repair-failed` as before. EZD-250 T6 and T7 change with this. | decision (1), standing rule 2026-11-05 |
| Daily log | The launcher (not the skill) appends one line per repair to `vault/handoff/overseer-log.md`: `- <ISO time> repair <kind>: <VERDICT>: <line>` plus `; commits <sha>..<sha>` and `; files: <list>` when the repair committed. Header `# Overseer log` written when the file is new. | decision (4) |
| Probe (dry run) | `vault/handoff/REPAIR_PROBE.md` present while the next unit is a `none:` wait and STOP is absent: the launcher removes it and runs `/repair probe` once. No repair-state file, no repair count, no "same wait" check, nothing sent. The skill edits `scripts/launcher/fix-mode-probe.txt` in fix mode and leaves the edit uncommitted for the session that asked to check and revert. | task step 5 |
| Auto-merge | `.claude/settings.json`: `Bash(gh pr merge *)` moves from `ask` to `allow`; guard-bash still refuses a merge without `--auto`. | Q-0261, CLAUDE.md rule 11 |
