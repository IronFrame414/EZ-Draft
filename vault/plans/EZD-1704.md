# EZD-1704 · Backups

- **ACs:** AC-EZD-1704-1, AC-EZD-1704-2, AC-EZD-1704-3 (`vault/spec/acceptance-criteria.md`, Stage 0)
- **Complexity:** medium (section 8)
- **User-visible result:** Josh can run `pnpm backup:check` to see whether the nightly file copy and the weekly database copy are current; a daily GitHub workflow runs the same check and GitHub emails him when it is red (Q-0301 (b)); and the restore drill is proved again in every phase-1 gate run on a fresh dump.

## 1. What to build

Data: no migration, no new table. Reads `public.backup_run` (EZD-025, `supabase/migrations/20261023140000_create_backup_run.sql`): a succeeded row always has `finished_at` (constraint `backup_run_finished_check`). No money.

Three parts. (A) A backup check, `scripts/backup/check.mjs`, that reads the newest succeeded `files` and `db_dump` rows and fails when either is not current (Q-0232: current = nightly copy < 26 h and weekly dump < 8 days). (B) A phase-1 re-run of EZD-025's drill on a fresh dump in the same test file as EZD-025's drill, which also runs the check. (C) A daily scheduled workflow `.github/workflows/backup-check.yml` in the GitHub environment `release` that runs `pnpm backup:check` against production, so a red run makes GitHub email Josh (Q-0301 (b); modelled on `backup-db.yml`), with the list edits in EZD-002 T2 and EZD-025 T11 (D18).

`CheckResult` = `{ ok: boolean, kind: 'backup_check', code?: string, stale: string[], files_succeeded_at: string | null, db_dump_succeeded_at: string | null }`; times are `Date.prototype.toISOString()` or `null`; `code` is present only when `ok` is false. Key order as written.

`runCheckCli` order (each step that ends the run prints one line `JSON.stringify(result)` through `stdout` and returns; nothing else is printed):
1. `parseArgs` with `strict: true`, options `local` (boolean, default false), `env-file` (string), `only-bucket` (string, multiple). A parse error, or `local` together with `env-file` → `usage`.
2. `checkLocalGuards({ processEnv, isTTY, envFile, repoRoot })` (`./local-guards.mjs`); not ok → its `code` (`agent_refused`, `ci_refused`, `tty_required`, `env_file_not_absolute`, `env_file_in_repo`). It returns ok when `envFile` is undefined.
3. `env` = `deps.loadEnvFile(envFile)` when `env-file` is given (a throw → `env_file_unreadable`), else `processEnv`.
4. Without `local`: `env.BACKUP_SOURCE_DB_URL` undefined, null or blank after trim → in GitHub Actions (`processEnv.GITHUB_ACTIONS === 'true'`, the signal `environment.mjs` line 7 reads) the refusal line with `code: 'not_configured'` and exit **0**; otherwise `env_missing`, exit 1 (D11). `makeSource` and `github` are not called. With `local` nothing is checked here.
5. `rule = await checkBackupEnvironment(processEnv, github)` (`./environment.mjs`, as `db.mjs` lines 135-136; `github` from `CheckDeps`); outside Actions it returns ok without calling `github`; not ok → `environment_unprotected`, exit 1; `makeSource` is not called. It runs before any value is used (step 4 reads only whether the name is set; Q-0112 finding 2).
6. `cfg = deps.loadConfig(env, { kind: 'db', local })`; `source = deps.makeSource({ dbUrl: cfg.sourceDbUrl })`. With `local` the real `loadBackupConfig` ignores `env` and takes `DB_URL` from `supabase status -o json` of the running local stack (`config.mjs` lines 42-50, 57-62); it needs no env name. A throw from `loadConfig` or `makeSource` → `internal_error`.
7. `filesScope` = `'all'` when `only-bucket` is absent or empty, else `` `buckets:${[...ids].sort().join(',')}` `` with the ids exactly as given: no dedupe, no rejection of an empty id (`--only-bucket ''` gives the scope `buckets:`, the array being non-empty), because the scope must equal the string `runFileBackup` wrote (`files.mjs` lines 36-37, 192). Call `source.lastSucceededAt('files', filesScope)`, then `source.lastSucceededAt('db_dump', 'all')`. A throw → `source_unavailable`. `source.close()` is awaited in a `finally` in every case where `source` was made; a throw from `close()` is swallowed, so the decided result stands (the read is complete).
8. `evaluateBackupCurrency({ filesSucceededAt, dbDumpSucceededAt, now: deps.now() })`. `stale` empty → `{ ok: true, kind, stale: [], files_succeeded_at, db_dump_succeeded_at }`, exit 0; else `ok: false`, `code: 'backup_stale'`, exit 1.

Every refusal in steps 1-7: `{ ok: false, kind: 'backup_check', code, stale: [], files_succeeded_at: null, db_dump_succeeded_at: null }`, exit 1, except `not_configured` (same line, exit 0, step 4). `runCheckCli` wraps steps 3-8 in one `try`; any other throw → the refusal line with `code: 'internal_error'`, exit 1. Main block: `runCheckCli({ argv: process.argv.slice(2), processEnv: process.env, isTTY: Boolean(process.stdin.isTTY && process.stdout.isTTY) })`; an uncaught throw prints the refusal line with `code: 'internal_error'`; `process.exitCode` = the exit code.
