# EZD-165 · Fix: membership end-sessions trigger covers user and company changes

- **ACs:** AC-EZD-165-1 (`vault/spec/acceptance-criteria.md` line 321)
- **Complexity:** low (section 8)
- **User-visible result:** if a membership is ever moved to another person (or to another company, where the database allows it, section 1 Decided), everyone it touched is signed out and gets fresh access on their next sign-in, so nobody keeps access they no longer have.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data: no table, column, policy or `schema_version` change. One new migration redefines the trigger function `private.membership_end_sessions()` (trigger `membership_end_sessions`, `after update or delete on public.membership`, unchanged). No money fields.

Function body after this ticket (the only logic change is the second `if`; the first `if` is the merged body of `supabase/migrations/20261020104902_membership_end_sessions_skip_invite_accept.sql` with the two identity clauses added):

```sql
begin
  if tg_op = 'DELETE'
    or (new.status is distinct from old.status and not (old.status = 'invited' and new.status = 'active'))
    or new.scope is distinct from old.scope
    or new.user_id is distinct from old.user_id
    or new.tenant_id is distinct from old.tenant_id
  then
    perform private.end_user_sessions(old.user_id);
  end if;
  if tg_op = 'UPDATE' and new.user_id is distinct from old.user_id then
    perform private.end_user_sessions(new.user_id);
  end if;
  return null;
end
```
