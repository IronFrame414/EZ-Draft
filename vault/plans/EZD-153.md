# EZD-153 · Fix: migration check flags objects created in dynamic SQL

- **ACs:** AC-EZD-153-1, AC-EZD-153-2
- **Complexity:** medium (section 8)
- **User-visible result:** the release safety check now refuses a migration that creates a table, function or column inside text the check cannot read (`execute '…'`, a function body, SQL built at run time, `select … into`), so a later release can never drop something production still uses without the check noticing.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned · Revised 2026-10-25 after review rounds 1 (**R1-R3**: test placement, comments in bodies, `sql` bodies) and 2 (**R4**: the scan matches tokens and fails closed; E-strings and string settings refused; PL/pgSQL the only proven exemption)

## 1. What to build

Data: none (no table, migration or policy). Short names: `scan` = `scripts/release/sql-scan.mjs`; `check` = `scripts/release/check-migrations.mjs`; "body" = a token of type `string` or `dollar` from the existing lexer (`scan` `lex`, from line 28), its `value` being the text inside the quotes.

The hole (sweep item 21): `findDefined` builds the released-object set from static SQL only, so an object created inside a body (or by `select … into`, or as a `create schema` element) is missing from it, and a later drop of it passes M1. Fix: every way of creating an object the scan cannot read is M4 (E1-E3 show each one creates a real object on the pinned PostgreSQL 17.11). With no release tag yet, the create reasons are also checked on every migration, so nothing created invisibly before launch is released at the first tag (E4: today's 33 migrations have none).

**Step 2 rules (R4).** The scan matches tokens, never regex text: `tokens = tokenize(stmt)`; a body is a token of type `string` or `dollar`; `tokenize` drops `ws` and `comment` tokens, so a comment or any whitespace PostgreSQL accepts between two keywords (E10 W1-W6, C1-C16) leaves two word tokens, and `lex` reads every string, identifier, comment and dollar form (E10 D1-D4).
0. **Lexer and splitter.** (a) `lex` line comment (worktree line 44): ends at `\n` or `\r` (PostgreSQL ends `--` at either; E10 C14). (b) `splitStatements` and `stripComments`: a `comment` token contributes one space `' '` (today `''`), so `create/*c*/table` stays two words for `findDefined`, `findDestructive` and every rule below (E10 TL1-TL3: today both return `[]` for it, an M1 hole of the released check). The 45 migrations still split into 258 statements and the existing sql-scan tests pass (E10).
1. **Lists** (exact): `CREATE_KINDS = ['table', 'view', 'function', 'procedure', 'type', 'domain', 'schema', 'sequence', 'extension']`; `CREATE_MODIFIERS = ['or', 'replace', 'unlogged', 'recursive', 'global', 'local', 'temp', 'temporary']`; `TEMP_WORDS = ['temp', 'temporary']`; `CONSTRAINT_WORDS = ['constraint', 'primary', 'unique', 'foreign', 'check', 'exclude']`; `DROP_KINDS = [...CREATE_KINDS, 'column', 'attribute']`; `RENAME_WORDS = ['to', 'column', 'value', 'attribute']`; `STRING_SETTINGS = ['standard_conforming_strings', 'backslash_quote']`; `REASON_ORDER = ['cascade', 'dynamic', 'dynamic_create', 'dynamic_sql', 'hidden_create', 'string_escape']`. `isBody(t)`: `t` defined and of type `string` or `dollar`. `isKindAt(toks, j, kinds)`: `toks[j]` is the word `materialized` ? `toks[j+1]` is the word `view` : `toks[j]` is a word whose value is in `kinds`.
2. **`bodyTokens(text)`**: `tokenize(text)` with each run of consecutive `string` tokens merged into one `{ type: 'string', raw: <raws joined>, value: <values joined> }` (PostgreSQL joins string constants separated by a line break; merging without checking for the break is stricter; E10 S1-S6).
3. **`hasCreateSequence(toks)`** (the `dynamic_create` forms): for each `k`: (i) `toks[k]` is the word `create`: `j = k + 1`, `temp = false`; while `toks[j]` is a word in `CREATE_MODIFIERS`: if it is in `TEMP_WORDS` then `temp = true`; `j++`; then `!temp && isKindAt(toks, j, CREATE_KINDS)` → true; (ii) `toks[k]` is the word `add` and `toks[k+1]` the word `column` → true; (iii) `toks[k]` is the word `alter` and `toks[k+1]` the word `table`: for `j` from `k + 2` while `toks[j]` exists and is not of type `semi`: `toks[j]` is the word `add` and `toks[j+1]` exists and is not a word in `CONSTRAINT_WORDS` → true. End → false.
4. **`hasDropSequence(toks)`** (the `dynamic` forms, the same as `DYNAMIC_RE`): for each `k`: `toks[k]` is the word `drop` and `isKindAt(toks, k + 1, DROP_KINDS)` → true; `toks[k]` is the word `rename` and (`toks[k+1]` is a word in `RENAME_WORDS`, or `isNamePart(toks[k+1])` and `toks[k+2]` is the word `to`) → true; `toks[k]` is the word `set` and `toks[k+1]` the word `schema` → true. End → false.
5. **`hasStringEscape(toks)`** (the `string_escape` forms; escapes are never decoded): for each `k`, `t = toks[k]`: `t` is a `string` whose `raw` matches `/^[Ee]'/` and includes `\` → true; `t` is the word `u`, `toks[k+1]` the punct `&` and `toks[k+2]` a `string` or `ident` → true (`U&'…'`, `U&"…"`); `t` is a word in `STRING_SETTINGS` → true; `t` is a `string` whose `value.trim().toLowerCase()` is in `STRING_SETTINGS` → true; `t` is the word `set_config` and `toks[k+1]` the punct `(`: true unless `toks[k+2]` is a `string` and `toks[k+3]` the punct `,` (a built setting name). End → false. An `E'…'` with no backslash reads as a plain string and is scanned as one (E10 N3).
6. **`isPlpgsql(tokens)`** (the only exemption, and it must be proven): walk `tokens` with `depth` (`(` +1, `)` −1) and collect `tokens[i+1]` for every `tokens[i]` that is the word `language` at `depth === 0`. `tokens[0]` is the word `do` and nothing collected → true; exactly one collected, of type `word`, `ident` or `string`, with `value === 'plpgsql'` → true (`lex` lower-cases words; an `ident` or `string` must read exactly `plpgsql`, as PostgreSQL reads them); anything else → false (`sql`, `"sql"`, `'sql'`, no clause, two clauses, `language` only inside parentheses).
7. **`scanBody(value, plpgsql, out)`**: `toks = bodyTokens(value)`; `hasDropSequence(toks)` → `out.add('dynamic')`; `hasCreateSequence(toks)` → `out.add('dynamic_create')`; `!plpgsql` and some `s` of `splitStatements(value)` has `hidesCreate(tokenize(s))` → `out.add('hidden_create')`; `hasStringEscape(toks)` → `out.add('string_escape')`; for each `t` of `toks` with `isBody(t)`: `scanBody(t.value, false, out)` (a nested literal is plain SQL whatever the outer language; recursion ends because each value is shorter than its token).
8. **`hasBuiltExecute(text)`** unchanged from round 1: `hasBuiltExecute(value)` is true for any body (called on each body's `value`, never on the statement text: a statement that is itself `execute <name>` runs a prepared statement, and PREPARE takes no DDL, E7). `hasBuiltExecute(text)`: `toks = tokenize(text)`; for each index `k`: if `toks[k]` is a body and `hasBuiltExecute(toks[k].value)` → return true (nested bodies; each value is shorter, so it ends); if `toks[k]` is not the word `execute` → next; if `toks[k+1]` is the word `on`, `function` or `procedure` → next (privilege and trigger words); `literal` = `toks[k+1]` exists and is a body; `ends` = `toks[k+2]` is undefined, or of type `semi`, or the word `into` or `using`; if not (`literal` and `ends`) → return true. After the loop return false.
9. **`hidesCreate(tokens)`** unchanged from round 1 (leading `(` dropped; `explain` → true; `create schema … create` → true; `select`/`with` … `into` at depth 0 with the first `QUERY_VERBS` word `select` → true; `QUERY_VERBS = ['select', 'insert', 'update', 'delete', 'merge']`).
10. **`findUnverifiable(stmt)`**: `tokens = tokenize(stmt)`; `out = new Set()`; the existing `cascade` code unchanged (adds `'cascade'`); floor: for each body `t` of `tokens`, `v = t.value.toLowerCase()`: `DYNAMIC_RE.test(v)` → `out.add('dynamic')`, `DYNAMIC_CREATE_RE.test(v)` → `out.add('dynamic_create')` (both regexes kept with their text unchanged so no match of today is lost, Q-0156 (a); the token rules are the check); `plpgsql = isPlpgsql(tokens)`; `stmtToks = bodyTokens(stmt)`; for each body `t` of `stmtToks`: `scanBody(t.value, plpgsql, out)`; some body `t` of `stmtToks` with `hasBuiltExecute(t.value)` → `out.add('dynamic_sql')`; `hidesCreate(tokens)` → `out.add('hidden_create')`; `hasStringEscape(stmtToks)` → `out.add('string_escape')`; return `REASON_ORDER.filter((r) => out.has(r)).map((reason) => ({ reason }))`.
11. **Why plpgsql is the exemption** (E10 L1-L11; E9 P2, P5, P14): PL/pgSQL `select … into` and `explain … into` take only variables and `execute 'select … into'` is refused; `do` runs PL/pgSQL unless it names a language, and `sql` cannot run inline. Every other body is scanned with `hidesCreate`; the 7 plpgsql bodies with `select … into <variable>` in the 45 migrations stay clean (0 hits).
