# EZD-153 · Fix: migration check flags objects created in dynamic SQL

- **ACs:** AC-EZD-153-1, AC-EZD-153-2
- **Complexity:** high (section 8)
- **User-visible result:** before a release changes production, the migration check now runs the new migrations on a throwaway database and refuses any that really drop or rename something the last release reads, or create something the check cannot read, however the SQL is spelled.
- Phase: 1 · Planned by: planner · Date: 2026-10-27 · Status: planned · Re-plan for Q-0334 (b) (replaces R1-R5).

## 1. What to build

Design (Q-0334 (b)): the database is the reader. With a base tag, at least one new migration and no M3, `check-migrations.mjs` builds a scratch Supabase stack from the base tag's migrations, stops every service container except Postgres, reads the catalog (S0), then applies the new migrations one file at a time with `supabase migration up --local` (the CLI applier prod's `db push` uses; architecture `### Environments and releases` step E), reading the catalog after each. Catalog identity is the object id (oid, column = `<rel oid>:<attnum>`), so a rename, a move and a drop-and-recreate all show. The static check (`checkMigrations`, M1-M5) stays exactly as on develop (AC-EZD-153-2); the scratch adds M1 and M4 lines. Start the build from develop: nothing from the R1-R5 commits on `t/EZD-153` is kept (Q-0334 (b); STATUS EZD-153).

No data, no migration, no table.

### `SNAPSHOT_SQL` (exact text; run on the pinned stack, PostgreSQL 17.11 / CLI 2.121.0, 2026-10-27)
```sql
with sch as (
  select oid, nspname from pg_namespace
  where nspname not in ('pg_catalog', 'information_schema', 'pg_toast')
    and nspname !~ '^pg_(toast_)?temp_'
), skip as (
  select classid, objid from pg_depend where deptype in ('e', 'i')
), rel as (
  select c.oid, c.relkind, s.nspname, c.relname from pg_class c join sch s on s.oid = c.relnamespace
  where c.relkind in ('r', 'p', 'f', 'v', 'm', 'S')
    and not exists (select 1 from skip k where k.classid = 'pg_class'::regclass and k.objid = c.oid)
), obj as (
  select 'schema' as kind, s.nspname as name, 'n' || s.oid as id, '' as owned_by from sch s
    where not exists (select 1 from skip k where k.classid = 'pg_namespace'::regclass and k.objid = s.oid)
  union all
  select case r.relkind when 'v' then 'view' when 'm' then 'materialized_view' when 'S' then 'sequence' else 'table' end,
    r.nspname || '.' || r.relname, 'c' || r.oid,
    coalesce((select tr.nspname || '.' || tr.relname || '.' || a.attname from pg_depend d
      join rel tr on tr.oid = d.refobjid
      join pg_attribute a on a.attrelid = d.refobjid and a.attnum = d.refobjsubid
      where r.relkind = 'S' and d.classid = 'pg_class'::regclass and d.objid = r.oid
        and d.refclassid = 'pg_class'::regclass and d.deptype = 'a' limit 1), '')
    from rel r
  union all
  select 'column', r.nspname || '.' || r.relname || '.' || a.attname, 'c' || r.oid || ':' || a.attnum, ''
    from rel r join pg_attribute a on a.attrelid = r.oid
    where r.relkind <> 'S' and a.attnum > 0 and not a.attisdropped
  union all
  select case p.prokind when 'p' then 'procedure' else 'function' end, s.nspname || '.' || p.proname, 'p' || p.oid, ''
    from pg_proc p join sch s on s.oid = p.pronamespace
    where not exists (select 1 from skip k where k.classid = 'pg_proc'::regclass and k.objid = p.oid)
  union all
  select case t.typtype when 'd' then 'domain' else 'type' end, s.nspname || '.' || t.typname, 't' || t.oid, ''
    from pg_type t join sch s on s.oid = t.typnamespace
    where t.typtype in ('b', 'c', 'd', 'e', 'r', 'm')
      and not exists (select 1 from skip k where k.classid = 'pg_type'::regclass and k.objid = t.oid)
  union all
  select 'extension', 'public.' || x.extname, 'x' || x.oid, '' from pg_extension x
)
select coalesce(json_agg(json_build_object('kind', kind, 'name', name, 'id', id, 'ownedBy', owned_by) order by id), '[]') from obj;
```

### `runScratchCheck` steps (all synchronous; every child gets `env: scratchEnv(deps.env)`)
1. `deps.lock(body)`; `{ ok: false }` returns `{ violations: [], notes: [], failure: 'scratch_db_lock_timeout' }` and runs nothing.
2. `w = mkdtempSync(path.join(deps.tmpRoot, 'ezd-migcheck-'))`; create `w/supabase/migrations`; copy `SCRATCH_CONFIG_PATH` to `w/supabase/config.toml`; write each `input.released` entry to `w/supabase/migrations/<name>`.
3. `run(supabaseBin, ['stop', '--no-backup', '--workdir', w], { cwd: w, timeoutMs: 120000 })`, status ignored (leftovers).
4. `run(supabaseBin, ['start', '--exclude', MIGCHECK_EXCLUDE.join(','), '--workdir', w], { cwd: w, timeoutMs: 600000 })` (no `--ignore-health-check`: the probe started with exactly these flags, exit 0); status ≠ 0: failure `scratch_start_failed`, note `scratch start: <last non-empty stderr line, or (no stderr)>`.
5. `run('docker', ['ps', '--format', '{{.Names}}'], { timeoutMs: 120000 })`; names = lines ending `_ezdraft-migcheck`. `SCRATCH_DB_CONTAINER` missing (or ps status ≠ 0): `scratch_start_failed`. Each other name, in ps order: `run('docker', ['stop', name], { timeoutMs: 120000 })`; any status ≠ 0: `scratch_services_stop_failed`.
6. S0 = snapshot: `run('docker', snapshotPsqlArgs(), { input: SNAPSHOT_SQL, timeoutMs: 120000 })` then `parseSnapshot(stdout)`; status ≠ 0 or a throw: `scratch_snapshot_failed`. `base = new Map(S0 by id)`, `before = S0`.
7. For each name of `Object.keys(input.newFiles).sort()`: write it to `w/supabase/migrations/<name>`; `run(supabaseBin, ['migration', 'up', '--local', '--workdir', w], { cwd: w, timeoutMs: 300000 })`.
   - status ≠ 0: push M4 `{ file: 'supabase/migrations/<name>', object: <name>, detail: 'cannot be checked: the migration failed on the scratch database' }`, plus `': ' + <first line of JSON stdout error.message>` when stdout parses and has it; stop the loop.
   - status 0: the basenames of `JSON.parse(stdout.trim()).applied` must equal `[name]`, else (or unparsable) M4 detail `cannot be checked: the scratch database did not apply it`; stop the loop.
   - else `after` = snapshot (a psql status ≠ 0 or a `parseSnapshot` throw is `scratch_snapshot_failed`, as step 6; that `try` covers only the psql run and the parse, so a throw from `scanCreatedKeys` or `compareStep` propagates past the `finally` of step 9); push `compareStep({ file: name, base, before, after, scanned: scanCreatedKeys(input.newFiles[name]), isRetired: input.isRetired, baseTag: input.baseTag })`; `before = after`.
8. When every new file applied: note `scratch database: <n> new migration(s) applied on top of <baseTag>`.
9. `finally`: `run(supabaseBin, ['stop', '--no-backup', '--workdir', w], { cwd: w, timeoutMs: 120000 })` (status ≠ 0 adds note `scratch_db_stop_failed`, nothing else changes); `rmSync(w, { recursive: true, force: true })`. A failure returns the violations found so far.

### `compareStep` rules (one file)
- **M1:** for each `[id, b]` of `base`: skip unless `before` has `id` with name `b.name`; skip when `after` has `id` with name `b.name`; skip when `isRetired({ kind: b.kind, name: b.name })`; skip a column whose relation (`id` before `:`) is itself reported in this step. Else `{ id: 'M1', file, object: b.name, detail: '<kind> is dropped or renamed on the scratch database but <baseTag> still reads it (retire it in supabase/retired.json and release that first)' }`.
- **M4:** for each entry `a` of `after` whose `id` is not in `before`, report unless covered: `scanned` has `<kind>:<name>`; or kind `column` and `scanned` has `table:`, `view:` or `materialized_view:` + its relation name (name minus the last segment); or kind `column` and its relation id (`id` before `:`) is also new in this step (the relation's own line stands for it); or kind `sequence` with `ownedBy` set and that column is covered by the column rules or is a column name in `before`. Detail `cannot be checked: the scratch database created this <kind> but the scan did not find its create statement in this migration`.
- Order: M1 in `base` id order, then M4 in `after` order. `file` in violations is `supabase/migrations/<name>`.

### `main` changes
- `--no-db` sets `opts.db = false` (default true). No other flag changes.
- With a base tag, after `checkMigrations`: `newNames` = head names not in the base set, sorted; `newFiles` = `Object.fromEntries(newNames.map((n) => [n, head.migrations[n]]))`. Exactly one status line, printed after `result.notes`: `--no-db` → `scratch_db_skipped (--no-db)`; else 0 new → `scratch database not needed: no new migration since <tag>`; else any M3 → `scratch database skipped: fix the M3 version first`; else call `scratch({ baseTag, released: base.migrations, newFiles, isRetired: (item) => isRetired(retiredEntries, item) })` (`retiredEntries` = what `checkMigrations` got) and print its `notes` instead.
- `scratch` = `opts.scratch ?? runScratchCheck`.
- Violations printed: static, then scratch ones except an M1 whose `file` and `object` equal a static M1, then M5. Then `scratch_db_failed: <failure>` when `failure` is set. Summary: violations → `migration check failed against <tag>: <n> violation(s)`; else failure → `migration check failed against <tag>: the scratch database check could not run`; else `migration check passed against <tag>`. Exit 1 on violations or failure. No-tag path unchanged.
