# EZD-153 · Fix: migration check flags objects created in dynamic SQL

- **ACs:** AC-EZD-153-1, AC-EZD-153-2
- **Complexity:** medium (section 8)
- **User-visible result:** the release safety check now refuses a migration that creates a table, function or column inside text the check cannot read (`execute '…'`, a function body, SQL built at run time, `select … into`), so a later release can never drop something production still uses without the check noticing.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Data: none (no table, migration or policy). Short names: `scan` = `scripts/release/sql-scan.mjs`; `check` = `scripts/release/check-migrations.mjs`; "body" = a token of type `string` or `dollar` from the existing lexer (`scan` `lex`, from line 28), its `value` being the text inside the quotes.

The hole (sweep item 21): `findDefined` builds the released-object set from static SQL only, so an object created inside a body (or by `select … into`, or as a `create schema` element) is missing from it, and a later drop of it passes M1. Fix: every way of creating an object the scan cannot read is M4 (E1-E3 show each one creates a real object on the pinned PostgreSQL 17.11). With no release tag yet, the create reasons are also checked on every migration, so nothing created invisibly before launch is released at the first tag (E4: today's 33 migrations have none).

**Step 2 rules** (after the existing `cascade` and `dynamic` checks, unchanged, in this order; `tokens = tokenize(stmt)` (whitespace and comments already dropped, scan line 174), `bodies` = the tokens of `tokens` of type `string` or `dollar`; a whole `do $$ … $$` or `create function … as $$ … $$` is one statement with one dollar body, since `splitStatements` never splits inside a body):
1. `dynamic_create` when any body's `value.toLowerCase()` matches, verbatim:
   `DYNAMIC_CREATE_RE = /\bcreate\s+(?:or\s+replace\s+)?(?!(?:(?:global|local)\s+)?(?:temp|temporary)\b)(?:unlogged\s+)?(?:recursive\s+)?(?:table|view|materialized\s+view|function|procedure|type|domain|schema|sequence|extension)\b|\badd\s+column\b|\balter\s+table\b[^;]*?\badd\s+(?!(?:constraint|primary|unique|foreign|check|exclude)\b)/`
2. `dynamic_sql` when `hasBuiltExecute(value)` is true for any body (called on each body's `value`, never on the statement text: a statement that is itself `execute <name>` runs a prepared statement, and PREPARE takes no DDL, E7). `hasBuiltExecute(text)`: `toks = tokenize(text)`; for each index `k`: if `toks[k]` is a body and `hasBuiltExecute(toks[k].value)` → return true (nested bodies; each value is shorter, so it ends); if `toks[k]` is not the word `execute` → next; if `toks[k+1]` is the word `on`, `function` or `procedure` → next (privilege and trigger words); `literal` = `toks[k+1]` exists and is a body; `ends` = `toks[k+2]` is undefined, or of type `semi`, or the word `into` or `using`; if not (`literal` and `ends`) → return true. After the loop return false.
3. `hidden_create` when `hidesCreate(tokens)`: first drop the leading tokens that are the punct `(` (a parenthesised `(select … into t)` creates `t`, E7); call the rest `t`. (a) `t[0]` is the word `explain` → true (`explain analyze` runs `select … into` and `create table … as`, E7; a migration never needs `explain`); (b) `t[0]` is the word `create` and `t[1]` the word `schema` → true when any later token is the word `create`, else false; (c) else, unless `t[0]` is the word `select` or `with` → false; (d) else walk `t` with `depth` 0 (`(` +1, `)` −1); at `depth <= 0`, the first word in `QUERY_VERBS = ['select', 'insert', 'update', 'delete', 'merge']` sets `verb` once (never overwritten by a later verb); a later word `into` at `depth <= 0` while `verb === 'select'` → true. End → false.

**Step 3, `check`.**

| Temporary objects | Not counted: a temp table, view or sequence is dropped at the end of its session, so no release can read it | E5; PostgreSQL 17 CREATE TABLE ("Temporary tables are automatically dropped at the end of a session") |

| `create function … language plpgsql` whose body creates (runs only when called) | Counted the same as a `do` block: the object would exist without the base set knowing it | sweep item 21 ("or a function body") |
| `hidden_create` scope | Statements starting `select` or `with` (after leading `(`), `create schema` with elements, and every `explain`; `insert … select`, `create table … as`, `create view … as select` are not counted | E2, E3, E7; T3 |

| Message wording | Section 6; tests never assert detail text | EZD-023a T-file header ("never message wording") |
| Other SQL runners | None needed: `dblink` is not installed and `query_to_xml` refuses DDL | E6 |
