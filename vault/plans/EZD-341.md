# EZD-341 · Fix: the projects-settings entry stays within its 200 KB size budget

- **ACs:** AC-EZD-341-1
- **Complexity:** medium (section 8)
- **Areas:** performance, testing
- **User-visible result:** every page downloads about 2 to 4 KB less JavaScript (the error reporter stops shipping parts the app has turned off), and the Projects/Settings entry is back under 200 KB.
- Phase: 3 · Planned by: planner · Date: 2026-11-05 · Status: planned

## 1. What to build

The fix: `app/src/instrumentation-client.ts` calls `Sentry.init`. Sentry 11.8.0's `init` always references `getDefaultIntegrations()` (`@sentry/browser/build/npm/esm/prod/sdk.js`), so nine integrations the app turns off (`defaultIntegrations: false`, `app/src/lib/errors/browser-options.ts`; architecture "Error reporting (EZD-024)": "No ... default integrations") are still in every entry's first download. Starting the client with `initAndBind` (what `init` itself calls) drops that dead code. This is "dropping what it no longer uses" (ticket Scope); the budget, `scripts/perf/*` and E4 stay as they are.

Measured in this session (section 2 P1–P3): `js-size:projects-settings` = 200,417 bytes (417 over). Estimated saving from removing the nine integrations: 2,407 compressed bytes; with the browser instrumentation only they use: 4,304. Expected after the fix: about 196,100 to 198,000 (estimate; the test checks ≤ 200,000).
