**1a. RM.**
- `reportProblems(text, name)`: lines = `text.split('\n')` with a trailing `\r` removed. Line 1 not exactly `---`, or no later line exactly `---`: return `['no front matter']`, preceded by P6 when `name` starts with `.`. Otherwise, between the two, each line with a `:` gives key = text before the first `:` trimmed, value = the rest trimmed with every `|` turned to `/`; only `title`, `scope`, `ticket` are kept, a later duplicate wins (all as `parse()` today). Problems in this order: P6 when `name` starts with `.`; `missing title`, `missing scope`, `missing ticket` for each empty or absent one; P5 when `ticket` is present and does not match `/^EZD-\S+$/` (T8's row pattern). `[]` means complete.
- `parse()` becomes a private `fields(text): { title?, scope?, ticket? } | null` (null = no front matter) holding the parsing rules above; `reportProblems` and `adopt` both call it. `adopt`: a non-empty `reportProblems(text)` skips the file with reason `problems.join('; ')`; otherwise the line uses `fields(text)`'s values as today. Everything else unchanged (T1 to T7 stay green).
- `checkPending(researchDir)`: entries of `<researchDir>/pending` (none when the folder is absent), sorted; an entry that is not a file is skipped, as adopt does; a read error throws and the CLI's existing catch prints `research: <message>` with exit 1; for each file: a name ending `.md` (dot names included) counts toward `count` unless it starts with `.`, and adds `pending/<name>: <p>` for each problem of `reportProblems(text, name)`; `.gitkeep` with size > 0 adds `pending/.gitkeep: ` + P7. Other files are ignored.
- CLI: `check` (exactly one argument) runs `checkPending` on the same `researchDir` as `adopt`; no problems: stdout K1, exit 0; else stdout K2 then one K3 line per problem, exit 1. Any other argument list: stderr U1, exit 2.

**1b. NT `checkStaged`** (P248 1c steps 1 to 5 stay; additions):
- Step 1: `Q` = some name starts `vault/questions/`; `R` = some name starts `vault/research/pending/` (deletions included). Neither: `{ ok: true, checked: false, output: '' }`.
- Step 2 (export) runs once for both. Step 3 (E3) only when `Q`. When `R` and `<tmp>/vault/tools/research.mjs` is absent: E6a.
- When `R`: `spawnSync(process.execPath, [<tmp>/vault/tools/research.mjs, 'check'], <P248 step 4 options>)`. `status === null` or `error` set: E6b. Status 0: pass. Otherwise output R1 + `\n` + `stdout.trim()` + `\n` + R2; R1's first problem follows P248 step 4's rule (first stdout line starting `- ` without the prefix, which is the first K3 line; else, as from a `research.mjs` without `check`, the first non-blank line of stdout, then stderr; else `(no output)`).
- Result: `ok` = every branch that ran passed; `checked` = `Q` or `R` ran its check; `output` = the failed branches' outputs joined by `\n`, the questions one first; an E line returns at once as in P248.
