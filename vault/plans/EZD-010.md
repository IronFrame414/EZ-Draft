## Approach

- the token stylesheet and its typed copy;
- the self-hosted fonts;
- the icon sprite pipeline and an `Icon` component;
- a dev-only token test page;
- one machine check (C10) that keeps colors inside the token file.

No npm package is added.

Choices that no source makes are marked *planner's choice (CLAUDE.md rule 4: agents decide how)*, and the code-reviewer confirms them at plan review.

### Step 2: Token files
- `app/src/styles/tokens.css` is the one stylesheet that holds literal values. It has a single `:root { … }` block that starts with the 36 declarations of Step 1, in that order, with values written exactly as in the table. Later tickets append board-cited tokens (tickets README rule 5) to this block and to `tokens.ts` together, for example EZD-011 (the darker amber review-pill text, Q-0037 (b)), EZD-012 (`--ez-radius-6`, Q-0040 (c)), EZD-014 and EZD-015 (`--ez-radius-14`, Q-0057 (b)) (their plans). There is no other selector, no theme or dark-mode variant (the spec has none), and no `@supports` fallback block: the `oklch()` values ship as written, with no sRGB fallback (Q-0026 (a); every browser in the Q-0013 (a) floor, Firefox 113+, reads `oklch()`).
- `app/src/styles/tokens.ts` is a typed copy for TypeScript code (the token page, and later the WebGL canvas, which cannot read CSS variables cheaply; 11 rule 4). It exports `TOKENS: readonly { name: \`--ez-${string}\`; value: string; group: 'color' | 'status' | 'radius' | 'shadow' | 'frame' }[]`, with the same entries as `tokens.css` in the same order (*planner's choice*). Tests T1 and T2 tie the 36 spec rows to the spec and every `--ez-*` token in one file to the other, so the two cannot drift apart. The tests do not fix the total count, so a later ticket that adds a token does not edit this ticket's tests (phase 0 plan review, finding 8).
- `app/src/styles/globals.css` holds only `body { font-family: var(--ez-font-sans); }` (04 Type: "Instrument Sans … for UI"). It does not set margins, colors or sizes. Those belong to the shell (EZD-011 and EZD-012).

### Step 3: Fonts (11 rule 8; 04 Type)
- The font files are committed to the repo (*planner's choice*: no npm dependency, and the build works offline). They go in `app/src/styles/fonts/`, copied unchanged from the `files/` folders of the newest stable `@fontsource/instrument-sans` and `@fontsource/dm-mono` on the build date (5.3.0 on 2026-10-11):
  - `instrument-sans-latin-400-normal.woff2`, `instrument-sans-latin-500-normal.woff2` and `instrument-sans-latin-600-normal.woff2`. The weights come from 04 Type: "Instrument Sans 400/500/600".
  - `dm-mono-latin-400-normal.woff2` and `dm-mono-latin-500-normal.woff2`. 04 names DM Mono but gives no weight. All 36 Studio boards load `DM+Mono:wght@400;500` (tickets README rule 5).
  - `LICENSE-instrument-sans.txt` and `LICENSE-dm-mono.txt`, which are the packages' `LICENSE` files (OFL-1.1).
- Why the latin subset (11 rule 8 "subsets"): its unicode range (see Sources) covers ASCII, so it covers measurement entry such as `12' 6 1/2"` (04 Measurement entry). It also covers U+00A0–U+00FF, which includes Spanish á é í ó ú ü ñ ¿ ¡ (R26 R17), plus · × ° and the U+2000–206F punctuation ("…", "′", "″").
- `app/src/styles/fonts.ts` makes two `next/font/local` calls (Next.js built-in, so no new package):
  - `instrumentSans`: `src` lists the three files with `weight` `'400'`, `'500'`, `'600'` and `style: 'normal'`; `variable: '--ez-font-sans'`; `display: 'swap'` (the boards use `display=swap`); `fallback: ['sans-serif']` (the boards' fallback).
  - `dmMono`: the two files with `weight` `'400'` and `'500'`; `variable: '--ez-font-mono'`; `display: 'swap'`; `fallback: ['monospace']`.
  - Each call keeps the `next/font` default `preload`.
- `app/src/app/layout.tsx` (EZD-001's file, extended):
  - It imports `../styles/tokens.css`, then `../styles/globals.css`.
  - It adds `className={\`${instrumentSans.variable} ${dmMono.variable}\`}` to `<html>`.
  - It keeps EZD-001's `lang="en"` and `metadata.title` unchanged.
- Nothing loads from `fonts.googleapis.com` or `fonts.gstatic.com`, and `next/font/google` is not used. With `next/font/google`, `next build` would have to reach Google over the network.

### Step 4: Icon sprite (11 rule 8; 04 Type)
- Icon style comes from the Studio boards, because 04 names only "Material Symbols Outlined":
  - weight 400 and grade 0 (`.ms` sets `font-weight:normal`);
  - FILL 0 by default; a filled variant (FILL 1, used on S17) is available as `<name>-fill`.
- Optical size is **20**. The boards draw icons at 17–23 px, and the font sets optical size from the font size; 20 is the nearest size published as SVG (*planner's choice*).
- Source files are committed in `app/src/components/icon/svg/`:
  - `<name>.svg` is `<name>_20px.svg`.
  - `<name>-fill.svg` is `<name>_fill1_20px.svg`. If no 20 px fill file exists, the script fails with that name rather than picking another size.
  - Both come from `google/material-design-icons`, folder `symbols/web/<name>/materialsymbolsoutlined/`, at one pinned commit SHA. A `LICENSE` file (Apache-2.0) sits next to them.
  - The npm package `@material-symbols/svg-400` is not used, because it ships optical size 48 only and lacks names such as `expand_more` (checked 2026-10-11).
- `app/src/components/icon/icons.json` is the list of icons the app uses. It is a sorted JSON array of names (`"<name>"` or `"<name>-fill"`). This ticket seeds it with **`["expand_more"]`**, the chevron beside the project name (04 Header card "Project name + chevron"; `S03Plan.dc.html` uses `expand_more`). EZD-011 and EZD-012 add their own icons. A single committed icon is enough to prove the pipeline. Filled icons and errors are tested with fixtures (T9).
- `app/scripts/icons-fetch.mjs <name>…` is used by developers only and needs the network. It downloads the named icons from the pinned commit into `svg/`. It is never run by tests or by the gate.
- `app/scripts/icons-build.mjs [--src <dir>] [--list <file>] [--sprite <file>] [--names <file>]` uses no network and no dependencies (Node 22 built-ins only). The defaults are `app/src/components/icon/svg/`, `icons.json`, `app/public/icons/sprite.svg` and `app/src/components/icon/icon-names.generated.ts`. It:
  - fails with exit 1 and names the problem if a listed icon has no source file, if a name appears twice, or if the list is not sorted;
  - writes one `<svg xmlns="http://www.w3.org/2000/svg">` containing one `<symbol id="<name>" viewBox="<source viewBox>">` per listed name, holding the source's `<path>` elements unchanged, with no `width`/`height`, no `fill`, no `<style>`, no `<text>` and no font reference, plus one leading comment naming the source repository, the commit and Apache-2.0;
  - writes `icon-names.generated.ts`, which contains `export const ICON_NAMES = [...] as const; export type IconName = (typeof ICON_NAMES)[number];`;
  - gives the same bytes for the same inputs every time (sorted output, `\n` line endings).
- `app/package.json` gets the scripts `icons:fetch` and `icons:build`. The outputs of `icons:build` are committed. The gate does not run it; test T8 fails when the committed files are out of date.
- `app/src/components/icon/Icon.tsx` is a server-safe component with no `'use client'` and no state. `Icon({ name, size }: { name: IconName; size: number })` renders `<svg width={size} height={size} aria-hidden="true" focusable="false" fill="currentColor"><use href={\`/icons/sprite.svg#${name}\`} /></svg>`.
  - It is decorative only. The button that holds an icon carries the label and tooltip (11 Accessibility), and that is the job of the shell tickets.
  - `size` is required, because the spec sets no default icon size.
  - The sprite is a separate file served from `public/`, not inlined into every page, so it is cached once (EZD-013's service worker will cache it as a static file; 11 rule 13).

## Risks
- **`oklch()` support (Q-0026 (a); Q-0013 (a)).** Seven tokens use `oklch()` and ship with no fallback. The floor Josh set is Firefox 113+, Safari/iOS 16.4+ and Chrome/Edge 111+, all of which read `oklch()`. A browser below the floor drops those colors; that is outside what Josh asked to support.
- **WebGL cannot use these strings directly.** Three.js `Color` does not parse `oklch()`. Canvas tickets (EZD-012 grid and later selection colors, EZD-027) need an sRGB value. The grid color is hex already, but cobalt is not. That ticket converts it; this ticket does not invent sRGB values.
- **Board colors versus spec.**
  - The boards use about twenty shades that are not in 04, for example `oklch(0.42 0.17 262)` 70 times and `oklch(0.48 0.13 65)` as the text of the amber review pill.
  - EZD-011's review pill meets this. Spec 04 says amber `oklch(0.72 0.16 65)` on `oklch(0.96 0.04 80)`, while the boards' pill text is `oklch(0.48 0.13 65)`. Josh decided: the pill text uses the boards' darker amber as a new token, and the spec amber stays for the dot (Q-0037 (b)). The ticket that builds the pill adds that token; this ticket does not.
  - C10 makes any added shade a token.
- **Exception radii.** Two radii outside 04's list are approved (6 px tooltip, Q-0040 (c); 14 px dialog, Q-0057 (b)) and are added by EZD-012 and EZD-015. If either of those tickets builds before this one's tokens exist, it has nothing to append to; `tickets.json` makes both depend on EZD-010, so that cannot happen. The answer column records them as (c) and (b) (finding V11).
- **Icon names.**
  - The boards use font ligature names. A few may not exist as SVG files under that name (the npm package lacks `expand_more`, while Google's repo has it).
  - `icons-fetch.mjs` and `icons-build.mjs` fail loudly on a missing name, so the shell tickets will see the problem rather than ship a blank icon.
  - Optical size 20 against board sizes up to 23 px could show slightly thinner strokes at the larger sizes; EZD-011's ui-verifier judges it against S03 (finding V12).
- **Sheet and PDF fonts.** 02 PDF out needs "text with metrics from bundled font files", and PDFKit embeds fonts (EZD-028, R26 R7). The browser woff2 subsets here may not suit the server-side drawing list. Where shared font files live is EZD-028's call, and moving these files later is cheap.
- **Clean-tree typecheck.** Settled (finding V5): `next typegen` writes `next-env.d.ts` before `tsc`, and the `next` types declare `*.module.css`, so no declaration file is added.
- **Vitest and JSX.** The app tsconfig sets `jsx: "preserve"` (finding V3); if `.test.tsx` does not compile, part b's test-author sets the transform in `app/vitest.config.ts` under the Oxc key of the pinned Vite 8.3.4. The test-author owns that file under guard-paths.mjs.
- **Font weight on the wire.** About 81 KB of woff2 is preloaded on every page (sizes in Sources). It is not JavaScript, so the EZD-017 budgets do not count it. If first paint on the phone suffers, a later ticket can preload only the 400 weights.
- **C10 is a text scan.** It can flag `url(#abc)` if the id looks like hex, and it misses named colors and TSX inline colors. Those two are marked "review".
