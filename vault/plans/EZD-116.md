## Split proposal

**Why.** Planned whole, the ticket touches about 31 files and needs about 36 tests, over the size rule (PROCESS.md section 6 "Ticket size": about 20 files, about 25 tests; Josh 2026-10-22). Sources of the count:
- 9 stage-0 ACs (`acceptance-criteria.md:1136-1144`); AC-EZD-116-4 alone carries 12 boundary cases (09o Value checks rows 1-6; Q-0697 03 "Defaults data" minutes 1 to 1,440; Q-0706 days 1 to 365, 0 for cleanup age and grace, reminder lead below expiry);
- a typed registry of about 50 rows over 15 groups (S15d Controls table rows 13-49; Q-0697 05 adds the Walls group of five rows and the Snap increment row, and splits S15d row 44 into two keys), each row with an `en.ts` label and hint key (board S15dDefaults per-row hints, Q-0697 05);
- a Settings page with nine field kinds on the board (length, two-field range, percent, days, minutes, count, segmented choice, on/off switch, scale chips) plus the waste factor table, Search defaults, Discard, the unsaved footer and status bar items (board S15dDefaults; Q-0697 05);
- a new write function on `tenant` with its permission check, a read and save route pair, the `tenant.defaults_updated` event (S15d Events; ARCH Events);
- changed project create functions (`public.create_project`, `20261105105039_create_create_project.sql:7`; `public.create_project_with_objects`, `20261107100756_create_project_with_objects.sql:3`) that main's live code still calls (Q-0264; template Live site), their two callers in `app/src/server/projects/projects.ts:228-229`, and the editor's model load (`app/src/server/model/model.ts:349-356`) and session, plus a first project-channel resync handler in the editor (no `src/editor` file uses the Realtime hub today: grep `realtime` in `app/src/editor`, 2026-11-11).

**Why cut here.**
- The Settings page and its save path stand alone: they read and write only `tenant.defaults` (Q-0697 03 "Defaults data"), so part a can be built and checked with Josh's Slice 8 script step 1 (`vault/tickets/PHASES.md` Slice 8) before any project code changes.
- Part b is every reader outside Settings: the copy made at project creation (S15d Decision 4; 09o Copy at creation), the editor's effective values (Q-0697 03), and the "Set in Defaults" note a feature shows (S15d Entry points). It needs part a's registry, effective-value helper and per-project flag, so it comes second.
- b's migration changes two functions main still calls (Q-0264), a different review from a's new function; keeping them apart keeps each security review to one write path.

Built a → b. Each part is planned as its own unit from its section here.
