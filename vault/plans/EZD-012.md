### Step 1: Frame, `app/src/components/shell/EditorFrame.tsx` + `EditorFrame.module.css`
- `'use client'` (02 Named tools: "the editor is a client-only shell so it can open offline").
- Props: `header?: ReactNode`, `rail: ReactNode`, `leftPanel?: ReactNode`, `leftPanelLabel: MessageKey`, `canvas?: ReactNode`, `inspector?: ReactNode`, `inspectorLabel: MessageKey`, `statusBar: ReactNode`. Labels are message keys resolved with `useT()` (R26 R17; EZD-026a).

### Step 2: Tool rail, `app/src/components/shell/ToolRail.tsx` + `ToolRail.module.css` + `rail-types.ts`
- `rail-types.ts`: `type RailTool = { kind: 'tool'; id: string; icon: IconName; label: MessageKey; shortcut: string }` (04: "every rail tool has a default key", so `shortcut` is required), `type RailSeparator = { kind: 'separator' }`, `type RailEntry = RailTool | RailSeparator`. The tool list itself (04 table, Shown on per tab) is EZD-230's; this ticket defines no registry.
- `ToolRail({ top, bottom, activeId, onSelect })` (`'use client'`, controlled): `top: RailEntry[]`, `bottom: RailTool[]` (pinned to the foot of the rail, where boards put Check and Help; 04 "above Help"; S03 "Help: Rail, bottom"), `activeId: string | null`, `onSelect(id)`. It holds no state, so the open model's store (EZD-120b) can own the active tool later.
- Markup: `<nav data-shell-region="rail" aria-label={t('office.shell.tools')}>` → `<div data-rail="top">` with the entries → `<div data-rail="bottom">`. Each tool: a `position: relative` wrapper holding
  - `<button type="button" data-rail-tool={id} aria-label={t(label)} aria-keyshortcuts={shortcut} aria-pressed={id === activeId}>` with `<Icon name={icon} size={21} />` (EZD-010 `Icon`; 21 px from board `.rb` font-size);
  - `<span data-rail-tooltip aria-hidden="true">{t(label)}<kbd>{shortcut}</kbd></span>`. The button already carries the name (aria-label) and key (aria-keyshortcuts), so the tooltip is visual only (*planner's choice*; 11 Accessibility "labels and tooltips").
  - Separator: `<span data-rail="separator" role="separator" aria-orientation="horizontal">`.
- CSS (tokens only; sizes from S03 `.rb`, `.rbon`, `.rs`, `.tip` and the rail `<nav>`):
  - Rail: card style; `width: var(--ez-rail-width)`; `display: flex; flex-direction: column; align-items: center; padding: 10px 0`; top and bottom groups are flex columns with `gap: 2px`; the top group has `flex: 1; min-height: 0` so the bottom group sits at the foot (board spacer `flex: 1`). No overflow handling is built: the Phase 0 rail never overflows (see Q-0038).
  - Button: `40px × 40px; border-radius: var(--ez-radius-8); border: 0; background: transparent; color: var(--ez-slate-700)`; hover `background: var(--ez-hover)`; active (`aria-pressed="true"`) `background: var(--ez-cobalt); color: var(--ez-surface)` (04: "The active tool is a cobalt button with a white icon"; board `.rbon` keeps cobalt on hover). `:focus-visible` outline in `var(--ez-cobalt)`, 2 px (*planner's choice*).
  - Separator: `24px × 1px; background: var(--ez-border); margin: 6px 0` (board `.rs`).
  - Tooltip: hidden by default (`display: none`); shown while the wrapper is hovered or the button has `:focus-visible` (04: "hovering shows a dark tooltip"; focus added for keyboard users, *planner's choice*). CSS only, so a hover causes no React commit and no Radix dependency (02 lists Radix for dialogs, menus, popovers, not tooltips). `position: absolute; left: 52px; top: 50%; transform: translateY(-50%); white-space: nowrap; display: flex; gap: 8px; padding: 5px 9px; font-size: 12px; background: var(--ez-ink); color: var(--ez-surface); z-index` above the left panel; `border-radius: var(--ez-radius-6)` (Q-0040 (a): "tooltip radius 6 px, as the approved mockups (board-cited exception token)"; S03 `.tip{…border-radius:6px…}`). Key: `<kbd>` with `font-family: var(--ez-font-mono); color: var(--ez-slate-300)` (board: `.mono`, `#9aa3af`; 04 Type: DM Mono for every code). The rail and its wrappers must not clip the tooltip (no `overflow: hidden` on the rail).
- Clicking a tool calls `onSelect(id)` only. "On screen within 50 ms" (11 Budgets) holds because only the rail re-renders.
- **Token `--ez-radius-6: 6px`** (Q-0040 (a)): appended to the `:root` block of `app/src/styles/tokens.css` and to `TOKENS` in `app/src/styles/tokens.ts` with `group: 'radius'`, after any tokens EZD-011 appended. ## Risks
- **Header margin owner (settled).** `HeaderCard` (EZD-011) owns the 60 px height and the 16 px margin; the frame adds none (phase 0 plan review, finding 3). S1 fails if `EditorFrame.module.css` names the header tokens, and B1 fails if a margin is applied twice.
- **Grid under the WebGL canvas.** The grid is a static CSS background over the whole frame (boards). EZD-207's canvas pans and zooms its own grid, so the two will not line up at the canvas edges. EZD-207 decides whether its canvas covers the grid or the shell drops the CSS grid inside the canvas region.
- **Rail capacity (Q-0038).** 04 shows 22 tools on the Plan tab. At the board's 40 px buttons the 846 px rail holds about 18 (42 px per button, 50 px for padding, border and two separators); at iPad's 44 px targets (EZD-014) fewer. Nothing overflows in Phase 0, but EZD-230 cannot ship the full Plan rail until Q-0038 is answered.
- **`oklch()` (Q-0026 (a)).** The active button uses `--ez-cobalt`, an `oklch()` value with no fallback. Every browser at or above the Q-0013 (a) floor (Firefox 113+, Safari/iOS 16.4+, Chrome/Edge 111+) reads it; older browsers would show no active color, which Q-0013 (a) and Q-0026 (a) accept.
- **Performance.** The shell must add no React commits during a pan (EZD-017). The CSS tooltip and the listener-free frame keep it at zero; later status bar readouts must update through refs (written into docs, Step 7).
- **Route for the Phase 0 build gate (settled by Q-0039 (c)).** This ticket proves the frame on a dev page that 404s in production. Josh chose no extra page or notice: production shows whatever sign-in provides until Phase 1, and the build-gate test (owned by EZD-032, Q-0085) signs in and opens `/dev/shell` on a non-production build. Josh's Phase 0 Field check at the production address therefore sees EZD-007's signed-in page, not the editor; that is the accepted outcome.
- **Tablets.** `position: fixed; inset: 0` and fixed pixel widths leave a 1180 px-wide iPad landscape viewport (Q-0053) with a 460 px canvas (1180 − 720, where 720 = 2 × 16 body padding + 3 × 16 gaps + 56 rail + 248 left panel + 336 inspector; 04 Frame and visual system), and a Surface at about 1440 px (Q-0088) with a 720 px canvas. EZD-014 owns device layouts; this ticket only guarantees nothing breaks below 1600 px (canvas has `min-width: 0`).
