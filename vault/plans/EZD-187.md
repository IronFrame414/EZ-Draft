# EZD-187 · Fix: the root `test` step runs the package tests even when a root node:test file fails

- **ACs:** AC-EZD-187-1, AC-EZD-187-2, AC-EZD-187-3
- **Complexity:** low (one script string, one docs sentence, one new node:test file, one test edit; reasoning in section 8)
- **User-visible result:** when a repo-script test fails, the gate still runs and reports every app and geometry test, so one red test no longer hides the others.
- Phase: 1 · Planned by: planner · Date: 2026-10-25 · Status: planned

## 1. What to build

No data, no migration, no app code.

**The new root `test` script** (string S, the contract; run once by the planner in a fixture workspace on macOS with pnpm 12.14.0, all six cases of section 4 behaved as expected):

```
pnpm run db:up && { node --import ./app/test-harness/net-guard/preload.mjs --test --test-concurrency=4 "scripts/**/*.test.mjs"; root=$?; pnpm -r --no-bail --if-present --filter "!./spikes/**" run test; pkgs=$?; [ $root -eq 0 ] && [ $pkgs -eq 0 ]; }
```

In `package.json` it is one JSON string, the inner `"` escaped as `\"`. POSIX `sh` syntax only (pnpm runs scripts with `sh` on macOS and ubuntu; `{ …; }`, `$?`, `[ … -eq … ]` are POSIX, so dash on ubuntu behaves as sh on macOS).

**Run rule:** `spawnSync('pnpm', ['run', 'test'], { cwd: fixture, env, encoding: 'utf8', timeout: 120000 })` (no in-process server, so `spawnSync` is allowed). `env` = a copy of `process.env` with these removed: (E1) every key matching `/^npm_/i` and `PNPM_SCRIPT_SRC_DIR` (set by the outer pnpm run); (E2) `EZD_TEST_SCOPE`, `EZD_PHASE`, `EZD_TEST_GREP` and every `FIX_*`; (E3) `NODE_TEST_CONTEXT` (set by the outer `node --test`; with it the nested `node --test` runs no file and exits 0); then `CI: '1'`, `FIX_LOG: <fixture>/log`, plus the case's values. The log is read as lines (trailing empty line dropped). A case with a timeout or `status === null` fails with the output.
