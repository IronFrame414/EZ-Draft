# EZD-337 · Fix: a phase PR merges unattended only when what landed after the phase audit has had a security pass

- **ACs:** AC-EZD-337-1, AC-EZD-337-2
- **Complexity:** high
- **Areas:** tooling, scripts, security
- **User-visible result:** nothing reaches the live site that the security review has not seen, even when the build merges its own pull requests.
- Phase: 1 · Planned by: orchestrator (from the EZD-336 security review) · Date: 2026-11-05 · Status: planned

## 1. What to build
Cause: auto-merge and the EZD-336 launcher merge take develop's tip, while the phase audit approved `Develop at PR` in `vault/tickets/gates/phase-NN.md` (PR 5: audited 0c42907d, head a57931ba, 20 commits later). Fix tickets after an audit are expected (gate-phase step 5), so the head may differ; a production-sensitive change in that delta must get a security pass first.
