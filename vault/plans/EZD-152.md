# EZD-152 · Fix: release and restore failure lines say why without leaking data

- **ACs:** AC-EZD-152-1, AC-EZD-152-2
- **Complexity:** low (section 8)
- **User-visible result:** when tenant 1 setup fails on the first release without saying "done", the release log now shows psql's last lines (passwords and secrets removed), and a failed restore, release or backup never prints the client data row that psql quotes under `DETAIL:`, `CONTEXT:`, `QUERY:` or `LINE n:`, nor the field value an `ERROR:` line quotes (Q-0288 (a)). Both psql runners now run terse, so psql itself prints only the severity and the message of each line.

**Step 2, `dropRowLines` rule.** One regex, anchored at the line start, allowing leading whitespace then PREFIX: `ROW_START` = `/^\s*(?:psql:\S*:\d+:\s+)?(?:DETAIL|CONTEXT|QUERY|LINE \d+):/`, a line that starts a row block. No block-end regex (the earlier `FIELD_START` list is removed from the file). Walk the lines in order with a flag `dropping` (starts false): a `ROW_START` line sets `dropping = true`; once `dropping` is true, every later line is dropped, whatever text it starts with (Decided: Block end, `QUERY:`).

**Step 2, ERROR value rule (Q-0288 (a)).** Applied to every kept line, before it is pushed. `ERROR_LINE` = `/^(\s*(?:psql:\S*:\d+:\s+)?ERROR:\s+)([\s\S]*)$/` (group 2 is `[\s\S]*`, not `.*`, so a line holding U+2028, U+2029 or a bare CR still matches; the builder's form, accepted by both reviewers in round 1; T9 (e)). On a match, `msg` = group 2; `i` = `msg.indexOf(': ')` (the first `: ` after the label text; the label's own `ERROR:` is in group 1, so `ERROR:  relation "x" does not exist` has none and is kept whole). When `i === -1`, keep the line. Else `tail` = `msg.slice(i + 2)`, `q` = `tail.indexOf('"')`, `z` = `tail.lastIndexOf('"')`:
- `q === -1`: keep the line unchanged.
- `z > q`: replace `tail.slice(q, z + 1)` with `"<value>"` (first to last quote, so a value holding `"` or `: ` is replaced whole); text before `q` and after `z` stays, so terse psql's ` at character N` suffix (probe case 2) reads `"<value>" at character 8`.
- `z === q` (the quote does not close on this line, a value with a newline): replace `tail.slice(q)` with `"<value>"` and set `dropping = true`, so every later line is dropped (the value's remaining lines and anything after them; probe case 5).
Only `ERROR:` lines (not NOTICE, HINT or others); table, column, constraint and type names before the first `: ` stay (Q-0288 (a)).

**Steps 2a and 2b, terse psql.** Both psql runners pass `-v VERBOSITY=terse`, so psql writes each message as `<SEVERITY>:  <primary text>` (plus ` at character N` where it has a position) and never a `DETAIL:`, `HINT:`, `QUERY:`, `CONTEXT:`, `LINE n:` or caret line (probe, section 2). `dropRowLines` stays as the backstop (Decided: Where the leak is stopped).
