# EZD-186 · Fix: no "React version detect" warning when lint runs from the repo root

- **ACs:** AC-EZD-186-1, AC-EZD-186-2
- **Complexity:** low (section 8)
- **User-visible result:** none for Josh on screen; every gate run's test step stops printing the "React version was set to detect" warning, and the root lint tests lint app code against React 19.3.1 instead of "latest".
- Phase: 1 · Planned by: planner · Date: 2026-10-25 · Status: planned

## 1. What to build

Cause (checked on develop, 2026-10-25, by running `calculateConfigForFile` and `lintText` against the root config): `eslint-config-next` 16.4.2 sets `settings.react.version: 'detect'` (`eslint-config-next/dist/index.js:144-146`). eslint-plugin-react 7.37.5 then resolves `react` from the linted file's folder, and falls back to `process.cwd()` when the file is not on disk (`lib/util/version.js` `resolveBasedir` line 29, `detectReactVersion` line 80). The root lint tests call `lintText(code, { filePath: 'app/src/…' })` with paths that are not on disk, from a process whose cwd is the repo root. `react` is an `app` dependency only (docs/architecture.md Dependencies, `react` row, Used in `app`), so it cannot be resolved there. The plugin prints the warning once per process and then assumes `999.999.999`. Linting from `app/` (the `app` lint script) and linting real files already find 19.3.1.

Fix: set an explicit version string. The plugin uses any value other than `detect` as is and never resolves `react` (`version.js` `getReactVersionFromContext`, line 109). The value is read from `app/package.json` `dependencies.react`. Check C1 keeps that value equal to the docs/architecture.md `react` row (`### Root config files`; `## Dependencies`), so the version stays written in one place.
