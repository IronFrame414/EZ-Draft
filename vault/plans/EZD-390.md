## 1. What to build

### Design (step design; Build steps, Decided and Do not touch below are the code-bound step)
The cause, found at this step (section 2 "Cause"), is in the test file's own harness, not in app code. The report is not expected behaviour: in production a request keeps its own cookies from start to end, so no production request goes through this path (section 2). Holding the alert lock would therefore hide a false alert, which the ticket row and rule 16 forbid. The fix changes only `app/src/lib/outbox/outbox-sync-conflicts.db.test.ts`, which the test-author writes (CLAUDE.md rule 5). The builder writes no app code unless the P3 check in D-Prod finds an app defect.
