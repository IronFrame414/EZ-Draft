# EZD-336 · Overseer: a cancelled phase PR gate run or auto-merge being off no longer holds the launcher

- **ACs:** AC-EZD-336-1 … AC-EZD-336-4
- **Complexity:** medium
- **Areas:** tooling, scripts
- **User-visible result:** a phase pull request whose check was cut off, or whose auto-merge is off, no longer leaves the build waiting for hours.
- Phase: 1 · Planned by: orchestrator (interactive fix mode, decision 2026-11-05) · Date: 2026-11-05 · Status: planned

## 1. What to build
Cause (2026-11-05, PR 5, head 1e9dbed4): push run 42049298178 was cancelled at `timeout-minutes: 30` in "Install browsers" (the Ubuntu package mirror stalled: one package took 4 minutes). It shares the required `gate` context with pull_request run 42049310266, which passed in 16m45s, so the PR stayed blocked. `gh pr checks` reports that run in bucket `cancel`, which `vault/tools/next_ticket.mjs` (EZD-250 D18) treats as a plain wait. Auto-merge was also off (the gate-phase unit's `gh pr merge --auto` meets the `ask` rule in `.claude/settings.json`). Normal runs take 17-19 minutes, on push and on pull_request alike.

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| Check states | From `statusCheckRollup` entries named `gate`: conclusion FAILURE, STARTUP_FAILURE or ACTION_REQUIRED → failed; CANCELLED or TIMED_OUT → cancelled; status not COMPLETED → pending. Failed wins over cancelled; the link is the entry's `detailsUrl` (or `no link`). | EZD-250 D18 |
| Texts | `none: phase N PR CI gate check failed (<pr>; <link>)` (unchanged), `none: phase N PR CI gate check cancelled (<pr>; <link>)`, `none: phase N PR auto-merge is off (<pr>)` (only when no gate run failed or was cancelled), else the existing waiting text. Unreadable output keeps the existing unreadable text. | this plan |
| Auto-merge | The launcher, not a unit (units meet the settings `ask` rule): once per wait text, `gh pr merge <pr> --auto --merge`; overseer log line `launcher: AUTO-MERGE: on for <pr>` or `launcher: AUTO-MERGE: FAILED: <first error line>`; no notification; then the normal wait. Never a repair unit for this text. | Q-0261, CLAUDE.md rule 11 |
| Re-run | The repair unit re-runs a cancelled or timed-out run once (`gh run rerun <id>`) when its log shows an outside cause (runner, network, package mirror, GitHub); attempt 2 or a cause in our code → as a failed run. A failed test is never re-run (rules 16, 20). | rule 17 |
| Timeout | 45 minutes. | CI run list 2026-11-05 (17-19 min) |
