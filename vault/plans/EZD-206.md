# EZD-206 · Snapping

- **ACs:** AC-EZD-206-1, AC-EZD-206-2
- **Complexity:** medium (section 8)
- **Areas:** geometry, testing, performance
- **User-visible result:** none on screen yet; the snap rules (endpoints, midpoints, wall faces, 90/45°, 1/2" increment) and the lookup that finds nearby walls exist as tested functions that the canvas hover (EZD-207) and the Wall tool's snap marker (EZD-210) use.
- Phase: 4 · Planned by: planner · Date: 2026-11-04 · Status: planned

## 1. What to build
Three modules in `@ezdraft/geometry` under `packages/geometry/src/snap/`: a uniform-grid spatial index (generic ids and rectangles), a wall snap index on top of it, and `snap()`. No UI, no data, no dependency. Units: model inches, +x east, +y north (EZD-203 Decided Axes).

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| Dependency | None. Own uniform grid; no `rbush`/`flatbush` (Stack lists no spatial package; geometry core is own pure TS) | architecture Stack, Named tools; 02 Geometry core |
| `Point`, `WallData` types | `import type { Point, WallData } from '../schema'` in `snap/snap.ts` and `snap/wall-snap-index.ts`; `import type { WallObject } from '../walls/wall'`; `import { wallFaceLines } from '../walls/wall'`; `import { pointsEqual } from '../tolerance'` | `schema/common.ts` line 6, `schema/wall.ts` line 40 (exported types); `walls/wall.ts` imports `../schema` the same way |
| Grid | Cells of `SPATIAL_INDEX_CELL_IN` (48) inches; cell of x = `Math.floor(x / cell)`; an entry is stored in every cell its bounds cover; storage `Map<string, Set<string>>` keyed `` `${cx},${cy}` `` plus `Map<string, Rect>` of entries | 11 rule 4 (index, not a scan); this plan |
| Query | Collect distinct ids from the covered cells; when covered cell count (`(cx1-cx0+1)*(cy1-cy0+1)`) exceeds the number of occupied cells, walk the occupied-cell map instead and keep cells in range (no huge loop at far zoom-out). Keep ids whose bounds meet the rect, edges inclusive (`a.minX <= b.maxX && b.minX <= a.maxX`, same for y). Return sorted ascending by `<` on the id string. `lastQueryExamined()` = number of distinct ids whose bounds were compared in the last `query`; `0` before any query | 11 rule 4; L-050 |
| Bad input, index | `createSpatialIndex` with `cellSizeIn` not finite or `<= 0` → `throw new RangeError('cell size must be a positive number')`; `upsert` with any non-finite bound, `minX > maxX` or `minY > maxY` → `throw new RangeError('bounds must be finite and ordered')`, index unchanged; `query` with such a rect → `[]` and `lastQueryExamined()` `0`; `remove` of an unknown id → `false` | L-052 |
| `upsert` | Replaces an existing id's bounds (removed from old cells first); `size()` counts ids | 11 rule 2 (update only what changed) |
| `wallBounds` | Min/max over `geometry.start`, `geometry.end` and the four ends of `wallFaceLines(data)` | EZD-203 Decided Face offsets |
| Wall snap index | `createWallSnapIndex` upserts each wall with `wallBounds`; keeps `Map<id, { wall, faces }>` (faces from `wallFaceLines`, computed once per upsert); `upsertWall` replaces; `removeWall` removes from both maps and returns `false` for an unknown id. It indexes every wall given; the caller passes one level's walls | 11 rules 2, 4; EZD-203 Performance row (one level) |
| Which objects | Walls only (phase 4 draws walls; openings arrive in phase 5); `spatial` takes any id, so EZD-208 can add others later | PHASES Slice 4/5; Q-0563 |
| Snap points per wall | endpoint: `geometry.start`, `geometry.end`; midpoint: midpoint of start→end; face: the nearest point on each of `left` and `right` face segments (clamped projection) | S03 Snap; Q-0570 (face = finished face); EZD-202 wall geometry |
| Order of work in `snap` | Validate; exactly one `spatial.query` per call, over `{ cursor.x − r, cursor.y − r, cursor.x + r, cursor.y + r }`, read by every object kind; an object snap that qualifies returns at once (no angle or increment step); only then the no-anchor or anchor branch. With `anchor` `null`, `referenceDirection` is ignored and no angle snap runs | 11 rule 4; Q-0570 priority |
| Capture | Radius `r = SNAP_CAPTURE_PX / pixelsPerInch` inches for the query rect (`cursor ± r`); a point qualifies when `distance * pixelsPerInch <= SNAP_CAPTURE_PX` (inclusive, as 09j reads "within" for closure) | Q-0570; 09j Snapping, Closure |
| Priority | Kinds in order endpoint, midpoint, face (each only when its toggle is on); the first kind with a qualifying point wins outright, even when a lower kind is nearer; within a kind the nearest wins; equal distance → lower `wallId` (`<`), then `start` before `end`, `left` before `right` | Q-0570; 09j rows 1–3 |
| Object snap result | `{ point: { x, y } (new object), kind, wallId }` | this plan |
| No anchor (first click) | No object snap → when `increment` is on and `incrementIn` finite `> 0`: each of x and y snaps to the nearest multiple of `incrementIn` with `Math.floor(v / inc + 0.5) * inc` (halfway up), kind `'increment'`; else cursor, kind `null` | Q-0585 (a); 03g halfway up |
| Anchor present | `v = cursor − anchor`; when `pointsEqual(cursor, anchor)` → cursor, kind `null`. Else `L = hypot(v)`, direction `θc = atan2(v.y, v.x)` | Q-0570; 03g tolerance |
| Angle reference | `referenceDirection` (the last wall's `end − start`) when finite and not `(0,0)`; otherwise the page: `(1, 0)`. Unit `ref = referenceDirection / hypot` | Q-0570 (last wall, or the page for a first wall) |
| Angle snap | `δ` = `θc − θref` in degrees normalised to `(−180, 180]`; `m = Math.round(δ / 45) * 45`; snaps when `angles` on and `abs(δ − m) <= SNAP_CAPTURE_DEG`, except `abs(m) === 180` with a last-wall reference (folding back, refused for typed angles). Direction `u = (c·ref.x − s·ref.y, s·ref.x + c·ref.y)` with exact `(c, s)` per `m`: 0 → (1,0); ±45 → (√½, ±√½); ±90 → (0, ±1); ±135 → (−√½, ±√½); ±180 → (−1, 0) (√½ = `Math.SQRT1_2`). Length `L' = L · cos((δ − m)·π/180)`; kind `'angle'`. No angle snap → `u = v / L`, `L' = L`, kind `null` | Q-0570; Q-0560; 09j Turn angle row 6; 09j Snapping rows 4–6 |
| Increment with an anchor | When `increment` on and `incrementIn` finite `> 0`: `L' = Math.floor(L' / inc + 0.5) * inc`; kind stays `'angle'` when set, else `'increment'`. Result `anchor + u · L'`; when neither angle nor increment applied, the result is `{ ...cursor }` exactly, kind `null`. Angle and increment combine (angle fixes direction, increment fixes length) | Q-0584 (a); Q-0569 (a) 1/2"; 09j rows 7, 8; 03g halfway up |
| Bad input, snap | `pixelsPerInch` not finite or `<= 0`, or a non-finite cursor coordinate → `{ point: { ...cursor }, kind: null, wallId: null }`, no query; non-finite `anchor` → treated as `null`; `incrementIn` not finite or `<= 0` → increment step skipped; `excludeIds` ids dropped from candidates; `settings` omitted → `DEFAULT_SNAP_SETTINGS`. Never throws | L-052 |
| Toggles | All on by default (`DEFAULT_SNAP_SETTINGS`) until EZD-219's popover sets them | Q-0570; Q-0569 (a); Q-0563 |
| Test numbers | Coordinates `toBeCloseTo(x, 9)`; exact grid results and `kind`/`wallId`/id lists `toEqual` | EZD-203 Decided Test numbers |
| Glossary code name | Spatial index → `SpatialIndex`, `createSpatialIndex` (00e "EZD-206 plan names it"); Snap marker stays with EZD-210 | 00e |
