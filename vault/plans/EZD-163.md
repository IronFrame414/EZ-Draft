# EZD-163 · Fix: find and remove the cause of the harness T12 "Worker closed" failure

- **ACs:** AC-EZD-163-1
- **Complexity:** medium (section 8)
- **User-visible result:** none on screen; the browser tests that check nothing secret reaches the browser stop failing at random, so a red gate always means a real problem.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

### Cause (found at planning, evidence in section 2)
- C1. "Worker closed" is thrown in exactly one place in the pinned Playwright: `playwright-core@1.64.1` `lib/coreBundle.js:24214`, when a page's or context's **service worker** closes. A read on a request or response made by a service worker (`allHeaders`, `headersArray`, `body`, `finished`, `response`, `sizes`) races that worker's lifetime (`coreBundle.js:14231-14236`, `raceWithPageClosure` uses `this._serviceWorker?.openScope`); page reads race the page instead and fail with "Target page, context or browser has been closed".
- C2. Since EZD-013 (8637f96, merged 2026-10-23 08:58) every page registers `/sw.js` (`app/src/app/layout.tsx:21`, `app/src/lib/pwa/register-sw.ts`). T12 was written 2026-10-20 (3ab81ab) and failed once in the EZD-035 loop after that merge (STATUS EZD-035 row; `vault/handoff/log/2026-10-23-17-44.md:9`).
- C3. Chromium reports the worker's own `GET /sw.js` (type `script`) as a request of the service worker; context listeners see it, page listeners do not (planner probes P1, P4, section 2).
- C4. T12 (`app/e2e/harness.spec.ts:171-173`) calls `allHeaders()` on every context request with no catch and awaits them all (`:191`). The worker request's raw headers did not arrive, so the test hung to the 60,000 ms timeout (`app/playwright.config.ts:92`; failure "after 1.0 min"; T12 normally takes 249 ms, `gate.log:4188`), and context teardown closed the worker, which rejected the read with "Worker closed".
- C5. The same pattern is in EZD-007f T21 (`app/e2e/gate-secret.spec.ts:32-44`, `allHeaders` and `body` on every context response) and EZD-007f T23 (`app/e2e/sign-in.spec.ts:265-273`, `body` on every context response, `.catch(() => '')`, which also counts an unread body as clean, against CLAUDE.md rule 16). All three are fixed here (Q-0268; PROCESS.md rule 20). Page-level listeners (`jobs.spec.ts`, `password-sign-in.spec.ts`, `entries.spec.ts`, `captcha.spec.ts`, `realtime.spec.ts`, `error-reporting.spec.ts`) never see worker traffic (C3) and are unchanged.
- C6 (plan gap 2026-10-26; run G1 and probes P5-P8, section 2): (i) an async read on a stopped service worker's response disconnects the whole browser (P5), so no test makes one; (ii) a response Chromium serves from its memory cache (`Network.requestServedFromCache`; the fonts on a second page load) has no body ("No data found for resource with given identifier": 20 of the 21 failed reads in G1); (iii) a body read that has not returned when the page's next document commits fails ("No resource with given identifier found"; G1 T21 `POST /sign-in`; P7: 30 of 30, even when started at the response); (iv) for a response whose request is aborted after its headers arrived (G1 T12 `POST /auth/confirm`: `loadingFailed net::ERR_ABORTED`, then `frameNavigated /`), Playwright resolves neither `finished()` (the client resolves it only on `requestfinished`, coreBundle 63886-63891 vs 63903) nor `body()` (P8).
- Reproduction: the original trace is gone (`app/test-results/` is rewritten every run). P3 reproduced `response.body: Worker closed`; R1 stops the worker on the real app. V1 (EZD-035's 20-run loop) is the verification.

### Fix
One collector, `captureTraffic`, used by T12, T21 and T23. It never makes an async read on a service worker's request or response (synchronous getters only). A GET body of the app origin that Chromium cannot give (service worker, memory cache, dropped at a navigation) is fetched again through `context.request` (Node side, same cookies). Page reads start at the response and are bounded: `settle()` fails after 20,000 ms naming what is pending. Non-GET bodies the browser drops (C6 iii-iv) cannot be read or fetched again: QP-1.

Step 1 algorithm (`captureTraffic(context, opts)`):
1. `origin = new URL(opts.baseURL).origin`; `limit = opts.settleTimeoutMs ?? TRAFFIC_SETTLE_TIMEOUT_MS`; `recording = true`; arrays `requests: TrafficRequest[]`, `responses: TrafficResponse[]`, `pending: { label: string; done: boolean; promise: Promise<void> }[]`, `swRefetch: { entry: TrafficResponse; url: string }[]`.
2. `context.on('request', r)`: return when `!recording`. `sw = r.serviceWorker() !== null`; push `entry = { method: r.method(), path: new URL(r.url()).pathname, resourceType: r.resourceType(), fromServiceWorker: sw, headerNames: [] }` into `requests` now (event order). When `sw`: `entry.headerNames = Object.keys(r.headers()).map(lower)`. Else push a pending read `r.allHeaders()` that sets `entry.headerNames = Object.keys(h).map(lower)` and, on rejection, stores the error for settle.
3. `context.on('response', x)`: return when `!recording`. `req = x.request()`; `sw = req.serviceWorker() !== null`; push `entry = { method: req.method(), path, resourceType: req.resourceType(), status: x.status(), fromServiceWorker: sw, headerValues: [], body: null, failed: false }` into `responses` now.
   - When `sw`: `entry.headerValues = Object.values(x.headers())`; when `req.method() === 'GET'` and `new URL(x.url()).origin === origin`, push `{ entry, url: x.url() }` to `swRefetch`; otherwise `entry.body` stays `null`.
   - Else, in the handler and without awaiting anything first, keep `{ entry, x }` in a list `page` and start two pending reads with the same label (never `finished()`, C6 iv; `body()` waits for the end itself, coreBundle 14540): header read `x.allHeaders()` → `entry.headerValues = Object.values(h)`; body read `x.body()` → `entry.body = buf.toString('utf8')`, and on rejection `entry.body = ''` for status 300-399, else `entry.body` stays `null` and the item is marked `bodyLost` (not a stored error).
4. Every pending promise gets its rejection handler when it is created (no unhandled rejection after a timeout) and sets `done = true` when it settles, whether it resolved or rejected. A rejection of a header read (`allHeaders()` on a request or response, including one the context or page closing causes) is stored on its item with its label. When several are stored, `settle()` throws the first in event order (lowest index in `pending`).
5. `stop()`: `recording = false`; `context.off` both listeners. Idempotent.
6. `settle()`: `stop()`; then `Promise.race([Promise.all(pending promises), timer(limit)])` with one `setTimeout`, cleared after. On timeout: a body read still pending for a `GET` response of `origin` is marked `bodyLost` (C6 iii-iv: the body is gone); every other not-done item is listed and `settle()` throws `Error('traffic reads pending after <limit> ms: ' + labels joined with ', ')`; label = `` `${method} ${path}` `` (path only: a query can hold a `token_hash`, STATUS EZD-016a security note). Then a stored rejection is thrown as `Error('traffic read failed: <label>: <message first line>')`. Then for each `{ entry, x }` of `page`: `entry.failed = x.request().failure() !== null`, and when failed `entry.body = ''`. Then, in event order, fetch again: every `swRefetch` item (`entry.headerValues = res.headersArray().map(h => h.value)` and the body) and every `bodyLost`, not failed, `GET` response of `origin` (body only; its header values stay the browser's): `res = await context.request.get(url, { maxRedirects: 0 })`, `entry.body = (await res.body()).toString('utf8')`; a throw sets `entry.body = null`. A `bodyLost` non-GET keeps `null` (QP-1). Return `{ requests, responses }`. A second `settle()` call returns the same result object. Callers call `settle()` before the context closes (T21 and T23 close their own context after it; T12, R1 and R2 use the fixture context); a header read the context close rejects is a stored rejection, so a late `settle()` throws `traffic read failed: …`, never returns partial data.
