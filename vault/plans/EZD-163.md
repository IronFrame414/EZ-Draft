# EZD-163 · Fix: find and remove the cause of the harness T12 "Worker closed" failure

- **ACs:** AC-EZD-163-1
- **Complexity:** medium (section 8)
- **User-visible result:** none on screen; the browser tests that check nothing secret reaches the browser stop failing at random and read every response the browser gets, so a red gate always means a real problem.
- Phase: 1 · Planned by: planner · Date: 2026-10-27 (re-plan after Q-0337 (b)) · Status: planned

## 1. What to build

### Cause (evidence in section 2)
- C1. "Worker closed" is thrown only when a service worker closes: an async read on a request or response the worker made races its lifetime (`coreBundle.js` 14231-14236, 24210-24215). Since EZD-013 every page registers `/sw.js`; T12 (`harness.spec.ts:171-173`) awaited `allHeaders()` on the worker's `GET /sw.js` (P1, P4), hung to the 60,000 ms timeout, and teardown closed the worker.
- C2. Reading bodies from `Response` objects cannot be made complete (memory-cache hits, non-GET bodies dropped at the next commit, aborted reads that never settle: G1, P5-P8). T21 (`gate-secret.spec.ts:31-44`) and T23 (`sign-in.spec.ts:263-274`) share the pattern and count an unread body as clean.

### Fix (Q-0337 (b))
T12, T21, T23 route every request through `captureTraffic`: `route.fetch` in Node, read the whole body, then `route.fulfill`, so the page gets only bytes the test read; no async read on any `Request` or `Response` object anywhere.

Step 1 algorithm, `captureTraffic(context, opts = {})`:
1. `fetchLimit = opts.fetchTimeoutMs ?? TRAFFIC_FETCH_TIMEOUT_MS`; `settleLimit = opts.settleTimeoutMs ?? TRAFFIC_SETTLE_TIMEOUT_MS`; `recording = true`; `requests: TrafficRequest[]`, `responses: TrafficResponse[]`; a `Map<Request, Item>` where `Item = { entry: TrafficRequest; index: number; done: boolean; finished: Promise<void>; resolve(): void; failure: string | null }`.
2. `entryFor(req)`: return the map's item; when absent and `recording`, create one (`entry = { method: req.method(), path: new URL(req.url()).pathname, resourceType: req.resourceType(), fromServiceWorker: req.serviceWorker() !== null, isNavigation: req.isNavigationRequest(), external: false, headerNames: [] }`, pushed to `requests`; `index` = its position), store and return it; when absent and not `recording`, return `null`. Synchronous getters only.
3. `context.on('request', (req) => { entryFor(req); })` (the event comes before the route, P12; `entryFor` makes the order irrelevant).
4. `await context.route(() => true, handler)`; `captureTraffic` resolves only after this, so no request of the test goes unrouted. The route stays until the context closes.
5. `handler(route)`, whole body in `try`/`catch` (a throw becomes `item.failure` = first line of its message; the handler never rejects); once item a has returned an item, a `finally` sets its `done = true` and resolves its `finished`:
   a. `item = entryFor(route.request())`; `null` → `await route.fallback()`, return.
   b. `url = new URL(req.url())`; protocol not `http:`/`https:`, or `!isLoopback(url)` → `entry.external = true`, `await route.fallback()` (the net guard of EZD-021 still sees it), return.
   c. `entry.headerNames` = lower-cased `Object.keys(req.headers())` (what `route.fetch` sends; `coreBundle.js` 60815).
   d. `res = await route.fetch({ maxRedirects: entry.isNavigation ? 0 : 20, timeout: fetchLimit })` (no `postData` option: `route.fetch` sends the request's own post data, `coreBundle.js` 60866); `buf = await res.body()`; on a throw of either: `item.failure` = first line of the message, `await route.abort().catch(() => {})`, return.
   e. Push `{ method, path, resourceType, status: res.status(), fromServiceWorker, headerValues: res.headersArray().map((h) => h.value), body: buf.toString('utf8'), redirectedTo: null }` to `responses`.
   f. When `entry.isNavigation` and `REDIRECT_STATUSES` has the status and `res.headers()['location']` is set: when the status is 307 or 308 and the method is not `GET`, set `item.failure = 'redirect <status> keeps the method'`, abort as in d, return; else `target = new URL(location, req.url())`, set the response's `redirectedTo = target.pathname`, and `await (route as unknown as RedirectableRoute)._redirectNavigationRequest(target.toString())`; when that property is not a function set `item.failure = 'route redirect unavailable'` and abort. The browser then navigates to `target` as a new, routed request (P10).
   g. Otherwise `await route.fulfill({ status: res.status(), headers, body: buf })`, `headers` = `res.headers()` without `DROPPED_RESPONSE_HEADERS`.
6. `stop()`: `recording = false`. Idempotent. Requests recorded before it are still handled in full; later ones fall through (5a).
7. `settle()`: first call only (later calls return the same promise): `stop()`; wait for `Promise.all(items' finished)` raced with one `setTimeout(settleLimit)`, cleared after. Timeout: throw `Error('traffic reads pending after <settleLimit> ms: ' + labels of items not done, in index order, joined ', ')`. Then the item with the lowest index whose `failure` is set: throw `Error('traffic read failed: <label>: <failure>')`. Label = `` `${method} ${path}` `` (path only: a query can hold a `token_hash`, STATUS EZD-016a security note). Then `cookieValues = (await context.cookies()).map((c) => c.value)`; resolve `{ requests, responses, cookieValues }`.
Callers settle before their context closes.
