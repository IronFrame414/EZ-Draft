# EZD-163 · Fix: find and remove the cause of the harness T12 "Worker closed" failure

- **ACs:** AC-EZD-163-1
- **Complexity:** medium (section 8)
- **User-visible result:** none on screen; the browser tests that check nothing secret reaches the browser stop failing at random, so a red gate always means a real problem.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

### Cause (found at planning, evidence in section 2)
- C1. "Worker closed" is thrown in exactly one place in the pinned Playwright: `playwright-core@1.64.1` `lib/coreBundle.js:24214`, when a page's or context's **service worker** closes. A read on a request or response made by a service worker (`allHeaders`, `headersArray`, `body`, `finished`, `response`, `sizes`) races that worker's lifetime (`coreBundle.js:14231-14236`, `raceWithPageClosure` uses `this._serviceWorker?.openScope`); page reads race the page instead and fail with "Target page, context or browser has been closed".
- C2. Since EZD-013 (8637f96, merged 2026-10-23 08:58) every page registers `/sw.js` (`app/src/app/layout.tsx:21`, `app/src/lib/pwa/register-sw.ts`). T12 was written 2026-10-20 (3ab81ab) and failed once in the EZD-035 loop after that merge (STATUS EZD-035 row; `vault/handoff/log/2026-10-23-17-44.md:9`).
- C3. Chromium reports the worker's own `GET /sw.js` (type `script`) as a request of the service worker; context listeners see it, page listeners do not (planner probes P1, P4, section 2).
- C4. T12 (`app/e2e/harness.spec.ts:171-173`) calls `allHeaders()` on every context request with no catch and awaits them all (`:191`). The worker request's raw headers did not arrive, so the test hung to the 60,000 ms timeout (`app/playwright.config.ts:92`; failure "after 1.0 min"; T12 normally takes 249 ms, `gate.log:4188`), and context teardown closed the worker, which rejected the read with "Worker closed".
- C5. The same pattern is in EZD-007f T21 (`app/e2e/gate-secret.spec.ts:32-44`, `allHeaders` and `body` on every context response) and EZD-007f T23 (`app/e2e/sign-in.spec.ts:265-273`, `body` on every context response, `.catch(() => '')`, which also counts an unread body as clean, against CLAUDE.md rule 16). All three are fixed here (Q-0268; PROCESS.md rule 20). Page-level listeners (`jobs.spec.ts`, `password-sign-in.spec.ts`, `entries.spec.ts`, `captcha.spec.ts`, `realtime.spec.ts`, `error-reporting.spec.ts`) never see worker traffic (C3) and are unchanged.
- Reproduction (ticket Scope): the original trace no longer exists (`app/test-results/` is rewritten every run, `retain-on-failure`). The mechanism is reproduced on purpose instead: P3 (section 2) gave `response.body: Worker closed` for a read pending when the worker stopped, and test R1 does the same on the real app. The 20-run loop of the ticket (EZD-035's V1 method) is the verification, V1.

### Fix
One collector, `captureTraffic`, used by T12, T21 and T23. It never calls an async read on a service worker's request or response; for those it uses synchronous getters and fetches GET bodies again through `context.request` (Node side, same cookies, no worker). Page reads are bounded: `settle()` fails after 20,000 ms and names what is still pending, so any other hang fails fast and says why.

Step 1 algorithm (`captureTraffic(context, opts)`):
1. `origin = new URL(opts.baseURL).origin`; `limit = opts.settleTimeoutMs ?? TRAFFIC_SETTLE_TIMEOUT_MS`; `recording = true`; arrays `requests: TrafficRequest[]`, `responses: TrafficResponse[]`, `pending: { label: string; done: boolean; promise: Promise<void> }[]`, `swRefetch: { entry: TrafficResponse; url: string }[]`.
2. `context.on('request', r)`: return when `!recording`. `sw = r.serviceWorker() !== null`; push `entry = { method: r.method(), path: new URL(r.url()).pathname, resourceType: r.resourceType(), fromServiceWorker: sw, headerNames: [] }` into `requests` now (event order). When `sw`: `entry.headerNames = Object.keys(r.headers()).map(lower)`. Else push a pending read `r.allHeaders()` that sets `entry.headerNames = Object.keys(h).map(lower)` and, on rejection, stores the error for settle.
3. `context.on('response', x)`: return when `!recording`. `req = x.request()`; `sw = req.serviceWorker() !== null`; push `entry = { method: req.method(), path, resourceType: req.resourceType(), status: x.status(), fromServiceWorker: sw, headerValues: [], body: null, failed: false }` into `responses` now.
   - When `sw`: `entry.headerValues = Object.values(x.headers())`; when `req.method() === 'GET'` and `new URL(x.url()).origin === origin`, push `{ entry, url: x.url() }` to `swRefetch`; otherwise `entry.body` stays `null`.
   - Else push one pending read: `const failure = await x.finished()`; when `failure !== null`: `entry.failed = true`, `entry.body = ''`, `entry.headerValues = Object.values(x.headers())`; else `entry.headerValues = Object.values(await x.allHeaders())`, then `entry.body = (await x.body()).toString('utf8')`; when `body()` rejects: `entry.body = status 300-399 ? '' : null`. Any other rejection is stored for settle.
4. Every pending promise gets its rejection handler when it is created (no unhandled rejection after a timeout) and sets `done = true` when it settles, whether it resolved or rejected. A rejection (including `finished()`, `allHeaders()` or `body()` rejecting because the context or page closed, except the `body()` case of item 3) is stored on its pending item with that item's label. When several are stored, `settle()` throws the first in event order (lowest index in `pending`).
5. `stop()`: `recording = false`; `context.off` both listeners. Idempotent.
6. `settle()`: `stop()`; then `Promise.race([Promise.all(pending promises), timer(limit)])` with one `setTimeout`, cleared after. On timeout throw `Error('traffic reads pending after <limit> ms: ' + not-done labels joined with ', ')`; label = `` `${method} ${path}` `` (path only: a query can hold a `token_hash`, STATUS EZD-016a security note). After all settle, a stored rejection is thrown as `Error('traffic read failed: <label>: <message first line>')`. Then for each `swRefetch` item in order: `res = await context.request.get(url, { maxRedirects: 0 })`; `entry.headerValues = res.headersArray().map(h => h.value)`; `entry.body = (await res.body()).toString('utf8')`; a throw from `get` sets `entry.body = null`. Return `{ requests, responses }`. A second `settle()` call returns the same result object. Callers call `settle()` before the context closes (T21 and T23 close their own context after it; T12, R1 and R2 use the fixture context, closed after the test); a read that the context close rejects is a stored rejection, so a late `settle()` throws `traffic read failed: …`, never returns partial data.
