# EZD-380 · Fix: the EZD-133 W1 money-pages smoke test fails with ECONNRESET when another lane runs a gate

- **ACs:** AC-EZD-380-1 (`vault/spec/acceptance-criteria.md:868`)
- **Complexity:** medium (section 8)
- **Areas:** testing, tooling, docs
- **User-visible result:** the money-hiding smoke check stops failing at random when two builds are checked at once, so builds stall less often; the app itself does not change.
- Phase: 4 · Planned by: planner · Date: 2026-11-10 · Status: planned

## 1. What to build

Cause (E1-E6 in section 2): the browser-test web server (`next start`, test only; production is Vercel, ARCH Hosting) closes an idle kept-alive connection 6,000 ms after its last response (Node 22: `keepAliveTimeout` 5,000 + `keepAliveTimeoutBuffer` 1,000). `captureTraffic`'s `route.fetch` (`app/test-harness/e2e/traffic.ts:160`) runs on Playwright's `new http.Agent({ keepAlive: true })` (playwright-core 1.64.1 `lib/coreBundle.js:27702`). That agent keeps idle sockets until the server closes them (E4). A request sent on a socket idle for 5,996-6,000 ms gets `read ECONNRESET` (E4 reproduces it with no load). Load makes the 6 s boundary likely: slower responses make a page burst open more sockets, and that reaches sockets last used about 5.9 s before (E2). Not the database (the reset files are static chunks) and not the server start (E3). Fix: the test web server never closes an idle connection during a run, which closes the race for every client of that server (route.fetch, `page.request`, browsers). No retry (ticket row).

Order (D-Order): test-author steps 1-3, code-reviewer test review, builder steps 4-5.
