  ```ts
  // All lengths are decimal inches (03 Architecture rule 5). Wall-local frame:
  // x along the wall from its start (0..length), y up from the floor, z through the thickness (0..thickness).
  export interface WallOpening { kind: 'door' | 'window'; offset: number; width: number; height: number; sill: number }
  //   offset = x of the opening's near edge; sill = y of its bottom edge (0 for a door).
  export interface WallCeiling { heightAtStart: number; rise: number; run: number }
  //   ceiling plane height at x = heightAtStart + x * rise / run (rise may be negative: falling slope).
  export interface WallInput { length: number; thickness: number; ceiling: WallCeiling; openings: WallOpening[] }
  export interface WallFace { outer: Array<[number, number]>; holes: Array<Array<[number, number]>> }  // (x, y) points
  export function topHeightAt(wall: WallInput, x: number): number;
  export function wallFace(wall: WallInput): WallFace;
  ```
  - "4:12" means rise 4 per run 12 (S05 Room ceiling summary writes pitch as `n/12`).
  - In wall-local terms, a sloped ceiling plane cut along a straight wall gives a straight top edge, so `heightAtStart` plus a signed rise / run along the wall is the general case for one wall. Mapping a room's ceiling (03: "heights by point or pitch"; S05: heights at points, or pitch) into these two numbers is EZD-504's job.

## Tests (written by test-author before any code)
All tests are Vitest unit tests in `spikes/EZD-030-wall-openings/src/wall-mesh.test.ts`, in Node. The Done-when tests carry the title prefix `EZD-030 done when:` (EZD-000 Tests section).

**Fixture inputs.** No source gives wall, door, window or ceiling sizes for this spike. The ticket fixes only "a door hole and a window hole" and "4:12". The inputs below are the planner's test-fixture choice: a technical choice under CLAUDE.md rule 4, not a product value, and they are used only by this throwaway test. Every expected value is worked out from them by the formula shown.

They are chosen so that:
- the wall is the 12' wall of the synthetic 12' × 10' room (EZD-016b, EZD-210);
- the window head (102") is above the low-end ceiling height (96"), so a hole cut against a flat 96" box would fail;
- every opening stays at least 2" below the sloped top in W1 and W2.

- **W1 (rising):** `length 144`, `thickness 4.5`, `ceiling { heightAtStart: 96, rise: 4, run: 12 }`, openings:
  - door `{ offset 12, width 36, height 80, sill 0 }`, so x 12–48, y 0–80;
  - window `{ offset 84, width 36, height 60, sill 42 }`, so x 84–120, y 42–102.
- **W2 (falling):** same as W1 but `ceiling { heightAtStart: 144, rise: -4, run: 12 }`.

**Tolerances.**
- Coordinates: 1/64 in = 0.015625 in (03 Architecture rule 5, "fixed comparison tolerance of 1/64 inch").
- Areas: 0.5 sq in. One opening edge 1/64 in off moves the area by at least 36 × 1/64 = 0.5625 sq in (36 in is the fixture's shortest opening edge), so 0.5 catches it. Float32 rounding at these sizes is about 0.01 sq in.
- Volume: 0.5 × 4.5 = 2.25 cu in.

**Mesh reading.** The test reads `geometry.getAttribute('position')` and `geometry.getIndex()`, and handles both indexed and non-indexed output. A triangle "lies on plane P" when all three vertices are within 1/64 in of P. Point coverage is tested in (x, y) against triangles lying on z = 0 (front) or z = 4.5 (back).

**Formulas for W1.**
- Top height: `top(x) = 96 + x·4/12`.
- Gross face area: 144 × (96 + 144)/2 = 17,280.
- Door area: 36 × 80 = 2,880. Window area: 36 × 60 = 2,160.
- Net face area: 17,280 − 2,880 − 2,160 = 12,240.
- Sloped top length: √(144² + 48²) = 48√10 = 151.7893.
