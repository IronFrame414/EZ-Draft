# External-attacker security audit, 2026-11-27

What a person with no account can reach or learn. Read-only audit of `develop` at `494c0451` plus 30 plain GET requests to `https://ezdraft.ezcontractorbinder.com` with no credentials. Nothing was posted, no sign-in, sign-up or reset was tried, no gate, e2e, database test or server was run, no `.env` file was read. `pnpm audit --prod` was run.

No high finding. No path was found by which an outsider reads or changes any company's data.

One correction to the brief: the Supabase project address and publishable (anon) key are **not** in the signed-out pages. They are sent only to a signed-in member by `/api/realtime/token` (`app/src/app/api/realtime/token/route.ts:33-37`; `NEXT_PUBLIC_SUPABASE_*` is read only in `app/src/server/db/env.ts`; the live `/sign-in` HTML holds neither). So no live call to Supabase was made; everything about the anon key below is "verified in code". The key is still not a secret (every member, past or present, has it), so the findings assume an attacker may hold it.

## Checked and found safe

Pages and routes without a session
- Public paths are only `/sign-in`, `/auth/confirm`, `/terms`, `/invite/<token>`, `/api`, `/dev` (`public-paths.ts`). Live: `/` answers 307 to `/sign-in`; `/api/projects`, `/api/realtime/token`, `/api/jobs/sweep` answer 401; `/dev/shell`, `/%64ev/shell`, `/dev/shell.txt`, `/dev/captcha/stub`, `/dev/sw-offline/worker`, `/dev/cloud-check/read`, `/api/dev/jobs` answer 404; `//dev/shell` is redirected to `/dev/shell` (404); `/.env` and `/.git/config` answer 404.
- Route handlers with no session check are only `api/health` (X7), `api/monitoring` (X3), `api/share-links/resolve` (X8), `api/jobs/sweep` (cron secret, constant-time compare) and three `/dev` routes (404 on Vercel, twice over).
- Server actions: one file (`server/auth/actions.ts`), all meant for signed-out use. Each that reaches Auth takes a throttle slot first and fails closed when the throttle is down. Answers are fixed codes; wrong password, unknown email and unconfirmed account give one answer.
- `public/` holds only icons, the service worker and one licence text.

Anon key
- PostgREST: `private.api_request_gate()` runs before every request and refuses `anon` and `authenticated` without the server-held header; the only exception is `anon` on `/rpc/health`. GraphQL goes through the same gate. `anon` holds no table grant; the functions granted to `anon` (`health`, the two sign-in throttle functions, `error_tunnel_take`, `record_error_alert`, `resolve_share_link`, `resolve_sent_package`) are all behind the gate except `health`.
- Storage: five buckets, all `public = false`, no policy for `anon`.
- Realtime: `realtime.messages` policies are for `authenticated` only; broadcasts are private.

Sign-up, sign-in, reset, invites
- Sign-up is invite-only: the before-user-created hook refuses any email that is not an active member or a live invitee, also for direct Auth calls. A password set on an unconfirmed account is wiped by `auth_users_password_guard`, so an outsider cannot pre-register an invitee and wait.
- No password reset flow exists in the app; a direct recovery call sends an email with no link and no code.
- The emailed sign-in link and the invite link do nothing on GET (only the button's POST verifies), and both pages send `Referrer-Policy: no-referrer` and `no-store` (live).
- Invite link token: 43 base64url characters from HMAC-SHA256, only its SHA-256 stored, 7-day life. Live: a made-up token shows the "invalid" page and no company name.
- Return path: live, `/sign-in?next=//evil.example/x` puts no `next` field in the form; a path with quotes and a script tag is HTML-escaped. `returnPath` was read in full.
- Captcha: the live sign-in page carries a Turnstile site key, so the security check is switched on in the app.
- Cookies: session and sign-in cookies are `httpOnly`, `SameSite=Lax`, `Secure` with the `__Host-` prefix on https.

Share links
- 32 random bytes, only the hash stored, expiry and revoke enforced in the database, expired answer gives the company name only, token travels in a POST body. No client page exists yet, so a signed-out viewer gets nothing but `{ status, expiresAt }`.

Headers, CORS, leaks
- Live: HSTS two years, `X-Content-Type-Options: nosniff`, `frame-ancestors 'self'`, camera, microphone and location off. No `Access-Control-Allow-Origin` on `/api/health` for a foreign Origin. Writes to `/api` from another origin are refused (403) except the error tunnel.
- Source maps: live request for a chunk's `.map` answers 403; Vercel builds emit none.
- Client bundle (local build under `app/.next/static`): no Supabase address, no publishable key, no secret key, gate secret, cron secret or private key text.
- Error answers are fixed codes (`{ error: { code, message_key } }`); route failures report the error name, never its message.

Webhooks and dependencies
- No inbound webhook route exists. The cron route needs `CRON_SECRET`.
- `pnpm audit --prod`: "No known vulnerabilities found".

Not covered
- Cloud settings (Supabase Auth captcha and rate limits, Realtime private-only, Vercel preview deployment protection and environment variables). Preview deployments, if public, use the same code; whether they point at the production database was not checked.
- No live call to Supabase (no key was available without reading `.env`). No POST of any kind was sent, so X1, X3 and X4 are from the code only.
