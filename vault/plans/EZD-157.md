# EZD-157 · Fix: realtime hub keeps project and user channels apart

- **ACs:** AC-EZD-157-1 (`vault/spec/acceptance-criteria.md`)
- **Complexity:** low (section 8)
- **User-visible result:** none on a product screen; a page that opens a project channel with a bad project id can no longer share or close the sign-out channel, and a bad id costs no network request.
- Phase: 1 · Planned by: planner · Date: 2026-10-24 · Status: planned

## 1. What to build

Defect (sweep item 28, `vault/tickets/sweep-2026-10-24.md`; Q-0268): `app/src/lib/realtime/hub.ts` keys project entries by the bare id (line 378) and the user entry by `USER_KEY = 'user'` (line 70), so `hub.project('user')` shares the user channel's entry (lines 305-311), and project ids are not checked as UUIDs. The ticket row allows "key entries by topic" or "refuse a non-UUID project id"; this plan does both (Decided D1, D2), because the sweep item names both faults and Q-0268 parks none.

No data, no migration, no route, no screen.

### Decided for the builder
| Choice | Decision | Source |
| --- | --- | --- |
| D1 Entry key | Project entry key = `projectTopic(projectId)` (`project:<lower-cased id>`); user entry key stays `USER_KEY = 'user'`. A project key always starts `project:`, so it never equals `'user'` | ticket row Scope ("key entries by topic"); `topics.ts` `projectTopic` |
| D2 Valid project id | Valid when `parseTopic(projectTopic(projectId)) !== null`: a canonical UUID after lower-casing. No trimming: a leading or trailing space is invalid. `parseTopic` and `UUID_RE` in `topics.ts` stay as they are (no new export) | ticket row Scope ("refuse a non-UUID project id"); `topics.ts` lines 3, 15-22; EZD-018 Step 1 (the database refuses any other topic form) |
| D3 Invalid id: no throw, own entry | `hub.project(<invalid>)` does not throw. When `ended` is true it returns `closedHandle()` as today (that check stays first). Otherwise it gets or creates the entry under its key (D1); a new invalid entry is created by `newEntry(key, 'project')` and then `refused = true` is set at once, so `openChannel`, `tokenFailed` and the reconnect paths never open or touch it (they already skip `refused` entries) | ticket AC ("throws or gets its own entry": own entry chosen); `hub.ts` lines 158, 184. Planner's choice: a throw would crash `/dev/realtime` and `/dev/jobs`, which pass `''` when the URL has no `project` (`app/src/app/dev/realtime/page.tsx`; `JobsProbe.tsx` line 37) |
| D4 Invalid id: status | The new invalid entry starts `connecting` (from `newEntry`); the hub queues `void Promise.resolve().then(() => { if (!ended) { setStatus(entry, 'refused'); entry.settle('refused'); } })` when it creates the entry, so `onStatus` callbacks registered right after `hub.project()` receive `'refused'` once and `ready` resolves `'refused'`. No timer | EZD-018 Step 5 item 4 (`refused`, `ready` resolves `'refused'`); 11 rule 11 (no timers); callers register `onStatus` after acquiring (`RealtimeProbe.tsx`) |
| D5 Invalid id: no side effects | An invalid handle never increments `openHandles`, never calls `start()`, `ensureUserEntry()` or `openChannel()`, so it causes no `fetchToken`, no `adapter.connect`, no `adapter.channel` and holds no user channel. Its `release()` removes its callbacks; when its entry has no handles left it calls `drop(entry)` (no channel to remove); it never decrements `openHandles` and never drops the user entry. Hold a `counted = valid` flag in `acquire` and guard the two `openHandles` lines of `release()` with it | sweep item 28 ("the user channel is untouched"); EZD-018 Step 5 item 1 (user channel removed with the last counted handle); item 3 (requests only on events) |
| D6 Session ended | `endSession()` is unchanged: it already sets every entry, invalid ones included, to `closed` and settles `ready`; the D4 microtask then does nothing (`ended` guard) | EZD-018 Step 5 item 8 |
| D7 Upper-case id | Unchanged behaviour: an upper-case UUID is lower-cased by `projectTopic` and shares the lower-case id's entry and channel | EZD-018 Step 5 `topics.ts` (lower-cased UUID); `hub.ts` line 378 today |
| D8 Callers | No caller changes: `index.ts`, `react.ts`, `RealtimeProbe.tsx`, `JobsProbe.tsx` keep calling `hub.project(projectId)` as today | `grep` of `app/src` for `.project(` (only those files) |
