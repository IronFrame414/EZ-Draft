# EZD-365 · Fix: the full gate tests the committed commit only, never other units uncommitted files

- **ACs:** AC-EZD-365-1 (T1-T3), AC-EZD-365-2 (T4)
- **Complexity:** low
- **Areas:** tooling, testing
- **User-visible result:** the phase gate is no longer turned red by plan files that other launcher units leave uncommitted in the main checkout; it tests exactly what the phase PR ships.
- Phase: 1 · Planned by: orchestrator (session 13) · Date: 2026-11-10 · Status: ready

## 1. What to build
Josh 2026-11-10 chat ("yes" to: make the gate's tests read only committed files).

On macOS the gate runs its checks as `ezdraft` from a run copy made by `makeSnapshot(dir)` (`scripts/gate-user.mjs` C9), which commits HEAD plus every tracked change and every untracked file (`git add -A`). That is right for a ticket worktree, whose uncommitted work is the thing under test. The phase gate (`gate.mjs . --full`, gate-phase SKILL step 1) runs on the main checkout, where plan, questions and build units leave their own in-flight files uncommitted by design. Those files reach the run copy, the ledger-copy fixtures copy them (`scripts/launcher/test-utils/ledger-copy.mjs:17`), and the suites fail with `fixture ledger check: LEDGER INVALID`. This stalled gate-phase 4 many times on 2026-11-09 and 2026-11-10 (EZD-5603a, 5604a/b, 135, 214, 218, 219, 224, 208b, 235: overseer log). The phase PR ships only commits, so the full gate tests the committed HEAD.
