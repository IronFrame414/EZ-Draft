# EZD-296 · Fix: the sources bucket limits file types and size

- **ACs:** AC-EZD-296-1, AC-EZD-296-2
- **Complexity:** medium
- **Areas:** migrations, security, storage, testing
- **User-visible result:** uploaded originals (scans, PDFs, DXFs, photos) are refused by Storage unless they are an allowed file type and within the size limit, so nobody can store a web page or script as a "source file".
- Phase: 1 · Planned by: planner · Date: 2026-11-02 · Status: planned

Types `L` = `['image/vnd.dxf', 'model/gltf-binary', 'application/pdf', 'image/jpeg', 'image/png', 'image/heic']` (Q-0513 (a), Josh 2026-11-03: photos and images JPEG, PNG, HEIC; order reports PDF only; field measure files the photo types; DXF, Polycam GLB, PDF as named); size `N` = 52,428,800 bytes (Q-0514 (a), Josh 2026-11-03: 50 MiB per file, no setting or billing change).

Data: no table or policy change. One forward-only migration sets `storage.buckets` `sources` `allowed_mime_types` = `L`, `file_size_limit` = `N` (Q-0477; same shape as EZD-290's merged `20261102201341_set_media_bucket_limits.sql`, proven on the pinned stack by its T6, L-009).
